# v0.84.0 td-dropdown rich rows — manual screen-reader checklist

Automated: `npm run test:a11y` (Chromium tree: listbox > group > option names) and the WTR test
`src/form/td-v084-dropdown-rich.engines.browser-test.js` (ids, `aria-describedby`, keyboard). This list covers what only
a real screen reader shows. Fixture: Storybook **Form/Dropdown → Dòng giàu thông tin + nhóm**.

Run once with **VoiceOver + Safari (macOS)** and once with **NVDA + Firefox (Windows)**. Tick each, note the exact
announcement when it differs.

| # | Step | Expect | VO/Safari | NVDA/Firefox |
|---|------|--------|-----------|--------------|
| 1 | Tab to the trigger | "Nơi xuất, combobox/pop-up button, Kho Hà Nội" — no icon name read | | |
| 2 | ↓ to open, move into the first group | The group name "Kho hàng" is announced on entering the group | | |
| 3 | On "Kho Hà Nội" | "Kho Hà Nội" (name = label only), then the description "Cầu Giấy Đang mở 128 SP"; not the label twice | | |
| 4 | ↓ to "Kho Đà Nẵng" | Skipped by ↓ (disabled); with VO cursor / NVDA browse it reads "dimmed / unavailable" | | |
| 5 | ↓ across into "Cửa hàng" | The new group name "Cửa hàng" is announced; headers are never a stop | | |
| 6 | "Bán online" (icon only) | "Bán online", nothing else | | |
| 7 | Type "saigon" in the search | "1 kết quả" is announced (polite); the list shows "Kho Sài Gòn" | | |
| 8 | Type "zzz" | "Không tìm thấy kết quả" | | |
| 9 | Clear the search, story with `create-label` (add it in devtools), press End | The create row is reached last and announced | | |
| 10 | Enter on an option, then Escape inside a td-modal | Menu closes first, focus on the trigger, the modal stays | | |

Known: Chromium's tree lists the row's inner text after the name in tools (`option "Kho chính": Kho chính Hà Nội…`);
that is content, not the name. If a reader reads the label twice (name + description), record it here — it is the
`aria-labelledby` + `aria-describedby` split from the plan and the fix belongs in a follow-up, not v0.84.0.
