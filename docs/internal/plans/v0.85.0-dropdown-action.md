# v0.85.0: td-dropdown action mode ("chọn để thêm")

> Codex plan review: APPROVE r3 (gpt-5.6-sol, high), 2026-10-27.

The request comes from dsuite-40 on 2026-10-27: `docs/internal/research/dsuite-request-dropdown-rich-2026-10-27.md`. This release covers R3 (`mode="action"`, `trigger-icon`, `trigger-meta`, `keep-open`) and the R3 part of R6 (the "Đã chọn {nhãn}" announcement). The roadmap queue is `docs/internal/roadmap.md` (v0.85.0 row).

Out of scope here:
- R5 `load()` / `reload()`, loading / error / retry rows and the 2000-option performance work are v0.86.0.
- The PHP adapter gets no action mode. An action dropdown is a JS-driven control with no form value; a server-rendered `<select>` shell would submit a value before the upgrade, which is the opposite of the contract.

## Target

`<td-dropdown mode="action">` is a "pick to add" menu. Picking an option fires `pick` `{ value, item }` (plus `onPick(item)`), closes the menu and puts focus on the trigger. It never holds a selection:
- no `change`;
- no form value, so no `name` key in `FormData`;
- `required` has no effect;
- no "Không chọn" row;
- no check marks.

The trigger always shows the `placeholder` text, an icon (default `plus`) and optional muted text on the inline end (`trigger-meta`, e.g. "4/10"). `keep-open` keeps the menu open after a pick so several items can be added in a row. A polite live region says "Đã chọn {label}" after each pick (`labels.picked`, `''` turns it off).

**Hard compatibility rule:** without `mode="action"` (and without `trigger-meta`), every DOM string, event and form behaviour is exactly 0.84.0. `test/contracts/dropdown.html` stays unchanged and green.

## Decisions (made, with reasons)

1. **`mode` attribute.**
   - `action` (case-insensitive, trimmed) = action mode; anything else, including absent, = select mode (0.84.0).
   - A `mode` property mirrors it (`'select' | 'action'`; setting `'select'` removes the attribute).
   - Changing `mode` at runtime goes through the existing structure path (close + `_doRender()`). Entering action mode drops any selection and any pending value. Leaving it starts with no selection.
   - Native `<select>` upgrade (0.17.0 path, `_upgradeSelect`): in action mode it still reads options / groups / `name` / `aria-label` / `disabled`, but it never sets `_selectedItem` (the select's live value and the reset default are ignored). The `mode` / `keepOpen` / `triggerMeta` / `onPick` properties are added to `UPGRADE_PROPS`, which `connectedCallback` replays BEFORE the select upgrade, so a pre-upgrade `el.mode = 'action'` is in force when the select is read.
   - Reason: one attribute, no new element. Same pattern as the other structural attributes.

2. **No selection in action mode.**
   - `_selectedItem` and `_pendingValue` are always null.
   - `getValue()` / `value` return `null`.
   - `setValue()`, the `value` attribute, the `value` property, reset (`_restoreDefaults`) and state restore are ignored (no error, nothing stored).
   - `options` re-assignment never selects anything; the first-assignment `value` attribute is ignored.
   - `_syncForm()` sets the form value to `null` and validity to `{}` (so `required` never blocks the form). `aria-required` is not put on the trigger and the label gets no asterisk.
   - Reason: the request says the control writes nothing into the form. Silently ignoring value writes is the least surprising contract for a control that has no value.

3. **Menu rows in action mode.**
   - No clear row (`allow-clear` is ignored).
   - Rows render with the 0.84.0 strings (plain or rich). Since nothing is selected, `aria-selected="false"` and no check mark, without any new code path.
   - The create row works exactly as in 0.22.0 (`create` `{ query }`, `onCreate`). With `keep-open` the create row still closes the menu: creating usually opens a form or modal.
   - Disabled options are never picked (the existing guard).

4. **Pick flow** (`_pickItem(item)`, called from `_commitActive()` in action mode instead of `_selectItem`).
   - Guard: host disabled, or item disabled → nothing.
   - Without `keep-open`, the order follows the create row:
     1. close the menu;
     2. focus the trigger;
     3. `onPick(item)`, guarded by `safeCall`;
     4. `pick` event `{ value: item[valueKey], item }`;
     5. announce.
   - With `keep-open`, the menu stays open and the search text stays:
     1. the active row moves to the next enabled row after the picked one (no wrap), else the previous enabled one, else none;
     2. focus stays where it is (search input or trigger);
     3. `onPick`, then `pick`, then announce.
   - Exactly one `pick` per activation: mouse click, Enter (trigger or search box), Space on the trigger, Alt+ArrowUp.

5. **Options re-assigned while open (action mode only).** This is required by `keep-open`, because a site typically marks the picked item "Đã thêm" / disabled inside its `pick` handler. Today the `options` setter and `updateData()` reset `_filteredData` to the full list even while a search text is typed.
   - New behaviour, in action mode only, only while the menu is open:
     - `options = …` / `updateData()` re-apply the current query (same filter as `_handleSearch`);
     - the active row is kept by value: the active item's value is looked up in the new nav model. If it is gone or disabled, the same index is kept, moved to the nearest enabled row (forward first).
     - The scroller's `scrollTop` is preserved (`_placeMenu` already restores it in the measured layout; the plain layout keeps it because only the scroller's children change).
   - Closed menu, and select mode in any state: unchanged (0.84.0).
   - Reason: without this, keep-open loses the typed text after the first pick. Select mode gets the same behaviour in v0.86.0 with the R5 bullet "gán `options` khi menu đang mở" (it reuses `_refreshOpen()`); keeping it out of v0.85.0 keeps select mode identical to 0.84.0.

6. **Trigger in action mode.**
   - Text = `placeholder` (default "Chọn một tùy chọn" — sites are expected to set it).
   - The value span gets `data-action` instead of `data-placeholder`: the text is the button's label, not a hint, so it uses the normal field text colour, not the placeholder grey.
   - Icon slot `.td-dropdown__value-icon`:
     - `trigger-icon` absent / empty → `plus`;
     - `none` / `off` / `false` → no icon;
     - any other value → that icon name when `hasIcon()` (after the `ICON_NAME_RE` grammar check, as `iconOf`); unknown → no icon + the same bounded one-time warn.
   - In select mode, `trigger-icon` keeps its 0.84.0 meaning (only `none` matters).
   - The arrow chevron stays (it still opens a list).

7. **`trigger-meta` (both modes).**
   - A non-empty trimmed value renders `<span class="td-dropdown__trigger-meta" id="{host}-trigger-meta">{text}</span>` inside the trigger, after the value span and before the arrow. It is escaped text, muted colour, `tabular-nums`, `flex: none`.
   - It goes into the trigger's `aria-describedby` through the base `_describedByIds()` merge (page ids and error / helper ids are kept), so screen readers read "4/10" as a description, not as part of the name.
   - Updated in place on attribute change (the span is added / removed / re-texted, and `_syncDescribedBy()` runs). No re-render, no focus loss.
   - Both modes because it is generic (a count next to a select is just as useful). It is absent by default, so select-mode DOM is unchanged.

8. **Live announcement.**
   - In action mode only, the host renders `<span class="td-sr-only td-dropdown__live" aria-live="polite" aria-atomic="true"></span>` after the `.td-dropdown` wrapper. It is not in the portal: the menu is hidden after a pick, and text in a hidden region is not announced.
   - After a pick, the text is cleared and then set to `labels.picked` with `{label}` replaced (split/join, no `$` patterns). This way a repeated pick is announced again (same pattern as `sortable-controller._announce`).
   - `labels.picked` defaults to `'Đã chọn {label}'`; `''` = no announcement.
   - The label is the option's `label-key` value as text (`textContent`, never HTML).

9. **`keep-open` attribute.**
   - A boolean presence attribute (`keep-open`; `keep-open="false"` / `"0"` / `"off"` = off, as the other flags).
   - Only meaningful in action mode; ignored in select mode (a single select closes on choice, as in 0.84.0).
   - A `keepOpen` property mirrors it.
   - It is read at pick time only, so it is NOT an observed structural attribute: toggling it never re-renders, never closes an open menu and does nothing in select mode.

10. **a11y.**
    - The trigger stays `role="combobox"` with the label / `aria-label` naming it (the existing naming code). The placeholder text is its displayed value.
    - Sites should give an action dropdown a `label` or `aria-label`. The docs say so, and the story uses `aria-label`.
    - `npm run test:a11y` gains an action-mode snapshot: combobox name, `aria-describedby` → meta, live region present.

   - Add `labels.picked`.
   - Add `_isAction()` and `_keepOpen()`.
   - Branch `_commitActive()` for action mode.
   - Add `_pickItem()` and `_announcePicked()`.
   - Action guards in `setValue`, the `value` setter, `_setInitialValue`, `_reconcileSelection`, `_restoreDefaults`, `_restoreState`, `_syncForm` and `_applyRequired`.
   - Render the trigger's `data-action`, icon and meta, plus the live span.
   - Add an `attributeChangedCallback` case for `trigger-meta` (in place). `mode` goes through the structure path.
   - `_upgradeSelect()`: no `_selectedItem` in action mode; `UPGRADE_PROPS` gains `mode`, `keepOpen`, `triggerMeta`, `onPick`.
