## P1 — Màu pastel cho màu ngữ nghĩa

Bộ token mới (light): `--td-pastel-{success,danger,warning,info}-bg` (mức ~100), `-border` (~200), `-fg` (~800/900):
success `#dcfce7` / `#bbf7d0` / `#14532d`; danger `#fee2e2` / `#fecaca` / `#7f1d1d`; warning `#fef3c7` / `#fde68a` /
`#78350f`; info `#dbeafe` / `#bfdbfe` / `#1e3a8a`. Dark: nền = màu ngữ nghĩa ~18 % trộn sẵn trên nền tối (giá trị
**đặc**), viền ~30 %, chữ mức ~200. Giá trị cuối phải qua contrast gate (chữ ≥ 4.7).
Áp dụng: nút `success` / `danger` / `warning` / `info` = nền pastel + chữ đậm cùng tông + viền `-border` (hover = mức
~200); toast (P4). Nối vào `button.css` hiện tại: mỗi variant đọc `background: var(--td-btn-{v}-tint, var(--td-btn-{v}-bg))`
(alias 0.20 giữ ưu tiên), `border-color: var(--td-btn-{v}-border)` (thay `transparent` cứng), hover `background:
var(--td-btn-{v}-hover)` — token mới `--td-btn-{v}-border/-hover` trỏ vào pastel `-border`; nếu site đặt `-tint` /
`-bg` riêng mà không đặt `-hover` thì hover rơi về `color-mix(… 92%, #000)` như 0.20 (ghi docs). Custom giữ đường `color-mix`
hiện tại; primary dùng `--td-btn-primary-hover` (P2). `--td-btn-{v}-bg/-fg` mặc định trỏ vào pastel; alias `-tint` của 0.20 giữ nguyên. Badge / alert:
nếu đang có biến thể "soft" riêng thì cho trỏ cùng token pastel để đồng bộ (không đổi API).

## P2 — Primary + tooltip mặc định đen

- `--td-btn-primary-bg` mặc định `#18181b`, `-fg` `#fff`; token mới `--td-btn-primary-hover` mặc định `#3f3f46` (đen
  sáng lên khi hover — đen thì không làm đậm hơn được); rule hover của primary đọc `var(--td-btn-primary-hover)`. Site
  đổi `-bg` (vd về accent) mà không đặt `-hover` → nên đặt kèm (docs); dark: hover `#d4d4d8`. Dark theme: đảo (`#f4f4f5` nền, `#18181b`
  chữ) để không chìm vào nền tối. Site muốn primary theo accent: `--td-btn-primary-bg: var(--td-accent-fill)` (ghi docs).
  `--td-accent` (focus ring, checkbox, link…) **không đổi**.
- Tooltip: `--td-tooltip-bg` `#18181b`, `--td-tooltip-fg` `#fff` ở cả hai theme (dark thêm viền `rgb(255 255 255 / 12%)`);
  vẫn đặc, không blur; fallback contrast / forced-colors giữ (v0.20 `--_td-glass-fill-a11y`).

## P3 — Shadow rõ hơn

Light: `--td-glass-shadow: 0 2px 6px rgb(0 0 0 / 6%), 0 8px 24px rgb(0 0 0 / 12%)`; `--td-glass-shadow-lg: 0 4px 12px
rgb(0 0 0 / 8%), 0 20px 48px rgb(0 0 0 / 18%)`; `--td-btn-lift: 0 1px 3px rgb(0 0 0 / 10%), 0 4px 10px -2px rgb(0 0 0 /
12%)`. Dark: cùng hình, alpha ×2 (tối đa ~40 %). Ghost / disabled vẫn không shadow; contrast-more vẫn bỏ shadow.

## P4 — Toast theo dcms

**Ưu tiên của owner:** "đổi sang các màu pastel cho hợp style" là yêu cầu chung cho cả bộ; "lấy style dcms toast" được
hiểu là **hình dạng + chuyển động + hành vi** của dcms (viên thuốc, không icon / nút đóng hiển thị, màu theo loại, bấm để
đóng, trượt từ phải). Màu: pastel theo loại thay cho màu đậm chữ trắng của dcms — ngoại lệ có chủ ý, báo owner khi bàn giao
(đổi sang màu đậm dcms chỉ là đổi token `--td-toast-{type}-bg/-fg`).
Style dcms: viên thuốc gọn (`rounded-xl` ~12px, padding 12×16, chữ 14px), **nền pastel theo loại + chữ đậm cùng tông +
viền `-border`** (pastel thay cho nền đậm chữ trắng của dcms — theo P1), shadow P3, không blur, **không icon hiển thị**,
không nút đóng hiển thị. Vị trí top-right như hiện tại; vào: trượt từ phải `translateX(1rem) → 0` + fade 200ms
ease-out; ra: ngược lại 180ms.
Logic dcms: bấm vào toast → đóng; tối đa 5 (FIFO, đã có); `error` 5000ms, khác 4000ms (đã có); `duration ≤ 0` → không tự
đóng. Giữ của td (không bỏ): API `show/success/error/warning/info/clear`, handle `close()`, `labels`, role/aria-live,
tạm dừng khi hover / focus / tab ẩn, layer registry, textContent.
A11y bắt buộc (vì bỏ icon + nút đóng hiển thị): thêm tiền tố loại **chỉ cho trình đọc màn hình** (`labels.types`:
"Thành công:", "Lỗi:", "Cảnh báo:", "Thông tin:") trong span `.td-sr-only`; nút đóng **giữ trong DOM** nhưng ẩn bằng
mắt tới khi focus bằng bàn phím (`.td-toast__close` hiện khi `:focus-visible`), nên toast dính (`duration 0`) vẫn đóng
được bằng bàn phím. Icon node bỏ khỏi DOM (đổi DOM contract — ghi breaking-changes). **Gỡ** `td-glass-surface td-glass-surface--strong`
khỏi class toast (`td-toast.js`), CSS toast tự vẽ nền / viền / shadow; forced-colors (`Canvas` / `CanvasText` / viền
`CanvasText`) và contrast-more (viền rõ, không shadow) viết lại trong `toast.css`; token gate khẳng định toast không
`backdrop-filter`. Màu không phải dấu hiệu duy nhất
nhờ tiền tố SR + role alert cho lỗi.

## P5 — Modal animation ease-in-out

Mở: scrim fade 0→1 (240ms `ease-in-out`), dialog `opacity 0 → 1` + `translateY(12px) scale(0.98) → none` 260ms
`cubic-bezier(0.4, 0, 0.2, 1)`. Đóng: ngược lại 180ms `ease-in`. Token `--td-modal-enter-dur`, `--td-modal-exit-dur`,
`--td-modal-ease`. Sheet điện thoại giữ trượt từ dưới (dùng cùng ease). `prefers-reduced-motion` → chỉ fade 120ms.
Logic data-state `opening|open|closing` hiện có không đổi; chỉ CSS. (Đây là ngoại lệ có chủ ý với luật "không scale
trang trí" của 0.20 — owner yêu cầu; ghi vào `docs/internal/design/liquid-glass.md` mục chuyển động: chỉ modal.)

## P6 — Datetime picker: wheel cuộn từ đầu tới giá trị khi mở

Như dcms: khi dialog mở, mỗi wheel (giờ, phút) bắt đầu ở **đầu danh sách** (scrollTop 0) rồi cuộn **mượt** tới giá trị
đang chọn (`scrollTo({ behavior: 'smooth' })`; các wheel cùng lúc). **Thay cả hai đường căn tức thì hiện có**
(`_centreWheels(false)` gọi ngay sau `TdModal.show` và trong `onShow`) bằng: sau layout đặt `scrollTop = 0`, rồi bắt đầu
**một** lần cuộn mượt khi modal vào xong — chờ `transitionend` (property `opacity` / `transform`) của `.td-modal__dialog`,
có timeout dự phòng = thời lượng enter (`--td-modal-enter-dur`) + 50 ms; `onShow` **không** được coi là "đã vào xong".
Reduced motion → căn tức thì một lần (như hiện nay). Đóng trước khi xong → huỷ listener + timer. Trong lúc cuộn
tự động: **không** đổi lựa chọn (bỏ qua handler "settle" chọn option dừng trong band; `aria-activedescendant` / giá trị
pending giữ đúng giá trị đích từ đầu), người dùng chạm / cuộn / gõ phím → huỷ animation, xử lý như bình thường.
`prefers-reduced-motion` → căn giữa tức thì như hiện nay. Đóng dialog giữa chừng → dọn timer / listener. Test: mở →
scrollTop ban đầu 0, sau khi xong option đích ở giữa band và vẫn được chọn; không có `change` / pending đổi trong lúc cuộn;
reduced motion → căn tức thì; phím mũi tên trong lúc cuộn → giá trị theo phím.

## P7 — Tooltip căn chữ

Mặc định chữ wrap **căn giữa** (token `--td-tooltip-text-align: center`). Thêm `data-tooltip-align="start|center|end"`
trên trigger → chip nhận `data-align` (CSS `[data-align="start"]` …; giá trị lạ → mặc định). Không inline style. Test:
mặc định center, start/end theo attribute, giá trị lạ bỏ qua; docs tooltip.md.

## P8 — Viền focus của ô nhập nhạt hơn (như dcms)

dcms: `border-color: #3b82f6; box-shadow: 0 0 0 3px rgb(59 130 246 / 10%)`. td: `--td-field-focus` mặc định
`color-mix(in srgb, var(--td-accent) 85%, #fff)` (fallback `#3b82f6`), `--td-field-focus-ring: 0 0 0 3px` + accent ~12 %
(`color-mix(in srgb, var(--td-accent) 12%, transparent)`, fallback `rgb(59 130 246 / 12%)`). Áp cho control kiểu ô nhập
dùng `--td-field-*` (input-field, dropdown trigger, chip-input, datetime trigger nếu cùng token). Viền focus vẫn ≥ 3:1 với
nền (WCAG 1.4.11 / 2.4.11) — đưa vào contrast gate. Focus ring của nút / checkbox / switch **không đổi**.
