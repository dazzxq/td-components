## A — Dialog layer dùng chung (chỉ phần drawer cần)

Tách từ `TdModal` (td-modal.js: `show()` ~:205, đăng ký lớp ~:246, `trapTab`, scroll lock, inert lease, Escape, focus
initial / restore, `coverFloatingIn`, promotion v0.21.1, transition đóng) một controller nội bộ
`src/feedback/dialog-layer.js` (`openDialogLayer({ root, dialog, layer, onEscape, initialFocus, opener, onClosing })` →
handle `{ close(reason) → Promise<reason>, release() }`). **Hai pha đóng tường minh:** `onClosing(reason)` chạy **trước**
transition (đúng thời điểm `onClose` hiện tại của TdModal → giữ hành vi modal); Promise trả về từ `close()` resolve **sau**
transition ra (đo bằng `transitionEndMs` như modal hiện nay) và sau khi root bị gỡ — drawer dùng mốc này để trả node + phát
`close` + resolve `closed`. Modal tiếp tục dùng `onClosing` (không đổi thời điểm sự kiện / focus của modal). `TdModal` chuyển sang dùng nó **không đổi hành vi** — chứng minh bằng toàn bộ test
modal hiện có (không sửa assertion) + test parity mới nếu cần. Không làm SelectionModel / composite navigation (YAGNI).

## B — `<td-otp-input>` (#1)

- **Một** `<input type="text" inputmode="numeric" autocomplete="one-time-code" maxlength="6" pattern="[0-9]{6}">` thật
  (paste, autofill / SMS OTP, password manager, chọn, không-JS); sau nâng cấp hiển thị **6 ô trang trí** (span
  `aria-hidden`) vẽ theo giá trị + vị trí con trỏ; input phủ trong suốt lên các ô (CSS, không inline style), focus ring trên ô
  hiện tại. **Cố định 6 chữ số** (không option `length` — dsuite chỉ cần 6; đổi sau nếu có nhu cầu thật).
- Lọc chỉ chữ số ASCII (chữ số full-width / Ả Rập-Ấn được chuẩn hoá về ASCII) khi gõ / dán; dán chuỗi có khoảng trắng / gạch nối → lấy các chữ số.
- Sự kiện: `input` như thường; **`complete`** (`detail: { value }`) phát **một lần** khi đạt đủ độ dài với một "thế hệ" giá
  trị mới (token / single-flight); xoá bớt hoặc `reset()` → bật lại. **Không** tự submit form, không gọi API, không đếm ngược
  có thẩm quyền (đếm ngược / gửi lại / mã HTTP là việc app). Kiểm tra race "dán rồi xoá" của dcms2 bằng test; chỉ giữ kỹ thuật
  readOnly 150ms nếu test chứng minh còn cần.
- Form-associated (`TdFormElement`): một giá trị, `required` (đủ độ dài), `disabled`, `readonly`, lỗi (`error-text`,
  `setError`, trạng thái lỗi đổ màu ô), `aria-invalid`; label (`label` attr / `<label for>`).
- **SSR / PHP (ADR 0012) từ ngày đầu:** `td_otp_input($name, $o)` mặc định in input native có class (không JS vẫn dùng
  được); `['element' => true]` / `ssr_elements` → `<td-otp-input data-td-ssr="otp-input@1">` + input; hydrate tại chỗ theo
  quy tắc v0.26 (allowlist, topology một control, giữ value / selection / focus, lệch → render an toàn ngay + khôi phục).

## C — `<td-drawer>` (#2)

**Gắn vào trang (mounting):** khi mở, drawer luôn có một **root overlay là con trực tiếp của `<body>`**
(`div.td-drawer-root` chứa backdrop + panel) — như modal / lightbox, để inert lease, focus trap, thứ tự chồng (dải
modal / lightbox v0.21.1, promotion theo thứ tự mở) chạy đúng. Drawer khai báo (`<td-drawer>` trong trang): lúc mở **di
chuyển các node con của host** vào panel (không clone — giữ listener / state / node identity), lúc đóng (sau transition)
**trả lại** vào host theo đúng thứ tự. Drawer tạo bằng JS (`TdDrawer.open`) dựng node trong root. Lease inert + scroll lock
thuộc **layer của drawer** qua dialog-layer controller (A) — cùng cơ chế modal sau refactor (modal giữ nguyên lease của nó).
Test chồng: drawer → modal, modal → drawer, drawer ↔ lightbox, đóng lớp dưới trước, Escape chỉ đóng lớp trên, focus trả
đúng opener.

**Vòng đời (API):**
- Khai báo: thuộc tính **`open`** (phản chiếu hai chiều); `el.show()` / `el.close(reason = 'programmatic')`; property
  `open`. Gọi `show()` khi đang mở / `close()` khi đã đóng = không làm gì (idempotent).
- JS: `TdDrawer.open({ title, label, body, footer, side, size, dismissible, onClose })` → handle `{ element, close(reason),
  closed: Promise<reason> }`.
- `dismissible` mặc định **true** (Escape + bấm nền đóng); `false` → chỉ nút × / `close()`.
- Thứ tự sự kiện: `before-close` (cancelable, `detail.reason`) → nếu không bị chặn: đóng, transition ra → gỡ / trả node →
  **`close`** (`detail.reason`) phát **sau** khi transition kết thúc và node đã trả / gỡ; `closed` resolve cùng lúc.
  `open` (sự kiện) phát sau khi mở xong + focus đã đặt.

**Tên cho trình đọc màn hình:** `title` → kit tạo `<h2 class="td-drawer__title" id="{auto}">` và `aria-labelledby` trỏ
vào đó; không `title` → bắt buộc `label` (→ `aria-label`) hoặc `aria-labelledby` hợp lệ do người gọi đặt; thiếu cả ba →
`console.warn` một lần + dùng `labels.drawer` ("Bảng điều khiển") làm `aria-label`. Test cả drawer khai báo lẫn JS.

**Không JS:** `<td-drawer>` khai báo khi chưa định nghĩa (`:not(:defined)`) **hiện nội dung tại chỗ** (CSS: không ẩn) —
dùng được như một khối thường; docs khuyên đặt drawer ở cuối nội dung / trong `<details>` nếu cần ẩn khi không JS.
`TdDrawer.open` là JS-only.

- Panel trượt từ `side="start|end"` (logic, RTL lật), kích thước token (`size="sm|md|lg|xl"` + `--td-drawer-w`), ≤ 640px
  **toàn màn hình**; vùng `header` (tiêu đề + nút đóng), `body` (cuộn), `footer` — nội dung là con của element
  (`[slot="header|footer"]` theo thuộc tính, không Shadow DOM) hoặc API JS `TdDrawer.open({ title, body, footer, … })`
  giống TdModal.
- Dùng **dialog layer** (A): blocking layer, inert nền, khoá cuộn, focus trap + trả focus, Escape, popup con đóng, thứ tự
  chồng với modal / lightbox (dải v0.21.1).
- Đóng: nút ×, Escape, bấm nền (bật / tắt bằng `dismissible`); mọi đường đóng phát **`before-close`** cancelable
  (`detail: { reason: 'escape'|'backdrop'|'button'|'programmatic' }`) → app có thể chặn (form chưa lưu); rồi `close`.
- `role="dialog"` + `aria-modal="true"` + `aria-labelledby`; chuyển động trượt (reduced motion → fade); Minimal surfaces
  (đặc, shadow-lg).
- PHP: không helper (nội dung tuỳ ý) — docs có mẫu Blade / HTML.

## D — `<td-copy>` (#4, kiểu action button dcms2)

- **Bản thân là một nút icon** (`<td-copy value="…" label="Copy mã khôi phục">` → render `<button type="button"
  class="td-copy" aria-label="{label}">` + **một** icon SVG từ registry tại một thời điểm (`copy` → `check` khi vừa copy);
  `size="sm|md"`, kiểu ghost; **không** có chế độ chữ (owner: chỉ icon). Nguồn: `value` hoặc `for="id"` (copy `textContent` / `value` của phần tử đó).
- Bấm → `navigator.clipboard.writeText` (trong user activation); thành công → **icon đổi `check` + tông thành công** +
  `aria-label` / live region "Đã copy" (`labels.copied`) trong `duration` ms (mặc định 2000) rồi **trả về trạng thái gốc từ
  cấu hình** (không chụp lại DOM đang hiển thị → bấm liên tiếp không kẹt "đã copy" — lỗi của dcms2); thất bại / không có
  clipboard → fallback: chọn văn bản nguồn (phần tử `for` hoặc ô tạm `readonly` đã chọn sẵn) + thông báo "Nhấn Ctrl/⌘+C để
  copy" (`labels.manual`), icon trạng thái lỗi. Sự kiện `copy-success` / `copy-error` (`detail` **không** chứa giá trị nếu
  attr `sensitive`, mặc định có). Tooltip `data-tooltip` theo `label`. Không toast mặc định (app tự gọi TdToast nếu muốn;
  docs có ví dụ).
- **Không JS:** hợp đồng markup khai báo **bắt buộc** có nguồn do server viết sẵn: `<td-copy label="…"><code
  class="td-copy__source">{value}</code></td-copy>` (giá trị lấy từ `<code>` này; `value` attribute vẫn nhận khi tạo bằng
  JS — trường hợp đó vốn cần JS nên không có đảm bảo trước JS). PHP in đúng cấu trúc này. Docs / ví dụ dùng dạng có `<code>`. CSS: khi `td-copy:not(:defined)` → hiện `<code>` (người dùng tự bôi đen copy), ẩn nút; khi đã định nghĩa →
  `<code>` ẩn (`hidden` / class sr-only? → **ẩn hẳn**, nút icon là giao diện duy nhất — đúng yêu cầu chỉ icon), nút hiện.
  Với `for="id"` không cần `<code>` (nguồn là phần tử khác trên trang).
- PHP: `td_copy($value, ['label' => …, 'size' => …])` in host `copy@1` + `<code>` nguồn + nút; JS hydrate theo allowlist.
- **Giá trị nguồn là state:** trước mọi quyết định render / hydrate, chụp text của **đúng một** `.td-copy__source` con trực
  tiếp (nhiều hơn một / lồng sai chỗ → không lấy, coi như không có nguồn); property / attribute `value` (JS) **ưu tiên** hơn.
  Render lại (lệch markup / tạo mới) dựng lại `<code class="td-copy__source">` với đúng giá trị đã chụp. Test: khai báo và
  SSR bị sửa (lệch) → sau render vẫn copy **đúng** giá trị gốc; `value` property ghi đè `<code>`.
