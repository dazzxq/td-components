## A. `<td-scroll-top>` reading progress

Source behaviour: `dwp/engine/dwp-core/assets/ui/scroll-top.js` + `assets/css/scroll-top.css` (read only).

### API (new, opt-in; no attribute = today's button, pixel-identical)

| Surface | Contract |
|---|---|
| `progress-target` attr | CSS selector. Each `update()` runs `querySelectorAll(sel)` and takes the first element with `getClientRects().length` (dwp "first visible marker wins"). Invalid selector → no ring + one `console.warn` per element (fixed text). |
| `progressTarget` property | `Element \| null`. Non-null wins over the attribute (no selector lookup). Disconnected / no client rects → no ring. Non-Element → `null`. Set back to `null` → the attribute applies again. Settable before define (upgrade property pattern as `renderOption`). |
| `update()` (exists) | Also recomputes progress. The SPA contract: a site that swaps content without scrolling calls `update()` (dwp bridges `dwp:article:mounted` / `dwp:view:changed` itself). |
| event `reading-progress-complete` | Bubbling, `detail { target }`, once per resolved target identity, on the first update where p = 1 (also immediately when a newly resolved target is already fully read). |

No page mode (`progress-target="main"` / `body` gives page-like progress through the same formula), no scroll containers
(window only, as today), no MutationObserver, no site events in the kit, no colour attribute for the ring.

### Progress formula (dwp, unchanged)

`rect = target.getBoundingClientRect()`, `end = rect.bottom - innerHeight`: `end <= 0` → 1; `rect.top >= 0` → 0; else
`min(1, -rect.top / (-rect.top + end))`.

### Refresh

Existing rAF-coalesced scroll / resize / pageshow → `update()`. Plus a `ResizeObserver` on the currently resolved
target (re-observed when the identity changes, disconnected on teardown) scheduling the same rAF update. Where
`ResizeObserver` is missing: skip it (scroll still updates).

### Completion check (dwp parity)

Two separate states:
- **history** (durable): a `WeakSet` of targets that already completed. Membership = the event fired and the check was
  "used" for that element. Never cleared by target changes (A → B → A, or A hidden → visible again: no second event, no
  second check). A different element (new article node) is a new identity.
- **UI** (transient): current target, check timer, `data-complete`.

First update where p = 1 for a target not in history: add it to history, dispatch `reading-progress-complete`, set
`data-complete="true"` (check replaces the arrow) for a fixed 3000 ms, then remove it. Scrolling back below 1 while the
check shows → remove at once. Target identity changes / target gone → clear the timer and `data-complete` (history
kept). Timer cleared on disconnect.

### Markup (fixed strings, built once; no user data)

Inside the existing `<button>`: `<svg class="td-scroll-top__ring" viewBox="0 0 48 48" aria-hidden="true"
focusable="false"><circle class="td-scroll-top__track" cx="24" cy="24" r="22.5"/><circle class="td-scroll-top__arc" …
pathLength="100" transform="rotate(-90 24 24)"/></svg>` + the existing up icon span + a check icon span
(`data-td-icon="check"`, filled by `fillIconSlots`). The ring is only rendered while a target resolves
(`data-progress="true"` on the button; otherwise `display: none`). The ring radius sits on the button edge inside the
1px border so it never paints outside the button box (touch target unchanged).

Arc length: `stroke-dasharray: 100` in CSS; `arc.style.strokeDashoffset = String(100 * (1 - p))` through CSSOM (CSP
safe): p 0 → 100 (empty), 0.5 → 50, 1 → 0 (full). Accessibility: ring + both icons `aria-hidden`; the button name stays "Lên đầu trang"; no live region.

### Tokens (CSS)

| Token | Default |
|---|---|
| `--td-scroll-top-progress-arc` | not declared; the rule falls back to `currentColor` (impl: a :root `var(--td-scroll-top-fg)` resolved at :root and ignored a per-element `color`) |
| `--td-scroll-top-progress-track` | not declared; fallback `color-mix(in srgb, currentColor 18%, transparent)` (transparent without color-mix) |
| `--td-scroll-top-progress-width` | `3px` (dwp stroke 3 in a 48 box) |

Layout CSS (in `scroll-top.css`): the button is already `position: fixed` (a containing block). Ring:
`position: absolute; inset: 0; inline-size: 100%; block-size: 100%; pointer-events: none; display: none` and
`.td-scroll-top[data-progress="true"] .td-scroll-top__ring { display: block }`. Track `stroke: var(--td-scroll-top-progress-track)` (declared first as `transparent`, then the color-mix value inside
`@supports (color: color-mix(in srgb, red 50%, blue))`), arc `stroke: var(--td-scroll-top-progress-arc)`. Track / arc: `fill: none`,
`stroke-width: var(--td-scroll-top-progress-width)`, arc `stroke-linecap: round`, `stroke-dasharray: 100`,
`transition: stroke-dashoffset .15s ease`. Icons: both spans `position: absolute` centred (`inset: 0; display: grid;
place-items: center`), check `opacity: 0; transform: scale(.6)`; `[data-complete="true"]` swaps (arrow 0 / .6, check 1 /
1), transition opacity + transform .25s. The existing up-icon span keeps its class; the check span is
`td-scroll-top__icon td-scroll-top__icon--check`.

Forced colours: arc `CanvasText`, track hidden; the glass-off / increased contrast surfaces keep the ring (arc follows
the surface fg). Reduced motion: no dashoffset / icon transitions. Icon swap: opacity + scale 0.6 → 1 (dwp), 0.25s,
off under reduced motion.

## B. `<td-dropdown>` option `font`

| Surface | Contract |
|---|---|
| option key `font` | A CSS `font-family` value (`'"Roboto", sans-serif'`). Applied via CSSOM (`style.fontFamily`) to the row's `.td-dropdown__option-label` and, when that option is selected, to the trigger `.td-dropdown__value` text. Inherited by a `renderOption` Node. Not on description / meta / status. |
| validation | string, trimmed, 1–200 chars; rejected: CSS-wide keywords (`inherit`, `initial`, `unset`, `revert`, `revert-layer`), anything a detached element's `style.fontFamily` does not accept (read back empty). Never `cssText`. Invalid → no font, no warning per row (one `console.warn` per element). |
| SSR | `<option data-font="…">` read on upgrade (raw, gated at render). PHP `td_dropdown` option `'font' => '…'` → `data-font` (PHP gate: string ≤ 200, no control chars, no `;{}<>`, not a CSS-wide keyword; escaped). |
| measuring | A list with any font row counts as measured (`_measured = true`, like `renderOption`). While the menu is open, `document.fonts` `loadingdone` (if present) re-runs the position / height update. |
| search | label / description / keywords only; the font string is never searched. |
| trigger | shows the selected font. `trigger-icon="none"` does not affect it. No new attribute. Applied in `_updateValueText()` (the single path for initial render, selection change, option list replacement, value set, clear / placeholder, action mode): set `fontFamily` for a selected item with a valid font, else clear it (`''`). |

Font loading is the site's job (`@font-face`, `font-src` in its CSP). The kit fetches nothing. Docs: recipe for a font
picker + note that an unloaded font falls back to the next family in the list.
