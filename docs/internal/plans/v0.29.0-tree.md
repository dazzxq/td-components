## Quyết định đã chốt (owner uỷ quyền "làm hết luôn"; theo use case dsuite: cây danh mục, chọn danh mục cha, chuyên mục bài viết)

## M1 — Mô hình dữ liệu thuần `src/utils/tree-model.js` (test `node --test`)

- **Hình dạng nút:** `{ value, label, children?, hasChildren?, disabled?, description?, expanded? }`. `value` chỉ nhận chuỗi
  hoặc số hữu hạn (ép `String()`); **`''` dành riêng cho "trống"** → nút có value `''` / `null` / `undefined` / object / mảng
  / boolean bị **bỏ cả nhánh + cảnh báo một lần** (PHP M8 cùng luật). Value phải **duy nhất** toàn cây (trùng → cảnh báo một
  lần, nút sau bị khoá và không vào được giá trị). Giá trị gán vào (`value` / attribute) cũng bỏ `''` và kiểu lạ. `label` / `description`
  chỉ là text. `children: [...]` = đã có con; `children` vắng + `hasChildren: true` = **lazy** (M4); `children: []` = lá.
  Không có `value-key` / `label-key` (app tự map — giữ lõi nhỏ).
- `normalize(data)` → nút nội bộ `{ uid, value, label, fold, parent, depth, children|null, lazy, disabled(own),
  locked(kế thừa), src }`; `uid` là số đếm theo instance (dùng cho **id DOM**, không bao giờ lấy từ dữ liệu); `fold` = khoá
  tìm (`fold()` sẵn có của `typeahead.js`) tính một lần. Duyệt **lặp** (không đệ quy), chặn object lặp lại / vòng (Set),
  độ sâu tối đa **16** (sâu hơn → bỏ nhánh + cảnh báo), > **5.000** nút → cảnh báo một lần "dùng `loadChildren`" (vẫn chạy).
- Hàm thuần: danh sách nút **đang hiện** theo thứ tự (gốc + con của nút mở), điều hướng (`next/prev/parent/firstChild/
  first/last`), type-ahead (tái dùng `nextTypeaheadIndex` trên nhãn nút đang hiện), lọc (M5), cascade (M3), giá trị (M6).
  Toàn bộ logic chọn / cascade / lọc nằm đây để test nhanh trên Node, component chỉ là lớp render + sự kiện.

## M2 — `<td-tree>` (form-associated, `src/form/td-tree.js`)

**Markup** (dựng bằng DOM API, nhãn qua `textContent`; chỉ nút thuộc nhánh **đang mở** có trong DOM):

```
<td-tree id="{h}">
  <div class="td-tree" data-selection="none|single|multiple">
    [<label class="td-field__label" id="{h}-label">…]  [<input type="search" class="td-tree__search" aria-controls="{h}-tree">]
    <ul role="tree" class="td-tree__list" id="{h}-tree" aria-labelledby|aria-label [aria-multiselectable="true"]>
      <li role="treeitem" class="td-tree__item" id="{h}-n{uid}" tabindex="0|-1" aria-level aria-setsize aria-posinset
          aria-labelledby="{h}-n{uid}-l" [aria-describedby="{h}-n{uid}-d"] [aria-expanded] [aria-selected | aria-checked]
          [aria-disabled="true"] [aria-busy="true"]>
        <div class="td-tree__row"><span class="td-tree__toggle" data-td-icon="next" aria-hidden="true"></span>
          [<span class="td-tree__check" aria-hidden="true"></span>]<span class="td-tree__label" id="…-l">…</span>
          [<span class="td-tree__desc" id="…-d">…</span>]</div>
        [<ul role="group" class="td-tree__group">…</ul>]
      </li>
    </ul>
    <p class="td-tree__empty" hidden>…</p>   <p class="td-sr-only" id="{h}-status" role="status"></p>
  </div>
```

`tree` / `group` chỉ chứa `treeitem` (và `group` trong `treeitem`); thông báo trống / live region nằm **ngoài** `ul`,
trong wrapper (test khẳng định).

- `aria-labelledby` trên mỗi treeitem là **bắt buộc**: tên tính từ nội dung của `li` sẽ gộp cả chữ của nhóm con.
  `aria-level/setsize/posinset` ghi **tường minh** (khi lọc, setsize = số anh em đang hiện). Thụt lề bằng lồng `group`
  (CSS `--td-tree-indent`); không `style=""`.
- **Focus: roving tabindex** (một tab stop, nút đang trỏ `tabindex="0"` + focus thật). Lý do: đúng ví dụ APG tree, giống
  `td-menu` / `td-tabs` của kit, trình duyệt tự cuộn tới nút, VoiceOver / Safari ổn định hơn `aria-activedescendant` trên
  `tree`. Ngoại lệ duy nhất là cây trong popup của tree-select **`single`** (M7): focus thật ở combobox, cây chạy chế độ
  **focus ảo** (`aria-activedescendant` + `data-active`) — APG combobox bắt buộc vậy (`multiple` dùng roving như thường). Cùng một model điều hướng; khác nhau
  đúng một hàm `_setActive(uid)` (~15 dòng). Thu gọn nút đang chứa focus → focus về nút đó. DOM bị dựng lại (lọc / tải
  nhánh) → giữ nút active theo `uid`, mất thì về nút hiện đầu tiên.
- **Bàn phím (APG):** ↓ / ↑ nút hiện kế / trước (không vòng); → đóng → mở, mở → con đầu, lá → không gì; ← mở → đóng, đóng /
  lá → cha; Home / End; type-ahead (500 ms, không phân biệt dấu); `*` mở mọi anh em cùng cấp; Enter / Space: `single` chọn,
  `multiple` lật check, `none` phát `activate`. RTL (`dir` tính được) → đổi ← / →. Nút khoá vẫn tới được bằng bàn phím
  (đọc được, mở / đóng được) nhưng không chọn được. Chuột: bấm mũi tên = mở / đóng; bấm hàng = như Enter. Không PageUp /
  PageDown, không Shift-dải, không Ctrl+A (non-goal).
- **Thuộc tính:** `name`, `label`, `selection="none|single|multiple"` (mặc định `none`), `cascade` (M3), `searchable`,
  `value`, `disabled`, `required`, `error-text`. **Property:** `data`, `loadChildren`, `value`. **Method:** `expand(value)` /
  `collapse(value)` (chỉ nút đã tải), `expandAll()` / `collapseAll()` (nút đã tải; không kích hoạt lazy), `getNode(value)` →
  object gốc của app. Gán `data` mới → thế hệ mới (huỷ mọi request lazy, `uid` mới; giá trị đối chiếu lại theo M6).
  Property gán **trước** khi nâng cấp: `value` qua `_earlyProps` của base (thắng attribute); `data` / `loadChildren` không
  phải attribute → danh sách `UPGRADE_PROPS` phát lại trong constructor (mẫu `td-dropdown`).
  Văn bản: `TdTree.labels` (`search`, `empty`, `noResults`, `loading`, `loadError`, `results`).
- **Sự kiện** (chỉ khi người dùng thao tác, không khi `setValue` / gán `data`): `change` `{ value, added, removed }`
  (`single`: `value` là chuỗi, `''` khi trống); `activate` `{ value, node }` (chỉ `selection="none"`); `expanded-change`
  `{ value, expanded }` (không dùng tên `toggle` — trùng sự kiện native của `<details>` / popover); `load-error`
  `{ value, error }`.

## M3 — Chọn: `single` / `multiple` độc lập / `multiple cascade` (khuyến nghị rõ)

- **`single`:** `aria-selected="true|false"` trên nút chọn được; **lựa chọn không đi theo focus** (chỉ Enter / Space /
  bấm) → không có `change` ngoài ý muốn khi duyệt. Mọi nút (cha hay lá) đều chọn được, trừ nút khoá. Lần render đầu tự mở
  tổ tiên của nút đã chọn.
- **`multiple` (mặc định = độc lập):** mỗi nút một checkbox riêng, **không** ba trạng thái; giá trị = mọi nút đã check.
  Đúng mô hình "chuyên mục bài viết" (giống category checklist của WordPress: check "Điện thoại" không có nghĩa là thuộc
  mọi chuyên mục con). An toàn với lazy: giá trị chưa có trong cây (nhánh chưa tải) được giữ theo luật đối chiếu M6.
- **`multiple` + `cascade` (cây quyền):** checkbox ba trạng thái, giá trị = **chỉ lá đã check** (nút cha là "nhóm", không
  phải quyền). **Khuyến nghị gửi lá**, vì: tập gửi đi không mơ hồ (không có "cha nghĩa là cả nhánh"), server không phải tự
  bung nhánh, thêm quyền con mới vào nhóm sau này không tự cấp ngầm. Không hỗ trợ dạng "gom về cha" (SHOW_PARENT) — non-goal.
  Luật:
  1. **Khoá kế thừa xuống:** nút `disabled` khoá **cả nhánh** của nó (cũng là cách chống vòng khi chọn cha: đánh dấu
     chính danh mục đang sửa là `disabled`). Mở / đóng vẫn được.
  2. **Hiển thị cha** suy từ **mọi lá con cháu, kể cả lá khoá**: tất cả check → `aria-checked="true"`, không lá nào →
     `"false"`, còn lại → `"mixed"`. Trung thực: cha không bao giờ hiện "đủ" khi còn lá khoá chưa check.
  3. **Bấm cha:** nếu mọi lá **không khoá** của nhánh đã check → bỏ check chúng; ngược lại → check hết chúng. Lá khoá giữ
     nguyên → không bao giờ kẹt (cha `mixed` vì lá khoá vẫn bấm qua lại được).
  4. **Bấm lá:** lật lá đó; tổ tiên tính lại theo luật 2 (O(độ sâu × số con), không quét cả cây).
  5. Giá trị ban đầu chứa value của **nút cha** hoặc value không có trong cây → bỏ + cảnh báo một lần (cascade cần dữ liệu đủ).
  6. **`cascade` + `loadChildren` không hỗ trợ** (không biết lá của nhánh chưa tải) → cảnh báo một lần, chạy như `multiple`
     độc lập. Cây quyền nhỏ và biết trước → không cần lazy.
- **Nút khoá = "khoá hiển thị", vẫn gửi đúng một lần:** trạng thái của nút khoá người dùng không đổi được và **vẫn nằm
  trong giá trị / FormData** (khác `<option disabled>` native). Lý do: server "đồng bộ theo danh sách nhận được" ngây thơ sẽ
  **thu hồi** quyền khoá nếu ta bỏ nó khỏi form. Theo chế độ:
  - `single` có **lựa chọn khoá** → không chọn được nút khác (mọi nút coi như không chọn được, cây vẫn duyệt / mở được),
    `allow-clear` ẩn, `setValue` bằng code vẫn được (app có quyền).
  - `multiple`: lựa chọn khoá không lật được; nút xoá (`allow-clear` của tree-select) chỉ gỡ mục **không khoá**;
    `setValue()` bằng code đặt tuỳ ý (app có quyền); `cascade` theo luật 3.
  - `required` tính cả mục khoá (có mục khoá đã chọn = không rỗng). Fallback native y hệt — M8. Server vẫn phải tự kiểm
    quyền / khoá (không tin client) — ghi docs.
- `aria-checked` dùng trên chính `treeitem` (ARIA cho phép `mixed` trên treeitem), ô check là `span aria-hidden` vẽ bằng
  icon có sẵn (`check` / `minus`) — **không** lồng `<input type=checkbox>` trong treeitem.

## M4 — Lazy children (`loadChildren(node, { signal }) → Promise<Array>`)

- Mở nút `lazy` lần đầu → gọi hook với **object gốc** của app + `AbortSignal`; `aria-busy="true"` + mũi tên quay (CSS, giảm
  chuyển động → tĩnh); "Đang tải…" vào live region chỉ sau 400 ms (như chip-input).
- **Latest-request-wins theo từng nút:** mỗi nút có `seq` + `AbortController` riêng; gán `data` mới tăng thế hệ và huỷ tất
  cả; kết quả về muộn / sai thế hệ / sau `disconnect` bị bỏ **kể cả khi hook phớt lờ `signal`**. Thu gọn khi đang tải → vẫn
  nhận và cache kết quả nhưng **không** tự mở lại (tôn trọng thao tác cuối của người dùng).
- Kết quả không phải mảng / reject → nút về đóng, `data-load="error"`, live region `labels.loadError`, phát `load-error`;
  mở lại = thử lại. Mảng rỗng → thành lá (bỏ `aria-expanded`). Con mới đi qua đúng `normalize` (trùng value, độ sâu, khoá kế
  thừa từ cha). `*` mở anh em lazy → mỗi nút một request độc lập.

## M5 — Lọc (`searchable` / `filter(query)`)

- Chỉ trên **nút đã tải** (không gọi server; tìm từ xa = app tự đổi `data` — non-goal). So khớp chuỗi con trên `fold`
  (nhãn, không dấu). Hiện = **nút khớp + mọi tổ tiên** của nó; tổ tiên được mở **tạm** (không đụng trạng thái mở thật — xoá
  chữ thì về đúng như trước); nút khớp có con thì hiện ở trạng thái đóng, mở ra thấy **toàn bộ** con (để chọn con của một
  danh mục vừa tìm thấy).
- Debounce 150 ms; dựng lại phần hiện; live region "{n} kết quả" / `noResults`. Ô tìm của `td-tree`: ↓ từ ô tìm → nút hiện
  đầu tiên. Không highlight đoạn khớp (non-goal).

## M6 — Gửi form

`name` **nguyên văn** (`perms[]`, không tự thêm `[]`); FormData **một mục mỗi giá trị**: `single` → 0/1 mục; `multiple` →
theo thứ tự cây (preorder), giá trị chưa tải (độc lập + lazy) nối sau theo thứ tự nhận. `required` → `valueMissing` khi
rỗng. State cho restore = JSON mảng giá trị. Reset → giá trị mặc định đã chụp. **Thứ tự ưu tiên giá trị ban đầu** (mẫu kit):
property gán sớm > attribute `value` (`single`: chuỗi; `multiple`: JSON mảng như chip-input) > state sống của `<select>`
(M7). `disabled` / `<fieldset disabled>` theo `TdFormElement`.

**Đối chiếu giá trị chưa có trong cây (một luật cho `td-tree` và `td-tree-select`, `single` lẫn `multiple`):** model
"**đủ**" = đã có `data` **và** không còn nút lazy chưa tải. Giá trị không tìm thấy là **chưa giải**:
- **Giữ** (vẫn gửi, vẫn tính `required`) khi model **chưa đủ**: gán trước `data`, hoặc cây còn nhánh lazy chưa tải.
- **Giải** khi một lần tải nhánh (hoặc `data` mới) đưa vào nút trùng value → thành giá trị thường (vị trí preorder, nhãn
  thật thay `value-label`), không phát `change`.
- **Bỏ + cảnh báo một lần** chỉ khi model **đủ** (dữ liệu eager / đã tải hết) mà vẫn không thấy — lúc gán `data` hoặc lúc
  nhánh lazy cuối cùng tải xong; không phát `change`. `cascade` luôn đủ (không lazy) → bỏ ngay (luật 5).
- Nhãn hiển thị cho giá trị chưa giải: `single` → attribute `value-label="…"`; `multiple` → attribute `value-labels` = JSON
  object `{"<value>":"<nhãn>"}` (PHP in sẵn; JSON hỏng → bỏ qua + cảnh báo); thiếu nhãn → hiện chính value.

## M7 — `<td-tree-select>` (form-associated, `src/form/td-tree-select.js`)

**Hợp đồng công khai.** Attribute: `name`, `label`, `placeholder`, `multiple` (không có → single), `cascade` (chỉ với
`multiple`), `searchable` (mặc định bật, tắt bằng `"false"` như dropdown), `allow-clear`, `display="label|path"`, `value`
(single: chuỗi; multiple: JSON mảng), `value-label` / `value-labels` (M6), `disabled`, `required`, `error-text`. Property:
`data`, `loadChildren`, `value` (`string` | `string[]`, = `getValue()` / `setValue()`). Sự kiện: `change`, `load-error`,
`expanded-change` (phát trên host). Văn bản `TdTreeSelect.labels`.
- **Chuyển tiếp:** host giữ **một** instance model (M1) là nguồn sự thật duy nhất (giá trị, trạng thái lazy, khoá). `<td-tree>`
  con trong popup được tạo một lần ở lần connect đầu, **không `name`**, nhận model qua hook nội bộ `_attachModel(model, {
  selection, cascade, virtualFocus })` — không copy dữ liệu, không đồng bộ hai chiều. Gán `data` / `loadChildren` / `value` trên
  host → cập nhật model → cây render lại phần bị ảnh hưởng + trigger cập nhật nhãn. Sự kiện của cây (portal, **không nổi bọt**
  tới host) → host phát lại (không phát `activate`).
- **Gán trước nâng cấp:** `value` qua `_earlyProps` (thắng attribute và select sống); `data` / `loadChildren` qua
  `UPGRADE_PROPS` phát lại trong constructor (mẫu `td-dropdown` L11 / L203). `value` gán trước `data` → chưa giải, giữ (M6).

**Hai mẫu ARIA, mỗi mẫu đúng một phần tử điều khiển:**
- **`single` = APG combobox, popup `tree`.** **Một** phần tử duy nhất mang `role="combobox"`, `aria-haspopup="tree"`,
  `aria-expanded`, `aria-controls="{h}-tree"`, `aria-activedescendant`:
  - `searchable` (mặc định): phần tử đó là **ô nhập trong trigger** (`input.td-tree-select__input`, combobox editable) — đóng
    thì hiện nhãn đã chọn, gõ là lọc tại chỗ (popup không có ô tìm thứ hai). Rời ô / đóng → trả nhãn đã chọn.
  - `searchable="false"`: phần tử đó là `button.td-tree-select__trigger` (select-only).
  Focus thật **không rời** combobox; cây chạy focus ảo (M2). Phím: ↑↓ (đóng → mở), Home / End (button luôn; ô nhập = phím con
  trỏ), ← → (button luôn; ô nhập **chỉ khi ô rỗng** — quyết định 4), `*`, Enter = chọn nút active + đóng + giữ focus ở
  combobox. **Space:** trên button = chọn nút active + đóng (đang đóng → mở), **chặn click kích hoạt sinh ra từ phím** theo
  đúng cơ chế `_suppressClick` của dropdown (mốc thời gian ở keydown, bỏ click `detail === 0` trong 1 s, xoá sau keyup); trong
  ô nhập = gõ dấu cách.
- **`multiple` = disclosure.** `button.td-tree-select__trigger` (không `role=combobox`) với `aria-expanded` +
  `aria-controls="{h}-menu"`; mở → popup chứa ô tìm (`input type=search`, `aria-controls` cây) + `ul[role=tree]
  [aria-multiselectable=true]`, **focus chuyển vào ô tìm** (≥ 768px; nhỏ hơn → vào cây) — cây dùng roving tabindex như
  `td-tree` thường (↓ từ ô tìm → cây, ← → trong ô tìm luôn là phím con trỏ). Space / Enter trên treeitem = lật check, popup
  **giữ mở** (treeitem không phải button → không có click kích hoạt kép). Space / Enter trên trigger = click native mở / đóng.
  Escape → đóng + focus trigger; Tab rời popup → đóng.
- `allow-clear` → nút × **anh em** của trigger (không lồng nút trong nút), theo luật khoá M3. Trigger hiện nhãn đã chọn
  (`display="path"` → "Điện thoại › Apple › iPhone"); `multiple`: tóm tắt "Apple, Samsung +3"; trống → `placeholder`.

**Popup:** portal ra `<body>`, `.td-tree-select__menu td-glass-surface td-glass-surface--strong` (popup nhỏ: nền 94 % + blur
12px + viền + shadow). Tái dùng nguyên các primitive đã kiểm: `placeFloating` (`width: 'match'`, `list` = vùng cuộn),
`isReferenceHidden` + `watchReference` (`utils/floating.js`), và layer theo **đúng chữ ký** `register(opts)` của
`utils/layers.js`: `this._layer = registerLayer({ element: menu, layer: LAYERS.popover, keyboard: 'boundary', anchor: this,
onCovered, onEscape, onTab })` → giữ handle; `close()`, `_closeCovered()` và `disconnectedCallback()` gọi `_releaseLayer()`
(release + null, idempotent — y như dropdown L1250 / L662). pointerdown ngoài → đóng. **Không** tạo lớp trừu tượng popup mới
(YAGNI; ứng viên gộp với dropdown / chip-input sau).

**Nâng cấp `<select>` con trực tiếp** (thường do PHP in, dùng được với select viết tay): option theo **preorder**,
`data-level="n"` (vắng = 0; nhảy cấp > +1 → kẹp về +1 + cảnh báo), nhãn thật ở `data-label` (vắng → `textContent` đã trim
khoảng trắng / NBSP đầu), `data-description`, `disabled` → nút khoá **trừ khi** có `data-native-only` (disabled chỉ cho
fallback native — option cha của `cascade`, option khác khi `single` có lựa chọn khoá; M8). Option `value=""` (placeholder)
bị bỏ. `<input type="hidden" class="td-tree-select__locked">` con trực tiếp → giá trị khoá đã chọn, rồi bị gỡ. `<optgroup>` bị
làm phẳng (như dropdown). `multiple` theo select. `name` / `required` / `disabled` / `aria-label` lên host **khi host chưa
có** (PHP in `required` trên host), `<label for>` → host, gỡ select. Select đang focus lúc nâng cấp → chờ `blur` (như
dropdown v0.26).

## M8 — PHP `td_tree_select($name, array $tree, string|array|null $selected = null, array $o = [])`

**Có làm**, vì: chọn danh mục cha / chuyên mục là form server-render phổ biến nhất của dsuite; server đã có cây; một lời gọi
cho ra `<select>` **dùng được khi không JS** (thay cho cách tự viết danh sách phẳng của dwp) và nâng cấp không nháy (ADR 0012).
Không làm helper cho `<td-tree>` dạng inline (cây quyền là trang admin có JS; fallback nested-checkbox là nhiều bề mặt cho ít
lợi — làm khi có nhu cầu thật).

- Nút `['value', 'label', 'children' => [...], 'disabled' => bool, 'description' => ?]`; duyệt lặp, chặn độ sâu 16; value
  chỉ chuỗi / số, **`''` / null / mảng / bool → bỏ cả nhánh** (cùng luật M1, `trigger_error` E_USER_WARNING một lần); value
  trùng → bỏ nút sau. Option: `multiple`, `cascade`, `placeholder`, `label`, `required`, `disabled`, `disable_subtree`
  (mảng value → nút + cả nhánh khoá: chống vòng cha-con), `display`, `size` (multiple, mặc định 8), `id`, `class`, `attrs`,
  `element`. `$selected` lọc cùng luật (bỏ `''`).
- **`placeholder`:** `single` → option `value=""` đầu tiên + `allow-clear` (như `td_dropdown`; không in khi có lựa chọn
  khoá); `multiple` → **không** có option rỗng, chỉ là chữ trigger khi trống + placeholder ô tìm.
- **Native:** `<select [multiple] name class="td-tree-select__native">`; thụt lề bằng **NBSP ở đầu text** (2 / cấp — kiểm tay
  popup native của Safari / iOS) + `data-level` + `data-label` (nhãn sạch); **không** dùng ký tự "—" trong nhãn (lỗi dcms2).
  `cascade` → option cha in `disabled data-native-only` (native chỉ chọn được lá, khớp M3).
- **Khoá đang chọn trong native — gửi đúng một lần, `required` vẫn đúng:**
  - `single`: option khoá in **`selected`, không `disabled`** (để chính select gửi nó); **mọi option khác** `disabled
    data-native-only`, không option rỗng → không đổi / xoá được, gửi đúng một mục, `required` thoả. Không input ẩn.
  - `multiple`: option khoá in `disabled selected` (không gửi, không bỏ chọn được) + **một** `<input type="hidden"
    class="td-tree-select__locked" name value>` mỗi giá trị khoá (gửi đúng một lần). Có ≥ 1 giá trị khoá → **không** in
    `required` trên select (trường đã khác rỗng; tránh `valueMissing` giả), `required` vẫn in trên host ở element mode.
  - Escape / allowlist / giữ chỗ tên như các helper element khác.
- **`['element' => true]` / `ssr_elements`:** `<td-tree-select data-td-ssr="tree-select@1" [required] …>` + đúng select
  (và input khoá) trên; select được CSS đặt **đúng hộp trigger** (như `td-dropdown__native`) → nâng cấp không xô lệch;
  `value-label` / `value-labels` in sẵn (M6).

## Non-goals (v0.29)

Kéo thả sắp xếp lại (v0.31 `td-sortable`) · virtualization (giới hạn ở dưới; cần hơn → lazy) · tìm phía server trong cây ·
`cascade` + lazy · gom giá trị về cha (SHOW_PARENT) · Shift-dải / Ctrl+A / PageUp-Down · chip cho tree-select `multiple` ·
hook render nút / nhãn HTML (không có hatch mới; chỉ text + description) · thao tác trên từng nút (sửa / xoá / thêm — app ghép
bằng `td-table` / menu) · lưu trạng thái mở (app nghe `expanded-change`) · highlight đoạn khớp · SSR / PHP cho `<td-tree>` inline
· `value-key` / `label-key`.

**Giới hạn kích thước (ghi docs):** ≤ 5.000 nút trong dữ liệu, ≤ 1.000 hàng **đang hiện** cùng lúc, sâu ≤ 16. Chỉ nhánh
đang mở có trong DOM (thu gọn = gỡ `group`); mở / đóng / check chỉ cập nhật phần bị ảnh hưởng, không render lại cả cây.
