## 1. Mục tiêu

1. Spec toolbar nhận `pressed(ctx) => boolean`: kit đặt `aria-pressed="true|false"` + hình đang bật, tính lại ở **mỗi lần
   đổi slide, lúc mở, khi thêm nút, và sau khi `onClick` xong** (đồng bộ hoặc promise).
2. `onClick` trả promise → nút bận (`aria-busy="true"` + không bấm được) đến khi settle, rồi đọc lại `pressed`.
3. Lỗi trong `pressed()` hoặc `onClick` bị từ chối **không làm vỡ lightbox**: fail closed (không bật), `console.warn` một
   lần.
4. Tuỳ chọn đổi icon khi bật (`pressedIcon`), API tối thiểu.
5. Tương thích ngược tuyệt đối: spec không có `pressed` chạy y như 0.95.0.

## 4. Thiết kế

### 4.1 API công khai

Spec toolbar (bảng `lightbox.md:658` "Spec nút toolbar") thêm 3 thuộc tính, đều tuỳ chọn:

| Thuộc tính | Kiểu | Mặc định | Ý nghĩa |
|---|---|---|---|
| `pressed` | `(ctx) => boolean` | — | Có hàm → nút là toggle: kit đặt `aria-pressed="true"` khi trả đúng `true`, `"false"` ngược lại (kể cả throw). Tính lại: mở, mỗi đổi slide, `addToolbarButton`, `refreshToolbar()`, sau khi `onClick` xong |
| `pressedIcon` | `string` | — | Tên icon registry thay cho `icon` khi đang bật. Tên không tồn tại → giữ `icon` |
| `busy` | `boolean` | `true` nếu có `pressed`, ngược lại `false` | `onClick` trả thenable → nút bận (`aria-busy="true"`, `aria-disabled="true"`) đến khi settle |

```js
TdLightbox.open(items, {
  toolbar: [{
    id: 'cover',
    label: 'Đặt làm ảnh bìa',
    icon: 'star',
    pressedIcon: 'star-filled',                      // site đăng ký bằng registerIcons (Q1)
    pressed: (ctx) => ctx.item.data.id === album.coverId,
    onClick: async (ctx) => { await api.setCover(ctx.item.data.id); album.coverId = ctx.item.data.id; },
    visible: (ctx) => ctx.item.type === 'image',
  }],
});
```

Handle thêm `refreshToolbar()` (D10). Không event mới (sự kiện `td-lightbox-change` đã có mỗi lần đổi slide).

**DOM:** nút toggle có `aria-pressed="true|false"`; khi bận thêm `aria-busy="true"` + `aria-disabled="true"` (gỡ cả hai
khi xong). Không class / data-attribute mới ngoài chúng (CSS đọc thuộc tính ARIA, như `[aria-pressed="true"]` hiện có).
`data-on` của site vẫn được tô như cũ.

**Tương thích ngược:** spec không có `pressed` / `busy` / `pressedIcon` → không code path mới chạy cho nút đó (D1, D4).
Nút có `pressed`: `aria-pressed` trước đây do site tự đặt → bây giờ kit ghi đè ở mỗi sync; ghi vào docs + CHANGELOG
(phiên chính): site khai báo `pressed` thì bỏ phần tự đặt `aria-pressed` / `data-on`.

### 4.2 Hành vi chi tiết

**Trạng thái trong `extras` Map** (dòng 352): mỗi entry thêm `{ busy: null | { token } }`. Dedupe cảnh báo (D7) nằm ở **`session.warned`**
(`Set<string>` khoá `${id}\u0000${kind}`, tạo cùng `session`, mất khi đóng) — **không** ở entry, để thay nút cùng id không reset
dedupe. `entry` là danh tính: thay nút cùng id tạo entry mới nên mọi callback của entry cũ tự bỏ (so `extras.get(id) === entry`).

**`syncExtras(ctx)`** (dòng 553): sau khi `visible` quyết định `button.hidden`, nếu nút hiện và có `pressed`:
`applyPressed(entry, ctx)`:
1. `let on = false; try { on = entry.spec.pressed(ctx) === true; } catch (e) { warnOnce(entry.spec.id, 'pressed', e); }`
2. `button.setAttribute('aria-pressed', on ? 'true' : 'false')`.
3. Có `pressedIcon` hợp lệ → thay phần tử `svg` hiện tại bằng `icon(on ? pressedIcon : icon)` (một lần dựng, không
   `innerHTML`); chỉ thay khi trạng thái đổi.
4. Giữ trạng thái bận hiện có (không gỡ `aria-busy`).

**Click handler** (dòng 535): `e.stopPropagation()` rồi:
1. `if (entry.busy) { e.preventDefault(); e.stopImmediatePropagation(); return; }` (D5: `aria-disabled` không chặn click của trình
   duyệt, nên guard ở JS và **nuốt hẳn** click như `setButtonBusy`: chặn default + listener sau). Listener này gắn **lúc tạo nút**
   (trong `addExtra`, trước khi code site lấy được nút) nên luôn đứng đầu hàng listener của nút.
2. `ctx = ctxOf()` (bắt slide hiện tại **lúc bấm**).
3. `let r; try { r = spec.onClick(ctx, b); } catch (err) { console.error(...); r = undefined; }` (log cũ).
4. **Nhận dạng thenable nằm trong vùng bắt lỗi:** `let then; try { then = r && (typeof r === 'object' || typeof r === 'function') ? r.then : undefined; } catch (err) { then = undefined; warnOnce(entry.spec.id, 'onClick', err) }`
   (getter `then` ném lỗi không làm vỡ). `then` là hàm → **thenable**. Một **chốt settle duy nhất** `settle(kind, err)` dùng
   chung cho thành công và thất bại: `if (settled) return; settled = true;` đặt **trước** mọi dọn dẹp (resolve rồi reject, hay một
   callback gọi nhiều lần → chỉ lần đầu có tác dụng). Thenable và `busy` bật → đặt `entry.busy = { token: ++seq }`, thêm
   `aria-busy` + `aria-disabled`; `try { then.call(r, () => settle('ok'), (e2) => settle('fail', e2)) } catch (err) { settle('fail', err) }`.
   `settle`: nếu `extras.get(id) !== entry || session.token !== token` → **bỏ** (nút đã gỡ / thay / phiên đã đóng).
   Chỉ khi lần bấm này **đã tạo** token bận (`myBusy = entry.busy = {…}` giữ trong closure) mới đọc / gỡ bận, và chỉ khi
   `entry.busy === myBusy` (không đọc `entry.busy.token` khi `busy` không được tạo — nhánh 5 không có); ngược lại gỡ bận (nếu có), `fail` thì `warnOnce(entry.spec.id,
   'onClick', err)`, rồi chạy lại **đúng đường đồng bộ có cổng `visible`** cho slide **hiện tại** (D6): `syncExtras(ctxOf())` (hoặc hàm một-entry dùng chung với nó: `visible` → ẩn / hiện → chỉ khi hiện mới `applyPressed`) + `syncOverflow()`. Nút đã ẩn ở slide hiện tại thì `pressed` **không** được gọi (D3).
5. **Thenable nhưng `busy` tắt** (`busy: false` tường minh trên nút có `pressed`, hoặc nút thường mặc định): kết quả vẫn được **quan sát** để
   rejection không thành unhandled rejection. Quy tắc tối thiểu giữ tương thích: nút **có `pressed`** (hoặc `busy: true`)
   luôn gắn `then` quan sát (cùng chốt settle, `fail` → `warnOnce`), nhưng **không** đặt UI bận khi `busy: false` (`entry.busy` giữ `null`, `settle` kiểm liveness entry / session rồi bỏ qua phần bận); sau settle (còn sống) → **cùng** đường đồng bộ có cổng `visible` như bước 4 (`syncExtras(ctxOf())` / một-entry tương đương), không gọi `applyPressed` trực tiếp.
   Nút **không** có `pressed` và không `busy: true` (spec cũ) **không** bị quan sát — promise bị bỏ như 0.95.0 (D4, tương thích tuyệt đối).
6. Không phải thenable → `applyPressed(entry, ctxOf())` ngay (đọc lại `pressed` sau onClick đồng bộ).
   `onClick` không trả promise nhưng thay đổi state bất đồng bộ qua cách khác → site dùng `refreshToolbar()`.

**Đồng thời / chuyển slide khi đang bận:** `show()` → `syncExtras()` vẫn chạy, `pressed(ctxB)` được đọc cho slide mới và
cập nhật `aria-pressed`, nhưng nút giữ `aria-busy`/`aria-disabled` (D6) nên không bấm được trên slide B cho tới khi
settle; settle → đọc lại cho slide hiện tại. Slide A đóng lightbox khi bận → `unmountToolbar()` (dòng 499) xoá entry, callback
trễ bị bỏ bởi so danh tính + token. `open()` mới khi lightbox đang mở → `session.token` đổi, cùng kết quả.

**Hết hạn phiên:** `done` / `fail` không bao giờ chạm DOM của phiên khác (kiểm `session && session.token === token`).

**`removeExtra`** (dòng 546): xoá entry → bận bị bỏ tự nhiên.

**Menu "Thêm"** (`overflowMenuItems`, dòng 586): nút có `pressed` → item **thường** `{ label, icon: <icon đang hiển thị>,
hint: busy ? labels.busy : on ? labels.pressedOn : undefined, disabled: entry.busy != null, onSelect: () => b.click() }`
(D11). Menu dựng lúc mở (lazy) và **đóng ngay khi chọn** (item thường) nên không có trạng thái "menu mở lúc đang bận" để
đồng bộ; nếu trạng thái bận đổi giữa lúc mở menu và lúc chọn thì guard ở handler của nút chặn.

## 5. Bảo mật

- Không chuỗi nào từ site thành HTML: `pressed` trả boolean (so `=== true`), `pressedIcon` chỉ là tên đi qua `icon()`
  (registry whitelist, `NAME_RE`); nhãn vẫn `aria-label` / `title` / `textContent` như hiện nay (security-model §1
  "không hatch HTML", ADR 0009).
- CSP strict: không `style=`, không `<style>`; trạng thái chỉ là thuộc tính ARIA + CSS có sẵn.
- Hook của site (`pressed`, `onClick`) là code tin cậy của site nhưng **không** được làm vỡ kit: mọi lệnh gọi trong
  `try/catch`, thenable độc hại (`then` ném lỗi, gọi `done` hai lần) bị chặn bằng cờ một-lần; không có DoS kiểu vòng lặp
  (`applyPressed` không gọi lại `pressed` đệ quy; `refreshToolbar` không phát sự kiện).
- Không đọc `Function.name` / `constructor.name` (thenable xác định bằng `typeof r.then === 'function'`, không `instanceof Promise`).
- `warnOnce` chỉ `console.warn` thông điệp tĩnh + đối tượng lỗi (không nội suy chuỗi từ site vào log có định dạng).
- Gate: **codex-security** chạy (hook gọi code của site + log) dù không đụng URL / input người dùng trực tiếp.

## 6. Trợ năng + cảm ứng

- `aria-pressed` chỉ trên nút có `pressed`; `aria-label` giữ nguyên (không đổi khi bật) → SR đọc "Đặt làm ảnh bìa, nút
  bật tắt, đã bật".
- Bận: `aria-busy="true"` + `aria-disabled="true"`, **focus ở lại nút** (D5); `Enter` / `Space` / chạm khi bận bị bỏ.
  Không live region mới: kết quả (bật xong) do SR đọc lại `aria-pressed` khi người dùng quay lại nút; thông báo thành
  công / thất bại là việc của site (toast).
- Menu "Thêm": item thường (`menuitem`) có chữ phụ `hint` ("Đang bật" / "Đang xử lý…", gắn `aria-describedby` bởi TdMenu) nên
  SR đọc được trạng thái; bận → `aria-disabled` (TdMenu: focus được nhưng không kích hoạt).
- Cảm ứng ([touch.md](design/touch.md)): vùng chạm `--td-lb-btn`/`--td-touch-min` không đổi; hình nhấn bằng
  `:active` / `[data-td-pressed]` có sẵn, không bật khi bận; không hover-only (trạng thái bật là thuộc tính, không phải
  hover); không đụng `touch-action`.
- Không RTL (chủ sở hữu: không kiểm RTL); CSS logical.

## 7. Test

**Node** (`src/feedback/td-lightbox-toggle.test.js`, mô-đun thuần): nếu logic tách được thành hàm thuần không DOM
(ví dụ `settlePressed`/`isThenable`), test bảng thật ngắn; còn lại để browser test (lightbox cần DOM). Nếu không có gì tách
đáng kể thì **bỏ** file node, không tách chỉ để có test.

**Browser 3 engine** (`src/feedback/td-v096-lightbox-toggle.engines.browser-test.js`, mẫu `td-v095-lightbox-preload.engines.browser-test.js`;
thêm vào danh sách engines trong `web-test-runner.config.js` cạnh dòng 35 nếu danh sách là liệt kê tường minh):
1. `pressed` đúng / sai / throw / trả `1` (không phải `true`) → `aria-pressed` `true` / `false` / `false` (+1 warn) / `false`.
2. Đổi slide: sao bật trên slide có bìa, tắt trên slide khác; mở ở `index` giữa → đúng ngay lần mở đầu (không nháy sai).
3. `visible()` false → không gọi `pressed` (đếm lời gọi).
4. onClick đồng bộ → đọc lại; onClick ném → `console.error` + vẫn đọc lại; không vỡ lightbox (còn mở, next() chạy).
5. onClick trả promise: nút `aria-busy` + `aria-disabled`, bấm lại không gọi onClick lần hai (listener của site gắn thêm trên nút cũng không chạy, `defaultPrevented` đúng), **focus vẫn ở nút**; resolve
   → gỡ bận + `pressed` đọc lại; reject → `console.warn` đúng **1** lần dù reject hai lần liên tiếp, fail closed.
6. Đồng thời: bấm ở slide A, đổi sang B khi pending → nút vẫn bận; settle → `pressed(ctxB)` (kiểm bằng ctx.index ghi
   lại); `onClick` nhận ctx của A.
7. Đóng / `open()` mới / `removeToolbarButton` / thay cùng id khi pending → settle trễ không ném, không chạm nút mới.
8. Thenable độc hại: `then` ném; **getter `then` ném**; gọi resolve rồi reject / một callback nhiều lần → chỉ lần đầu có tác dụng (một chốt settle), không vỡ.
8b. `pressed` + `busy: false` + onClick trả promise reject → không UI bận, không unhandled rejection, `console.warn` đúng 1 lần; nút **không** `pressed` trả promise reject → không bị quan sát (như 0.95.0).
8d. Đang bận → đổi sang slide mà `visible()` false → settle → `pressed` **không** được gọi (đếm lời gọi); quay lại slide hiện thì đọc đúng. Chạy cả hai biến thể: nút bận (`busy` mặc định) và `busy: false` (nhánh quan sát).
8c. Thay nút **cùng id** rồi lỗi lại → `console.warn` không lặp (dedupe theo session).
9. `pressedIcon`: đổi `svg[data-icon]` theo trạng thái; tên sai → giữ icon; `refreshToolbar()` tính lại.
10. Nút không `pressed`: không có `aria-pressed`; `data-on` tự đặt vẫn tô; promise trả về không bận (D4); `busy: true` thì bận.
11. Menu "Thêm" (viewport < 480px): nút toggle → item `menuitem` (không phải `menuitemcheckbox`), `hint` "Đang bật" khi bật,
    bận → `aria-disabled="true"` + hint bận; chọn item → menu đóng + `onClick` chạy đúng một lần; bận giữa lúc mở và chọn → onClick không chạy.
13. Hợp đồng bận dùng chung (cùng hình với test của busy helper): `aria-busy="true"` + `aria-disabled="true"`, không `disabled` gốc,
    focus giữ, click / Enter / Space bị nuốt, gỡ sạch cả hai khi settle.
12. Màu: nút bật có `color` = `--td-lb-pressed`; bận có `opacity` 0.5 (`getComputedStyle`). Hover khi bận không kiểm ở
    engines (cần chuột thật, không vào `POINTER_FILES`); phần chạm kiểm ở `test:touch`.

**Test hiện có cần xem lại:** `src/feedback/td-lightbox.browser-test.js:199–225` (toolbar), `:763–782` (addToolbarButton) —

## 11. Câu hỏi mở (đã có mặc định đề xuất — owner chỉ cần sửa nếu không đồng ý)

Người dùng cuối thấy được các lựa chọn dưới đây; không việc nào chặn làm plan.

- **Q1 — Sao "đầy" (đang là ảnh bìa) có sẵn trong kit không?** Hiện kit chỉ có sao viền (`star`); sao đầy chưa có. Mặc định
  đề xuất: **chưa thêm** icon core; nút bật vẫn đổi màu vàng (có sẵn) và site (dwp) đăng ký `star-filled` bằng
  `registerIcons` rồi đưa vào `pressedIcon` (docs có công thức). Thêm icon core kéo theo `icons.json`, bảng tìm icon, PHP
  parity, `check:icons` (lane riêng, ~nửa ngày) — chỉ làm nếu owner muốn mọi site có sẵn.
- **Q2 — Đang lưu ảnh bìa mà người dùng lướt sang ảnh khác thì nút sao ra sao?** Mặc định: nút **vẫn mờ / chưa bấm được**
  cho đến khi lưu xong (thường dưới 1 giây), rồi hiện đúng trạng thái của ảnh đang xem. Cách còn lại (cho bấm ngay ảnh mới)
  có thể gây hai yêu cầu lưu chồng nhau và hiển thị sai.
- **Q3 — Lưu quá lâu / treo?** Mặc định: nút mờ mãi cho đến khi người dùng đóng ảnh; kit **không** tự mở khoá sau N giây
  (site quyết thời gian chờ và báo lỗi bằng toast của site).
- **Q4 — Nút thường (không phải bật/tắt) có tự mờ khi thao tác đang chạy không?** Mặc định: **không** (giữ như cũ cho mọi
  site đang chạy), site muốn thì khai `busy: true`.
- **Q5 — Trên điện thoại (< 480px) nút bật/tắt nằm trong menu "Thêm", nó trông ra sao?** Hôm nay mọi nút trong menu đó chỉ
  là một dòng chữ + icon, bấm là menu đóng lại và việc được làm. Menu của kit có kiểu "ô chọn" có dấu tích, nhưng kiểu đó
  tự lật dấu tích ngay khi chạm và để menu mở; với thao tác lưu cần chờ máy chủ thì dấu tích sẽ hiện sai (đã tích mà lưu
  chưa xong hoặc bị lỗi). Mặc định đề xuất: **giữ dòng thường**, đổi icon thành sao đầy (nếu site có) và thêm chữ nhỏ
  "Đang bật" bên dưới khi đang bật, "Đang xử lý…" khi đang lưu (mờ, không bấm được). Cách còn lại (ô chọn có dấu tích) đẹp
  hơn khi chỉ bật / tắt tức thì không cần chờ, nhưng dễ sai hơn. Hai chữ này site đổi được qua `labels`.
