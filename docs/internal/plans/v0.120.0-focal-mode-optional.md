# v0.120.0: `focal-optional` in focal mode (dcms2 K1)

Requested by dcms2 (owner-approved 2026-11-22; dcms2 `.planning/2026-11-21-hard-crop-wave-plan.md` §3.7). Same API
names as v0.119.0. Today `focal-optional` / `focalPointOptional` is ignored in focal mode; dcms2 needs a focal-only
field where the point is optional and no crop rect is ever produced.

## Decisions
- QĐ1 td-cropper: `_focalOpt()` (src/form/td-cropper.js:668) holds in focal mode too (`focal-optional` && (focal mode ||
  box/pan with the focal tool)). With it, focal mode does NOT auto-centre (`_autoFocal` :661 skips): the unset centre
  marker shows, `getResult().focalPoint` stays null, a pointer places the point, the first focal key starts from the
  centre (source 'keyboard'), "Dùng giữa ảnh" shows while a point is set (focal-change null, source 'clear', focus kept),
  "Đặt lại" restores the initial focal. Focal mode never draws a crop frame (unchanged). Without the flag focal mode is
  byte-identical (mandatory, auto-centred).
- QĐ2 crop dialog (src/feedback/crop-dialog.js:233): forward `focal-optional` in focal mode as well (focal mode does not
  need `allowFocalPoint`). The result in focal mode keeps `crop: null` and gives `focalPoint` {x,y} | null.
- QĐ3 picker (td-media-picker.js:3905, media-picker-core.js:1017): pass `focalPointOptional` through for focal mode;
  a null focal yields `usage.focalPoint: null`, `usage.crop: null`. A seeded `crop.focalPoint` still pre-places it.
- QĐ4 field (td-media-field.js:422 `_focalOptional`): true with `crop-mode="focal"` (no `focal-point` needed); box/pan
  still need `focal-point`. Field value/form fields: focal empty when null, crop always empty in focal mode.
- `crop.output 'new-asset'` + focal mode: unchanged (warn once, metadata).
- QĐ8 (review R2) runtime toggle in focal mode (`attributeChangedCallback` 'focal-optional'): the cropper already tracks
  an auto-placed centre with `_focalAuto` (src/form/td-cropper.js:259/:661). Adding the flag: if `_focalAuto` is true,
  drop that point (`_focal = null`, `_focalAuto = false`) and re-render as unset, silently (no event). Removing the flag:
  call `_autoFocal()` so an unset point becomes the silent centre again. An explicit user or seeded point
  (`_focalAuto` false) is never changed. Test: both directions, plus an explicit point surviving both toggles.
- QĐ5 (review R1) the dialog apply guard: focal-mode dialogs today reject a null focal point on apply. With
  `focalPointOptional`, apply accepts null; the changed-state calculation compares against the initial focal (null vs
  null = unchanged, so the field emits no event). Without the flag the mandatory guard stays.
- QĐ6 (review R1) focal-mode toolbar: today focal mode enforces "Reset is the only tool". With the flag, the clear control
  is also allowed (only while a point is set; focus is kept after clearing as in v0.119). Ordinary focal mode stays
  Reset-only.
- QĐ7 (review R1) every focal-mode option-building path must forward the flag:
  (a) core resolution: focal-mode resolution does not call `resolveCropExtras` today; it must keep `focalPointOptional`;
  (b) picker → dialog: stop stripping `focalPointOptional` for focal mode;
  (c) the field's picker path; and
  (d) the field's direct dialog path. Both build dedicated focal-mode option objects without `_cropExtras()`, and must
  forward the flag.
  Seeded focal-point behaviour stays. Each boundary gets a test.

## Tests
- Update the v0.119 tests that asserted "focal mode ignores the flag" (td-v119-cropper-focal-optional, td-v119-crop-output).
- New cases: cropper focal mode + flag (no auto-centre, null result, pointer place, keyboard from unset, clear, reset);
  picker focal mode + flag: null round-trip, no rect in the outcome; field crop-mode=focal + focal-optional: null value,
  clear → input/change with empty focal, crop never set; without the flag focal mode unchanged.
- Regression: v113 focal suites, v119 suites, v035 crop suites, test:csp, preupgrade table, full test:engines, test:node.
