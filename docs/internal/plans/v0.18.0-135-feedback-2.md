# v0.18.0 — Đề xuất đợt 2 từ 135 (sau khi áp v0.17.0)

Owner: "ok nốt đi xong gọi codex ra review" — làm cả 9 đề xuất 135 gửi sau khi áp v0.17.0 (135 đang còn vài chỗ native
vì kit thiếu). Tham khảo chỉ đọc: repo 135 (`docs/05-ui-kit.md` §"Đề xuất đã gửi", CSS `td-stamp`, `templates/admin/layout.php`
flash `p.td-alert[data-flash]`). Không dependency mới; mỗi mục có test; docs + CHANGELOG + breaking-changes.

## F1 — `<td-button>` gửi `name` / `value` khi là submitter

`name`, `value` (và `form` **không**) trên host → chuyển xuống `<button>` bên trong (cập nhật tại chỗ, bỏ khi gỡ
attribute) — button light-DOM là submitter thật nên `FormData(form, submitter)` / submit native có cặp `name=value`.
Chỉ áp cho `<button>` (không cho link `href`). Test: `form.requestSubmit(btn)` và click thật → FormData chứa cặp;
hai nút cùng `name` khác `value` → đúng nút được bấm; gỡ `name` → không gửi.

## F2 — `<td-input-field>` type `month`, `datetime-local`, `time`

Thêm vào `_types`; control native tương ứng; validity tự tính dùng probe input cùng type cho `min`/`max`/`step`
(`rangeUnderflow`/`rangeOverflow`/`stepMismatch`, `badInput`). Giá trị form = **đúng `.value` đã chuẩn hoá của control
native** (`YYYY-MM`; `YYYY-MM-DDTHH:mm` hoặc có giây / phần lẻ giây khi `step` cho phép, ví dụ `…T10:30:15.5`;
`HH:mm[:ss[.sss]]`) — kit không cắt bớt. Test: FormData, min/max/step, reset, `setValue`, và `step="1"` với giá trị có
giây cho `time` + `datetime-local` (FormData + `setValue` giữ nguyên giây).

## F3 — `<td-datetime-picker>` chế độ + điểm mở lịch

- Attribute `mode`: `datetime` (mặc định, như cũ) | `date` | `month` | `year`. Mỗi mode chỉ hiện bánh xe tương ứng,
  định dạng hiển thị (`dd/mm/yyyy - hh:mm` | `dd/mm/yyyy` | `mm/yyyy` | `yyyy`), placeholder mặc định, và giá trị
  form (`form-value-format` iso: `YYYY-MM-DDTHH:mm:00` | `YYYY-MM-DD` | `YYYY-MM` | `YYYY`; display / db tương ứng).
  `min` / `max` hiểu theo độ chi tiết của mode (month: tháng đầu/cuối; year: năm).
- Khoảng năm mặc định (khi không có `min`/`max`) giữ như cũ; có `min`/`max` thì bánh xe năm phủ đúng khoảng đó
  (kể cả < 2000).
- Attribute `open-at`: `today` | `min` | `max` | một ngày (cùng định dạng `min`) → vị trí bánh xe khi mở mà chưa có
  giá trị (kẹp vào [min, max]). **Mặc định khi không có `open-at`**: nếu năm của `min` < 2000 → mở tại `min` (ảnh
  film cũ — yêu cầu của 135, không cần site thêm gì); ngược lại → hôm nay (kẹp). `open-at` tường minh luôn thắng.
- **Hợp đồng giá trị theo mode** (API hiện có giữ tên):

  | | datetime (cũ) | date | month | year |
  |---|---|---|---|---|
  | display / attribute `value` / `getValue()` / `setValue()` | `dd/mm/yyyy - hh:mm` | `dd/mm/yyyy` | `mm/yyyy` | `yyyy` |
  | `getDBValue()` / `setDBValue()` | `yyyy-mm-dd hh:mm:00` | `yyyy-mm-dd` | `yyyy-mm` | `yyyy` |
  | form `iso` (mặc định) | `yyyy-mm-ddThh:mm:00` (**giữ nguyên như v0.17.0**) | `yyyy-mm-dd` | `yyyy-mm` | `yyyy` |

  `setValue` / attribute `value` nhận display của mode **hoặc** ISO của mode; `setDBValue` nhận db của mode (ISO cũng
  được). Event `change` detail `{ value, dbValue }` theo đúng định dạng của mode. Phần không thuộc mode (giờ ở `date`,
  ngày ở `month`…) không tồn tại trong giá trị. **Đổi `mode` khi đã có giá trị**: giữ các thành phần còn ý nghĩa (ví dụ
  datetime → date bỏ giờ; date → month bỏ ngày; month/year → date lấy ngày 1 / tháng 1). Thành phần **mới xuất hiện**
  khi mở rộng mode có mặc định cố định: tháng = 01, ngày = 01, **giờ = 00, phút = 00** (ví dụ date `15/06/1985` →
  datetime `15/06/1985 - 00:00`; year `1985` → datetime `01/01/1985 - 00:00`). Chuẩn hoá lại, kẹp vào [min, max], cập
  nhật form value, không phát `change`.
- Test: từng mode (render bánh xe, chọn, FormData, min/max, reset, `getValue`/`getDBValue`/`setValue`/`setDBValue`,
  attribute `value`, detail `change`), **regression**: mode datetime mặc định gửi FormData đúng chuỗi của v0.17.0
  (`yyyy-mm-ddThh:mm:00`), đổi mode khi có giá trị (thu hẹp và mở rộng, ít nhất date → datetime ra `00:00`), `open-at` min/max/ngày cụ thể, và `min="1950-01-01"`
  **không** có `open-at` mở tại 1950.

## F4 — Component mới: `<td-progress>` và `<td-dropzone>`

- `<td-progress value max label>`: thanh tiến độ (`role="progressbar"`, `aria-valuenow/min/max`, `aria-valuetext`
  "N%"), không có `value` = indeterminate (animation, tắt theo `prefers-reduced-motion`), biến thể màu
  (`variant` primary|success|danger|warning), kích thước sm|md; CSSOM cho độ rộng (CSP).
- `<td-dropzone accept multiple max-size max-files name label>`: vùng kéo-thả + nút chọn file (input `type=file`
  thật bên trong, bàn phím Enter/Space mở hộp chọn), lọc theo `accept` (MIME/đuôi), `max-size` (byte, hỗ trợ `5MB`),
  `max-files`; danh sách file đã chọn (tên — **text**, kích thước, nút xoá), lỗi file bị loại (nhãn dịch được
  `TdDropzone.labels`). **Form-associated**: submit các file qua `ElementInternals.setFormValue(FormData)` với `name`;
  `required`. Vòng đời form: **reset** form → xoá danh sách + form value (và huỷ upload đang chạy); đổi attribute
  `name` → dựng lại `FormData` với tên mới; **effectively disabled** (attribute `disabled` hoặc `<fieldset disabled>`) →
  không mở hộp chọn, bỏ qua drop, ẩn/khoá nút xoá, không submit (như control native).
  Event `files-change` `{ files, rejected }`. Hook tuỳ chọn `upload(file, { onProgress, signal })` →
  hiện `<td-progress>` từng file, huỷ bằng nút xoá (abort). Không tự upload nếu site không cấp hook.
- Bảo mật: tên file chỉ render bằng `textContent`; lọc phía client là **gợi ý** (docs: server phải kiểm lại loại /
  kích thước / nội dung); không đọc nội dung file, không tạo object URL trừ khi site bật `preview` (ảnh, revoke khi xoá).
- Cả hai: token CSS, story, CSP matrix state, docs trang mới, exports + sideEffects + barrel.
- Test: progress (aria, indeterminate, reduced motion); dropzone (chọn file qua input, drop DataTransfer giả, lọc
  accept/size/count, xoá, FormData có file, required, upload hook progress + abort, tên file `<img onerror>` hiện
  dạng text, **reset** form xoá file + FormData, **đổi `name`** → FormData dùng tên mới, **disabled** / `<fieldset
  disabled>` chặn chọn / drop / xoá và không submit).

## F5 — Badge/stamp + alert/banner

- CSS component `.td-badge` (`--neutral|--accent|--success|--warning|--danger|--info`, `--outline`, `--stamp` = kiểu
  con dấu chữ in hoa viền đôi nghiêng nhẹ như `td-stamp` của 135, token màu/nghiêng tắt được) — thuần CSS, không JS.
- `<td-alert variant dismissible heading>`: khối thông báo tĩnh (info|success|warning|danger), icon theo variant,
  `role="status"` (danger → `role="alert"`), nút đóng tuỳ chọn (event `dismiss`, nhãn `TdAlert.labels.close`), cũng có
  dạng CSS-only `.td-alert` cho SSR/flash không JS.
- **Hợp đồng SSR một kiểu duy nhất**: PHP `td_alert($message, $opts)` luôn in host `<td-alert variant=…
  [dismissible] [heading]>` chứa sẵn markup đầy đủ `div.td-alert.td-alert--{variant}[role]` (icon, heading, message) —
  td.css tạo dáng **không cần JS** (flash của 135 hiện được ngay). Khi JS nạp, `<td-alert>` **nâng cấp tại chỗ** (giữ
  nội dung, không render lại chữ) và gắn nút đóng nếu `dismissible` (không JS: không có nút đóng — tránh nút chết).
  `td_badge($text, $opts)` in `span.td-badge…` thuần CSS.
- **Đóng gói**: CSS badge + alert thêm vào `src/styles/manifest.json` (+ `td.css` build lại); `package.json#exports`
  `./alert`; `sideEffects` thêm `src/feedback/td-alert.js`; barrel `index.js` export `TdAlert`; test manifest
  (`src/package-manifest.test.js`) + `index-exports` + `npm pack --dry-run` có file mới.
- Test: markup/role theo variant, **trước nâng cấp** (markup PHP có dáng, không nút đóng) và **sau nâng cấp** (nút
  đóng, dismiss phát `dismiss` + gỡ khối, nội dung giữ nguyên), contrast gate cho badge/alert text (≥ 4.7 trên nền của
  chúng, light+dark), PHP snapshot + escaping.

## F6 — Alias icon ở JS + cảnh báo

Registry JS nhận alias giống PHP (`x→close`, `chevron-left→prev`, `chevron-right→next`, `chevron-up→up`,
`chevron-down→down`, `ellipsis→more`, `external-link→external`, `expand→fullscreen`, `pen→pencil`) — một nguồn chung
(`icons.json` thêm `aliases`, PHP đọc cùng dữ liệu). `td-button icon="…"`: tên kiểu registry (kebab-case, một token)
không có trong registry sau alias → `console.warn` một lần (thay vì im lặng ra `<i>` rỗng); class Font Awesome kiểu cũ
(`fas fa-…`) giữ đường legacy. Test: alias ra đúng SVG (JS + PHP), tên lạ warn.

## F7 — `td_link` bỏ được kiểu nút

Option `bare => true` **chỉ cho `td_link`** → `<a>` **không** có class `td-btn…` và không có span con của nút, chỉ class
của site + cùng URL whitelist/target/download/`rel`; docs sửa câu "giữ kiểu cũ bằng class". (Không thêm
`variant => 'none'`.) Test snapshot.

## F8 — `td_dropdown` `searchable` dạng chuỗi

Chỉ **vắng mặt / `null`** → tự động (> 8 mục). `false`, `0`, và chuỗi `'false'` / `'0'` / `'off'` / `'no'` / `''`
(không phân biệt hoa thường, trim) → tắt. **Mọi giá trị khác giữ truthiness của PHP** như trước (`true`, `1`, `'1'`,
`'true'`, `'yes'`, `'on'` … → bật) — không đổi hành vi của cấu hình hiện có ngoài các chuỗi "false". Test cho từng nhóm.

## F9 — Yêu cầu PHP thật

Kiểm mã chỉ dùng tính năng ≤ 8.0 (không enum, readonly, first-class callable, `never`, `new` trong initializer,
`array_is_list`…) → header + docs "PHP ≥ 8.0"; test harness (`test/php/php.mjs`) đổi ngưỡng bỏ-qua và thông báo sang
8.0. **Kiểm chứng thật trên PHP 8.0**: thêm job CI `php80` (GitHub Actions: `shivammathur/setup-php@v2` với
`php-version: '8.0'` — chỉ công cụ CI, không phải dependency của kit) chạy `php -l php/td.php` và cả bộ
`node --test "test/php/*.test.js"` bằng PHP 8.0. Quét cú pháp chỉ là kiểm tra phụ. Nếu có chỗ bắt buộc 8.1 thì giữ 8.1
và ghi lý do.
