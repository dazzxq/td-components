# v0.118.0 (part 2): media picker card meta format + name clamp

Request: dsuite, 20/11 (the owner asked). The card meta "174.32 KB • 17/11/2026 02:02" wraps to 2 lines on narrow
cards. The owner wants on the card: the name clamped to at most 2 lines, and the meta on exactly 1 line as size plus a
short relative time ("174 KB · 5m trước"). No tooltip. The detail pane keeps the absolute date. Built as generic
options (rule: site requests become generic slots/hooks), shipped together with the TdMenu submenu in 0.118.0.

## Decisions (QĐ)

**QĐ1. `cardMeta` option** (on `open()` and `configureDefaults()`, like `pageSize`):
- absent or `'absolute'`: today's text, byte for byte (`{size} • {DD/MM/YYYY HH:mm}`), today's wrapping CSS.
- `'relative'`: `{short size} · {relative time}`. Short size (`shortFileSize`): units `B`, `KB`, `MB`, `GB`, `TB`
  (1024 steps; `B` replaces `formatFileSize`'s `Bytes`). The value is rounded to at most 3 significant digits
  (`n >= 100` → integer, `>= 10` → 1 decimal dropped to integer only if `.0`, i.e. `12.3 KB`; `< 10` → up to 2
  decimals trimmed, i.e. `1.2 MB`, `9.99 KB`); if rounding reaches 1024 it carries to the next unit (`1023.9 KB` →
  `1 MB`, `1048575 B` → `1 MB`). Examples: `12 B`, `1023 B`, `1 KB`, `174 KB`, `1.2 MB`. `byteSize` absent, 0 or
  invalid → no size part (as today's card, which omits a falsy `byteSize`). Relative time is computed from `createdAt`
  when the card is painted (it does not tick live): units s, m, h, d, w, mo, y (floor; 1mo = 30d, 1y = 365d), rendered
  through a label `relativeTime` = `"{n}{unit} trước"` and unit labels `relativeUnits` = `{ s, m, h, d, w, mo, y }`
  (sites can translate). A future or invalid date: a future one shows `0s`; a missing or invalid one omits that part.
  Either part missing → just the other one, no separator.
- a function `(asset, ctx) => string`: the app's own text. `ctx = { formatSize, formatShortSize, formatDate,
  formatRelative, now }` (the kit's helpers, so an app can mix them). A non-string or empty result, or a throw
  (console.error once per open), falls back to the `'absolute'` text. Set as textContent, never HTML.
- Any other value warns once and acts as absent.
- The detail pane, metadata and the absolute date there are unchanged in every mode.
- The open button's accessible name uses the same card meta text it shows (as today).
- In `'relative'` and function mode the meta line is one line: the root gets `data-card-meta="single"` and CSS gives
  `.td-media-picker__meta` `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` (touch font-size rule stays).
  No `title` tooltip.

**QĐ2. `nameLines` option** (open + defaults): integer 1 to 3; absent = 1 (today's single-line ellipsis, unchanged).
2 or 3 sets `data-name-lines="2|3"` on the root; CSS clamps `.td-media-picker__name` with `display: -webkit-box;
-webkit-box-orient: vertical; -webkit-line-clamp: N; white-space: normal; overflow-wrap: anywhere` (CSP safe: no
inline style). Invalid values warn once and act as absent.

**QĐ2b. Warnings.** The invalid `cardMeta` / `nameLines` warnings are module-level once-flags (like `warnedLoadMore`,
reset by `_resetCoreWarnings`), so a static `open()` that resolves options twice warns once. Test through the public
static `TdMediaPicker.open()` path: a bad value warns exactly once.

**QĐ3. Not doing.** No live ticking, no `Intl.RelativeTimeFormat` (the short "5m trước" form is wanted), no tooltip,
no change to the detail pane, no change to defaults.
