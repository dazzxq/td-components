# v0.118.0: nested submenus in TdMenu (one level)

Request: dsuite admin, image-album card. The 3-dot menu needs "Chuyển sang ›". Hovering it opens a side menu of target
albums. The owner approved the feature, called it important, and asked for native parity with Chrome, macOS and Windows
context menus (section "Native parity"). dcms2 uses the same menus.

Today the kit has one menu at a time and no submenu:
- `docs/internal/plans/v0.53.0-menu-custom-item.md:48` (non-goal "Không submenu / TdMenu lồng").
- `docs/internal/plans/v0.96.0-action-fold.md:380` (a folded menu button re-opens a second TdMenu on "…").
- `src/feedback/td-menu.js:40` ("one menu at a time"), `:901-911` (open() toggles or closes the old session).

dsuite works around it by re-opening a second TdMenu on the same trigger. This plan keeps "one menu at a time": the
submenu is part of the same session, not a second `TdMenu.open()`.

## Goal

- An item `{ label, icon, items: [...] }` is a parent. It shows a trailing chevron and opens a child menu.
- Desktop (fine pointer, wide screen): a flyout beside the parent. Hover intent, a safe triangle, click opens at once.
- Touch or narrow screens: in-place drill-down (the child list plus a Back row replaces the root list).
- Keyboard and ARIA follow the WAI-ARIA APG "Menu" pattern for submenus.
- Picking a child behaves exactly like picking a root item today.
- A menu without any `items` field renders and behaves byte-for-byte as in 0.117.0 (markup, ids, focus, listeners).

## Native parity

Sources: the platform behaviour as commonly documented and observed. Numbers marked "approx." are not measured by us.
"Chrome" means Chrome's own menus (Windows / Linux views menus); on macOS Chrome uses the native NSMenu.

| Behaviour | macOS | Windows | Chrome | Our decision |
|---|---|---|---|---|
| Side choice | Right of the parent menu; left when no room | Right; left when no room | Same as the platform | Inline-end when it fits, else inline-start when it fits, else the side with more room, then clamped into the viewport (8px margin) even if it overlaps the root (QĐ3) |
| Horizontal gap | Abuts the parent menu, slight overlap | Abuts, slight overlap | Abuts | 0px: abuts the root edge. No dead strip for the pointer to cross. No overlap (simpler, no z-fight with the root border) |
| Vertical alignment | First child item level with the parent item; shifted up at the bottom edge | Top level with the parent row; shifted up | Same | `top = parent.top - panel padding-top`, so the first child row lines up with the parent row. Shift up to fit, then clamp to the top edge (QĐ3) |
| Taller than the screen | Scroll arrows at the ends | Scroll arrows | Scroll arrows | Native scrollbar with `max-height = min(448, viewport - 16)`, the same cap as the root (`td-menu.js:86`, `:537`). Scroll arrows cost a lot for little value: not doing |
| Parent highlight while open | Stays highlighted, also with the pointer in the child | Stays highlighted | Stays highlighted | `[aria-expanded="true"]` fill `--td-menu-item-active`, outside the hover gate (state, touch.md rule 3) |
| Hover open delay | Near instant (approx. 0) | `MenuShowDelay`, default 400ms | Follows the platform (approx.) | 120ms (QĐ4). Filters a pointer passing over the row, feels instant. 400ms feels slow on the web |
| Diagonal move to the child | Direction-aware safe area | No triangle; the 400ms delay does the job | Delay-based (approx.) | Safe triangle with a 300ms grace (macOS style), because our open delay is short (QĐ4) |
| Pointer moves to a sibling | Child closes once the sibling is hovered (after the safe area) | Child closes after the delay | Same as the platform | After the grace (if any) plus the 120ms intent, the child closes; a sibling parent opens its own child |
| Pointer leaves both panels to empty space | Child stays open | Child stays open | Child stays open | Child stays open. A pending intent is cancelled. Only hovering another root row changes it |
| Click on the parent | Opens at once, menu stays | Opens at once, menu stays | Same | Opens at once (no delay), never closes the tree, focuses the first enabled child (the kit's focus-first rule, `td-menu.js:1041-1044`). A click on an open parent keeps it open |
| Keyboard: open | Right opens, first child highlighted | Right / Enter opens, first child selected | Same | ArrowRight (inline-end key), Enter, Space: open + focus the first enabled child |
| Keyboard: close one level | Left closes the child | Left / Escape close the child | Same | ArrowLeft (inline-start key) and Escape close the child, focus goes back to the parent |
| Escape twice | Escape closes the whole menu | Escape closes one level per press | Same as the platform | Windows style, as the consumer asked: the first Escape closes the child, the second closes everything |
| RTL | Arrow keys mirror | Arrow keys mirror | Mirror | Keys and sides are logical in code (computed `direction` of the root menu). No RTL tests (owner rule) |
| Home / End / type-ahead in the child | Type-ahead yes | First letter yes | Yes | Yes, the same functions as the root, scoped to the child list |
| Press on the trigger, drag, release on an item | Picks the item | Picks the item (menu bar) | Picks on native mac | Not relevant: the kit opens on `click` (`td-menu.js:1097-1100`) and activates items on `click` (`:827-844`). Unchanged, no drag-release pick |
| Viewport resize / scroll | Menus are modal, the page cannot scroll | Menu closes when the window moves | Closes | Same as the root today: reposition both panels (`td-menu.js:987-992`, `:542-549`). The child closes alone when its parent row is clipped; the whole tree closes when the trigger hides |
| Disabled parent | Greyed, no child | Greyed, no child | Same | `aria-disabled="true"`, greyed chevron, never opens |
| Empty child list | Not shown | Not shown | Not shown | The parent row is omitted (QĐ1) |
| Outside click | Closes all levels | Closes all | Closes all | Closes all levels, the press continues (D5, `td-menu.js:968-986`) |
| Touch | n/a | Tap on the parent opens the flyout | Android has no submenus | Tap opens. Drill-down on a touch-first device or a viewport below 480px (QĐ5) |

## Decisions (QĐ)

**QĐ1. API and validation.**
- A parent is any item with `Array.isArray(it.items)`, except `type: 'custom'`. A custom item with `items` stays a
  custom row; `items` is ignored with a fixed `console.warn`.
- A parent keeps these existing fields: `label` (required, as today `td-menu.js:260-261`), `icon`, `iconNode`, `hint`
  (also the 1-3 character kbd form, `:442-443`), `danger` (colour only), `disabled`, `id`, `when`, `order`.
- A parent ignores, with one fixed `console.warn` per item: `onSelect` / `onClick`, `href` (and `newTab`, `download`),
  `type: 'checkbox' | 'radio'` and `checked`. The parent is always a plain `menuitem`. Reason: an item that both acts
  and opens is ambiguous on touch, and APG has no such item.
- Children are normalised by the same `normalise()` (`td-menu.js:240-296`) with the same `isAllowedUrl`, after the same
  `when(ctx)` filter (`:920`). So `href`, `download`, `danger`, `disabled`, `hint`, `icon`, checkbox and radio work as on
  the root. Radio groups are scoped to the child list.
- Children are resolved once, at root open (the ctx is known then). `items` must be an array; a function is not
  supported (the root builder `(ctx) => items` already covers lazy lists).
- Empty after filtering (`items: []`, all hidden by `when`, all invalid) → the parent row is omitted, like a label-less
  item. Separators around it collapse as today.
- Depth > 1: a child with `items` is kept as a normal item; its `items` are ignored with one fixed `console.warn`
  ("TdMenu: only one submenu level"). No throw: the kit never throws on bad items (`normalise` warns, `:251`, `:284`).
- A child `type: 'custom'` is dropped with a fixed warning. The child panel is always a plain `role="menu"`.
- Registry (`define` / `register`, `:1127-1175`): a registered item may be a parent. `order` and `group` apply to the
  root list only.

**QĐ2. DOM, ids, one session.**
- The child panel is a second `<body>` child, built by the same `build()` (`td-menu.js:311-329`) and `buildItem()`
  (`:386-449`), with an extra class: `div.td-menu.td-menu--sub.td-glass-surface.td-glass-surface--strong`.
- It cannot live inside the root menu. `.td-glass-surface` sets `backdrop-filter` (`src/styles/glass.css:30-31`), which
  makes the root a containing block for `position: fixed` children, and the root clips (`menu.css:51-52`).
- The session holds `s.sub = { parent, entries, menu, items, rows, layer, mode, typeBuffer, typeTimer }`. Only one child
  is open at a time. Opening another parent closes the current child first.
- The child registers its own layer: `registerLayer({ layer: LAYERS.popover, element: sub, keyboard: 'none', anchor:
  s.anchor, onCovered: () => closeSession(s, 'covered') })`. `keyboard: 'none'` keeps the root as the only keyboard
  boundary. The registration is needed so the child is exempt from a lower modal's inert lease
  (`layers.js:211-247`, `inert-lock.js:109-111`), and so `floatingContains` / `coverFloatingIn` of a parent dialog or
  hovercard see it (`layers.js:302-326`). `bridgeTheme()` is applied to it as to the root (`td-menu.js:1001`).
- Ids, only for menus that have a parent (root markup is unchanged otherwise):
  - each parent row: its label span gets `id="{m}-label-{i}"` (already the hint pattern, `:438`);
  - parent: `aria-haspopup="menu"`, `aria-expanded="false|true"`, `aria-controls="{m}-sub"` while open;
  - child: `id="{m}-sub"`, `role="menu"`, `aria-labelledby="{m}-label-{i}"` (the parent's label, so the hint is not in
    the name; accname does not follow a nested `aria-labelledby` through the parent item);
  - child rows use `buildItem(e, j, "{m}-sub")`, so their hint ids are `{m}-sub-label-{j}` / `{m}-sub-hint-{j}`.
- Parent row markup: `<button class="td-menu__item td-menu__item--parent" role="menuitem" …>` + label + optional icon
  + `<span class="td-menu__chevron" data-td-icon="next" aria-hidden="true">` + optional hint. `next` is the registry
  name of `chevron-right` (`src/icons/icons.json:13`, `:76`).
- Everything that today means "inside the menu" must include the child: `hadFocus` in `closeSession`
  (`td-menu.js:478-479`), the outside press test (`:969-970`), the scroll filter (`:988`). `closeSession` closes the
  child first (release its layer, remove it). `releaseSession` clears `sub` (`:531-532`).
- `TdMenu.isOpen()`, `close()`, the handle and `onClose(reason)` are unchanged. Opening or closing a child does not
  call `onClose`.

**QĐ3. Positioning (flyout).**
- `placeFloating` is vertical only (`src/utils/floating.js:183-232`: sides `bottom | top`). Do not stretch it. Add
  `placeBeside(ref, panel, { edge, list, listMax, dir })` in `floating.js`, about 30 lines, reusing `viewportBox()`
  (`:16-24`) and the 8px margin (`:6`):
  - horizontal: `edge` is the root menu rect. Inline-end x = `edge.right` (LTR) / `edge.left - width` (RTL). Fits if
    inside `box ± 8`. Else inline-start. Else the side with more room, clamped into the box.
  - vertical: `top = ref.top - padTop`, where `padTop` = computed `padding-top` of the panel (`--td-glass-pad`,
    6px, `tokens.css:144`). If `top + h > box.bottom - 8` → `top = box.bottom - 8 - h`. Then `top = max(top,
    box.top + 8)`. `list.max-height = listMax` as in `place()` (`td-menu.js:535-540`).
  - returns `{ side: 'end' | 'start', top, left }`; the child gets `data-placement="end|start"`.
  - writes only `top` / `left` / `max-height` through CSSOM, like `placeFloating`.
- `dir` comes from `getComputedStyle(root).direction`. Kept logical, not tested (owner rule).
- Resize, scroll, visual viewport: `reposition(s)` (`td-menu.js:542-549`) also repositions the child. A scroll inside
  the root (ignored today, `:988`) now repositions the child in the same rAF. When the parent row is clipped by the
  root's scroll box (`isReferenceHidden(rect, parentNode)`, `floating.js:66-77`), the child closes alone and focus, if
  it was in the child, moves to the root menu's nearest row. A scroll inside the child is ignored, like the root.
- The mode (flyout or drill) is fixed for the life of one child. A resize repositions; it never switches mode.

**QĐ4. Hover intent and safe triangle (flyout mode only).**
- Gate, the same as `td-hovercard.js:136-139`, `:649`: hover logic runs only when `e.pointerType !== 'touch'` and
  `(hover: hover) and (pointer: fine)` matches. Add `MQ_HOVER_FINE` next to `MQ_COARSE` in
  `src/utils/breakpoints-internal.js:25` and read it with `matches()` (`:58-64`). Hovercard and lightbox keep their
  local copies (not in scope).
- Numbers: `SUB_OPEN_MS = 120`, `SUB_GRACE_MS = 300`, triangle padding 4px.
- Listeners: `pointermove` + `pointerleave` on the root, `pointerenter` on the child. A passive `pointermove` on
  `document` only while a hover-opened child and a grace are active (touch.md rule 15: passive, no preventDefault).
- Algorithm:
  1. Pointer moves onto a root row R (row changed). Clear the intent timer.
  2. R is the open parent → nothing (a pending close is cancelled).
  3. A grace is active and the point is in the triangle → do nothing now. When the grace ends (timer), re-run step 1
     for the row under the pointer.
  4. Else start the intent timer (120ms). When it fires: R is an enabled parent → close the current child, open R's
     child (no focus move). Otherwise → close the current child (focus rule of QĐ7).
  5. The pointer leaves the open parent row while its child is open → start a grace: the triangle is the exit point
     (moved 4px back toward the parent) plus the two corners of the child's near edge (expanded 4px outward). The
     grace ends after 300ms, on a move outside the triangle, or on entering the child.
  6. Pointer leaves the root to empty space → clear the intent timer; the child stays open.
- Pure helper `inTriangle(p, a, b, c)` (sign of cross products) in `floating.js`, node tested.
- Hover never moves keyboard focus, like root items today (CSS hover only, `menu.css:115-119`).

**QĐ5. Drill-down mode.**
- Applies when `matches(MQ_COARSE) || matchesBelow('sm')` at the moment a child opens (`breakpoints-internal.js:25`,
  `:67`; MQ_COARSE = `(hover: none) and (pointer: coarse)`, sm = 480px). A wide touch laptop with a fine pointer
  gets a flyout, and a tap opens it. An iPad with a trackpad matches `hover: hover`, so it gets a flyout.
- Same child panel element as the flyout, different placement (the ONE geometry rule, R2 + R4; no `placeFloating`
  call, no side selection):
  - left and top = the root panel's resolved left and top; width = the root's exact `offsetWidth` (CSSOM); max-height =
    the root's resolved cap; the child scrolls inside it;
  - the root gets `data-sub="drill"` → CSS `visibility: hidden` (out of focus order and the a11y tree, still laid out).
    Focus moves into the child before the root hides. Back restores the root exactly where it was.
- First row: the Back row, then a separator, then the children.
  - `button.td-menu__item.td-menu__back`, `role="menuitem"`, `tabindex="-1"`, `data-td-back`:
    `<span class="td-menu__chevron" data-td-icon="prev">` + label `TdMenu.labels.back` (new key, default `Quay lại`).
  - Activating it (click, Enter, Space) goes back: the child closes, the root shows again, focus goes to the parent.
  - Typeahead skips it (null label, `typeahead.js:15`).
- Opening (tap, click, Enter, Space, ArrowRight) focuses the first enabled child, not the Back row. ArrowUp / Home
  reach the Back row.
- Height: the child's natural height up to the root's cap (above), scrolling inside; it may be shorter than the root.
- Escape and ArrowLeft go back. The second Escape closes everything.
- No hover logic in drill mode.

**QĐ6. Keyboard and focus model (roving real focus, as today `td-menu.js:640-689`).**
- `onMenuKeydown`, `focusRow`, `activate`, `setItemDisabled` take a "level" (`rows`, `items`, type-ahead buffer and
  timer) instead of reading `s.rows` / `s.items` directly. The root level is the current data; root behaviour is
  unchanged.
- Root, focus on an enabled parent: ArrowRight (inline-end), Enter, Space → open + focus the first enabled child
  (all disabled → the first child, like `:1042-1044`). On a disabled parent: nothing.
- Root, other rows: ArrowRight / ArrowLeft do nothing (as today). Custom rows keep their keys (`:658`).
- Child: ArrowDown / ArrowUp wrap, Home / PageUp, End / PageDown, type-ahead (own 500ms buffer, `:85`), Enter / Space
  activate. ArrowLeft (inline-start) → close the child, focus the parent. ArrowRight on a child row: nothing (one level).
- Escape: the root layer's `onEscape` (`td-menu.js:1016`) first closes an open child (focus the parent) and returns
  true; with no child it closes the tree as today. Layers give Escape to one boundary only (`layers.js:63-77`), so
  levels are handled inside this one handler.
- Tab / Shift+Tab from the child: close the whole tree, D4 (`:1019-1023`, `closeSession(s, 'tab')` → `'pass'`). In a
  root panel (custom rows), Tab from the child does the same (no walk into the child stops).
- Whenever the child closes while focus is inside it (hover on a sibling, ArrowLeft, Escape, Back, clipped parent),
  focus moves to the parent row first, so focus never lands on `<body>`.

**QĐ7. Closing semantics.**
- Child pick: `activate` on the child level → `closeSession(s, 'select')` (focus the trigger) → `onSelect(ctx)`, the
  exact order of `td-menu.js:574-575`. Links: the same deferred close as `:833-841`. Checkbox children toggle in place
  and keep the tree open (`:557-563`).
- Click on a parent never calls `closeSession`; it branches before `activate` closes anything.
- Outside press: closes all levels (`'outside'`). A press inside either panel is inside. The lightbox `'swallow'`
  mode (`:973-985`) treats the child as inside too.
- A press on a root sibling while a child is open: the sibling activates as today (closes the tree, or opens its own
  child when it is a parent).
- Trigger re-click: the existing toggle (`:901-904`) closes all levels (`'api'`).
- Trigger hidden or removed, a covering modal: as today (`'hidden'`, `'covered'`), the child goes with the root.
- Async handlers: TdMenu has no busy state. A promise is not awaited, only its rejection is logged (`:461-469`). The
  tree closes before `onSelect` runs. Unchanged for children.

**QĐ8. Events and hooks.** None new. TdMenu fires no DOM events; it calls `onSelect(ctx)` and `onClose(reason)`. A
child pick gets the same ctx shape: `{ ...ctx, item: <child item>, anchor, checked }`. No `parent` field (the caller
knows it from its own closure). `onClose` reasons are unchanged; child open / close is silent. One new label:
`TdMenu.labels.back` (`td-menu.js:883`).

**QĐ9. CSS (`src/styles/components/menu.css`, no new public token).**
- `.td-menu__chevron`: same box as `.td-menu__icon` (`menu.css:157-167`), 16px svg, colour `--td-menu-icon-fg`,
  `margin-inline-start: auto` only when there is no icon. `:dir(rtl)` mirrors the svg (logical, no test).
  Order in a parent row: label, icon, chevron, hint (the hint wraps below, `:198-204`).
- Expanded parent: `.td-menu__item[aria-expanded="true"] { background: var(--td-menu-item-active) }`, outside the
  hover gate (state, touch.md rule 3). `:focus-visible` (`:125-130`) still adds the bar on top.
- Disabled parent: the existing `[aria-disabled="true"]` rule (`:141-144`) greys the chevron with the row.
- Child panel: the same `.td-menu` + `.td-glass-surface--strong` recipe (popup small: 94 % + `blur(12px)` + border +
  `--td-glass-shadow`, liquid-glass.md table row "Popup nhỏ"). Only fade, no scale (rule 4): `.td-menu--sub` sets
  `transform-origin` by `data-placement`. Nothing else new.
- Drill mode: `.td-menu[data-sub="drill"] { visibility: hidden }`.
- Back row: a normal `.td-menu__item` (pressed rule `:377-380` and coarse min-height `:313-316` apply). The chevron
  leads (`.td-menu__back > .td-menu__chevron` first in DOM).
- Touch: no new control class, so `PRESS_TARGETS` (`src/utils/press.js:89-90`) and `check:css` lints stay as they are.
  No new `touch-action`.
- forced-colors: `.td-menu__item[aria-expanded="true"] { outline: 1px solid CanvasText }` in the existing block
  (`menu.css:335-370`).
- CSP matrix (`test/csp/matrix.json:3498` `td-menu`): add `submenu-open` (flyout with the expanded parent, a disabled
  parent, a child with hint and danger) and `submenu-drill` (Back row + children). Existing menu baselines must not
  change. Run `npm run test:csp` locally after the CSS (memory: a new min-*/max-* property can flip old baselines).

**QĐ10. PHP SSR parity.** None. `php/td.php` never renders a menu; it only writes the `data-td-menu` name on
page-actions triggers (`td.php:1522`, `:1710-1715`, `:1842`). The menu DOM is always built by JS on open
(`test/contracts/menu.html:1-4`). Nested items are JS only.

**QĐ11. ADR.** Add ADR 0046 "Menu submenu (one level, same session)". It lifts the v0.53.0 non-goal, records why the
child is a second body child with its own floating layer, the native parity choices and the drill-down rule.

## Not doing

- More than one level (deeper `items` warn and are ignored).
- Hover on touch; hover logic in drill mode.
- Scroll arrows; drag-release picking; macOS "Escape closes all".
- Lazy or async child lists (`items` as a function or a promise).
- Custom rows inside a child; a parent that also acts (`onSelect`, `href`) or is checkable.
- A `parent` field in ctx; new DOM events; a busy state.
- Switching mode on resize while a child is open.
- Changes to `td-page-actions` / action-fold to use submenus (dsuite can drop its workaround itself).
- Migrating hovercard / lightbox to `MQ_HOVER_FINE`.
- PHP support. RTL tests (owner rule).

## Review fixes (Codex plan review; R2 and R4 are folded into QĐ5, which is the single geometry rule)

- **R1. Child event boundary.** The child panel gets its own `click` and `keydown` listeners, attached when the child is
  built and removed when it closes. They use the same handlers as the root, made level-aware: `activate(node)`,
  `onMenuKeydown(e)` and `focusRow()` take the level (`root` or `sub`) and look the record up in that level's row map
  (`s.sub.rows`). Ordinary children and link children (`href`, after `isAllowedUrl`) activate the same way root items
  do. Tests: click and Enter on an ordinary child, click and Enter on a link child, and no listener left after the
  child closes.
- **R2. Drill-down keeps the root's geometry.** In drill-down the child panel does not run side selection again. It
  copies the root panel's resolved placement (side, top/left, the exact width of the root (R4), the same max-height cap) and
  scrolls inside it. Back restores the root panel exactly where it was. Test: a root that fits below the trigger with a
  child taller than the root still opens in place, scrollable, and does not jump above the trigger.
- **R3. Tab routing with custom rows.** Layer Tab handling: when focus is inside `s.sub.menu`, Tab closes the whole
  session and passes Tab through (focus moves on, as for a normal menu). The existing panel Tab traversal for custom
  rows (v0.53) applies only when focus is in the root panel. Test: a root menu with a custom row plus a parent with
  children; Tab from a child closes everything; the existing custom-row Tab tests still pass.
- **R4. Drill-down width.** The drill-down child uses the root panel's exact resolved width (not "at least"); long
  labels wrap or ellipsize as root items do. Left/top are the root's. No separate horizontal clamp is needed because the
  root is already viewport-safe. Test: narrow viewport, root near the right edge, a child with a label wider than the
  root stays inside the viewport with the root's width.
