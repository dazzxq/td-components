## 1. Tóm tắt

dcms2 (màn phân quyền, `require_once php/td.php` qua `app/Support/Kit.php`) cần mỗi ô có **3 trạng thái**: *kế thừa*
(theo mặc định của vai trò), *cấp quyền* (override bật), *từ chối* (override tắt), cộng ô khoá và nút **đặt lại về kế
thừa**. Hiện dcms2 chỉ có cột override boolean `can_*` + ma trận chỉ đọc (`dcms-users-permissions-matrix.js`: default /
override / không có quyền) — tức là "kế thừa" đang được suy ra, không gửi được "từ chối".

Thêm vào `<td-check-matrix>` một chế độ **opt-in** `mode="override"`. Chế độ mặc định (`mode` vắng hoặc `check`) giữ
**nguyên từng byte**: markup JS, markup PHP, FormData (`_v=1`), marker SSR `check-matrix@1`, event `change`
`{added, removed}`. Chế độ mới có model trạng thái riêng, FormData riêng (`_v=2`), contract SSR riêng `check-matrix@2`, và
một ADR mới (số kế tiếp sau 0039, phiên chính gán lúc gộp vì lane media-picker-bulk cũng thêm ADR) bổ sung ADR 0022.

## 5. API dữ liệu (chế độ override)

```js
m.setAttribute('mode', 'override');            // trước dữ liệu (D3)
m.setData({
  columns: [{ key: 'publish', label: 'Xuất bản' }, { key: 'media', label: 'Xem mọi media' }],
  rows: [{ key: 'u12', label: 'Nguyễn A (BTV)' }, { key: 'u31', label: 'Trần B (PV)' }],
  cells: {
    u12: { publish: { inherited: true },                       // kế thừa = đang có quyền (hiển thị)
           media: { inherited: false, locked: true, note: 'PV không được override' } },
  },
  value: {                                       // chỉ ô KHÔNG kế thừa; 'inherit' tường minh được chấp nhận và bị bỏ khi chuẩn hoá
    publish: { u31: 'grant' },
    media: { u12: 'deny' },
  },
});
```

- `value` (override) = `{ [cột]: { [hàng]: 'grant' | 'deny' | 'inherit' } }`. Thiếu cột / thiếu hàng = `inherit`.
  Lỗi cấu trúc (fail closed như ADR 0022 §4, `reason` mới): `value-shape` (không phải object thường, `value[cột]` là mảng
  / không phải object thường), `value-unknown-column`, `value-unknown-row`, `value-state` (chuỗi khác 3 giá trị — so
  **chính xác**, không trim / không đổi hoa thường), `value-na` (ô n/a mang `grant` / `deny`; `inherit` trên n/a được
  chấp nhận vì nghĩa là "không có gì"). Map khoá theo dữ liệu đọc bằng `Object.keys` + `Object.hasOwn`, dựng bằng
  `Object.create(null)` (bài học review r1 #1 v0.47: `constructor`, `__proto__`, `assign` là khoá hợp lệ).
- Ở chế độ override, `value` dạng mảng của chế độ check (`{ owner: ['r1'] }`) → `value-shape` (không đoán).
- `cells[hàng][cột].inherited` (mới, chỉ override): boolean thật hoặc vắng (= không biết). Sai kiểu → `cells-flag`. Ở chế
  độ `check` trường này là "trường lạ trong ô → bỏ qua" như luật hiện tại (không thành lỗi, không đổi hành vi cũ).
- Cột / hàng / nhóm / `locked` / `na` / `note` / trần (500 hàng, 32 cột, 10 000 ô, 64 nhóm, `data` 512 KiB) **giữ
  nguyên**. Trần ô có thể hạ cho override nếu ngân sách hiệu năng (§13.2 ca M0) không đạt — quyết lúc code, ghi vào plan.
- `getValue()` / `value` (override) = `{ [cột]: { [hàng]: 'grant'|'deny' } }` **mọi cột** (cột không override = `{}`),
  dựng bằng `Object.fromEntries` (thuộc tính riêng). Khoá là chuỗi (khoá object JS); khoá số của app vẫn so được bằng
  `String()`. `setValue(v)` / `value =` im lặng, sai → từ chối + cảnh báo (như hiện tại).
- `changedCount` = số ô có trạng thái khác mặc định (mặc định = lần dữ liệu hợp lệ đầu, như hiện tại).
- Attribute `data` (override) = `{"v":2,"columns":…,"rows":…,"cells":…,"value":{cột:{hàng:"grant"}}}`. `v` khác mode →
  fail closed `data-version`.
- Restore state (bfcache / autofill) = `{"v":2,"value":{…}}`; lệch dữ liệu hiện tại → bỏ (như QĐ 14).

## 6. FormData override (hợp đồng công khai mới)

| Mục | Khi nào | Thứ tự |
|---|---|---|
| `name[<cột>]=` (rỗng) | mọi cột, luôn luôn | đầu tiên, thứ tự cột |
| `name[<cột>][<hàng>]=inherit\|grant\|deny` | **mọi ô áp dụng được**, gồm ô khoá (đúng một lần) | theo hàng (thứ tự hiển thị), trong hàng theo cột |
| `name[_v]=2` | luôn luôn | cuối cùng |

PHP đọc: `$_POST['perms'] = ['publish' => ['u12' => 'inherit', 'u31' => 'grant'], 'media' => ['u12' => 'deny', …], '_v' => '2']`;
cột mà mọi ô đều n/a → `''`. Không có key `perms` = không đụng (disabled / fail closed / không name).

- **Vì sao đủ tập kể cả `inherit`** (không chỉ ô override): form không JS dùng `<select>` — select luôn gửi giá trị, nên
  ô kế thừa phải có mục `inherit`; muốn JS **giống từng byte** (ADR 0022 §2) thì JS cũng gửi. Đã loại: (a) chỉ gửi
  override (ít biến hơn nhưng hai cách viết cùng nghĩa → server có hai cách đọc; trái ADR 0022); (b) hai danh sách
  `name[col][grant][]` / `name[col][deny][]` (một hàng có thể nằm ở cả hai → server phải kiểm thêm một loại mâu thuẫn; map
  khoá hàng thì mâu thuẫn không biểu diễn được).
- **Hệ quả `max_input_vars`:** số biến = số ô áp dụng được + số cột + 1 + field khác, **luôn** (không phụ thuộc số ô
  override). Ví dụ trong trần (`MATRIX_LIMITS` 32 cột / 500 hàng): 32 quyền (cột) × 40 user (hàng) = 1 280 ô + 32 marker
  + 1 `_v` = 1 313 > 1 000 mặc định → server bắt buộc tăng `max_input_vars` và **bắt buộc 422 khi `_v` ≠ `'2'`** (sentinel
  cuối mất trước). Docs ghi con số này rõ hơn bản hai trạng thái.
- **Marker rồi khoá con:** `perms[col]=''` rồi `perms[col][row]=x` — PHP thay chuỗi bằng mảng khi gặp chỉ số lồng. ADR
  0022 đã đo cho `[]`; ca **khoá có tên** phải được test PHP chứng minh (bước 2), không suy ra.
- **Khoá hàng thành khoá mảng PHP:** `"12"` → `int 12`; `"012"`, `"1.5"`, `"a.b"` giữ chuỗi. Regex khoá đã cấm `[` `]`
  và `_` đầu (không đụng `_v`). PHP chỉ đổi `.`/dấu cách thành `_` ở **tên gốc** của biến, không trong ngoặc — test chứng
  minh với hàng `cat.view`. Recipe server ép `(string)` khoá.
- Server **bắt buộc** (recipe trong docs): `_v === '2'`, gỡ `_v`, mỗi cột có thật, mỗi giá trị đúng `''` hoặc map khoá
  hàng có thật → một trong 3 chuỗi; **đủ mọi hàng áp dụng được** (thiếu → 422, không coi là inherit — thiếu nghĩa là form
  bị sửa / cắt); khác → 422, không lọc im lặng. Khoá / quyền ghi đè vẫn do server cưỡng chế (ô khoá chỉ là UI).
- `name` lồng (`role[perms]`) chạy như hiện tại; `name` rỗng / kết thúc `[]` → fail closed.

## 7. Model `OverrideState`

- `st: Uint8Array` (0 inherit, 1 grant, 2 deny), `def` (mặc định), `changed`.
- Bộ đếm cho mỗi tập (hàng / cột / nhóm / nhóm×cột / tất cả), O(1) mỗi ô như `MatrixState`: `total` (ô áp dụng được),
  `n[0..2]` (số ô mỗi trạng thái, gồm ô khoá), `free` (không khoá), `freeN[0..2]`.
- `cycle(r, c, dir = +1)` → trạng thái kế theo thứ tự vòng (Q2; mặc định inherit → grant → deny → inherit); khoá / n/a →
  `null`. `setCell(r, c, s)` (phím trực tiếp).
- `bulkState(kind, a, b)` → `{ state: 'inherit'|'grant'|'deny'|'mixed', disabled }`: đồng nhất khi **mọi ô áp dụng được**
  (gồm khoá) cùng trạng thái; `disabled` khi `free === 0`.
- `cycleSet(kind, a, b)` (Q5 mặc định): nếu các ô **không khoá** của tập đồng nhất trạng thái `s` → tất cả sang `next(s)`;
  không đồng nhất → tất cả về `inherit`. Ô khoá / n/a không bao giờ đổi → không bao giờ kẹt.
- `resetSet(kind, a, b)` → mọi ô không khoá về `inherit` (nút đặt lại).
- `entries(name)`, `valueObject()`, `encodeState()` như §5–6.

## 8. Bàn phím, trợ năng

### 8.1 Ngữ nghĩa — vì sao `button` chứ không `aria-checked="mixed"`

| Phương án | Đánh giá |
|---|---|
| `role=checkbox` / checkbox native, `aria-checked` true / false / **mixed** = cấp / từ chối / kế thừa | **Loại.** APG định nghĩa `mixed` = "một phần được chọn" của checkbox cha nhóm; trình đọc đọc "half checked / chọn một phần" — sai nghĩa với "kế thừa". "Bỏ chọn" ≠ "từ chối" (người nghe hiểu là chưa cấp). Checkbox native không cho người dùng tự về `indeterminate` (click xoá cờ). Ma trận này **đã** dùng `mixed` cho ô hàng loạt → cùng chữ hai nghĩa trong một lưới. |
| `aria-pressed` 3 giá trị | **Loại**, cùng lý do (`mixed` của toggle button). |
| Radio group 3 nút mỗi ô (native) | Ngữ nghĩa đúng nhất, chạy không JS, nhưng: 30 000 input ở 10 000 ô; mũi tên đổi giá trị radio đụng mũi tên của lưới (APG grid); 3 nút trong ô 5.5rem không đủ 44px cảm ứng. **Loại** cho JS. |
| `<select>` native mỗi ô (combobox) | Đúng nghĩa, typeahead miễn phí, picker native trên điện thoại; nhưng 10 000 select + 30 000 option nặng (render / bộ nhớ, chưa đo), đổi trạng thái luôn 2 thao tác, ↑↓ trên select đóng đổi giá trị ở Windows → phải chặn. **Dùng cho form không JS** (đúng, đơn giản), **không** cho JS. |
| **`<button type="button">` trong `gridcell`, tên = hàng + cột + trạng thái, bấm = trạng thái kế, phím trực tiếp** | **Chọn.** Một node nhẹ mỗi ô (như checkbox hiện tại); mũi tên vẫn hoàn toàn của lưới; trạng thái đọc bằng chữ thật ("Cấp quyền"), không mượn nghĩa `mixed`; cách dùng nói qua mô tả chung. Nhược: không có vai "3 trạng thái" chuẩn → bù bằng mô tả + live region; kiểm tay VoiceOver / NVDA trước phát hành (rủi ro §16). |

Markup ô dữ liệu (JS, override):

```text
<td class="td-check-matrix__cell" data-c="{j}" data-state="inherit|grant|deny" [data-inherited="on|off"] [data-locked] [data-na] [data-note] [data-changed] tabindex="-1">
  <button type="button" class="td-check-matrix__tri" tabindex="-1"
          aria-labelledby="{h}-r{i} {h}-c{j} {h}-s{idx}" aria-describedby="{h}-keys[ {h}-n{k}]" [disabled]>
    <span class="td-check-matrix__glyph" aria-hidden="true"></span>
    <span class="td-sr-only" id="{h}-s{idx}">Kế thừa (có quyền)</span>
  </button>
</td>
```

- Id luôn từ id host + chỉ số (`{idx}` = chỉ số ô), không từ dữ liệu. `{h}-keys` = **một** `span.td-sr-only` chung ("Space:
  đổi trạng thái. +: cấp, −: từ chối, Delete: về kế thừa") — một node cho cả lưới. `helper-text` vẫn gắn id theo ô active
  như hiện tại (nối thêm vào `aria-describedby`).
- Đổi trạng thái → chữ span đổi tại chỗ + live region `role=status` sẵn có đọc "{trạng thái}" (một ô) hoặc "Đã đổi {n} ô"
  (hàng loạt / đặt lại). Trình đọc không luôn đọc lại tên khi tên của phần tử đang focus đổi — live region là đường chắc.
- Ô khoá: `button disabled` + `pointer-events: none`, focus vào `td` (như ô khoá hiện tại); trình đọc đọc tên + trạng thái
  + "bị làm mờ" + ghi chú.
- Ô hàng loạt override: `button` cùng mẫu, tên "Đổi cả cột {col}" + span trạng thái ("Cấp quyền" / "Lẫn lộn").
  Chế độ `check` vẫn checkbox như cũ.

### 8.2 Phím (override; mọi phím điều hướng giữ nguyên bảng hiện tại)

| Phím | Hành vi |
|---|---|
| Space | Trạng thái kế theo vòng (Q2). Trên ô hàng loạt: `cycleSet`. **Xử lý trong `_onKey`**, không để native (xem dưới). |
| Shift+Space | Trạng thái trước (vòng ngược) — một lần ấn tới "từ chối" từ "kế thừa". Xử lý trong `_onKey`. |

| Delete / Backspace / `0` | Về kế thừa (như trên). |

  hiện tại); Ctrl+chữ không bị nuốt.

  `_onKey` lùi một bậc ở keydown rồi để native, `click` sau đó lại tiến một bậc → không đổi gì + **hai** `change`. Luật:
  keydown Space / Shift+Space trên `.td-check-matrix__tri` (và nút hàng loạt override) → `preventDefault()` + đổi trạng thái
  trong `_onKey` + đặt cờ `_spaceKey` (gắn với nút đó); keyup Space → `preventDefault()` + **không** xoá cờ ngay (click tổng
  hợp, nếu engine vẫn phát, đến **sau** keyup) mà hẹn xoá bằng `setTimeout(0)`; `click` trên đúng nút đó khi cờ còn bật →
  **tiêu thụ** cờ (xoá) + bỏ qua. Không có click nào tới → cờ tự xoá ở tick kế, click chuột / chạm sau đó chạy bình thường.
  Test 3 engine §13.2-1 (đúng một bậc + một `change`) giữ nguyên làm bằng chứng. Hôm nay `_onKey` (`src/form/td-check-matrix.js` L1002-1004) để Space native trên input / button

## 18. Tiêu chí nghiệm thu

1. Không có `mode` (hoặc `mode="check"`): mọi test v0.47 / v0.51.1 / v0.54 cũ pass **không sửa**; fixture SSR cũ không
   đổi byte; FormData `_v=1` y hệt.
2. `mode="override"`: 3 trạng thái đổi được bằng chuột, phím, chạm; ô khoá không bao giờ đổi và luôn gửi; nút đặt lại +
   hàng loạt theo §7 / §9; một `change` mỗi thao tác với `changes` đúng.
3. FormData JS = form không JS PHP, giống từng byte; `_v=2` cuối; PHP đọc ra map đúng (test).
4. Dữ liệu sai → fail closed, không mục FormData; SSR lệch → không lấy giá trị từ markup.
5. Hình đọc được không cần màu (✓ / ✕ / viền), forced-colors phân biệt 3 trạng thái; contrast gate xanh.
6. Mọi gate `npm test` (node + cổng tĩnh trong lane; cổng trình duyệt do phiên chính chạy tuần tự / CI) xanh; docs + ADR
   mới cập nhật. CHANGELOG / roadmap / version: phiên chính.
