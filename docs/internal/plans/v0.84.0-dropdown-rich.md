## Target

In `td-dropdown`, an option may carry:
- `icon`, drawn in a toned tile;
- `iconTone`;
- `description` (a second line);
- `status` (`{ tone, text }`: a dot plus short text);
- `meta` (muted text aligned right);
- `keywords` (used for search only);
- `group`.

These fields have fixed names and do not follow `value-key` / `label-key`. Groups have ordered headers, given by a `groups` property or by `<optgroup>`. Search matches label, description and keywords, and `search-fields` can restrict it. Screen readers hear a result count while filtering. The option's accessible name is its label; description, status and meta are its accessible description.

**Hard compatibility rule:** an option that uses none of the new fields renders exactly the 0.83.0 row string, behaves identically and places identically. `test/contracts/dropdown.html` stays unchanged and green.

## Decisions (made, with reasons)

1. **Rich row**
   - A row is rich when at least one of these fields is valid after gating:
     - `icon`: a string where `hasIcon(name)` is true;
     - `description`: a non-empty string or number after trim;
     - `status`: an object with a non-empty `text`;
     - `meta`: a non-empty string or number.
   - A plain row keeps the exact 0.83.0 string.
   - Rich row DOM (`r` = `{host}-opt-{i}`):
     ```html
     <div class="td-dropdown__option td-dropdown__option--rich" role="option" id="r" aria-selected [aria-disabled="true"]
          [aria-labelledby="r-label" aria-describedby="r-desc r-meta"] data-value data-index data-nav>
       [SWATCH_SVG]
       [<span class="td-dropdown__icon" data-tone="{tone}" data-td-icon="{icon}" aria-hidden="true"></span>]
       <span class="td-dropdown__text">
         <span class="td-dropdown__option-label" id="r-label">{label}</span>
         [<span class="td-dropdown__desc" id="r-desc">[<span class="td-dropdown__desc-text">{description}</span>][<span class="td-dropdown__status" data-tone="{tone}"><span class="td-dropdown__status-dot" aria-hidden="true"></span>{status.text}</span>]</span>]
       </span>
       [<span class="td-dropdown__meta" id="r-meta">{meta}</span>]
       [<span class="td-dropdown__check" data-td-icon="check" aria-hidden="true"></span>]
     </div>
     ```
   - `aria-labelledby` and `aria-describedby` are printed only when the row has a desc or meta part. `aria-describedby` lists only the ids that exist.
   - Name = label, because `aria-labelledby` points at the label span; the description is never folded into the name. An icon-only rich row needs neither attribute, since its tile is `aria-hidden`, so the name from content is the label alone.
   - Tone is set by a `data-tone` attribute, as in `.td-tabs__count`.
2. **Gates**
   - Every text is escaped through `escapeHtml`, as today.
   - `iconTone` and `status.tone` must be one of neutral / accent / success / warning / danger / info; anything else becomes neutral.
   - Icon names: an unknown name means no tile, plus `console.warn('td-dropdown: unknown icon "<name>"')` exactly once per name per page (a module-level `Set`). The slot is never printed for an unknown name, so `fillIconSlots` never warns about it. `hasIcon` is imported from `src/icons/td-icon.js:125`. Icons are never SVG or HTML from the option.
   - `keywords` is a string or an array of strings or numbers, flattened with `' '`; nothing else is accepted.
   - No `style` attribute anywhere.
3. **Trigger**
   - With a selected item that has a valid icon, the value span prints `<span class="td-dropdown__value-icon" data-td-icon="{icon}" aria-hidden="true"></span>` before the text, after any swatch. It is filled by `fillIconSlots` in both `render()` (through `afterRender`) and `_updateValueText()`.
   - The icon is plain `currentColor`, with no tile and no description.
   - It carries the same `margin-inline-start: 1px` as `.td-dropdown__value > .td-dropdown__swatch` (the v0.83.0 clip lesson), since the span clips.
   - Opt-out: attribute `trigger-icon="none"` (also `off` / `false`) means text only.
   - In select mode, any other `trigger-icon` value is ignored and reserved: v0.85.0 action mode will use it as a fixed icon name (default `plus`). It is documented as such now, so one attribute serves both releases.
   - The trigger's accessible name and `title` stay the label text only. The icon is `aria-hidden`, and `displayedValueText` must ignore it; verify this with `value-title.js`.
4. **Groups**
   - Property `groups: Array<{ key, label }>`, which can be set before upgrade (add it to `UPGRADE_PROPS`). There is no attribute, because JSON in attributes is avoided.
   - Grouping is active only when `groups` is a non-empty array. Otherwise any option `group` is ignored, which keeps 0.83.0 behaviour.
   - Display order:
     - each declared group in `groups` order, with options keeping their array order inside it;
     - then options whose `group` is missing or unknown, as a trailing section with no header and no wrapper.
   - `_filteredData` stays a flat list in display order, so `data-index`, `_applySwatchFills` and the row id keep working. `_options` stays the raw site array; selection uses it.
   - DOM inside the scroller, after the clear row, which stays first and outside any group:
     ```html
     <div class="td-dropdown__group" role="group" aria-labelledby="{host}-grp-{n}">
       <div class="td-dropdown__group-label" role="presentation" id="{host}-grp-{n}">{label}</div>
       rows…
     </div>
     ```
     This copies `td-chip-input.js:1502-1519`. `n` = index in `groups`.
   - A group with no rows (for example after filtering) is not printed at all. A declared group with an empty label prints its rows unwrapped, like the trailing section.
   - Headers have no `data-nav` and are not `.td-dropdown__option`. Navigation, type-ahead, click and hover therefore skip them by construction.
   - Scroll: after `scrollIntoView({block:'nearest'})` of the active row, if the row is the first row of a group, the group header is also scrolled into view (`header.scrollIntoView({block:'nearest'})`). Moving up into a group then shows its title.
   - `groups` re-assigned → `_handleSearch(current query)`, in place (as `options`).
5. **`<select>` upgrade**
   - When any `<optgroup>` child exists:
     - `groups = [{ key: 'g{n}', label: optgroup.label.trim() }]`;
     - options inside `optgroup n` get `group: 'g{n}'`;
     - direct options get none, so they form the trailing section, keeping native order of the rest.
   - Native interleaving (option, optgroup, option) changes order: the trailing options move to the end. This is documented.
   - New `data-*` read from `<option>`:
     - `data-icon` → `icon`;
     - `data-icon-tone` → `iconTone`;
     - `data-description` → `description` (same name as chip-input);
     - `data-status` + `data-status-tone` → `status`;
     - `data-meta` → `meta`;
     - `data-keywords` → `keywords`.
   - Absent attributes add no keys, so the items of a plain select are unchanged.
   - Update the flatten doc comment at `td-dropdown.js:76` and `docs/components/dropdown.md:216`.
6. **Search**
   - Default fields are label, description and keywords, folded with `fold` (`src/utils/typeahead.js:9`), substring match. `status.text`, `meta` and the group label are not searched.
   - New attribute `search-fields`: a space- or comma-separated subset of `label description keywords`. Unknown tokens are ignored; empty or none-valid means the default.
   - Changing `search-fields` re-filters in place (`_handleSearch` with the current search value) with no re-render. Add it to `observedAttributes` with its own `case`, before the `default:` that re-renders.
   - This is a behaviour change only for sites whose options already carry a `description` or `keywords` field. It is noted in the CHANGELOG, with `search-fields="label"` as the opt-out.
7. **Result count**
   - New label `labels.resultCount = '{count} kết quả'`, built with plain `split('{count}').join(n)`.
   - It is written into the existing `.td-dropdown__empty` `role=status` region only when a query is typed (trimmed, non-empty) and results > 0. That count is `_filteredData.length`; the clear and create rows are not counted.
   - It is visually hidden: the region gets `data-count`, and CSS applies the `.td-sr-only` geometry to `.td-dropdown__empty[data-count]`. The owner was told; dsuite asked only for the announcement.
   - With 0 results the visible "Không tìm thấy kết quả" stays, as today.
   - With an empty query the region is empty, so opening announces nothing.
   - `labels.resultCount = ''` turns the count off.
   - No debounce: a polite live region coalesces.
8. **Height**
   - When the rendered list contains at least one rich row or a group header (the "measured layout"), `_placeMenu` computes `listMax` from the DOM instead of `max-height × OPTION_PX`:
     1. Clear the scroller's max-height.
     2. Take the N-th `.td-dropdown__option` inside the scroller (the clear row counts, as it does today in the count model), where N = `_getMaxHeight()`.
     3. `listMax = row.getBoundingClientRect().bottom - scroller.getBoundingClientRect().top` (scroller content starts at its top; it has no padding today, so verify).
     4. Fewer than N + 1 rows means `listMax = 0` (natural height; `placeFloating` still clamps to the viewport).
   - The previous `scrollTop` is restored after measuring.
   - Group headers add their height but do not count as rows. With `max-height="5"`, exactly 5 option rows show from the top, of either kind.
   - In the measured layout, every `_renderMenuOptions` while open also calls `_updatePosition()`; this covers search, `options` and `groups` changes.
   - Plain lists keep `N × OPTION_PX`. The coarse-pointer 44px versus 40px mismatch is a pre-existing bug, unchanged here and noted in the roadmap as a follow-up.
9. **PageUp / PageDown**
   - Unchanged: they move by N `_nav` entries. Because the measured `max-height` now shows exactly N rows, a page equals N rows in both layouts. The test asserts that PageDown from the first row lands on row N + 1 in a mixed list.
10. **Tokens and CSS** (`src/styles/components/dropdown.css`)
    - One new public token, `--td-dropdown-icon-size` (tile, `1.75rem`); the glyph is 60% of it via a private calc. Add light and dark entries to `test/tokens/golden.json` "added" (the `--print-missing` workflow; never `--capture`).
    - Tile colours use private `--_td-dd-tone-bg/-fg/-edge`, read from `--td-badge-{tone}-bg/-fg/-border` (the `tabs.css:176-217` pattern, plus `accent`).
    - `.td-dropdown__desc` is a single-line flex row (`display: flex; gap: var(--td-space-xs); min-width: 0; align-items: center`, muted, `--td-text-xs`). `.td-dropdown__desc-text` is `flex: 0 1 auto; min-width: 0` with ellipsis (as `chip-input.css:441-448`). `.td-dropdown__status` is `flex: none`, nowrap, so a long description is cut with … and never hides the status (Codex plan r1 #2).
    - The status dot uses the tone fg colour and the status text is muted; meta is muted `xs`, `flex: none`.
    - `.td-dropdown__text { flex: 1; min-width: 0; display: flex; flex-direction: column; }`.
    - Rich rows keep `min-height: var(--td-dropdown-option-h)` (and the coarse `--td-touch-min`), with padding 6px block.
    - Group header copies `chip-input.css:336-352`.
    - Forced colours:
      - the tile gets a `1px solid CanvasText` border;
      - the dot gets `forced-color-adjust: none; background: CanvasText`;
      - the disabled meta and description use `GrayText`.
    - Hover, pressed and reduced-motion rules apply unchanged, since the row class is the same.
    - Every colour pair used is either an existing badge pair (already contrast-gated) or muted text on the menu surface (already gated). No new pair: verify by grepping the contrast harness, and add a case only if one is missing.
11. **PHP `td_dropdown`** (`php/td.php:1624`)
    - Accept a group entry `['label' => …, 'disabled' => bool, 'options' => [leaf…]]`, which prints `<optgroup label [disabled]>`. This copies `td_multiselect`'s shape and leaf printer; nesting is one level only.
    - Leaf keys:
      - `icon` (printed only if it matches the icon name regex used for registry names in `td.php`; find it, else `/^[a-z0-9][a-z0-9-]*$/`), as `data-icon`;
      - `icon_tone` / `iconTone` (allowlist), as `data-icon-tone`;
      - `description`, as `data-description`;
      - `status` (array `text` and `tone`), as `data-status` and `data-status-tone`;
      - `meta`, as `data-meta`;
      - `keywords` (string or list joined with ' '), as `data-keywords`.
    - Everything goes through `Td::e`, and an attribute is printed only when non-empty. Existing cases stay byte-identical: `test/ssr/dropdown.native.json` and `test/ssr/fixtures/dropdown.html` are unchanged unless new fixture cases are added. New cases go into a new PHP test, not the old JSON.
    - The SSR marker version is unchanged (`dropdown@1`): the shell box is the same and only the options' attributes are added.
12. **Labels doc:** `TdDropdown.labels` gains `resultCount`. Update the jsdoc text list (`td-dropdown.js:113`) and the labels table in `docs/components/dropdown.md`.
