# v0.26.0 — SSR hydrate tại chỗ: `<td-input-field>`, `<td-toggle>`, `<td-checkbox>` (form-associated)

Bước 2 của [ADR 0012](../decisions/0012-ssr-hydration.md) (đề xuất 135: ô nhập trang đăng nhập flash lúc tải). Dựa trên
nền v0.25.0 (base `canHydrate()` / `hydrateExisting()` / `canRebind()`, `static hydratable`, dấu `data-td-ssr`, allowlist
thuộc tính, fixture dùng chung, nhóm test SSR 3 engine, element mode opt-in). Owner: "cứ làm hết cùng codex". Không
dependency mới; mặc định native giữ nguyên.

## F1 — PHP element mode cho `td_field`, `td_toggle`, `td_checkbox`

- Cùng cơ chế opt-in v0.25: `['element' => true|false]` từng lần gọi ghi đè `Td::configure(…, ['ssr_elements' => true])`;
  từ v0.26 cờ toàn cục áp cho cả 3 helper này (đã có contract).
- In host + **đúng cấu trúc / BEM của `render()` JS** cho cùng attribute, với dấu `data-td-ssr`:
  `input-field@1`, `toggle@1`, `checkbox@1`. Control native **giữ `name`, `value` / `checked`, `required`, ràng buộc
  (`min` `max` `step` `pattern` `minlength` `maxlength`), `autocomplete`, `inputmode`, `id`** để form chạy khi chưa có JS
  (submit, validation native, password manager / autofill). Host mang thuộc tính component (`type`, `label`, `name`,
  `value` / `checked`, `required`, `size`, `helper-text`, `error-text`, …) như JS cần.
- Bảng chiếu host ↔ control đầy đủ cho mọi option hiện có của 3 helper (như v0.25), dữ liệu `attrs` lên control (allowlist),
  key trùng option → option thắng, tên component sở hữu được giữ chỗ không phân biệt hoa thường, `data-td-*` bị chặn.
- **ID:** `id` người gọi đưa = id của **control** native (để `<label for>` ngoài trỏ đúng khi chưa JS — contract trợ năng,
  ADR mục 9). Host luôn có **id riêng không trùng**: `{id}-host` khi người gọi có `id`, ngược lại id PHP sinh
  `td-{name đã làm sạch}-{bộ đếm}` (bộ đếm tăng trong request). Biểu diễn id control trên host: input-field dùng
  thuộc tính **`field-id`** đã có (`_controlId()` = `field-id` || `{host-id}-control`, td-input-field.js ~:214) — PHP in
  `field-id="{id}"`; không có `id` → control nhận `{host-id}-control` đúng như render. toggle / checkbox (render không đặt id
  control): `id` control là **thuộc tính state được giữ** — allowlist chấp nhận `id` trên input, hydrate giữ nguyên; khi phải
  render lại (lệch markup) thì id đã chụp được gán lại cho input mới. Fixture phủ: có `id` / không `id` × 3 helper; label
  ngoài `for` trỏ đúng trước + sau hydrate; không trùng id trong trang có nhiều field.

## F0 — Bổ sung base (cần cho F2)

> **Sửa sau review v0.26 vòng 3 (2026-10-03):** bỏ cơ chế hoãn tới blur (`'defer'` / `deferHydration` / mirror) — mọi
> lệch markup với control có state → render an toàn ngay + khôi phục value / selection / checked / focus. Xem ADR 0012
> mục 5. Các đoạn nói về `'defer'` bên dưới là thiết kế cũ, không còn áp dụng.

- **Nguồn gốc replay property sớm:** `_setupProperties()` (td-base-element.js ~:189) hiện replay `early` thành attribute
  rồi quên. Ghi lại tập tên đã replay vào `this._earlyProps` (Set, chỉ đọc sau khởi tạo). Hydrate dùng tín hiệu này: tên
  có trong `_earlyProps` → **giá trị host thắng** state native; ngược lại state native sống thắng attribute host. Giá trị
  reset luôn lấy từ `defaultValue` / `defaultChecked` native (không từ property sớm).
- **Hoãn khi lệch mà đang focus:** `canHydrate()` được trả thêm giá trị `'defer'` (ngoài `true` / `false`). Base:
  `'defer'` → **không** `_doRender()` và **không** `_bindStep()`; gọi hook `deferHydration(resume)` của component. Component
  chụp state, gắn **một** listener `blur` (capture, trên control) → khi blur: gỡ listener, `resume()` = **một** lần
  `_doRender()` (đã gồm `afterRender()` = bind, như mọi render) rồi khôi phục state đã chụp vào control mới **không** phát
  sự kiện — không gọi `_bindStep()` thêm. Test: sau resume, một thao tác native (gõ / tích) phát **đúng một** `input` /
  `change` của component. Ngắt kết nối trước blur → gỡ listener, xoá trạng thái hoãn; gắn lại → đánh giá
  lại từ đầu. Test: markup bị từ chối không bao giờ bị bind (không listener nào của component trên control cũ), blur →
  render + state đúng, ngắt trước blur → không rò listener.

## F2 — Hydrate form-associated (base `TdFormElement`)

Thứ tự trong `hydrateExisting()` (ADR mục 3–4):
1. **Chụp state sống** của control native: input-field → `value`, `defaultValue`, `selectionStart/End/Direction` nếu
   đang focus; toggle / checkbox → `checked`, `defaultChecked`, `indeterminate` (checkbox) **và** `value` /
   `defaultValue` (giá trị gửi đi). Ưu tiên theo F0: property sớm (`_earlyProps`) > state sống native > attribute host;
   reset = mặc định native. Test xung đột: (a) PHP `value="a"`, người dùng gõ `b` trước define → `b`; (b) như (a) nhưng
   `el.value = 'c'` gán sớm → `c`; (c) checkbox PHP checked, người dùng bỏ tích trước define → bỏ tích; (d) `el.checked =
   true` sớm thắng; (e) `.value` của checkbox đổi trước define → `FormData` gửi đúng giá trị đó; reset về mặc định native.
2. Khởi tạo `ElementInternals` (`setFormValue` = giá trị chụp, `setValidity` theo ràng buộc hiện có) **trước**.
3. Rồi mới **gỡ `name`** (và các ràng buộc gây chặn submit trùng: `required` / `pattern` / `min` … trên control nếu
   component đã tự quản validity) khỏi control → `FormData` đúng **một** mục; giữ `autocomplete`, `id`, nhãn.
4. **Chỉ label ngoài**: chụp các `<label>` **nằm ngoài host** có `htmlFor === id control` (không dùng cả
   `control.labels`, vốn gồm label bọc / label nội bộ) → chuyển `for` sang host (như dropdown v0.17). Label nội bộ / label
   bọc giữ nguyên. Test: label nội bộ vẫn nằm trong `control.labels` và vẫn đặt tên truy cập cho control sau hydrate; label
   ngoài click vẫn focus / bật đúng.
5. Không phát `input` / `change`. Giữ **đúng node đang focus**; chỉ ghi lại value khi chuẩn hoá bắt buộc, khi đó khôi
   phục selection.
6. `formResetCallback` → về **mặc định đã chụp** (`defaultValue` / `defaultChecked`), không về state lúc nâng cấp.
   `formStateRestoreCallback` giữ hành vi hiện có.

**Chính sách `type` trước hydrate (input-field):** component hiện render `email` / `url` / `number` thành `type="text"` +
`inputmode` (`_neutralizeTypes`, td-input-field.js ~:117) để tự quản validation. PHP element mode in **type native**
(`email` / `url` / `number`, date / time giữ native như render) để chưa JS vẫn có bàn phím + validation native. Hydrate
**chấp nhận** cặp (type SSR native ↔ type render) theo bảng: `email→text+inputmode=email`, `url→text+inputmode=url`,
`number→text+inputmode=decimal`, các type khác phải trùng. Thứ tự: chụp state → đổi `type` **trên cùng node** sang type
render (khôi phục value + selection nếu trình duyệt xoá) → đặt `inputmode`. **Ràng buộc native sau hydrate = đúng tập
mà component bình thường đã bind có** (gồm cả thứ `afterRender()` thêm, không chỉ chuỗi `render()`). Mã hoá tường minh theo
quy tắc hiện có của component (đọc từ td-input-field.js khi implement, ghi vào bảng trong code + docs):
`date` → giữ `min` / `max`; `month` / `datetime-local` / `time` → giữ `min` / `max` / `step`; counter → giữ `maxlength`
khi component in; email / url / number (render thành text) → bỏ `min` / `max` / `step` / `pattern` native (component tự
kiểm); `required` / `pattern` / `minlength` theo đúng việc component bình thường có đặt lên control hay không. Gỡ khỏi control
**chỉ** ràng buộc ngoài tập đó. Test: với mỗi type × ràng buộc, thuộc tính control sau hydrate **bằng** thuộc tính control
của một component **tạo bằng JS và gắn bình thường** với cùng host attribute. Không đổi hành vi của component bình thường; `afterRender()` / `_syncState` giữ nguyên logic hiện có
(tập sau hydrate đã trùng tập render nên không có gì để "thêm lại"). Test sau hydrate: `form.checkValidity()` + `validity`
của host cho email sai, url sai, number ngoài range / sai bước, date / time, `pattern`, `required` rỗng — khớp hành vi
component hiện tại; chưa JS: validation native chặn submit.

**Cấu trúc phải khớp** (lệch → không nhận): tag / `type` của control (theo bảng trên), class BEM, các phần tử phụ (label, helper, error
note, counter, nút hiện mật khẩu nếu có trong render) theo đúng option; allowlist thuộc tính theo từng phần (như v0.25:
`on*`, `style`, `form*`, `formaction`, `data-td-*` trên control… → không nhận). **Lệch / thiếu markup** (ADR mục 5):
component có state → chụp state trước, control **đang focus** → `'defer'` (F0) tới `blur` rồi render + khôi phục state; không focus
→ render ngay + khôi phục. Gắn lại (di chuyển) → `canRebind()` kiểm lại, lệch → render + khôi phục state.

## F3 — Từng component

- `td-input-field`: các `type` hiện có (text, password, email, number, url, search, tel, date, month, datetime-local, time,
  textarea, contenteditable — **contenteditable và textarea**: textarea có contract riêng `input-field@1` biến thể textarea;
  contenteditable **không** có element mode (không có fallback native) — helper không hỗ trợ → in như hiện nay). Giữ
  counter, helper / error note, toggle hiện mật khẩu nếu `render()` có.
- `td-toggle`: `label.td-switch > input[type=checkbox][role=switch].td-switch__input` + phần trang trí; size.
- `td-checkbox`: `label.td-checkbox > input.td-checkbox__input` + phần trang trí; size; `indeterminate`.

## Test

- Fixture dùng chung `test/ssr/form.fixtures.json` (mọi option của 3 helper × element on/off × cờ toàn cục), PHP sinh
  `test/ssr/fixtures/form.html` (kiểm stale như v0.25).
- Nhóm SSR 3 engine (`*.ssr.browser-test.js`): DOM sau hydrate = `render()` JS; bounding box 0 lệch (Chromium: không
  `layout-shift`); **node control giữ identity**; gõ / tích **trước define** → giá trị giữ sau define, không `input` /
  `change`; focus + selection giữ; `FormData` trước = sau và đúng **một** mục mỗi `name` (cả tên PHP `[]`), unchecked không
  gửi, disabled không gửi; `form.reset()` về mặc định đã chụp; `<label for>` ngoài bấm vẫn đúng sau hydrate; không-JS:
  submit, validation native (`required`, `pattern`), password manager attribute (`autocomplete`) có mặt; markup lệch /
  thiếu / bị chèn thuộc tính lạ → render an toàn + giữ state; control đang focus khi lệch → hoãn tới blur; gắn lại;
  property gán sớm thắng.
- PHP: bảng chiếu, giữ chỗ tên (hoa thường), `data-td-*`, escape, cờ toàn cục × từng lần gọi.
- CSP: state `td-input-field.ssr`, `td-toggle.ssr`, `td-checkbox.ssr` + baseline. `npm test` đầy đủ.
