## Mục tiêu

1. Một component **hiển thị** (không form, không event bắt buộc) so sánh trước / sau **theo trường**, đủ cho màn chi
   tiết audit của dsuite với cả ba policy có giá trị: `fields`, `keys`, `snapshot` (+ `hash_version` là chuỗi do server
   định dạng).
2. Đọc được trên điện thoại (xs → inline), trên trang tối và trên palette sinh bởi `td-theme`.
3. Nội dung là **dữ liệu không tin cậy** (giá trị do người dùng khác nhập, tên khoá JSON tuỳ ý): text-only, có trần, không
   treo trình duyệt với payload lớn / sâu / vòng lặp.
4. Có trang server-rendered (PHP) không flash, không cần JS.

## Non-goals (v0.46.0)

- **Diff mức dòng / mức từ cho chuỗi dài** — không làm (QĐ 6). Không thuật toán LCS / Myers trong kit ở bản này.
- So khớp phần tử mảng object theo id (move detection) — mảng object so theo **chỉ số** (QĐ 4); server muốn diff ổn định
  thì gửi object theo khoá (`{ "line:123": {…} }`).
- Tự che dữ liệu (redaction) phía trình duyệt — **server che trước khi gửi**; `masked` của kit chỉ là chỉ thị hiển thị
  (QĐ 9).
- Nút "Hiện" giá trị bị che bên trong diff (site đặt `<td-masked-value>` ở chỗ khác của trang nếu cần — có audit riêng).
- Link hoá URL / email trong giá trị, render HTML / markdown của giá trị, highlight cú pháp JSON.
- Copy JSON, tải JSON, tìm trong diff, lọc theo loại thay đổi, sort cột.
- Danh sách / timeline sự kiện audit (là `td-table` / `td-timeline` của app; `td-diff` đặt trong drawer / trang chi tiết).

## Quyết định (owner uỷ quyền — mặc định đề xuất; câu hỏi thật ở cuối)

### Dữ liệu

1. **Hai cách đưa dữ liệu, một model.**
   - **`items`** (đã phẳng — hợp policy `fields` / `keys`): `Array<DiffItem>`.
   - **`before` + `after`** (object — hợp policy `snapshot`) + tuỳ chọn **`fields`**: `Array<FieldDef>` cấu hình nhãn /
     kiểu / che / thứ tự theo đường dẫn. Kit tự phẳng + so sánh (QĐ 3–5).
   - Gán `items` ⇒ bỏ qua `before` / `after` (cảnh báo một lần nếu có cả hai). Mọi property gán **im lặng**, render lại
     một lần trong microtask (gán liền `before` rồi `after` không render hai lần).

   ```ts
   DiffItem = {
     key: string,                    // đường dẫn ổn định (id hàng, khoá JSON); text, ≤ 200 code point
     label?: string,                 // nhãn hiển thị; thiếu → nhãn suy từ key (QĐ 3)
     before?: unknown, after?: unknown,   // thiếu thuộc tính ≠ null (QĐ 2)
     kind?: 'added'|'removed'|'changed'|'unchanged',  // thiếu → kit tính (QĐ 2); có → kit tin (policy `keys`)
     masked?: boolean,               // true → hai bên "[ĐÃ ẨN]", kit KHÔNG đọc before/after (QĐ 9)
     type?: 'text'|'number'|'money'|'boolean'|'date'|'enum'|'list'|'json',   // gợi ý định dạng (QĐ 7)
     options?: Record<string,string>,     // cho type 'enum': mã → nhãn ("pending" → "Chờ xử lý")
     decimals?: number, unit?: string,    // cho number / money (unit mặc định '₫' với money)
   }
   FieldDef = { path: PathSeg[] | string, label?, type?, options?, decimals?, unit?, masked? }
   PathSeg  = string | number      // string = khoá object (nguyên văn, KHÔNG tách theo '.'), number = chỉ số mảng (nguyên ≥ 0)
   // ['lines', 1, 'qty'] = lines[1].qty · ['a.b'] = khoá có dấu chấm ở gốc · ['a', 'b'] = a lồng b · 'status' ≡ ['status']
   ```
   `DiffItem.key` là **một chuỗi nguyên văn** (định danh hàng ở chế độ `items`, không có ngữ nghĩa đường dẫn).

2. **Loại thay đổi (`kind`) do kit tính** khi không truyền: giá trị **rỗng** = thiếu thuộc tính, `undefined`, `null`, `''`
   (sau trim), `[]`, `{}`. Trước rỗng + sau không rỗng → `added` ("Thêm"); trước không rỗng + sau rỗng → `removed`
   ("Xoá"); cả hai không rỗng và khác → `changed` ("Đổi"); bằng → `unchanged`. **Bằng** = bằng nhau của dạng chuẩn (JSON
   chuẩn hoá, khoá object theo thứ tự gốc **không** quan trọng khi so: so theo tập khoá; `1` khác `"1"` — đổi kiểu là thay
   đổi thật). Rỗng hiển thị `—` + chữ ẩn cho trình đọc màn hình "trống". `kind` truyền vào sai giá trị → kit tự tính +
   cảnh báo một lần (chỉ mã, không giá trị).
   *Lý do coi `null → x` là "Thêm":* đúng ngôn ngữ audit (trường "có giá trị lần đầu"); phân biệt "thiếu" vs `null` không
   có ích cho người đọc và dsuite không đảm bảo giữ được khác biệt đó qua JSON.

3. **Phẳng hoá object (chế độ `before` / `after`):**
   - Chỉ duyệt **plain object** (prototype `Object.prototype` hoặc `null`) và **Array**; chỉ **own enumerable string key**
     (`Object.keys` trong `try`). `Date` → ISO; `bigint` → chuỗi số; mọi thứ khác (Map, Set, class instance, function,
     symbol) → lá chữ cố định `[không hỗ trợ]` — **không** gọi `String()` / `toString()` của object lạ.
   - **Đường dẫn = mảng đoạn có kiểu** (Codex r1-1: chuỗi nối `.` mơ hồ khi khoá chứa `.`). Không có cú pháp chuỗi, không
     escape: `FieldDef.path` là mảng `PathSeg`; dạng chuỗi chỉ là viết tắt của **một** đoạn khoá gốc (`'a.b'` ≡ `['a.b']`,
     không bao giờ thành `['a', 'b']`). Đoạn `string` chỉ khớp khoá **object** (kể cả khoá dạng số `"12"` của object),
     đoạn `number` chỉ khớp chỉ số **mảng** — `['lines', '0']` (object có khoá "0") ≠ `['lines', 0]` (phần tử đầu của
     mảng). `path` sai hình (rỗng, đoạn không phải string / số nguyên ≥ 0, > 7 đoạn, đoạn > 200 code point) → bỏ
     `FieldDef` đó + một cảnh báo (chỉ chỉ số của nó, không nội dung).
   - **Khớp theo đoạn:** *chính xác* = cùng độ dài + từng đoạn bằng nhau (cùng kiểu, `===`); *tiền tố* = mọi đoạn của
     `FieldDef` bằng các đoạn đầu của hàng (dùng cho nhãn tiền tố và che nhánh, QĐ 9). Không glob / wildcard.
   - **Định danh hàng** (`id` trong model, khoá parity) = `JSON.stringify(segments)` (vd `["a.b"]` vs `["a","b"]`, `["l",0]`
     vs `["l","0"]`) — duy nhất, không va chạm. DOM không mang id này (không cần).
   - **Nhãn** = nhãn của `FieldDef` khớp chính xác; không thì ghép từng đoạn: nhãn của `FieldDef` khớp tiền tố dài nhất
     (vd `['lines']` → "Dòng hàng") hoặc khoá gốc nguyên văn, chỉ số mảng thành `#n` (1-based), nối bằng ` › ` →
     "Dòng hàng › #2 › SL". Khoá có dấu chấm hiện nguyên (`a.b`), nên hai hàng `["a.b"]` và `["a","b"]` có nhãn khác nhau
     (`a.b` vs `a › b`).
   - **Thứ tự hàng:** theo thứ tự `fields` trước, rồi khoá còn lại theo thứ tự xuất hiện trong `after` rồi `before`
     (không sort chữ cái — giữ thứ tự ngữ nghĩa server gửi).
   - **3a. Thứ tự khoá chuẩn = thứ tự own-property của JS** (Codex r2-4), dùng cho thứ tự hàng, nhãn tiền tố, JSON view,
     cả JS lẫn PHP: (1) khoá **dạng chỉ số mảng** trước, tăng dần theo giá trị số; (2) mọi khoá khác theo thứ tự chèn.
     "Dạng chỉ số mảng" định nghĩa **đúng như JS**: chuỗi `k` mà `String(ToUint32(k)) === k` và giá trị
     `≠ 2^32 − 1` — tức chuỗi thập phân chuẩn của số nguyên `0 ≤ n ≤ 4294967294`: không dấu `+` / `-`, không số 0 đứng
     đầu (trừ chính `"0"`), không khoảng trắng, không phần thập phân / mũ (`"01"`, `"-0"`, `"1.0"`, `"1e3"`, `" 1"`,
     `"4294967295"` là khoá **thường**). JS có sẵn thứ tự này (`Object.keys` sau `JSON.parse`); model JS vẫn đi qua cùng
     hàm `orderKeys()` cho chắc (object do app dựng tay cũng theo luật engine, nên kết quả không đổi). PHP: hàm
     `Td::diffOrderKeys()` tự tách hai nhóm (regex `^(0|[1-9][0-9]{0,9})$` + so `<= 4294967294`, không dùng `is_numeric`
     / `ctype_digit` một mình), sort nhóm số bằng so sánh số (chuỗi 10 chữ số vượt `PHP_INT_MAX` 32-bit không xảy ra vì
     PHP 64-bit là yêu cầu của `td.php`; vẫn so bằng độ dài rồi `strcmp` để không phụ thuộc kiểu int), giữ nguyên thứ
     tự chèn nhóm còn lại. Khoá trùng trong JSON (`{"a":1,"a":2}`): giá trị cuối thắng, **vị trí của lần xuất hiện đầu**
     (cả `JSON.parse` lẫn `json_decode` vào `stdClass` đều vậy) — có fixture.

4. **Mảng:**
   - Mảng **toàn scalar** (role, tag, quyền) = **một lá** `type: 'list'`: hiển thị từng phần tử; khi `changed`, so **tập**
     theo dạng chuẩn ⇒ phần tử mới đánh dấu "+" (chữ ẩn "thêm"), phần tử bị bỏ "−" (chữ ẩn "bỏ") — đây là diff có giá trị
     nhất cho bộ lọc "Đổi quyền" của dsuite và rẻ (O(n) bằng Set, trần 200 phần tử / bên).
   - Mảng có object → phẳng theo **chỉ số** (non-goal: không khớp theo id). Ghi rõ trong docs.
   - Mảng / object vượt trần (QĐ 10) → một lá `json` tóm tắt "Mảng 120 phần tử" / "Object 80 khoá" + nội dung trong JSON
     view.

5. **Độ sâu:** phẳng tối đa **6 cấp**; nhánh sâu hơn thành một lá `json` (chuỗi JSON gọn, cắt theo QĐ 10). Vòng lặp
   (`WeakSet`) → lá `[vòng lặp]`.

6. **Không có diff mức từ / mức dòng ở v0.46** (quyết định, có lý do):
   - Dữ liệu thật của dsuite **không** chứa văn bản dài trong diff: HTML / nội dung dài theo policy `hash_version` (version
     + hash), PII theo `keys` / hậu tố, tiền / số lượng / trạng thái là giá trị ngắn. Chuỗi dài nhất có thật là tiêu đề /
     mô tả SEO (~160 ký tự) — đọc hai cột cạnh nhau vẫn được.
   - Chi phí không nhỏ cho một kit solo: thuật toán + trần O(n·m), token màu inline thứ ba (nền `ins` / `del` trong ô đã
     có nền tint → thêm cặp tương phản cho generator), a11y của `<ins>` / `<del>` (đa số trình đọc màn hình không đọc) phải
     bù bằng chữ ẩn ở từng đoạn → ồn.
   - **Đường mở rộng không phá vỡ:** sau này thêm `granularity="word"` (additive) cho `type: 'text'` khi có consumer lưu
     văn bản đầy đủ (vd so sánh revision nội dung). Câu hỏi owner Q3.

7. **Định dạng theo `type`** (cùng luật JS = PHP, bảng parity):
   | `type` | Hiển thị |
   |---|---|
   | `text` (mặc định cho chuỗi) | nguyên văn, giữ xuống dòng (`white-space: pre-wrap`) |
   | `number` (mặc định cho số hữu hạn) | `12.990.000` / `1.234,5` (vi-VN, qua `number-format.js` `fromNumberString` + `format`; `decimals` kẹp 0–6) |
   | `money` | như `number` + ` ₫` (hoặc `unit`) |
   | `boolean` (mặc định cho boolean) | "Có" / "Không" (`TdDiff.labels`) |
   | `date` | chỉ chuỗi `YYYY-MM-DD` hợp lệ → `DD/MM/YYYY`; khác → nguyên văn. **Không** đổi múi giờ: ngày giờ có múi giờ do server định dạng sẵn thành `text` (dsuite biết múi giờ site; JS và PHP không bao giờ lệch nhau) |
   | `enum` | `options[value]` (own key, chuỗi) → nhãn; không có → mã gốc |
   | `list` | QĐ 4 |
   | `json` | JSON gọn một dòng, cắt (QĐ 10); đầy đủ trong JSON view |
   Không có hook `format` tuỳ ý ở v0.46 (giữ parity JS = PHP và text-only); app cần gì khác thì định dạng sẵn thành chuỗi
   `text` trong `items`. Câu hỏi owner Q4.

7a. **Một luật số JSON chung JS = PHP** (Codex r3-5; chốt trước M4). Mục tiêu: model chuẩn hoá **giống hệt** ở hai runtime
    cho cùng chuỗi JSON, không bao giờ hiện một giá trị **sai**.
    - **Phân loại** (chạy trên giá trị đã parse — JS `number`, PHP `int` / `float`), **theo đúng thứ tự bảng — kiểm không
      hữu hạn TRƯỚC** mọi xử lý nguyên / thập phân (r4-6):
      | Giá trị | Model |
      |---|---|
      | **Không hữu hạn** — JS `!Number.isFinite(x)` (`Infinity`, `-Infinity`, `NaN`), PHP `is_float($x) && !is_finite($x)` (`INF`, `-INF`, `NAN`). Đến được từ **JSON hợp lệ**: mũ tràn `1e309`, `-1e309`, `1e99999` parse thành `±Infinity` / `±INF` ở cả hai runtime (không phải lỗi parse); `NaN` chỉ từ JS object dựng tay (`jsOnly`) | **số không biểu diễn được**: hiện `TdDiff.labels.unsupported` **`[không hỗ trợ]`** (chữ muted), JSON view là chuỗi `"[không hỗ trợ]"` (không bao giờ `Infinity` / `INF` / `null` — `JSON.stringify` / `json_encode` không dùng ở đây, QĐ 10), cùng ghi chú một lần như số không an toàn; dấu `-` **không** giữ (một sentinel duy nhất, model giống hệt) |
      | Nguyên (PHP `int`, hoặc `float` / `number` có phần lẻ = 0) và `\|x\| ≤ 2^53 − 1` | **số nguyên an toàn**: chuỗi chuẩn = thập phân nguyên, không dấu `+`, `-0` → `0`; PHP `1.0` ≡ JS `1` |
      | Nguyên và `\|x\| > 2^53 − 1` (gồm `2^53`, `2^53 + 1`, `−2^53`, `9223372036854775807` (PHP `int`), `9223372036854775808` (PHP `float`), `1e21`) | **số không an toàn**: hiện `TdDiff.labels.unsafeNumber` **`[số quá lớn]`** (chữ muted), trong JSON view là chuỗi `"[số quá lớn]"`, ghi chú một lần "Có số vượt độ chính xác — server nên gửi dạng chuỗi" |
      | Có phần lẻ | **số thực**: chuỗi chuẩn = đúng **`Number.prototype.toString`** của ECMAScript (chữ số ngắn nhất round-trip; dạng thường khi `1e-6 ≤ \|x\| < 1e21`, ngược lại dạng mũ `1e-7`, `1.5e-10` — chữ `e` thường, mũ dương không có ở số thực vì ≥ 1e21 luôn nguyên) |
    - **Vì sao "không an toàn" dừng ở giới hạn chứ không dùng chữ nguồn:** sau `JSON.parse`, JS không còn thấy chữ số
      gốc (`9007199254740993` thành `…992`); "JSON.parse source text access" (`context.source` của reviver) chưa có ở mọi
      engine trong sàn hỗ trợ ⇒ không dùng. PHP thì thấy được, nhưng dùng nó sẽ làm model lệch. Nên **cả hai** đều không
      hiện giá trị ⇒ không bao giờ hiện số sai, model giống hệt.
    - **So sánh (QĐ 2):** số so bằng chuỗi chuẩn (`1` = `1.0`, `-0` = `0`). Ô có số **không an toàn hoặc không hữu hạn** ở **bất kỳ** bên
      nào ⇒ `kind = 'changed'` (trừ khi bên kia rỗng ⇒ `added` / `removed` như thường) + cờ `uncertain` (nhãn phụ chữ
      "không so sánh được", không chỉ bằng màu). Lý do: JS thấy `2^53` = `2^53 + 1` còn PHP thấy khác — chỉ có "đổi?"
      là kết quả giống nhau ở hai runtime, và **không bao giờ giấu** một thay đổi thật (có thể báo dư — chấp nhận, đúng
      chiều an toàn cho audit). Trong `list` (QĐ 4): phần tử không an toàn / không hữu hạn là token `[số quá lớn]` / `[không hỗ trợ]`, set-diff coi mỗi token
      là khác nhau (luôn hiện ở cả "bỏ" và "thêm" nếu ở hai bên) — cùng lý do.
    - **Cài đặt PHP số thực:** lấy chữ số ngắn nhất bằng `json_encode($f)` với `serialize_precision = -1` (đặt tạm bằng
      `ini_set`, khôi phục trong `finally`; PHP 8 mặc định đã là `-1`), tách phần định trị / mũ, rồi **dựng lại theo thuật
      toán Number::toString** (`k`, `n` của spec) — không dùng `(string)$f` / `var_export` / `sprintf('%.17g')` (phụ thuộc
      `precision`). JS: `String(x)` (đã đúng spec). Hàm `canonicalNumber()` JS và `Td::diffNumber()` PHP có bảng parity.
    - **Hiển thị theo `type`** (QĐ 7) chạy **trên chuỗi chuẩn**, bằng chuỗi, không qua float lần hai: `number` / `money`
      chỉ thêm phân cách nghìn + dấu phẩy thập phân cho dạng thường (dạng mũ hiện nguyên chữ); `decimals` = làm tròn
      half-up **trên chuỗi thập phân** (không `toFixed` / `round()` — tránh `1.005`). JSON view in chuỗi chuẩn (số an toàn /
      số thực) hoặc `"[số quá lớn]"`.
    - **Chuỗi JSON chứa chữ số** (`"12345678901234567890"`) luôn là **text**, hiện đúng từng chữ ở cả hai runtime ⇒ docs
      (trang component + security / mục dsuite): *ID, mã, số tiền có thể vượt 2^53 − 1 phải gửi dạng chuỗi*. JS `bigint`
      (object dựng tay, `jsOnly`) → chuỗi thập phân chính xác của nó, kiểu `text`.

8. **Chuỗi:** bỏ ký tự điều khiển C0 (trừ `\t`, `\n`) và C1; ký tự **định hướng / vô hình** (U+200B–200F, U+202A–202E,
   U+2066–2069, U+FEFF) **không bị xoá mà hiện ra** dạng chữ `⟨U+202E⟩` (lớp `td-diff__ctl`, màu muted) — trang audit
   phải cho thấy *đúng* cái đã được lưu, kể cả nỗ lực đánh lừa thị giác (Trojan Source). Mỗi giá trị nằm trong phần tử
   `unicode-bidi: isolate` + `dir="auto"`.

9. **Che (`masked`)** — hợp đồng giống tinh thần `td-masked-value`:
   - `item.masked === true` hoặc `FieldDef.masked` khớp **tiền tố theo đoạn** (QĐ 3: che cả nhánh; `['a','b']` che `a.b`
     lồng nhưng **không** che khoá gốc `"a.b"`, và ngược lại) ⇒ hai ô hiện
     `TdDiff.labels.masked` = **`[ĐÃ ẨN]`**, `kind` = `kind` truyền vào hoặc `'changed'` ("Đổi" — policy `keys`).
   - Kit **không truy cập** `before` / `after` của item bị che, và **không đi xuống** nhánh bị che trong object (không gọi
     getter, không đưa vào JSON view — JSON view in `"[ĐÃ ẨN]"` ở đúng chỗ, không lộ cả kiểu / độ dài).
   - **Đây là trình bày, không phải bảo mật:** dữ liệu đã ở trình duyệt khi app gán vào. Docs + security-model ghi đậm:
     **server phải che trước khi gửi** (dsuite: redactor theo `diffPolicy`); `masked` chỉ dùng khi server gửi kèm tên
     trường bị che **không có giá trị** (`{ key, masked: true }`).
   - Giá trị đã che một phần do server gửi (`"***123"`) là **giá trị thường** (`type: 'text'`), không phải `masked`.

10. **Trần (DoS, cùng số JS = PHP):**
    | Trần | Giá trị | Vượt thì |
    |---|---|---|
    | Nút duyệt (object + mảng + lá) mỗi bên | 10 000 | dừng duyệt; phần còn lại không thành hàng; ghi chú "Dữ liệu quá lớn, chỉ hiện một phần" |
    | Khoá mỗi object / phần tử mỗi mảng được duyệt | 1 000 | như trên (đếm vào ghi chú) |
    | Hàng hiển thị | 500 | "Còn {n} trường không hiện" (n đếm được trong ngân sách) |
    | Độ sâu phẳng | 6 | lá `json` (QĐ 5) |
    | Khoá / nhãn | 200 code point | cắt `…` |
    | Giá trị: xem trước | 300 code point | phần còn lại trong `<details>` "Xem đầy đủ ({n} ký tự)" |
    | Giá trị: đầy đủ | 10 000 code point | cắt + "… đã cắt" |
    | Tổng chữ giá trị đầy đủ trong một diff | 300 000 code point | các giá trị sau chỉ còn bản xem trước + ghi chú |
    | JSON view mỗi bên | 100 000 code unit | cắt ở ranh giới dòng + "… đã cắt" |
    | `list` mỗi bên | 200 phần tử | phần còn lại "+{n} phần tử" |
    Chuỗi thô cắt ở **4 × trần** trước mọi regex / tách code point (tiền lệ filter-chips SEC-1). Mảng thưa dài: duyệt theo
    chỉ số tới `min(length, trần)`, không `for…of`. JSON view **không** dùng `JSON.stringify` trên input (ném với vòng lặp
    / bigint, không dừng sớm): serializer riêng có ngân sách, cùng thứ tự khoá gốc, thụt 2 dấu cách.

### Giao diện

11. **Một DOM, hai bố cục bằng CSS** (tiền lệ card của `td-table`): đổi bố cục không render lại.
    - `view="auto"` (mặc định, cả giá trị lạ): **bảng** khi bề rộng host ≥ 480, **inline** khi < 480
      (`container: td-diff / inline-size`, `@container td-diff (width < 480px)`; fallback `@supports not` do build sinh —
      ADR 0014). `view="table"` luôn bảng (cuộn ngang **trong** `.td-diff__scroll`, không bao giờ cuộn trang);
      `view="inline"` luôn inline.
    - **Bảng:** cột "Trường" (rowheader, gồm nhãn + nhãn loại) · "Trước" · "Sau". Bề rộng cột trường `--td-diff-label-w`
      (30 %), `table-layout: fixed`, chữ dài `overflow-wrap: anywhere`.
    - **Inline:** mỗi hàng là một khối: dòng 1 = nhãn + nhãn loại; dòng 2 = trước → sau (trước gạch ngang khi `changed` /
      `removed`, mũi tên `aria-hidden`), nhãn nhỏ "Trước" / "Sau" hiện thật (`aria-hidden`, nghĩa đã có từ role — QĐ 14).
      `added` chỉ hiện "Sau", `removed` chỉ hiện "Trước" (ô kia rỗng bị ẩn ở inline, vẫn có trong DOM).
12. **Trường không đổi:** thuộc tính `unchanged="collapse|show|hide"` (mặc định `collapse`): hàng `unchanged` gom vào một
    `<details class="td-diff__unchanged">` "{n} trường không đổi" đặt **sau** bảng chính (bảng thứ hai cùng cấu trúc bên
    trong). Native, không JS. Policy `fields` thường không có hàng không đổi ⇒ khối không xuất hiện.
13. **JSON view:** thuộc tính boolean `json` (opt-in). `<details class="td-diff__json">` + `<summary>` "Xem JSON"; bên trong
    hai khối `<figure>` "Trước" / "Sau", mỗi khối `<pre class="td-diff__pre" tabindex="0">` (cuộn được bằng bàn phím,
    `max-block-size: --td-diff-json-max-h`), đóng mặc định, chữ qua `textContent` / escape. Nội dung = dữ liệu **đã chuẩn
    hoá**: chế độ object → `before` / `after` theo cấu trúc gốc với nhánh che = `"[ĐÃ ẨN]"`; chế độ `items` → object
    `{ key: value }` dựng từ items (che như trên). Không highlight cú pháp. Thu gọn bằng `<details>` native ⇒ chạy cả khi
    không JS / SSR, không cần listener; trình duyệt cũ không có `<details>` không còn trong sàn hỗ trợ.
14. **A11y:**
    - `<table role="table">` + `role="rowgroup|row|columnheader|rowheader|cell"` **tường minh** (bố cục inline dùng
      `display: block/grid` làm rơi ngữ nghĩa bảng ở WebKit — tiền lệ `td-table`). Tên bảng: thuộc tính `label` →
      `aria-label`; mặc định `TdDiff.labels.table` "So sánh thay đổi". Caption hiển thị: không (app đặt heading ngoài).

    - Ô rỗng: `—` `aria-hidden` + `<span class="td-sr-only">trống</span>`. `[ĐÃ ẨN]` là chữ thật (đọc được).

### PHP + SSR

19. **`td_diff(array $items, array $o = [])` và `td_diff_snapshots(string|stdClass|array|null $before,
    string|stdClass|array|null $after, array $o = [])`** (`php/td.php`, `Td::SSR_DIFF = 'diff@1'`).
    **Hợp đồng snapshot PHP có kiểu** (Codex r1-2: mảng PHP không phân biệt object và list):
    | Đầu vào | Hiểu là |
    |---|---|
    | `string` (**khuyên dùng** — dsuite có sẵn cột `changes JSON`) | `json_decode($s, false, 64, JSON_THROW_ON_ERROR)` — **không** `JSON_BIGINT_AS_STRING` (r3-5: chuỗi nó sinh ra không phân biệt được với chuỗi JSON thật ⇒ model lệch JS; số lớn đi theo QĐ 7a): object JSON → `stdClass` (giữ **object**, kể cả khoá số `{"0":…}` và `{}`), mảng JSON → `array` list. Chuỗi > 2 MB → không decode, ghi chú "Dữ liệu quá lớn"; JSON sai / sâu > 64 → ghi chú "JSON không hợp lệ", không hàng (không in chuỗi gốc, không ném) |
    | `stdClass` (đệ quy) | object; duyệt **trực tiếp** `foreach ($obj as $k => $v)` (không `get_object_vars` / ép `(array)` — chúng biến khoá số thành khoá int), mọi khoá ép `(string)` ⇒ `"12"` luôn là đoạn **string**; thứ tự khoá theo **thứ tự own-property của JS** (QĐ 3a) |
    | `array` (quy tắc **hẹp**, có tài liệu) | `array_is_list()` ⇒ **list**; ngược lại ⇒ **object** (khoá int được chuyển thành đoạn string, vì PHP đã ép `"12"` → `12`; thứ tự khoá cũng theo QĐ 3a). Hệ quả đã biết: mảng kết hợp có khoá đúng `0..n-1` bị hiểu là list, và `[]` không phân biệt `{}` (cả hai là *rỗng* — QĐ 2, vô hại). Cần chính xác ⇒ truyền chuỗi JSON / `stdClass` |
    | `null` | rỗng (sự kiện tạo / xoá: một bên rỗng) |
    | object khác (`JsonSerializable`, model, `DateTime`) | **không nhận** (`TypeError` qua kiểu tham số cho scalar lạ; object lạ ở mức lồng → lá `[không hỗ trợ]` như JS) — app tự `json_encode` (không gọi code của app trong helper) |
    Cùng luật áp cho `before` / `after` của **từng item** trong `td_diff()` (giá trị lồng: `stdClass` = object, `array` theo
    `array_is_list`). JS không có vấn đề này (`JSON.parse` giữ object / array), nên parity so trên **cùng chuỗi JSON**: ca
    fixture lưu JSON; JS `JSON.parse`, PHP truyền **chuỗi**; ca riêng `phpArray` kiểm quy tắc hẹp cho mảng PHP literal.
    Snapshot dsuite (`snapshot` policy: object ngữ nghĩa, khoá chuỗi, list scalar / list object) nằm trọn trong đường chuỗi
    JSON — không mất thông tin. Options: `fields`, `view`, `unchanged`, `json`, `label`, `class`, `id`,
    `attrs` (allowlist như các helper khác; `on*`, `style`, `data-td-*` bị chặn). In **markup cuối cùng** (giống hệt
    `render()` của JS cho cùng dữ liệu) — trang audit server-rendered hiện đầy đủ không cần JS (JSON / không đổi / xem đầy
    đủ là `<details>` native).
    *Lý do có PHP:* dsuite có thể mở chi tiết audit bằng URL riêng (link từ request ID / cảnh báo) render bằng Blade; 135 /
    dwp có thể dùng cho lịch sử cài đặt. Chi phí thấp vì không cần hydrate (QĐ 20).
20. **Hydrate = nhận markup, không đọc dữ liệu** — theo đúng vòng đời ADR 0012 (Codex r1-3):
    - `canHydrate()` trả `true` **chỉ khi** dấu đúng **chính xác** `diff@1` (`_ssrMatches('diff', 1)`) **và** không có
      `items` / `before` / `after` gán sớm (`_earlyProps`) **và** host có đúng một con phần tử đầu tiên là
      `.td-diff__scroll` hoặc `.td-diff__empty` (kiểm hình tối thiểu để không nhận nhầm nội dung lạ). Khi đó
      `hydrateExisting()` giữ nguyên markup — **không bao giờ đọc dữ liệu ngược từ DOM** (không cần cổng cấu trúc kiểu
      filter-chips vì không có gì được trích ra thành state / event; markup là HTML của chính site).
    - **Mọi trường hợp khác → render bình thường** (`_doRender()`, thay con của host bằng `render()` từ property; không có
      dữ liệu ⇒ trạng thái rỗng "Không có thay đổi."):
      - không có dấu → render, không cảnh báo (host viết tay / tạo bằng JS);
      - dấu có nhưng sai (`diff@2`, `diff`, `diff@01`, `filter-chips@1`, chuỗi rỗng) → **một** cảnh báo (chỉ tên dấu đã
        chuẩn hoá, không nội dung) + render;
      - dấu đúng nhưng có property gán sớm → render từ property (property thắng — ADR 0012 QĐ 3), không cảnh báo.
    - Dấu luôn bị gỡ sau lần kết nối đầu (nhận hay không). Gắn lại (di chuyển node) → không render lại nếu đã hydrate và
      không có property mới (`canRebind()` kiểm cùng điều kiện hình tối thiểu).
    - Property gán **sau** khi đã nhận markup → render từ property (thay markup).
21. **Parity JS = PHP** bằng bảng ca dùng chung `test/ssr/diff.fixtures.json`: mỗi ca → (a) **model** (hàng chuẩn hoá
    `{ id, path: PathSeg[] (giữ kiểu string / number), label, kind, uncertain, before, after, masked, type }` + `counts`) từ JS `diff-model.js` và PHP `Td::diffModel()` phải
    bằng nhau từng byte (JSON); (b) **markup** PHP → fixture HTML → browser test so DOM với `render()` của JS. Ca bắt buộc:
    rỗng / null / thiếu, đổi kiểu `1` vs `"1"`, số / tiền / boolean / date / enum, list set-diff, mảng object theo chỉ số,
    độ sâu 7, mọi trần (biên ± 1), masked item + masked nhánh, khoá `__proto__` / `constructor`, emoji /
    tổ hợp (cắt theo code point), ký tự bidi / zero-width, C0 / C1, XSS `<img src=x onerror=…>` ở khoá / nhãn / giá trị /
    option enum.
    **Ca đường dẫn (r1-1):** `{"a.b":1,"a":{"b":2}}` → hai hàng riêng (`["a.b"]`, `["a","b"]`), nhãn `a.b` vs `a › b`;
    `FieldDef` `['a','b']` masked che **chỉ** hàng lồng, `'a.b'` (≡ `['a.b']`) che **chỉ** khoá gốc; JSON view in
    `"[ĐÃ ẨN]"` đúng chỗ trong từng trường hợp; `['lines', 0]` vs `['lines', '0']` trên list và trên object khoá số; `path`
    sai hình bị bỏ + cảnh báo.
    **Ca object / list (r1-2):** object khoá số `{"0":"a","1":"b"}` (object, đoạn string, không phải list) vs list
    `["a","b"]` (lá `list`); `{}` vs `[]` (cả hai rỗng); lồng: `{"lines":{"12":{"qty":1}}}` (object theo khoá) vs
    `{"lines":[{"qty":1}]}` (theo chỉ số); object khoá số trong list trong object; ca `phpArray` (mảng PHP literal: list,
    kết hợp, khoá int không liên tục `[3 => 'x']` → object `{"3":"x"}`, kết hợp `0..n-1` → list — hành vi hẹp được ghi);
    JSON sai / quá sâu / > 2 MB → ghi chú, không ném.
    **Ca số (r3-5)** — mỗi giá trị đặt làm chữ số JSON (không ngoặc kép) ở before / after, trong `list`, lồng trong object, và
    một bản dạng **chuỗi** để đối chứng; so model (chuỗi chuẩn / `[số quá lớn]`, `kind`, `uncertain`) + JSON view + markup
    từng byte: `9007199254740991` (an toàn, hiện đủ), `9007199254740992`, `9007199254740993`, `-9007199254740992`,
    `9223372036854775807` (PHP `int`), `9223372036854775808` (PHP `float`), `1e21` (đều `[số quá lớn]`), `0.30000000000000004`
    (chữ nguồn của `0.1 + 0.2`, hiện `0,30000000000000004` với `type: number`), `1.0` (→ `1`), `-0` và `-0.0` (→ `0`),
    `1e-7` (→ `1e-7`), `0.000001` (→ `0.000001`), `1.5e300`, `123.456` + `decimals: 2` (→ `123,46`), `1.005` + `decimals: 2`
    (→ `1,01`, làm tròn trên chuỗi); `kind`: `1` vs `1.0` = `unchanged`, `2^53` vs `2^53 + 1` = `changed` + `uncertain` ở
    **cả hai** runtime, `null` → `2^53` = `added`; chạy dưới PHP với `serialize_precision` khác `-1` (vd `17`) và
    `precision = 14` ⇒ kết quả không đổi.
    **Ca không hữu hạn (r4-6)** — `1e309`, `-1e309`, `1e99999` dạng chữ số JSON trần (before / after), trong `list`, lồng
    hai cấp trong object: model **giống hệt** ở JS (`JSON.parse`) và PHP (`json_decode` chuỗi) = `[không hỗ trợ]`, JSON
    view `"[không hỗ trợ]"`, `1e309` vs `-1e309` = `changed` + `uncertain`, `1e309` vs `1e309` = `changed` + `uncertain`
    (không bao giờ `unchanged`), `null` → `1e309` = `added`, list `[1e309, 1]` → `[1]` hiện `[không hỗ trợ]` ở "bỏ"; không
    ngoại lệ, không cảnh báo PHP (`json_encode(INF)` không bao giờ được gọi — test kiểm `error_get_last()` rỗng).
    **Ca thứ tự + kiểu khoá (r2-4)** — so `path` (kiểu từng đoạn) **và thứ tự hàng** + thứ tự khoá trong JSON view, từng
    byte: `{"b":1,"10":2,"2":3,"a":4,"1":5}` → `1, 2, 10, b, a`; khoá số trước khoá chuỗi khi JSON viết ngược; biên
    `"4294967294"` (chỉ số, xếp trước) vs `"4294967295"` (khoá thường, theo thứ tự chèn); `"01"`, `"-1"`, `"1.5"`,
    `"1e3"`, `" 1"` là khoá thường; số 10 chữ số vs 2 chữ số (so số, không so chuỗi); lồng ba cấp với khoá số ở mọi cấp
    (`{"x":{"20":{"3":1,"k":2,"1":3},"5":{}}}`); object khoá số trong list trong object; khoá trùng; cùng các ca đó qua
    đường `phpArray` (mảng PHP literal `['b'=>1, 10=>2, 2=>3]` → cùng thứ tự `2, 10, b`). Mọi đoạn khoá object trong output
    PHP là **chuỗi JSON** (`"12"`, không `12`) — test kiểm `gettype` trước khi `json_encode`.
    Khác biệt đã biết phải ghi rõ: PHP không phân biệt "thiếu" và `null` sau `json_decode` (cùng là rỗng — QĐ 2 làm cho
    khác biệt này vô hại); PHP không có `undefined` / `Date` / `bigint` (ca chỉ-JS đánh dấu `jsOnly`).
