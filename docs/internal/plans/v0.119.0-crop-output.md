# v0.119.0: crop round-trip, optional focal point, presets per call, crop output 'new-asset'

Requested by dcms2 (owner-approved), spec: dcms2 `.planning/2026-11-21-crop-modes-decision.md` "Kit request" items 1-6.
dcms2 accepted the adjusted API on 21/11 (names below are final). Additive; defaults behave exactly as v0.118.1.

## Goals

dcms2 retires cropperjs. td-cropper stays geometry-only (no canvas, no blob). A hard crop is cut server-side by the
site through an adapter method. The kit must let the site reopen a stored crop, keep the focal point optional, set
presets per call, and, if asked, swap the selection for a server-made derivative asset.

## Decisions (QĐ)

### QĐ1 Round-trip `crop.initial`
- `TdMediaPicker.open({ crop: { initial } })` and `configureDefaults` accept `initial`: a CropValue (`{normalized}`), a
  plain `{x, y, width, height}` (normalized 0..1, the shape `openCropDialog({crop})` already accepts), or null/absent.
  Invalid → treated as absent, plus one warning.
- `resolveOptions` (src/utils/media-picker-core.js, around :862) keeps it on `cropResolved.initial`.
  `_openCrop` (src/feedback/td-media-picker.js:3853) passes `crop: cropResolved.initial` instead of `null`.
- The stored focal keeps the existing key `crop.focalPoint`. It now also seeds box mode (`allowFocalPoint`), not only
  focal mode.
- td-media-field picker path (src/form/td-media-field.js:1006-1015) forwards its `crop` / `focal-point` attributes as
  `crop.initial` / `crop.focalPoint` (same parsing as its standalone "Cắt ảnh" path :1236-1239).
- When the same asset is reopened and nothing has changed, the field still emits no event (`changed` is compared against
  the initial value).
- Asset identity guard: `crop.initial`, and the new box-mode seeding from `crop.focalPoint`, apply only while the crop
  target is the asset the values belong to:
  - for the picker, the single preselected asset of that open (the existing preselection option);
  - for the field, its current value.
  If the user picks a different asset, the crop opens with no rect and no focal (box mode). The focal-mode seed keeps
  today's behaviour unchanged. Acceptance case: field with stored crop → open the picker → choose another asset → the
  crop starts at the defaults.

### QĐ2 `focalPointOptional`
- New option `crop.focalPointOptional` (bool, default false), dialog option `focalPointOptional`, field attribute
  `focal-optional`, cropper attribute `focal-optional`.
- Applies to box mode with `allowFocalPoint`. In focal mode (`crop-mode="focal"`), and without `allowFocalPoint`, the flag is ignored.
- With the flag on:
  - A null focal renders a centre marker (class `--focal-unset`, dimmer) while `_focal` stays null. `getResult().focalPoint`
    stays null until the user places it by pointer or keyboard.
  - Keyboard from unset: today the focal key handler returns early when `_focal` is null. With the flag on, the first
    focal key press (the same keys and focus target as the existing focal keys) first sets the point to the displayed
    centre (0.5, 0.5) and then applies the normal step. It fires one `focal-change {source:'keyboard'}` per press.
    Without the flag, the early return stays.
  - The existing on/off focal toggle (src/form/td-cropper.js:1143) is not rendered. A "Dùng giữa ảnh" button
    (labels.focalClear) takes its place. It is a normal toolbar button, reachable by Tab, shown only while a point is set.
    Activating it sets the point to null, fires `focal-change {focalPoint:null, source:'clear'}`, and moves focus to the
    next toolbar control (or back to the cropper box) so focus is never lost.
  - "Đặt lại" (`_reset`, :1182) restores the initial focal, so a null initial value goes back to null.
- Without the flag, behaviour is unchanged, byte for byte (existing tests are untouched).

### QĐ3 `presets` + `ratioLabel` per call
- `crop.presets: [{label, ratio|null}]` and `crop.ratioLabel: string`, plus dialog options `presets` and `ratioLabel`.
  The dialog sets `cropper.presets` (the existing property, :419-422) and its title suffix uses `ratioLabel` when given
  (crop-dialog.js:86/:199), else today's text.
- Field attributes: `crop-presets` (JSON array; invalid JSON → ignored + one warning) and `crop-ratio-label`.
- Locked extreme ratios 14:1, 28:2 (becomes 14/1), 64:9 and 9:16 must open, keep the ratio on resize and keyboard nudge,
  and round-trip. The 16 px minimum short side stays (dcms2 accepted). Touch hit areas stay as they are (dcms2: desktop-first).
- Presets are validated like the global TdCropper.presets: drop invalid entries, keep order, empty → global default.

### QĐ4 `crop.output: 'metadata' | 'new-asset'`
- Default 'metadata' = today. Field attribute `crop-output`.
- 'new-asset' needs an adapter method `createCropDerivative({ sourceAssetId, crop, focalPoint, signal }) => Promise<MediaAsset>`.
  - `crop` is always `{ normalized: { x, y, width, height } }` (0..1). A dialog result of `crop: null` (a whole-image
    box) becomes `{ normalized: { x:0, y:0, width:1, height:1 } }`.
  - `focalPoint` is `{ x, y }` (normalized) or null.
  - 'new-asset' applies to box and pan modes. In focal mode there is no rect to cut: `warnOnce`, then 'metadata'.
  - If the method is missing: `warnOnce`, then 'metadata'.
- Flow inside the existing apply gate (crop-dialog.js `onApply` :313-334; the picker wires `onApply` whenever
  output is 'new-asset' OR `beforeApply` is set):
  1. busy state (button busy, cropper disabled, aria-busy), as today;
  2. `await createCropDerivative(...)` with the gate's single `AbortController` signal;
  3. if `beforeApply` is set, it runs on the final selection (the derived asset), sharing the same signal;
  4. on success, `finish` once.
  Esc / × aborts the signal. A late result after abort is ignored, and there is no second finish (existing guard :325).
- A rejection or throw (including a non-object result or one without `id`) keeps the dialog open with the rect and the
  focal. The footer message is `err.userMessage` when it is a string (the kit rule: raw `err.message` is never shown; changed at implementation), else the label `cropDerivativeError`
  ("Không tạo được ảnh đã cắt. Thử lại."). Retry calls the adapter again.
- Transaction: until the whole gate succeeds, the derived asset and the swapped selection are provisional. `beforeApply`
  sees the provisional outcome. Only after it approves (or when it is absent) does the kit cache the asset and commit the
  swap. If `beforeApply` rejects, or the gate aborts or throws, the live selection keeps the source asset and source id
  unchanged. A retry calls the adapter again (the server is idempotent, as dcms2 confirmed). Test: derivative success, then
  `beforeApply` rejects, then a retry → the selection is still the source until the approved retry.
- On success the derived asset is normalized like list assets (normalizeAsset) and cached. It replaces the source in
  the selection at the same position. If the id equals another selected asset, the kit dedupes and keeps a single entry
  at the source position. Its usage is `{ altText, crop: null, focalPoint: null, derivedFromAssetId: sourceId }`
  (`buildOutcome`, :1452, and the UsageDraft typedef :158 gain `derivedFromAssetId`, absent for 'metadata').
  The `selection.minSize` check stays on the crop pixels (the derived asset is trusted).
- td-media-field `crop-output="new-asset"`:
  - the picker path takes the outcome, so its value becomes the new id and it emits input + change;
  - the standalone "Cắt ảnh" button (`_openCrop` :1210) resolves the adapter through the field's existing
    resolution (`_adapterProp` / pickerOptions / configureDefaults) and runs the same gate. On success it commits once:
    - the value becomes the derived id and the normalized derived asset is installed for the preview;
    - the field's crop and focal usage are cleared (the `crop` / `focal-point` state is removed);
    - exactly one input + change pair is emitted, whose detail selection carries
      `usage.derivedFromAssetId` (the same shape as the picker path).
    Provenance lives only in that event detail, not as field state, so later unrelated value changes do not carry it.
    A rejection, an abort, or a `beforeApply` rejection leaves the value, the preview and the usage untouched.
  - with no adapter or no method: `warnOnce`, then metadata.

### QĐ5 Unchanged
The modes box|pan|focal, shape circle, minSize, the keyboard model, the focus trap, the live region, the existing events.
There are no new lifecycle events. Labels added: `focalClear` ("Dùng giữa ảnh"), `cropDerivativeBusy` (live region
text "Đang tạo ảnh đã cắt…"), `cropDerivativeError`.

## Tests (acceptance, dcms2 item 6)
- node: resolveOptions cases (initial valid/invalid, output fallback, presets validation), buildOutcome derivedFromAssetId.
- engines (new file `src/feedback/td-v119-crop-output.engines.browser-test.js`, after td-v117-media-picker-before-apply):
  1. reopen with a stored rect, box and pan: the cropper starts at the rect; unchanged apply → field emits nothing.
  2. focal-optional: a null focal stays null on apply; place a point, then press "Dùng giữa ảnh" by keyboard
     (focal-change source 'clear', focus kept); a null focal becomes non-null through keyboard input alone (first arrow
     press = centre + one step, source 'keyboard'); "Đặt lại" restores null; focal mode ignores the flag.
  3. new-asset success: the selection is swapped, usage.derivedFromAssetId, field input+change with the new id.
  4. reject then retry: the dialog stays, footer message, the second call succeeds.
  5. abort: Esc during a pending derivative → signal aborted, the late resolve is ignored, a single finish.
  6. adapter without the method: one warning, metadata outcome.
  7. field crop-output on both paths (picker and standalone button).
  8. extreme locked ratios 14:1, 28:2, 64:9, 9:16: open, resize keeps the ratio, round-trip.
  9. asset switch: a stored crop does not seed a different asset (see QĐ1).
  10. derivative success + beforeApply reject + retry: the selection stays the source until the approved retry.
  11. payload: a whole-image box sends {0,0,1,1}; focal mode with 'new-asset' → one warning, metadata.
  12. presets per call: free ratio → the given presets in order and selectable; an empty list → the global default;
      a locked ratio with `ratioLabel` → the custom title suffix.
  13. field `crop-presets` / `crop-ratio-label` forwarded on both paths; invalid `crop-presets` JSON → one warning.
- Regression: existing crop/cropper/field/focal/before-apply suites, test:csp (cropper states), touch, test:node.

## Non-goals
Canvas/blob output; larger touch handles for thin boxes; deriving inside the kit; batch derivatives for multi-select.
