# Plan v0.92.0 — `td-tabs layout="fit"`: tab rộng theo chữ, trough ôm sát

Yêu cầu: dsuite (01/11/2026), owner dsuite: "hỗ trợ 2 mode là tận dụng full width của tabs hoặc adapt theo width của
text". Đo được: host 1093px, 2 tab → mỗi tab 541px. Nguyên nhân: `src/styles/components/tabs.css:102`
`.td-tabs__tab { flex: 1 1 0 }` + hành vi chia đều trong header `src/display/td-tabs.js` (~L76), không có opt-in.

Owner kit chốt 02/11/2026:
- Chế độ fit: **trough ôm sát các tab** (co lại vừa nội dung, nằm đầu dòng, phần còn lại của hàng không nền) — kiểu
  segmented control iOS. Không chọn "trough full width + tab dồn đầu dòng".
- Phát hành **v0.92.0 ngay**; grid drop `td-media-picker` lùi sang **v0.93.0**.

## Mục tiêu

1. Attribute mới `layout` trên `td-tabs`: `equal` (mặc định, giá trị lạ / vắng = `equal`) | `fit`. `equal` giữ nguyên
   từng byte hành vi + DOM hiện tại (không thêm class khi `equal`).
2. `fit`: mỗi tab `flex: 0 0 auto` (rộng theo nội dung, label không bao giờ cắt như nay); trough `.td-tabs`
   `inline-size: fit-content; max-inline-size: 100%` → ôm sát khi vừa, bị kẹp ở bề rộng host khi không vừa.
3. Tràn: vẫn dùng `data-overflow` (cuộn ngang, snap, fade cạnh) như chế độ equal. Quy tắc quyết định riêng cho fit:
   `need = Σ outer width tự nhiên (đo ở style active, cùng pass `data-measuring` hiện có) + gap × (n − 1)`;
   vào tràn khi `need > avail + 1` (dung sai subpixel 1px); ra khi
   `need ≤ avail − HYSTERESIS` (4px, như equal). **Ở fit, `avail` KHÔNG đo trên trough** (Codex plan r1 #1: trough
   `fit-content` co về đúng `need` ngay khi vừa, kể cả lúc còn `data-overflow` → điều kiện ra `need ≤ need − 4`
   không bao giờ đúng). `avail` = content box của **host `td-tabs`** (`display: block`, rộng theo cha, không phụ
   thuộc trough) trừ padding + border của trough. ResizeObserver quan sát thêm host; ở fit, mọi quyết định tràn dùng
   bề rộng host (cả `_decideFromLayout` sau render lẫn `_onResize`). Trough vẫn được quan sát cho indicator / cạnh
   cuộn như nay. Ở equal giữ nguyên đo trough (trough luôn rộng hết host nên hai số bằng nhau, không đổi hành vi).
4. Token mới `--td-tabs-tab-px` (padding ngang của tab, mặc định `12px` = giá trị hiện tại ở cả md và sm) dùng cho
   **cả hai** layout → output mặc định không đổi; site muốn chữ thoáng hơn ở fit thì đặt token (có thể chỉ trong
   `td-tabs[layout="fit"]`). Padding dọc giữ nguyên (8px md / 6px sm).
5. Áp dụng cho cả chế độ tab (button) lẫn link mode (`<nav>`); class modifier `td-tabs--fit` trên trough (cùng kiểu
   `td-tabs--sm`), cập nhật tại chỗ khi attribute đổi lúc chạy (không render lại, không mất focus): đổi class,
   `_remeasure()` (đo lại + quyết định tràn), `_scheduleIndicator()`.

## Thiết kế

- JS (`src/display/td-tabs.js`):
  - `observedAttributes` thêm `layout`; `_layout()` (giống `_size()`, `LAYOUTS = ['equal','fit']`);
    `_listClass()` dựng `td-tabs td-tabs--{size}[ td-tabs--fit]` dùng ở cả 3 chỗ render (empty / tab / link) và ở
    nhánh `attributeChangedCallback` của `size` + `layout`.
  - `_availFit()`: host content width − padding/border trough; `_ro.observe(this)` thêm host (bỏ observe khi
    disconnect như trough).
  - `_measure()` lưu thêm `_sumOuter` (tổng outer width) ngoài `_maxOuter`; `_nextMode()` rẽ nhánh theo layout.
  - Không property `layout` (giống `size`: chỉ attribute) → không cần dòng trong bảng pre-upgrade v0.54.1.
- CSS (`src/styles/components/tabs.css`): token trong `@layer td.tokens :root`; `.td-tabs__tab` padding ngang
  `var(--td-tabs-tab-px)` (md + sm); `.td-tabs--fit { inline-size: fit-content; max-inline-size: 100%; }`,
  `.td-tabs--fit > .td-tabs__tab { flex: 0 0 auto; }`. Indicator đã định vị theo offset tab → không đổi.
- Trước upgrade: trough chỉ tồn tại sau upgrade; `td-tabs:not(:defined)` (link `<a>` server in sẵn) vốn đã là hàng
  link rộng tự nhiên → không có layout shift mới, không cần selector pre-upgrade riêng. Ghi rõ trong docs.
- Docs `docs/components/tabs.md`: bảng Attribute, mục "Tuỳ biến giao diện" (token), mục Responsive (quy tắc fit),
  ví dụ; header JS; CHANGELOG; roadmap (v0.92.0 = tabs fit, v0.93.0 = grid drop).

## Phần 2 — fix: helper PHP in `name` lên host (dsuite báo 02/11)

Lỗi: `td_dropdown` (element mode, `php/td.php` ~L1630, host dựng ~L1660-1683) và `td_tree_select` (~L1927) chỉ in
`name` trên `<select>` bên trong; JS (`td-dropdown.js` ~L448, `td-tree-select.js` ~L291) chỉ chép `name` lên host
khi upgrade (lúc connected). Hệ quả: `form.querySelector('td-dropdown[name="x"]')` trên form tách rời / clone
(template, trước khi modal gắn vào trang) không tìm thấy → dsuite điền sẵn giá trị bị bỏ qua âm thầm.

Fix (generic, không chỉ 2 helper được báo):
- Soát **mọi** helper PHP in một `<td-*>` bọc control native mang `name` (dropdown, tree-select, multiselect và các
  helper SSR khác) → in thêm `name` trên host, giống `td_choice_group` đã làm. Cả element mode lẫn markup thường
  (JS vốn đã chép y giá trị đó lên host khi upgrade → sau upgrade DOM không đổi; trước upgrade custom element chưa
  định nghĩa không phải form-associated → không submit trùng; `<select name>` bên trong vẫn submit khi không có JS).
- `name` đã nằm trong danh sách reserved của `attrs` (L1683) → không xung đột với `attrs`.
- Test PHP: markup có `name` trên host cho từng helper đã sửa; test trình duyệt / node: parse markup vào form tách
  rời (`template.content` clone) → `querySelector('td-dropdown[name="x"]')` tìm thấy; sau upgrade vẫn đúng một cặp
  name/value trong `FormData` (không trùng). Cập nhật golden / fixture SSR nếu có.
