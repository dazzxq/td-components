Read-only survey, repo `/Users/theduyet/Documents/Code/components` @ `9b74bae` (v0.6.0), plus the 135 kit
(`/Users/theduyet/Documents/Code/135/public/assets/css/td-ui.css`, `td-tokens.css`, `td-cup-loader.css`).
Line numbers refer to the current files.

Common infrastructure (applies to all four):

- `TdBaseElement._doRender()` (src/base/td-base-element.js:55-62) = `innerHTML = render()` → `afterRender()` →
  `_applyStyles?.()`. **Every observed-attribute change re-renders the whole subtree** (base
  `attributeChangedCallback`, :108-112) unless the subclass overrides it (only td-toggle does). Result: focused
  inner controls get destroyed → focus loss (see gaps).
- `TdFormElement` (src/base/td-form-element.js): `formAssociated`, observes `name/disabled/required`,
  `_effectiveDisabled` (attr OR ancestor fieldset), `_ensureId()` gives host `id="td-<tag>-N"`,
  `focus()` delegates to `_focusTarget()`, reset via `_captureDefaults/_restoreDefaults`, `setCustomValidity`,
  `checkValidity/reportValidity`, `form/validity/labels` getters. Roadmap says error contract
  (`setError` + `aria-invalid` + `aria-errormessage`) lands in TdFormElement within the batches.
- Auto property ↔ attribute sync for every observed attribute (camelCase; booleans from `booleanAttributes`).
- `adoptStyles(css, key)` (src/utils/adopt-styles.js) = constructable sheet adopted once per document; ADR 0008
  §2 says token-native components must **not** use it (td.css only). All four currently use it or CSSOM.
- `applyStyles(el, map)` (src/utils/css-safe.js:100) = CSSOM `style.setProperty` per key (CSP-safe).
- Tokens that exist today in `src/styles/tokens.css`: `--td-accent/-contrast`, `--td-focus`, `--td-focus-ring`,
  `--td-control-bg/fg/border/radius`, `--td-touch-min: 44px`, `--td-color-success/warning/error/info/on-status`,
  `--td-color-hover(-strong)`, `--td-color-overlay`, `--td-z-overlay 300 … --td-z-toast 500`, motion
  `--td-dur-fast/base/slow`, `--td-ease(-out/-spring)`, glass `--_td-glass-press/-lift-knob/-dur/-ease-flex`
  (reduced-motion privates on :root). **Missing vs 135:** `--td-btn-*`, `--td-switch-*`, `--td-field-invalid`.
  Dark theme remaps accent/control/status/focus (theme-dark.css) — nothing for btn/switch yet.
- Icon registry (`src/icons/registry.js`): close check prev next up down back plus minus more search calendar
  fullscreen download external info success error warning eye eye-off zoom-in inbox star. **No spinner/loader
  glyph** (spinners stay CSS). `check` exists (checkbox tick); no "x" beyond `close` (toggle off glyph).
- Finished example conventions (lightbox.css): block-local custom props at top of block (`--td-lb-*`),
  `[hidden]{display:none!important}` restore, state via `[data-state]/[data-*]`, `:focus-visible` outline,

## 1. td-button (`src/form/td-button.js`, 307 lines)

### 1.1 Public API
- Tag `td-button`, class `TdButton extends TdBaseElement` (**not** form-associated; submit/reset works because
  the inner native `<button type=…>` sits in the light DOM inside the `<form>`).
- `observedAttributes` (:22-24):

| attr | semantics / default |
|---|---|
| `variant` | primary\|secondary\|success\|danger\|info\|warning, default `primary`; unknown → primary |
| `size` | sm\|md\|lg, default `md`; unknown → md |
| `icon` | **Font Awesome class string** (e.g. `fas fa-edit`), rendered as `<i class="…">` (escaped) |
| `icon-position` | left\|right, default left |
| `loading` (bool) | shows spinner, disables inner button, hides content (opacity-0, keeps width) |
| `disabled` (bool) | disables inner button |
| `full-width` (bool) | `w-full` |
| `color` | custom bg (safeColor) — overrides variant entirely (no glass, no variant classes) |
| `text-color` | custom fg (safeColor); default = `_getContrastColor(color)` |
| `label` | text; else captured initial `textContent` (`_originalText`, :124-131); else literal `"Button"` |
| `type` | inner button type, whitelist submit\|reset\|button, default `button` (:169) |

- JS properties (auto): `variant, size, icon, iconPosition, loading, disabled, fullWidth, color, textColor, label, type`.
- Methods: `setLoading(bool)` (:137), `setDisabled(bool)` (:149); statics `_getContrastColor`, `_hexToRgb`.
- Events: JSDoc says `@fires click` but **no custom event is emitted** — native `click` bubbles from the inner
  `<button>`; handler (:278-283) `stopPropagation+preventDefault` when loading/disabled (dead code mostly: a
  disabled `<button>` doesn't dispatch click). Comment explains removal of double-fire.
- Keyboard/a11y today: native `<button>` → Enter/Space OK. No `aria-busy`, spinner SVG has no `aria-hidden`,
  `<i>` icons no `aria-hidden`. Focus ring via Tailwind `focus-visible:ring-4 ring-offset-1` + variant
  `focus:ring-<color>/30` (colour), plus JS box-shadow swap on focus/blur.

### 1.7 A11y / quality gaps
1. Loading: no `aria-busy="true"`, spinner not `aria-hidden`, label hidden via opacity (still in a11y tree → OK
   name), but inner `<button disabled>` **drops focus** and removes it from tab order; plus `setAttribute('loading')`
   re-renders the whole subtree → focus lost even without disabled. Prefer `aria-disabled="true"` + click guard
   while loading, keep node (update in place).
2. Any attribute change re-renders (focus loss on e.g. `label` change).
3. Contrast (white text on glass over white page): success 2.04:1, warning 2.43:1, info 2.98:1, danger 3.18:1 —
   **all fail AA 4.5:1**. Token colours fix it (success #15803d 5.02, warning #b45309 5.02, error #b91c1c 6.47,

4. Contrast helper uses 0.5 YIQ threshold, not WCAG relative luminance; misses 3-digit hex / named colours.
5. `active:scale` + transitions have no reduced-motion guard; hover shadow done in JS.
6. Icon `<i>` (Font Awesome dependency, not in td) lacks `aria-hidden`; icon-only buttons have no way to set
   `aria-label` (no `aria-label` passthrough).
7. `disabled` host attribute is not reflected as `aria-disabled` on host; host is not focus-delegating
   (`focus()` on `<td-button>` does nothing).
8. JSDoc `@fires click` misleading.
9. Touch target: sm = 12px text + 6px padding ≈ 28px tall (< 44px `--td-touch-min`).

## 4. td-loading (`src/feedback/td-loading.js`, 338 lines) — NOT a custom element

### 4.1 Public API
- Exports `TdLoading` (static class) and `TdLoadingSpinner` (factory). No tag, no attributes, no events.
- `TdLoading.element` (static, the overlay div), `_maxDurationTimer`.
- `TdLoading.init()` — builds `#td-loading` overlay once, appends to `document.body`.
- `TdLoading.show(messageOrOptions = 'Đang tải...')` — string or `{ message, maxDuration }` (default 30000 ms;
  `false`/0 disables). Sets `#td-loading-message` textContent; removes `hidden` class + `style.display='flex'`;
  auto-hide timer logs `console.warn`.
- `TdLoading.hide()` — clears timer, adds `hidden` + `display:none`.
- `TdLoading.wrap(asyncFn, message)` — show → await → finally hide. **Not ref-counted**: nested/parallel
  `wrap()` calls hide on the first completion.
- `TdLoadingSpinner.create({ size='md', color='#3b82f6', trackColor='rgba(59,130,246,.15)', className='' })`
  → returns detached `<div class="td-spinner {className}">`. sizes sm 20px/stroke 3 · md 32/4 · lg 48/5.
  Colours via safeColor into SVG presentation attrs. `className` is NOT sanitised (goes to `className` property —
  safe from injection, just arbitrary classes).
- Consumers: `td-modal.js:510` comment (TdModal.loading removed → TdLoading), stories
  `td-modal.stories.js:79-80`, `td-composition.stories.js:113-115`, `index.js` export.

### 4.7 A11y / quality gaps
1. Overlay has **no `role`/`aria-live`/`aria-busy`/`aria-modal`**; message change not announced; background stays
   focusable/clickable-by-keyboard (no `inert`, no focus management). Should be `role="status"`/`aria-live=polite`
   (or `role="alert"` for long waits) + `aria-busy` on `document.body`/main? + `inert` on siblings or a
   dialog-ish focus hold.
2. Inline spinner: no `role="status"`/`aria-label`, not `aria-hidden` either.
3. Inline spinner has **no reduced-motion** handling (inline `animation`); overlay under reduced motion still
   rotates (liquid-glass.md table says: reduced-motion/forced-colors → stop spinning, keep label).
4. No forced-colors: hard-coded blue strokes → use `currentColor`/`CanvasText`.
5. `z-[99999]` vs token scale (`--td-z-overlay 300`, modal 400, toast 500): loading is meant to sit above modal
   → needs a new token (e.g. `--td-z-loading: 480`, below toast) rather than 99999.
6. Card is solid white + hard colours; liquid-glass.md says fullscreen loading = scrim (`--td-glass-scrim`) +
   **Regular strong** glass card when it has text (`td-glass-surface td-glass-surface--strong`).
7. Not ref-counted (`wrap` concurrency), message defaults Vietnamese-only (fine, but no i18n hook).
8. Three separate spinner implementations exist (td-button SVG, td-loading SVG, lightbox CSS ring) → one shared
   `.td-spinner` in td.css would dedupe.
