## 2. Target (dsuite wording)

A continuous tinted band with no per-row outline. Round it only at the range start / end and at row ends. Cells keep a
small gap so a ring or fill never touches a neighbour. Nothing is clipped at the grid edges, and outside-month days in
the range look consistent.

## 3. Design (scoped to the range panel: `.td-dtr-panel .td-cal…`; the single picker does not change)

- **Rows:** `border-spacing: 0 2px` on the range grid. Rows are separate bars and a band never touches the next row.
  The grid grows 12px (6 × 2px). Check the sheet height on a 320 × 568 phone.
- **Band = the td background** (`--td-cal-range-bg`, committed; `--td-cal-preview-bg`, preview), square inside a row.
  Rounded (`--td-radius-md`) only on the range start / end side and on the row's first / last cell. Remove the preview
  hairlines. The preview reads as the lighter tint only; the preview end is rounded on its inline-end side, with no
  border or outline of its own (no four-sided box around any cell outside forced colours). Forced colours keep the
  dashed outline (there the tint is gone, so an outline is the only cue).
- **Cell state = an inner pill** (`::before`, `position: absolute; inset: 2px`, radius md, `z-index: -1`; every range-panel `.td-cal__day` gets
  `position: relative` (the pill's containing block) and `isolation: isolate`):
  selected endpoint (solid), hover, pressed, today ring. The focus ring is drawn on the pill (`box-shadow`), so nothing
  crosses into a neighbour cell. Forced colours: keep `outline` on the td (box-shadow is dropped there).
- **Range-scoped overrides (explicit):** under `.td-dtr-panel` every shared state rule that paints on the td
  (`[aria-selected="true"]` fill, fine-pointer `:hover`, `:is(:active, [data-td-pressed])`, `[aria-current="date"]` ring,
  `:focus-visible` outline) is overridden: the td carries only the band (or transparent), the `::before` pill carries
  the state. The shared rules in calendar.css stay as they are, so the single picker is pixel-identical.
- **Endpoints:** the td keeps the band colour on the inner side only (start: rounded start corners; end: rounded end
  corners; single: no band). The solid pill sits on top, so the endpoint reads as a cap of the band.
- **Outside-month days:** the band continues through them with full ink, the same as in-month days (current M0.6 rule).
  Alternative (owner decision): no band on outside days. Recommended: keep the band. It is honest about the range, and
  hiding it makes a range that crosses months look broken.
- **Edges:** nothing paints outside the td (no outward outline / shadow), so no clipping at the grid edge.

## 5. Tests

A new `src/form/td-v0963-range-band.engines.browser-test.js` on 3 engines. The range starts 28/10 and the preview
runs to 06/11, so it crosses outside-month days and both grid columns 1 and 7:
- adjacent rows do not touch: the td rects of two rows have a vertical gap ≥ 1px;
- preview / band cells: `box-shadow` none and outline style none (outside forced colours); band colour = the token;
- radii from computed style: in-row band cells 0; the row's first column has start radii, the last column end radii;
  the range start has start radii only, the preview end has end radii only;
- outside-month cells in the band: the same background as in-month band cells and full ink (`color` = `--td-cal-fg`);
- the pill (`getComputedStyle(td, '::before')`): the td computes `position: relative`; the pill `position: absolute`, all insets ≥ 2px, endpoint background = the
  selected token, focus ring as `box-shadow` without spread beyond the inset, so nothing reaches past the td;
- no clipping: the column 1 / column 7 td rects lie inside the `.td-cal` rect and the panel's scroll box
  (`scrollWidth === clientWidth`);
- the single picker's selected / today / hover computed styles match today's values (unchanged).
