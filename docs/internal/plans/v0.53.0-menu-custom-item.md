# v0.53.0 — `TdMenu` mục tuỳ biến (`type: 'custom'`) + chế độ "menu panel"

## Nguồn

- **dsuite — menu tài khoản** (mở từ thẻ profile): muốn đặt công tắc theme Tự động / Sáng / Tối (chính
  `<td-choice-group variant="segmented">` của v0.52) **bên trong** `TdMenu`. dsuite đề xuất một item cứng
  `{ type: 'segmented', … }`.
- **Owner bác item cứng** (2026-10-07): "components mục đích là phải hỗ trợ linh động chứ ko fix cứng cố định cái gì cả"
  — menu phải chứa được **nội dung bất kỳ** (HTML của site, hoặc một td component như tabs / segmented).
- **Quyết định release lead (khớp ý owner):** một item **chung** `{ type: 'custom', render(ctx) → Element }`, nhận
  **Element**, không nhận chuỗi HTML — `docs/internal/security-model.md:59–60` ("Component mới phải tránh thêm hatch. Nếu
  cần (vd. `panel(ctx)` của lightbox), nhận **Element** chứ không nhận chuỗi HTML", ADR 0009). Kit **không** có code riêng
  cho theme; theme switcher thành **công thức docs** (menu + custom + segmented + API theme v0.41 / v0.42).
- **Hiện trạng kit:** `TdMenu` (`src/feedback/td-menu.js`, 945 dòng) là APG Menu Button + Menu thuần: `role="menu"`, con chỉ
  là `menuitem` / `menuitemcheckbox` / `menuitemradio` / `separator`; roving focus thật; Tab đóng menu (D4). Không có ADR
  riêng cho menu (quyết định nằm ở plan v0.12.0 D1–D7, v0.14.0 G9, v0.21.1, v0.36.0, v0.39.0, v0.42.0).
- ADR liên quan: [0009](../decisions/0009-td-lightbox-hooks.md) (hook nhận Element), [0011](../decisions/0011-minimal-surfaces.md)
  (bề mặt popup), [0019](../decisions/0019-touch-standard.md) (cảm ứng), [0020](../decisions/0020-theme-scope-portal.md)
  (theme theo vùng cho popup), [0023](../decisions/0023-unowned-radio-group.md) (nhóm radio của choice-group).
  Bản này thêm **ADR 0026** (QĐ 1–2: menu có nội dung tuỳ biến thì không còn là `role="menu"`).

Ràng buộc: additive, không breaking; **menu không có item custom phải giống từng byte DOM + hành vi v0.52**; không
dependency mới; light DOM; CSP strict; không token `THEME_TOKENS` mới (mục tiêu: **0 token mới**); không PHP (menu không có
helper PHP — `docs/components/menu.md:398–400`); nhãn tiếng Việt.

## Mục tiêu

1. Item `{ type: 'custom', render(ctx) → Element | null, label?, id?, order?, when? }` chứa **mọi** Element: segmented,
   `td-tabs`, toggle, form nhỏ, khối thông tin tĩnh (header profile), markup clone từ `<template>`.
2. Ngữ nghĩa **hợp lệ ARIA** khi có nội dung tuỳ biến (QĐ 1), trình đọc màn hình đọc đúng ở 3 engine + checklist
   VoiceOver / NVDA.
3. Bàn phím: hàng custom là **một điểm dừng** trong ↑ / ↓; khi focus trong nội dung, menu **không cướp** phím widget cần
   (← → Space Enter Home End, gõ chữ); Escape vẫn đóng; Tab đi được trong nội dung; type-ahead của mục thường giữ nguyên;
   focus về trigger khi đóng.
4. Vòng đời sạch: `render` gọi **mỗi lần mở** (element mới), `ctx.signal` abort khi đóng (mọi lý do) → không rò listener;
   bấm / nhập trong nội dung **không** đóng menu trừ khi gọi `ctx.close()`.
5. An toàn: chỉ Element (chuỗi → bỏ + cảnh báo cố định), không `innerHTML`, không sửa element của caller ngoài việc
   append; `render` ném lỗi → bỏ hàng + cảnh báo cố định.
6. Docs: mục "Mục tuỳ biến" trong `menu.md` + **công thức theme switcher trong menu tài khoản** + công thức `<template>`;
   gate đủ (Node, browser, 3 engine, CSP, contrast, touch, responsive, stories).

## Không làm (non-goals v0.53)

- **Không** item cứng `segmented` / `theme` / `toggle`; không API theme mới (công thức docs).
- **Không** nhận chuỗi HTML / `TrustedHTML` / `DocumentFragment` (QĐ 7) — `<template>` đi qua `firstElementChild`.
- **Không** row `heading` cho nhóm mục thường (QĐ 6: `label` của custom đủ cho ca dsuite; heading cho mục thường → backlog).
- **Không** cache nội dung giữa các lần mở; không `onClose` riêng cho từng item (đã có `ctx.signal`).
- **Không** submenu / `TdMenu` lồng (kit vẫn một menu một lúc: mở `TdMenu` từ trong nội dung sẽ đóng menu cha — ghi docs).
- **Không** đổi `td-dropdown` / `td-choice-group` / `td-tabs`; không đổi Tab của menu **không** có custom (D4 giữ).
- Ô nhập chữ trong panel **trên điện thoại** (bàn phím ảo): best-effort, không cam kết ở v0.53 (Rủi ro R5).

## Quyết định

### A. Ngữ nghĩa (a11y)

**QĐ 1 — Có ít nhất một item custom ⇒ popup là "menu panel": `role="dialog"` (không modal), mục thường nằm trong các
khúc `role="menu"`; không có custom ⇒ y hệt v0.52.**

Hai phương án đã cân:

| | (a) Giữ `role="menu"`, hàng custom = `role="group"` / `none` chứa widget | (b) **Chọn:** panel `role="dialog"` + khúc `role="menu"` |
|---|---|---|
| Hợp lệ ARIA 1.2 | **Không.** `menu` chỉ được sở hữu `group` / `menuitem*` / `separator`; `group` trong `menu` chỉ được chứa `menuitem*`. Radio / tab / textbox trong `menu` là con không cho phép | **Có.** `dialog` chứa nội dung bất kỳ; mỗi khúc `menu` chỉ chứa `menuitem*` / `separator` đúng luật |
| Trình đọc màn hình | Chạy được "tình cờ" khi focus thật vào radio, nhưng: tổng "n mục" sai, JAWS / VO có thể giữ chế độ menu và nuốt phím; vai trò nói dối (popup không chỉ là danh sách lệnh) | "Tài khoản, hộp thoại" → "Hồ sơ, mục menu, 1 trên 2" → "Giao diện, nhóm, Sáng, nút radio, đã chọn, 2 trên 3". Mỗi phần tử đọc đúng vai trò của nó |
| Tiền lệ | Radix cho nội dung tự do trong `role=menu` (không kiểm hợp lệ) | Primer / GitHub chuyển menu tài khoản có nội dung giàu sang overlay `dialog`; Spectrum / Fluent không cho widget trong menu |
| Chi phí | Nhỏ | Vừa: vỏ panel + bọc khúc + Tab qua các điểm dừng (QĐ 4) — chỉ chạy khi có custom |

Kit xưa nay chọn đúng chuẩn (CDP AX tree cho toggle `locked` v0.52) ⇒ **(b)**. DOM panel:

```html
<div class="td-menu td-menu--panel td-glass-surface td-glass-surface--strong" id="{m}" role="dialog" tabindex="-1"
     aria-labelledby="{trigger id}" | aria-label="{opts.label}" data-state="open" data-placement data-align>
  <div class="td-menu__section" role="menu">            <!-- một khúc = dãy mục thường liền nhau (+ separator giữa chúng) -->
    <button class="td-menu__item" role="menuitem" tabindex="-1">Hồ sơ</button> …   <!-- markup mục: y hệt v0.52 -->
  </div>
  <div class="td-menu__separator" role="separator"></div>  <!-- separator giáp hàng custom: ở cấp panel -->
  <div class="td-menu__custom" [role="group" aria-labelledby="{m}-c{i}-label"] [data-item="{id}"]>
    [<div class="td-menu__custom-label" id="{m}-c{i}-label">Giao diện</div>]          <!-- chỉ khi có label (textContent) -->
    {Element của caller — append nguyên trạng}
  </div>
  <div class="td-menu__section" role="menu">…Đăng xuất…</div>
</div>
```

- Khúc `role="menu"` **không có tên riêng** (panel đã mang tên; tránh đọc lặp "Tài khoản" ở mỗi khúc). M0 kiểm; nếu
  Chromium / VO đòi tên → `aria-labelledby` cùng nguồn với panel (RL Q3).
- `tabindex="-1"` trên panel: bấm vào vùng không focus được trong panel → focus về panel (không về `<body>`), phím vẫn chạy
  (↓ từ panel = hàng đầu). Chỉ chế độ panel (menu thường giữ byte-identical). Focus sau khi bấm **trong hàng custom**: QĐ 5b.
- Trigger (codex r1 #3): `bind()` / `bindAll()` **luôn** đặt `aria-haspopup="menu"` như v0.52 — **không** đoán trước "dialog"
  kể cả với mảng tĩnh (`when` có thể ẩn hàng, `render` có thể trả `null` / bị từ chối ⇒ lúc bind không bảo đảm có hàng
  custom). `open()` cập nhật **sau** khi đã giải `when` + `render`: có ít nhất một hàng custom thật được dựng → `"dialog"`,
  không có → `"menu"`; chỉ khi kit sở hữu trigger (`TRIGGER_OWNERS`) hoặc trigger chưa có attribute (open() trên anchor
  có `aria-haspopup` của tác giả: không đụng, như td-menu.js:689). Giá trị giữ sau khi đóng (lần mở sau ghi lại). Hệ quả
  đã chấp nhận (RL Q4): trước lần mở đầu trigger báo `"menu"` dù sẽ mở panel — docs ghi rõ; site muốn đúng ngay thì dùng
  `open()` trên trigger tự đặt `aria-haspopup="dialog"`. `aria-expanded` / `aria-controls` như cũ.
- Mọi hàng của menu thường (markup item, id, hint, check mark) **không đổi**: chỉ được bọc vào khúc. Code `build()`
  (td-menu.js:291–370) tách "dựng mục" khỏi "dựng vỏ".

**QĐ 2 — Hàng custom: `role="group"` + `aria-labelledby` caption khi có `label`; không `label` ⇒ `div` generic.**
Nội dung tự mang tên (choice-group `aria-label` → radiogroup, td-choice-group.js:306) thì bỏ `label` để khỏi đọc hai lần.
Khuyến nghị docs: **hoặc** `label` của item (caption kiểu menu) **hoặc** tên của widget, không cả hai. Không có
`labelHidden` ở v0.53 (RL Q1).

### B. Bàn phím & focus

**QĐ 3 — Roving ↑ / ↓ qua "hàng": mục thường (mỗi mục một hàng) + hàng custom (một điểm dừng).**
- Đi vào hàng custom: ↓ / Home / mở với `focus: 'first'` → **điểm dừng Tab đầu** của nội dung; ↑ / End / `focus: 'last'`
  → điểm dừng **cuối**. "Điểm dừng Tab" = `tabSequence(row)` (util mới cạnh `focusablesIn`, layers.js:301): như
  `focusablesIn` nhưng **gộp nhóm radio** (cùng `name` + form owner; radio không tên là nhóm riêng) thành radio đang
  chọn, không có thì radio đầu (đi tới) / cuối (đi lùi) — đúng thứ tự Tab native. `focusablesIn` không gộp radio ⇒
  không dùng thẳng được (segmented có 3 radio, chỉ 1 điểm dừng).
- **Cây composed (codex r1 #2).** Kit là light DOM, nhưng nội dung là của **site** và có thể chứa custom element có shadow
  root. `tabSequence` duyệt **theo thứ tự cây phẳng** (flat tree), không chỉ `querySelectorAll`:
  - Phần tử có **shadow root mở** (`el.shadowRoot`): host là điểm dừng nếu tự focus được (`tabIndex ≥ 0`) **và không**
    `delegatesFocus`; sau đó duyệt **vào** shadow root; gặp `<slot>` thì duyệt `assignedElements({ flatten: true })` tại
    vị trí slot (con light DOM được chiếu); con light DOM **không** được gán slot thì không hiển thị ⇒ bỏ.
  - `shadowRoot.delegatesFocus === true`: host **không** là điểm dừng riêng; điểm dừng là các phần tử focus được bên trong
    (`focus()` gọi thẳng lên phần tử bên trong, không gọi `host.focus()`).
  - **Shadow root đóng** (không đọc được — `el.shadowRoot === null`): host là **một** điểm dừng nếu host tự focus được
    (`tabIndex ≥ 0` / control native / `delegatesFocus` không đọc được ⇒ dựa vào `tabIndex` của host); không thì **không
    hỗ trợ** — docs ghi "control nằm trong shadow root đóng không vào được bằng ↑ ↓ / Tab của menu, trừ khi host có
    `tabindex`".
  - Nhóm radio gộp theo **root node** (`getRootNode()`) + `name` + form owner (radio cùng tên ở hai shadow root khác nhau là
    hai nhóm, đúng như trình duyệt).
  - Các phép "focus đang ở đâu" dùng **active element sâu** (đi `shadowRoot.activeElement` từ `document.activeElement`) và
    **chứa theo cây composed** (đi `getRootNode().host` lên tới row) thay cho `row.contains()`; phím: target thật =
    `e.composedPath()[0]` (listener ở panel thấy target bị retarget về host) — dùng cho cả bảng "control tự dùng ↑ ↓"
    (QĐ 4) và `data-td-menu-keys` (đi `closest` qua ranh giới shadow).
- Hàng custom **không có** điểm dừng (khối tĩnh: header profile, nội dung toàn disabled) → **bị bỏ qua** khi roving / Tab;
  tính **lúc bấm phím** (nội dung động). Không còn hàng nào focus được → focus panel.
- Mục `aria-disabled` vẫn là điểm dừng (APG, giữ).

**QĐ 4 — Ai giữ phím nào khi focus ở trong nội dung custom.**

| Phím | Focus trên mục thường | Focus trong nội dung custom |
|---|---|---|
| ↑ / ↓ | Menu (như cũ) | **Menu** — sang hàng trước / sau — **trừ khi** target là control tự dùng ↑ ↓ (dưới) hoặc nằm trong `[data-td-menu-keys="content"]` → để nội dung |
| ← → Home End PageUp PageDown | Menu: Home/End/PgUp/PgDn (như cũ) | **Nội dung** (segmented ← → đổi chọn; td-tabs ← → Home End) |
| Enter / Space | Kích hoạt mục | **Nội dung** |
| Gõ chữ | Type-ahead (chỉ nhãn mục thường; hàng custom = `null` → không bao giờ khớp, typeahead.js:13–33) | **Nội dung** (ô nhập gõ được) |
| Escape | Đóng, focus trigger | **Đóng, focus trigger** (layers.js:54–71, capture cấp document — đi trước mọi listener; popup lồng đăng ký sau thì nhận Escape trước) |
| Tab / Shift+Tab | Menu thường: đóng + pass (D4, không đổi). **Panel:** điểm dừng kế / trước trong chuỗi | Điểm dừng kế / trước trong chuỗi |

- **Cơ chế ↑ / ↓ phải ở capture** trên panel: choice-group tự `preventDefault` + vòng ở **hai đầu** nhóm
  (td-choice-group.js:489–504), còn ở giữa thì để radio native di chuyển. Nếu menu nghe bubble (như nay, td-menu.js:682)
  thì ở giữa menu chặn mặc định nhưng ở đầu lại thấy `defaultPrevented` → hành vi lệch theo vị trí. Capture: menu quyết
  trước, khi nó lấy ↑ / ↓ thì `preventDefault()` + `stopPropagation()` (widget bên trong không thấy phím đó).
- **Control tự dùng ↑ ↓** (menu nhường): `textarea`, `select`, `input` trừ `checkbox|radio|button|submit|reset|image|file|color`
  (gồm text / number / range / date…), `[contenteditable]`, phần tử (target hoặc tổ tiên trong hàng) có `role` ∈
  `slider|spinbutton|listbox|combobox|textbox|tree|treegrid|grid`. Radio **không** trong danh sách: segmented ngang dùng
  ← → , ↑ ↓ thuộc về menu (đúng trực giác "menu dọc, widget ngang"). Ngoại lệ còn lại → site đặt
  `data-td-menu-keys="content"` (hook duy nhất, không option JS).
- **Tab trong panel = di chuyển thủ công** (`preventDefault` + focus): chuỗi = mỗi mục thường một điểm dừng + mọi điểm dừng
  của từng hàng custom (QĐ 3), theo thứ tự DOM; **qua mép** (sau điểm cuối / trước điểm đầu) → hành vi D4 cũ: đóng + focus
  trigger + `'pass'`. Thủ công thay vì native vì native trong panel không đáng tin: mục thường `tabindex=-1` (Tab native
  nhảy qua), radio chưa chọn bị bỏ, panel nằm cuối `<body>` (Tab native ra khỏi trang). Tiền lệ: `trapTab` xử lý mép
  thủ công (layers.js:319). `onTab` trả `'handled'` (layers.js:76–80) — không pass xuống modal bên dưới.
- Type-ahead chỉ khi focus trên mục thường hoặc panel. Phím có `isComposing` / 229 → bỏ (như td-menu.js:509).

**QĐ 5 — Focus khi mở / đóng.** Mở: `focus: 'first' | 'last'` theo hàng (QĐ 3), mục enabled ưu tiên như cũ (td-menu.js:708–710).
Đóng: giữ nguyên bảng `back` của `closeSession` (td-menu.js:415–418) — `ctx.close()` dùng lý do `'select'` ⇒ focus về
trigger. Focus đang ở **popup lồng** (dropdown mở từ nội dung) khi menu đóng → coi như "focus trong menu"
(`floatingContains(menu, active)`, layers.js:264) để không rơi về `<body>`.

**QĐ 5b — Focus sau khi bấm chuột / chạm trong hàng custom (codex r1 #1).** WebKit (và Safari iOS) **không** focus radio /
`<button>` / checkbox khi bấm ⇒ sau cú bấm vào ô segmented, focus nằm ở panel (nhờ `tabindex=-1`) hoặc ở mục / chỗ cũ;
↓ / ← → lúc đó không làm việc với control vừa bấm, khác Chromium / Firefox. Luật (chỉ chế độ panel, chỉ target trong hàng
custom):
- Nghe `click` trên panel (pha bubble — **sau** hành động mặc định: radio đã được chọn, focus native đã xảy ra nếu engine
  có focus). Không dùng `pointerdown`: focus sớm ở đó có thể huỷ / đổi cú bấm (kéo chọn chữ, label).
- **Không làm gì** khi: active element sâu đã ở **trong hàng** đó (Chromium / Firefox, ô nhập chữ — control tự nhận focus
  không bị đụng); focus ở popup lồng (`floatingContains`); `e.defaultPrevented`; panel đã đóng (handler của caller gọi
  `ctx.close()`).
- Ngược lại: focus **control gần nhất của cú bấm** — đi `e.composedPath()` từ target lên tới hàng, lấy phần tử đầu tiên là
  điểm dừng hợp lệ theo `tabSequence` (thuộc tập điểm dừng của hàng **hoặc** là radio của một nhóm có trong tập — radio
  vừa bấm luôn là radio đang chọn); target là `<label>` → dùng `label.control`. Không tìm được (bấm caption, chữ tĩnh,
  khoảng trống, control `disabled`) → focus **panel**.
- Lý do chọn "control gần nhất" thay vì luôn về panel: người dùng bấm ô "Tối" rồi bấm ← phải đổi sang "Sáng" ở **mọi**
  engine (cùng hành vi Chromium / Firefox); focus về panel thì ← vô tác dụng và ↓ nhảy về hàng đầu — mất vị trí. Focus
  về panel chỉ là đường lui khi cú bấm không trúng control. `focus({ preventScroll: true })`; `:focus-visible` không bật
  (focus theo sau cú bấm chuột ⇒ engine coi như không phải bàn phím — kiểm ở M3), nên không hiện vòng focus thừa khi bấm.
- Chạm (`pointerType` touch): cùng luật (Safari iOS giống WebKit desktop); không gọi focus lên ô nhập chữ (đã tự focus)
  ⇒ không bật bàn phím ảo ngoài ý muốn.

### C. Item & vòng đời

**QĐ 6 — Hình dạng công khai (chốt).**

```js
{
  type: 'custom',                         // bắt buộc
  render(ctx) { return element; },        // bắt buộc: → Element (mới, chưa gắn vào trang) | null (không có hàng)
  label: 'Giao diện',                     // tuỳ chọn: caption hiển thị (TEXT) + tên của hàng (role="group")
  id: 'theme',                            // tuỳ chọn: data-item="theme" trên hàng (test / style)
  order: 500, when: (ctx) => true,        // như mọi item (registry / ẩn hiện)
}
// ctx của render — dựng mới mỗi lần mở:
ctx = {
  ...opts.ctx, ...data-td-menu-* của anchor,  // như ctx hiện nay (menu.md:205–223)
  anchor, name,                               // như hiện nay
  item,                                       // object item gốc của caller (không bị sửa)
  close(),                                    // đóng menu, lý do 'select' (focus về trigger); sau khi đóng: no-op
  signal,                                     // AbortSignal — abort khi menu đóng (mọi lý do) hoặc hàng bị bỏ
}
```

- `close` / `signal` được gán **sau** khi trải ctx ⇒ thắng khoá trùng tên của `opts.ctx`; **không** thêm vào
  `RESERVED_CTX` (td-menu.js:99) để không đổi ctx của `onSelect` / `when` hiện có.
- **Không** có `ctx.menu`: nội dung không được đụng vỏ popup; caller cần thì đã có `handle.element` (Q2).
- `onSelect`, `href`, `icon`, `hint`, `danger`, `disabled`, `checked` trên item custom: **bỏ qua** (nội dung tự lo). Không
  cảnh báo (giữ code nhỏ) — ghi docs.
- `type` lạ (vd. `'segmented'`) → như hôm nay: coi là `'item'` (td-menu.js:248); không có `label` → bị bỏ. Docs ghi rõ.
- Không thêm `heading`: `label` của custom phủ ca dsuite; heading cho nhóm mục thường cần bọc `role="group"` trong khúc
  menu — backlog nếu có ca dùng.

**QĐ 7 — Chỉ Element; xử lý kết quả `render`.**

| `render` trả / làm | Kết quả |
|---|---|
| `Element` **chưa gắn** vào document | Append vào hàng (không `cloneNode`, không đặt attribute / class / style nào lên nó) |
| `null` / `undefined` | Không có hàng, **không** cảnh báo (tương đương `when` → false) |
| Chuỗi | Bỏ hàng + `console.warn('TdMenu: custom item render() must return an Element — strings are not rendered (no HTML)')` |
| Kiểu khác (số, object, `DocumentFragment`, Text node, Promise) | Bỏ hàng + `console.warn('TdMenu: custom item render() must return an Element')` |
| Element **đang gắn** trong trang (`isConnected`) | Bỏ hàng + `console.warn('TdMenu: custom item render() must return a detached Element')` — append sẽ **giật** nó khỏi trang và mất khi đóng |
| Ném lỗi | Bỏ hàng + `console.warn('TdMenu: custom item render() threw — row omitted', err)` (mẫu `when()` td-menu.js:183) |

- Mọi trường hợp bỏ hàng: **abort `signal` của hàng ngay** (listener caller đã gắn trước khi ném được dọn).
- Chuỗi cảnh báo cố định (không ghép dữ liệu caller), một lần mỗi lần mở.
- Sau khi bỏ hàng hỏng, nếu không còn hàng nào → `open()` trả `null` (như td-menu.js:633), abort mọi signal.
- `<template>`: `document.importNode(tpl.content, true).firstElementChild` (Element; custom element bên trong được nâng cấp
  khi gắn). Đúng tiền lệ hovercard (`template` được **clone**, td-hovercard.js:24–25).

**QĐ 8 — `render` gọi mỗi lần mở, sau `when` + sắp xếp, trước khi dựng DOM; không cache.** Thứ tự trong `open()`
(td-menu.js:624–636): ctx → items (hàm lười / registry gọi lại mỗi lần mở — giữ) → `when` → `normalise` (thêm nhánh
custom **trước** kiểm `label` ở :246–247) → **gọi `render` từng custom** (mỗi hàng một `AbortController`) → dựng vỏ → gắn
`<body>` (custom element trong nội dung connect + render đồng bộ tại đây) → `place` → focus. Caller **tự** cache element thì
vẫn chạy (element đã tách khỏi DOM khi menu cũ bị gỡ) — docs không khuyến khích.

**QĐ 9 — Tương tác chuột / chạm: không bao giờ tự đóng.** `onMenuClick` (td-menu.js:542–558) chỉ xử lý target thuộc mục
thường (`indexOfNode` trên `s.items` — hàng custom không nằm trong đó ⇒ đã đúng, giữ tách `s.items` / `s.rows`).
`pointerdown` trong panel không phải "outside" (td-menu.js:661). **Popup lồng** mở từ nội dung (td-dropdown, color
picker — cùng `LAYERS.popover`, đăng ký sau): `onPointerDown` coi `floatingContains(menu, target)` là bên trong;
`closeSession` gọi `coverFloatingIn(menu)` trước khi gỡ (tiền lệ hovercard td-hovercard.js:410–417, :522 và dialog-layer.js:168–170).
`TdMenu` lồng: không hỗ trợ (một menu một lúc).

**QĐ 10 — Dọn dẹp khi đóng.** `closeSession` (td-menu.js:393–424): thứ tự mới = huỷ listener / layer như cũ →
`coverFloatingIn(menu)` → trả focus (như cũ) → **abort mọi signal của hàng custom** → `menu.remove()` → `onClose`.
Abort trước `remove()` để handler `abort` của caller còn thấy element trong DOM (vd. lưu nháp). `ResizeObserver` (QĐ 11)
`disconnect()`. Test: 50 lần mở / đóng ⇒ listener `change` caller gắn qua `{ signal }` không còn gọi; không giữ tham chiếu
tới element cũ trong session.

### D. Giao diện

**QĐ 11 — Hàng custom thừa hưởng bề mặt menu; 0 token mới.**
- `.td-menu__custom`: `padding: var(--td-menu-item-py) var(--td-menu-item-px)`, `min-width: 0`, không nền, không hover,
  không hình nhấn (không vào `PRESS_TARGETS`, press.js:67–68 giữ nguyên), không `min-height` (nội dung tự quyết).
  `:focus-within` không đổi nền (focus ring là của widget bên trong).
- `.td-menu__custom-label`: chữ `--td-text-xs`, `--td-fw-medium`, màu `--td-menu-hint-fg` (cặp đã được gate như hint),
  khoảng dưới `--td-space-2xs`.
- `.td-menu__section`: `display: flex; flex-direction: column` (**không** `display: contents` — Chromium / WebKit cũ bỏ
  vai trò ARIA của phần tử `display: contents`).
- Chiều rộng: giữ `--td-menu-min-w` / `--td-menu-max-w` (13–22rem, ≤ 100vw − 16px, menu.css:47–48). Segmented sm 3 ô
  "Tự động / Sáng / Tối" vừa trong 22rem; nội dung rộng hơn → bọc / xuống dòng trong hàng (`overflow-x: hidden` của menu
  sẵn có). Site cần panel rộng hơn: token `--td-menu-max-w` (đã có).
- Nội dung lớn lên / co lại (td-tabs đổi panel): `ResizeObserver` trên các hàng custom → `reposition` (gộp rAF). Không
  vòng lặp: `placeFloating` chỉ ghi top / left / max-height lên panel.
- Sáng / tối / theme vùng: `bridgeTheme` (td-menu.js:686) đã đưa scope theme lên panel ⇒ nội dung đọc đúng token. Forced
  colors: panel giữ viền `CanvasText` (menu.css:305–307); caption `CanvasText`; widget tự lo.
- Cảm ứng (ADR 0019): control của nội dung tự đạt ≥ 44 px (segmented coarse ≥ 44 đã có từ v0.52); gate đo **trong** panel.
- CSP: kit chỉ thêm class + `textContent`; element của caller có `style="…"` là lỗi của caller (docs, như mọi hatch §2).

### E. Bảo mật

**QĐ 12 — Hàng custom là DOM tin cậy của caller, không phải đường dữ liệu mới của kit.**
- Kit không parse, không `innerHTML`, không clone, không sanitize element (giống `panel(ctx)` lightbox, td-lightbox.js:604–610
  — nhưng lightbox **im lặng** bỏ chuỗi; menu **cảnh báo** cho dễ gỡ lỗi).
- `label` → `textContent`; `id` → `setAttribute('data-item')` như mục thường (td-menu.js:320).
- `security-model.md` §2 thêm dòng: "`TdMenu` item `type: 'custom'` `render(ctx)` → **Element** (DOM tin cậy của dev;
  chuỗi bị từ chối). Dữ liệu người dùng vào nội dung qua `textContent` / thuộc tính, như mọi Node hook."
- Nội dung **không** đổi mô hình quyền: thao tác trong menu vẫn phải được server kiểm (như `when()`, menu.md:454).

  - Nội dung đổi cao (td-tabs đổi panel) → panel đặt lại vị trí trong khung nhìn (side top lẫn bottom).

Công thức (docs, không phải code kit):

```js
import { TdMenu } from '@dazzxq/td-components/menu';
import '@dazzxq/td-components/choice-group';

const THEMES = [
  { value: 'auto', label: 'Tự động', icon: 'monitor' },
  { value: 'light', label: 'Sáng', icon: 'sun' },
  { value: 'dark', label: 'Tối', icon: 'moon' },
];
const currentTheme = () => {
  const v = document.documentElement.getAttribute('data-td-theme');
  return THEMES.some((t) => t.value === v) ? v : 'auto';
};

TdMenu.bind(profileCard, () => [
  { label: 'Hồ sơ', href: '/profile' },
  { separator: true },
  {
    type: 'custom', id: 'theme', label: 'Giao diện',
    render: ({ signal }) => {
      const g = document.createElement('td-choice-group');
      g.setAttribute('variant', 'segmented');
      g.setAttribute('size', 'sm');
      g.setAttribute('value', currentTheme());
      g.options = THEMES;                                  // nhãn = tên truy cập; không aria-label (hàng đã có tên)
      g.addEventListener('change', (e) => {
        const v = e.detail.value;
        document.documentElement.setAttribute('data-td-theme', v);
        document.cookie = `td_theme=${v}; path=/; max-age=31536000; SameSite=Lax`;
      }, { signal });                                      // tự gỡ khi menu đóng
      return g;
    },
  },
  { separator: true },
  { label: 'Đăng xuất', icon: 'log-out', danger: true, onSelect: logout },
], { label: 'Tài khoản' });
```
