## C. Dropzone SSR (ADR 0012 roadmap step "sau đó datetime, dropzone"; datetime done)

PHP helper `td_dropzone(string $name, array $o = [])` in `php/td.php`, following the contract of the existing SSR
helpers (`td_datetime_picker` at php/td.php:4670 is the model: native mode by default, `['element' => true]` or
`Td::configure(..., ['ssr_elements' => true])` → custom-element markup; shared fixture between PHP and JS renderers;
node test in test/php + SSR hydrate browser test `src/form/td-dropzone.ssr.engines.browser-test.js` like
`td-datetime-picker.ssr.engines.browser-test.js`).
- Native mode: `<input type="file" name="…" accept multiple>` with label / hint: works with no JS, real form post.
- Element mode: `<td-dropzone …attributes…>` containing exactly the markup `td-dropzone.js` renders for an empty
  dropzone (docblock at td-dropzone.js:80-95), with the real `<input type="file">` inside, PLUS these
  no-JS-only native attributes on that input (absent from the JS render): `name`, `required`, `accept`, `multiple`
  (so the form posts and validates natively before upgrade). `canHydrate()` validates the BEM tree and accepts exactly
  these extra input attributes; on adoption the component takes ownership (ElementInternals form value + its own
  validity) and REMOVES `name` / `required` from the input (accept / multiple stay if the JS render keeps them).
- No-JS operability of element mode (before definition): the SSR input does NOT carry the JS render's
  `tabindex="-1"` / `aria-hidden="true"` (so these two are the other permitted differences), is labelled by the
  dropzone label + `aria-describedby` hint, and narrow `td-dropzone:not(:defined)` CSS (ADR 0012 point 6, in
  dropzone.css, CSSOM-free) shows the native input visibly and hides the JS-only "Chọn file" button. On adoption the
  component sets `tabindex="-1"` + `aria-hidden="true"` like its own render; the browse button works again. Tests:
  before define, the input is focusable by Tab, has an accessible name, the browse button is not displayed, native
  FormData has the files under `name` and `required` blocks submit; after define, the JS render's attributes are back. Hydrate in place per ADR
  0012: the file input is NEVER rebuilt (files the user picked before the upgrade stay; point 4/5), no `input` /
  `change` on hydrate, focus kept; mismatched markup → safe render while keeping the native input's files.
- Schema marker: element-mode markup carries `data-td-ssr="dropzone@1"` (PHP constant next to the other SSR schema
  constants, same pattern as datetime). `td-dropzone`'s `canHydrate()` (or the equivalent used by the SSR helpers'
  components) validates marker + structure + the attributes it renders before adopting; anything else → mismatch path.
- File state handoff (single owner of the field name): pre-upgrade, the native `<input type="file" name="…">` submits
  itself. On hydrate (valid markup) the component ADOPTS that input node (never rebuilt), reads its current `FileList`
  silently into the queue (rows rendered, no `input` / `change` / `files-change` events, no validation side effects
  beyond what a normal render shows), then removes the input's `name` and sets the FormData through
  `ElementInternals`, so the form has exactly ONE entry per file. Mismatch path: the same input node is moved into the
  safe render, same handoff. Focus on the input / choose button is kept. Tests use a REAL pre-upgrade FileList
  (DataTransfer → input.files before `customElements.define` / upgrade): valid hydrate and mismatch both assert same
  File objects in the queue, rendered rows, one FormData entry per file under `name`, no events fired, focus kept.
- Options → host attributes (verify each against `td-dropzone.js` observedAttributes / docblock; the agent STOPS if one
  does not exist): `name`, `id`, `label`, `hint` → `helper-text` (inherited field attribute), `accept`, `accept_label` →
  `accept-label`, `multiple`, `max_size` → `max-size`, `max_files` → `max-files`, `prompt_title` → `prompt-title`,
  `prompt_text` → `prompt-text`, `hint_style` → `hint-style`, `disabled`, `required`. Every rendering-affecting
  attribute is supported so the PHP and JS renders match; the shared fixture covers each. Escaping per
  docs/internal/security-model.md. No upload adapter on the server side.
- Docs: docs/components/dropzone.md (PHP section) + php/README.md helper list. ADR 0012 roadmap line: dropzone done.
- Gates: node test (php fixture parity), SSR browser test 3 engines, test:csp if CSS touched, check:dist.
