# v0.51.0 — Gallery: chú thích (caption) theo ảnh + giới hạn độ dài alt / caption cho `<td-media-gallery>`

## Nguồn

- **Owner duyệt 2026-10-06:** yêu cầu dsuite dưới đây thành bản v0.51.0, additive, không breaking. Branch
  `feat/v0.51.0-gallery-caption` từ `main` 48428e3 (= v0.50.0).
- **dsuite** (yêu cầu gửi kit, tóm tắt nguyên văn): caption theo từng ảnh (chữ thường, không HTML) gửi cùng item, được
  `trackFormDirty` theo dõi. Attribute `alt-maxlength` / `caption-maxlength` (mặc định tắt) đếm **code point sau khi
  trim**, JS và PHP đếm giống hệt. Gần giới hạn thì hiện bộ đếm. Vượt thì **chặn submit bằng lỗi inline, không cắt**. PHP
  helper tương đương + SSR / no-JS. Additive trong hình dạng hiện có.
  **Hợp đồng server của dsuite:** `alt_text` ≤ 255, `caption` ≤ 500 code point sau trim, `''` = null, vượt → **422**
  (server không bao giờ cắt). **Ngữ nghĩa khoá con (chốt với dsuite 2026-10-06, Codex plan-review r1 #1):** hàng
  **không có** `[caption]` = **giữ** caption đang lưu; `caption=''` = **null** (xoá). Bối cảnh: `dsuite/docs/05-FOUNDATION.md` L350 (`media_usages(…, alt_text, caption, …)`),
  L375 (`SelectedMedia.usage{altText, caption, crop, focalPoint}`); `dsuite/docs/06-TD-COMPONENTS-REQUESTS.md` L150
  ("gallery **chưa có caption** từng ảnh → dsuite giữ phần caption tự thêm"; "kit cho alt tới 500 → dsuite validate
  `max:255` (422)").
- **dsuite bổ sung (2026-10-06, đã chấp nhận):** caption có **hai chế độ**, cùng tên field `name[i][caption]`:
  - `caption` / `caption="line"` (mặc định): `<input type="text">` một dòng, không gõ được xuống dòng. Dán CR / LF / CRLF
    → gộp thành **một dấu cách**.
  - `caption="multiline"`: `<textarea>`, giữ `\n` (CRLF / CR → `\n`).
  - PHP `'caption' => true | 'line' | 'multiline'`. Giá trị khác → cảnh báo + coi như `'line'`.
  - Server dsuite đếm **sau khi gộp mọi chuỗi khoảng trắng thành một dấu cách rồi trim**. Kit đếm theo trim ECMAScript,
    **không gộp**, nên số kit đếm luôn **≥** số server đếm. Giữ luật của kit (an toàn một phía: kit không bao giờ cho qua
    một giá trị mà server sẽ 422 vì độ dài — trừ ca CRLF trên dây, xem QĐ 9).
- **Thiết kế đã hứa với dsuite** (giữ nguyên trừ khi có vấn đề cụ thể. Mọi lệch đều ghi ở "Quyết định owner", không âm thầm đổi):
  opt-in `caption` chỉ ở usage mode. ADR 0021 có phụ lục, không ADR mới, không đổi version hình dạng form. Caption = chữ
  thường, CRLF/CR → `\n`, `trackFormDirty` thấy (reason `'caption'`). Hai attribute giới hạn: bộ đếm từ ≥ 80 %, lỗi inline
  + `aria-invalid` + `aria-describedby`, `customError` qua ElementInternals, không cắt. Có trần cứng riêng cho caption.
  PHP `caption` / `alt_maxlength` / `caption_maxlength` + no-JS. Hợp đồng SSR không phá markup 0.43–0.50.
- **Kit (đọc ở `main` 48428e3):** `src/form/td-media-gallery.js` (1617 dòng), `src/utils/media-field-model.js`
  (`galleryEntries`, `validateItems`, `parseItems`, `encode/decodeGalleryState`, `GALLERY_CASES`), `php/td.php`

  `src/base/td-form-element.js`, `src/form/td-input-field.js` (bộ đếm `td-field__counter` có sẵn), ADR

  `name[i][caption]`, additive"), plan [v0.43.0-media-gallery](v0.43.0-media-gallery.md) (owner O1),
  `security-model.md` §6e, `design/touch.md`, `design/liquid-glass.md` (Minimal surfaces).

## Mục tiêu / Non-goals

**Mục tiêu:**
1. Caption theo từng ảnh (opt-in, usage mode), hai chế độ line / multiline, gửi `name[i][caption]` ngay sau
   `name[i][alt]`.
2. Giới hạn mềm `alt-maxlength` / `caption-maxlength`: bộ đếm, lỗi inline theo ô, chặn submit qua validity, **không cắt**.
3. Một luật chuẩn hoá + một luật đếm, JS ≡ PHP, chung một bảng ca.
4. PHP `td_media_gallery()` có đủ option, no-JS gửi đúng FormData, hydrate tại chỗ vẫn chạy.
5. Markup 0.43–0.50 vẫn hydrate tại chỗ, không bị render lại.

**Non-goals (v0.51):**
- Caption ở reference mode (`name[]=id` không có trường theo ảnh).
- Caption cho `<td-media-field>` (một ảnh).
- Rich text / markdown / link tự nhận diện trong caption.
- Textarea tự giãn chiều cao (`field-sizing: content` / CSSOM height).
- Đếm theo từ (`limit-type="word"` của `td-input-field`).
- Giới hạn tối thiểu (`minlength`).
- Chuẩn hoá lại alt (ký tự điều khiển, CR) — giữ hành vi 0.43, xem O3.
- Picker điền caption (picker không có ô caption. `usage.caption` chỉ được đọc nếu adapter / app đưa vào).
- Đổi `trackFormDirty` (không cần — QĐ 6).

## Quyết định đã chốt (owner uỷ quyền; O1–O6 đã chốt ở cuối plan)

**A. Hình dạng + FormData**

1. **Opt-in `caption` (JS attribute, PHP option `'caption'`), chỉ ở usage mode.**
   - Có `usage`: mỗi ô thêm một control caption. FormData theo thứ tự khoá: `name[i][id]`, `name[i][alt]`,
     **`name[i][caption]`**, `name[i][crop]` (+ `name[i][focal]`).
   - Không có `usage` (reference `name[]=id`): **bỏ qua `caption` + một cảnh báo** (JS `_warnOnce`, PHP
     `E_USER_WARNING`), giống luật hiện có của `croppable` / `focal-point` (`_usageOn()` L331–337, PHP L2803–2819). Lý do:
     reference mode không có chỗ cho trường theo ảnh. Tự chuyển sang usage sẽ đổi hình dạng form mà site không xin.
   - Không bật `caption` → FormData, markup, attribute `items`, state khôi phục **giống từng byte** v0.50 (gate hồi quy:
     fixture SSR cũ + mọi test v0.43 xanh nguyên).
   - **Ba trạng thái của khoá con** (chốt với dsuite, r1 #1), cùng tinh thần "vắng = giữ" của ADR 0021 ở cấp gallery:

     | Hàng `name[i]` gửi | Server dsuite |
     |---|---|
     | **không có** `[caption]` (gallery tắt `caption`, kit < 0.51, JS / PHP lệch phiên bản) | **giữ** caption đang lưu của asset ở chỗ dùng đó |
     | `[caption]=` (chuỗi rỗng, hoặc chỉ khoảng trắng sau trim) | **null** (xoá caption) |
     | `[caption]=<chữ>` | lưu chữ (sau trim), > 500 → 422 |

     Kit: tắt `caption` → **không bao giờ** gửi khoá `[caption]` (không gửi `''` thay). Bật → **luôn** gửi khoá, kể cả
     rỗng (người dùng xoá chữ = xoá caption). Không có trạng thái "bật nhưng không gửi".
   - **Không** ADR mới, **không** đổi version hình dạng form: ADR 0021 có **phụ lục v0.51** (QĐ 20). Lý do: ADR 0021 §5
     đã hẹn đúng cách này ("opt-in `caption` → `name[i][caption]`, additive").
   - Ngân sách biến form: 100 ảnh × 5 mục = 500 < `max_input_vars` 1000 mặc định của PHP (docs nêu lại).
2. **Hai chế độ** (bổ sung của dsuite):

   | Giá trị attribute (JS) | PHP `'caption'` | Chế độ | Control |
   |---|---|---|---|
   | vắng | vắng / `false` / `null` | tắt | — |
   | `""` (boolean), `"line"` | `true`, `'line'` | **line** | `<input type="text" class="td-field__control td-media-gallery__caption" maxlength="1000">` |
   | `"multiline"` | `'multiline'` | **multiline** | `<textarea class="td-field__control td-media-gallery__caption" rows="2" maxlength="1000">` |
   | khác (`"rich"`, `"2"`…) | khác (chuỗi lạ, số, mảng…) | **line** + một cảnh báo | như line |

   - Hai chế độ cùng tên field. Server không cần biết chế độ.
   - Đổi `caption` lúc chạy (bật / tắt / đổi chế độ) → render lại toàn bộ (`_doRender`, giữ focus như hiện có). Caption
     trong state được giữ (QĐ 3).
   - Mặc định là line. Lý do: caption sản phẩm thường một dòng, ô hẹp (2 cột ở 320 px). Multiline là lựa chọn của site.
3. **Chuẩn hoá caption — một hàm, JS ≡ PHP**, chạy ở **mọi lối vào state**: attribute `items`, `$items` của PHP, khôi
   phục form, `setSelection()` (`usage.caption`), picker (`usage.caption` nếu là chuỗi) và chữ người dùng gõ.

   `normCaption(s)` (JS, `media-field-model.js`) = `td__media_caption()` (PHP):
   1. Không phải chuỗi → `''`. PHP: UTF-8 hỏng → `''` (như alt / name qua `td__utf8_prefix`).
   2. CRLF, CR → LF.
   3. Bỏ C0 **trừ** `\t` và `\n`. Bỏ DEL (U+007F) và C1 (U+0080–U+009F, gồm U+0085 NEL).
   4. Cắt ở **trần cứng 1000 code point** (cắt, không từ chối — giống alt 500 hiện nay. QĐ 7).

   State luôn giữ dạng **multiline** đã chuẩn hoá. Chế độ chỉ là **phép chiếu** `captionValue(c, mode)`:
   - line → mỗi chuỗi LF liên tiếp thành **một** dấu cách;
   - multiline → giữ nguyên.

   Phép chiếu dùng cho: giá trị của control, FormData, bộ đếm, PHP in ra. Lý do tách: `validateItems` không phụ thuộc chế
   độ (bảng ca gọn), và đổi chế độ lúc chạy không mất dữ liệu.

   Chuyện gõ / dán:
   - **Không trim** giá trị gửi đi (server trim, `''` = null). Trim chỉ dùng để **đếm** (QĐ 9).
   - Ký tự định hướng / zero-width **giữ nguyên**: đó là chữ của người dùng, chỉ đi vào text sink (QĐ 4). Server muốn lọc
     thì tự lọc.
   - Chuẩn hoá áp vào **state**, không viết đè ngược vào control khi đang gõ (không nhảy con trỏ). Khác biệt duy nhất có
     thể có là ký tự điều khiển vô hình mà người dùng dán vào.
   - Ô line: trình duyệt đã bỏ xuống dòng khỏi `value` của `input[type=text]` (thuật toán sanitize của HTML; tiền lệ
     `td__js_length` L4480–4486). Riêng **dán** nội dung nhiều dòng: M0 đo trên 3 engine. Engine nào **xoá** xuống dòng
     (dính chữ "ab") thay vì thay bằng dấu cách → thêm handler `paste` chỉ cho ô caption line: `preventDefault` + chèn chữ
     đã chiếu bằng `execCommand('insertText')` để giữ undo và phát `input` thật. Nếu cả 3 engine đã thay bằng dấu cách thì
     không thêm code.
4. **Chỉ là chữ — text sink.**
   - JS: `render()` in control **rỗng**. Giá trị gán bằng property `.value` (như alt: `_syncAlt` L778–782). Nhãn, bộ đếm,
     lỗi đi qua `textContent` / `escapeHtml`. Không có nội suy `innerHTML` nào chứa caption.
   - PHP: `Td::e()`. Ô line in `value="…"`. Textarea in `"\n" . Td::e($caption)` ngay sau thẻ mở, theo tiền lệ `td_field`
     L4564. Parser HTML bỏ **đúng một** LF đầu, nên caption bắt đầu bằng xuống dòng vẫn còn nguyên.
   - `</textarea>` trong dữ liệu bị escape thành `&lt;/textarea&gt;` (test XSS).
5. **Event:** `input` mỗi lần gõ, `change` khi rời ô sau khi sửa, `detail.reason: 'caption'`. Event native của control bị
   chặn tại host, như alt: `_onAlt` (L802–814) tổng quát thành `_onText` cho cả `.td-media-gallery__alt` và
   `.td-media-gallery__caption`. Detail giữ hình `{ value, selection, reason }`.
6. **`trackFormDirty` không phải sửa.** Tracker nghe `input` / `change` ở **capture trên `document`**
   (`form-dirty.js` L261, `onUserChange` L214–225), trước listener capture của host. Nó so snapshot `new FormData(form)`
   (L143). Caption nằm trong FormData của internals, nên gõ caption → bẩn, xoá về như cũ → sạch. `value =` /
   `setSelection()` không phát event → không bẩn. Việc phải làm: **cập nhật test hợp đồng** (M3) + câu trong
   `form-validation.md` L257.
7. **Trần cứng caption = 1000 code point** (JS `GALLERY_CAPTION_MAX`, PHP `Td::MEDIA_GALLERY_CAPTION_MAX`).
   - Native `maxlength="1000"` trên control. Đơn vị là UTF-16, cùng cách với alt `maxlength="500"` hiện nay. Chặt hơn
     với ký tự astral, xem Rủi ro.
   - Lý do chọn 1000 (không phải 2000 như ví dụ trong yêu cầu — xem **O2**):
     - gấp đôi giới hạn 500 của dsuite;
     - giữ attribute `items` / state khôi phục trong trần **256 KiB** hiện có (`GALLERY_ITEMS_MAX_LEN` L311, PHP L2847):
       100 ảnh × 1000 = 100 k đơn vị UTF-16 cho caption BMP. Ở 2000 thì riêng caption đã có thể là 200 k (BMP) / 400 k
       (astral). `items` vượt trần là **fail closed** (gallery không dùng được);
     - chặn input không giới hạn (DoS DOM / FormData).

**B. Giới hạn mềm `alt-maxlength` / `caption-maxlength`**

8. **Attribute** (JS) / **option** (PHP `alt_maxlength`, `caption_maxlength`). Mặc định tắt.
   - **Parser nghiêm, một luật JS ≡ PHP** (Codex plan-review r1 #4; **không** dùng `Td::intOpt`, vốn lỏng hơn):
     `parseLimit(v, ceiling)` (JS, `media-field-model.js`) = `td__media_limit_opt($v, $ceiling)` (PHP):
     - JS chỉ nhận chuỗi attribute; PHP nhận `int` (không phải `bool`) **hoặc** chuỗi;
     - chuỗi phải khớp đúng `^[1-9][0-9]{0,6}$` (regex neo, PHP cờ `D`): không khoảng trắng, không dấu `+` / `-`, không
       số 0 đầu, không `.`, không số mũ, không hex, tối đa 7 chữ số (chặn số khổng lồ trước khi đổi kiểu);
     - giá trị (int hoặc chuỗi đã đổi) phải ∈ **1…ceiling** (`alt` 500, `caption` 1000);
     - **vắng** (JS: không có attribute; PHP: không có khoá / `null`) → tắt, **im lặng**;
     - mọi thứ khác → tắt + **một** cảnh báo (JS `_warnOnce` theo attribute, PHP một `E_USER_WARNING`, chỉ nêu tên
       option, không in giá trị).
     Bảng ca chung mới `test/ssr/media-limit.cases.json` (`{ input, ceiling, expect: number|null, warn }`), JS chạy các
     ca chuỗi, PHP chạy tất cả: `"255"` → 255; `"1"`; `"500"` (alt) → 500; `"501"` (alt) → null + warn; `"1000"` (caption)
     → 1000; `"0"`, `"0255"`, `" 255"`, `"255 "`, `"+255"`, `"-1"`, `"2.5e2"`, `"255.0"`, `"0x1F"`, `"1e3"`, `""`,
     `"abc"`, `"99999999"` (8 chữ số), `"9999999"` (> trần) → null + warn; PHP thêm: `255` (int) → 255, `0` / `-5` /
     `PHP_INT_MAX` → null + warn, `true` / `false` / `255.0` (float) / `[255]` / `'٢٥٥'` (chữ số Ả Rập) → null + warn,
     `null` → null, **không** warn.
   - `alt-maxlength` cần `usage`; `caption-maxlength` cần `caption` đang bật. Thiếu điều kiện → tắt + một cảnh báo.
   - Không kẹp: kẹp âm thầm sẽ đổi hợp đồng với server.
   - **Đổi lúc chạy — chọn: render lại khi *trạng thái bật thực tế* đổi** (Codex plan-review r1 #5). Định nghĩa
     `limitOf(field)` = số giới hạn hiệu lực hoặc `null`. Trong `attributeChangedCallback` của `alt-maxlength` /
     `caption-maxlength` (và của `usage` / `caption`, vốn đã render lại), so `limitOf` cũ với mới:
     - `null → số` (tắt → bật, kể cả sai → đúng) hoặc `số → null` (bật → tắt, kể cả đúng → sai): **`_doRender()`**;
     - `số → số khác` (đúng → đúng): **`_syncLimits()`** — chỉ đổi chữ bộ đếm (`{count}/{max}`), chữ lỗi (`{max}`),
       `hidden`, `data-state`, `aria-*`, validity. Không đổi cấu trúc, giữ identity `li` + focus;
     - `null → null` (vắng → sai, sai → sai khác): không làm gì ngoài cảnh báo.

     Lý do chọn render lại thay vì để `_syncLimits()` tạo / gỡ phần tử: phần tử bộ đếm / lỗi chỉ được tạo ở **một** chỗ
     là `render()` / `_itemHtml`, đúng cây PHP in và cổng hydrate so. Sau khi tắt, cây **giống từng byte** một gallery
     chưa từng bật, không cần chứng minh một đường DOM thứ hai. Đổi bật / tắt lúc chạy hiếm (cấu hình, không phải thao
     tác). `_doRender` đã giữ focus (`_focusInfo` / `_restoreFocus`) và state (chữ đã gõ nằm trong state sau mỗi
     `input`). Cái giá: luồng cắt ảnh đang mở bị huỷ (ISSUE-2 của v0.43, đã có test) — chấp nhận.
   - Dữ liệu server **đã vượt** giới hạn (alt 400 ký tự cũ, `alt-maxlength="255"`) → bộ đếm + lỗi hiện **ngay khi render**
     (JS và PHP như nhau), form không submit được tới khi sửa. Lý do: submit thì server cũng 422. Báo sớm tốt hơn.
9. **Luật đếm — một luật, JS ≡ PHP.** `limitCount(s)` = số **code point** của `s` sau **trim ECMAScript**.
   - JS: `[...s.trim()].length`.
   - PHP: `preg_match_all('/./su', preg_replace('/^[' . Td::JS_WS . ']+|[' . Td::JS_WS . ']+$/u', '', $s))`. `Td::JS_WS`
     ở L298 là đúng tập `String.prototype.trim`, đã có bảng ca `test/ssr/choice-label.cases.json`.
   - Áp lên giá trị **sau phép chiếu** (line: đã gộp LF). Alt đếm trên alt nguyên văn (alt không chuẩn hoá thêm, O3).
   - **Bảng ca chung mới** `test/ssr/media-text.cases.json`, chạy bởi node + PHP. Mỗi ca:
     `{ input, mode?, norm, line, count }`. Có các ca: U+180E / U+200B (không phải khoảng trắng ES → được đếm), U+0085
     (C1 → bị bỏ khỏi caption, nhưng được **đếm** trong alt), U+FEFF / U+3000 / U+00A0 ở hai đầu (bị trim), CRLF / CR /
     LF giữa chữ, chuỗi chỉ toàn khoảng trắng (đếm 0), ký tự astral (1 / ký tự), 1001 code point (cắt), surrogate lẻ (chỉ
     JS: 1 code point), UTF-8 hỏng (chỉ PHP → `''`).
   - **Khác `td-input-field`** (đếm UTF-16 `text.length`, `_countValue` L1004): có chủ đích, gallery theo hợp đồng dsuite (O5).
   - **So với server dsuite:** server gộp khoảng trắng rồi trim → số của server ≤ số của kit. Giữ luật của kit.
   - **Xuống dòng trên dây:** khi submit, trình duyệt chuyển LF → **CRLF** (bộ mã hoá urlencoded / multipart của HTML,
     áp cho cả textarea no-JS lẫn FormData của ElementInternals; M0 xác nhận trên 3 engine bằng harness PHP). Server đếm
     thô sẽ đếm mỗi xuống dòng **2**: caption 495 code point có 10 xuống dòng → kit "hợp lệ", Laravel `max:500` thấy 505
     → 422. dsuite gộp khoảng trắng nên an toàn. **Docs bắt buộc ghi:** chuẩn hoá CRLF → LF trước khi validate
     (`prepareForValidation`, mẫu Laravel + PHP thuần).
10. **Bộ đếm + lỗi inline theo ô.** Mỗi trường có giới hạn có **hai phần tử luôn có mặt**. Không thêm / gỡ DOM khi gõ, và
    `render()` = PHP là tất định.

    ```
    label.td-media-gallery__{alt|caption}-field > span.td-sr-only + control
    span.td-media-gallery__counter#{hid}-{i}-{alt|caption}-count [hidden] [data-state="limit"|"over"]   "{count}/{max}"
    span.td-media-gallery__error#{hid}-{i}-{alt|caption}-error [hidden]                                  altTooLong | captionTooLong
    ```

    - Bộ đếm **hiện** khi `count × 5 ≥ max × 4` (≥ 80 %, số nguyên, không sai số float). `data-state="limit"` khi
      `count = max`, `"over"` khi `count > max`.
    - Lỗi hiện khi `count > max`. Chữ **tĩnh theo trường** (không chứa số đếm), nên PHP và JS dễ khớp.
    - Control:
      - `aria-describedby` = id bộ đếm (khi hiện) + id lỗi (khi vượt);
      - `aria-invalid="true"` khi vượt;
      - không dùng `aria-errormessage` (hỗ trợ kém; `aria-describedby` là thứ đã hứa).
    - Id theo **vị trí**: `_relabel()` (L908–953) viết lại id + `aria-describedby` sau mỗi lần sắp / gỡ / thêm (rẻ, ≤ 100
      ô), như nhãn "Mô tả ảnh {n}". Lý do: PHP in theo vị trí, cổng hydrate so với `render()` theo vị trí.
    - Class riêng `td-media-gallery__counter` / `__error`, dùng **lại token màu** của `.td-field__counter` /
      `.td-field-error` (`field.css` L251–261). Không dùng chính class `.td-field-error`: hợp đồng lỗi của base tìm
      `.td-field-error` con trực tiếp của host (`ssrIsErrorNote`, `afterRender` L742) và lỗi của gallery (Add button)
      dùng class đó.
11. **Validity (chặn submit, không cắt).**
    - Ô vượt bất kỳ → `customError` (đúng như đã hứa) qua `_setValidity`.
    - Message = `tooLongItem` "Ảnh {n}: {message}" của ô **vượt đầu tiên** theo thứ tự hiển thị. Anchor = control đó
      (light DOM descendant, hợp lệ cho `ElementInternals.setValidity`; M0 xác nhận 3 engine). Bong bóng / focus khi
      submit rơi đúng ô.
    - Ưu tiên khi trùng: `rangeOverflow` > `valueMissing` > `rangeUnderflow` > `customError` (độ dài). `_syncForm()`
      L1010–1033 thêm nhánh cuối.
    - Ghép với `setCustomValidity()` của base không đổi (`_customMessage` riêng).
    - `disabled` / fail closed → không có validity (như hiện nay).
12. **Vượt giới hạn mềm vẫn GỬI FormData đầy đủ** (không cắt, không `setFormValue(null)`). Đây là chỗ **khác có chủ
    đích** với vượt `max` (QĐ 8 v0.43, gửi rỗng):
    - Vượt `max` mà gửi một phần → server **thay toàn bộ** → mất ảnh. Nên phải chặn ở tầng dữ liệu.
    - Vượt độ dài mà gửi đủ → server (dsuite) **422**, không mất gì.
    - Nếu ở đây gửi "không có key" thì server dsuite hiểu là "giữ nguyên" → lưu "thành công" nhưng âm thầm bỏ thay đổi.
      Tệ hơn.
    - `novalidate` / `form.submit()` / no-JS → server là chốt cuối (docs + security-model ghi rõ).
13. **Live region (lịch sự, có throttle).**
    - Dùng region `role="status"` sẵn có của gallery (`_announce` L1087–1092). Không thêm region mới. Không nói trong lúc
      controller sắp xếp đang nhấc (region của controller).
    - Chỉ đọc khi **dừng gõ 1000 ms** trong một trường có giới hạn **và** bộ đếm đang hiện.
    - Chữ: `limitLeft` "{field}: còn {n} ký tự." / `limitOver` "{field}: vượt {n} ký tự.", với `{field}` = nhãn của ô
      ("Chú thích ảnh 2").
    - Bỏ qua nếu trùng câu vừa đọc của cùng trường. Huỷ timer khi rời ô, gỡ ô, render lại, `disconnectedCallback`.
    - Không đọc theo từng phím. Lúc focus, mô tả (bộ đếm / lỗi) đã được đọc qua `aria-describedby`.

**C. State, API, nhãn**

14. **Item** thêm `caption: string` (đã chuẩn hoá, QĐ 3). Thay đổi:
    - `validateItems` / `td__media_gallery_items` đọc khoá `caption` (luôn chuẩn hoá, kể cả khi tắt).
    - `_newItem` / `_rawOf` (L375–385) mang theo `caption`.
    - `value =` giữ caption của id còn lại.
    - `setSelection()` đọc `s.usage.caption` (kiểu `UsageDraft.caption?: string` **đã có** ở `media-picker-core.js`
      L128–134).
    - Picker thêm: `sel.usage?.caption` nếu là chuỗi, ngược lại `''`.
    - `selection[i].usage.caption` = caption đã chiếu, **chỉ có khi `caption` bật**. Vắng khi tắt, để site / test
      `deepEqual` của 0.43–0.50 không đổi.
15. **State khôi phục:** `{"v":1,"items":[{"id","alt","crop","focal","caption"?}]}`. Đường dữ liệu chính xác (Codex
    plan-review r1 #3):
    - Chữ ký: `encodeGalleryState(items, { caption = false } = {})`. `caption: false` (mặc định) → **không bao giờ** ghi
      khoá `caption`, dù item có caption trong bộ nhớ (từ `items`, hoặc đã gõ rồi tắt) → **giống từng byte** v0.50 cho
      cùng id / alt / crop / focal. `caption: true` → ghi `caption` = **raw** `it.caption` (không phải phép chiếu, để xuống
      dòng sống qua khôi phục ở chế độ line) **luôn luôn**, kể cả `"caption":""`, sau khoá `focal` (Codex plan-review r2:
      bỏ khoá khi rỗng sẽ không phân biệt được "người dùng đã xoá caption" với "state cũ / đang tắt", và khôi phục sẽ hồi
      sinh caption đã xoá từ item cùng id). Khoá chỉ vắng khi `caption` tắt.
    - Lời gọi duy nhất: `_syncForm()` (L1023) đổi thành
      `this._setFormValue(fd, encodeGalleryState(this._items, { caption: this._captionMode() !== null }))`.
      `_captionMode()` = `'line' | 'multiline' | null` (null khi tắt hoặc thiếu `usage`). Nhánh fail closed (L1011–1015)
      giữ `setFormValue(null)` không state, như cũ.
    - `decodeGalleryState` nhận thêm `caption`: **khoá có mặt** (kể cả `""`) → đúng giá trị đó (chuỗi; sai kiểu → coi như
      vắng); **khoá vắng** → `undefined` (state cũ ≤ 0.50 hoặc ghi khi đang tắt). `_restoreState` (L1047–1056):
      - `caption !== undefined` → dùng nó (`""` = người dùng đã xoá → giữ rỗng, **không** lấy lại từ item cùng id);
      - `caption === undefined` → caption của item **cùng id** đang sống → `''`;
      - luôn qua `normCaption`. Nhờ vậy khôi phục khi đang tắt không xoá caption đã nạp từ `items` (bật lại vẫn còn).
      Vẫn `v:1`.
    - Test **từng byte** (M1 node + M3 trình duyệt đọc lại state qua `formStateRestoreCallback` giả):
      tắt + items có caption → chuỗi state = chuỗi v0.50 của cùng input (so với hằng chép từ output v0.50);
      bật line với caption `a\nb` → state chứa `"caption":"a\nb"` (raw); bật multiline; bật + caption rỗng → **có** khoá `"caption":""`; tắt → không có khoá;
      **gõ caption rồi tắt `caption`** → state không còn khoá `caption`, FormData không còn `[caption]` (= giữ ở server);
      **xoá → serialize → khôi phục** (r2), cho **line và multiline**: item `items` có caption `"Áo"` (line) / `"a\nb"`
      (multiline), người dùng xoá hết chữ → state chứa `"caption":""` → `formStateRestoreCallback(state)` trên gallery mới
      dựng từ cùng `items` → caption **rỗng** (không hồi sinh `"Áo"` / `"a\nb"`), FormData `[caption]=` (= null ở
      server); đối chứng: state cũ không có khoá → lấy caption cùng id.
    - Trần 256 KiB giữ nguyên: vượt thì state bị bỏ khi khôi phục (đã có: cảnh báo + giữ state hiện tại), không fail
      closed.
16. **`items` attribute** nhận khoá `caption` (chuỗi). PHP chỉ in `caption` vào JSON khi bật **và** khác rỗng (QĐ 1: byte

19. **Hợp đồng SSR giữ `media-gallery@1`** (không `@2`). Lý do:
    - Thay đổi là attribute + phần tử **opt-in**. Không bật thì markup giống từng byte 0.50, nên mọi markup 0.43–0.50 vẫn
      được JS mới **nhận tại chỗ**. Gate: fixture `test/ssr/media-gallery.fixtures.json` hiện có không đổi một ca nào và
      vẫn nhận tại chỗ trên 3 engine.
    - `@2` sẽ buộc JS chấp nhận cả `@1` lẫn `@2`, mà không mua thêm được an toàn gì: cổng vẫn so **từng node** với
      `render()`.
    - Lệch phiên bản (PHP 0.51 in caption, JS ≤ 0.50): `HOST_ATTRS` cũ từ chối → render an toàn từ `items` → **không gửi
      `[caption]`** → server dsuite **giữ** caption (r1 #1), không mất dữ liệu; chỉ là người dùng không sửa được caption
      tới khi JS cùng phiên bản. Ngược lại (JS 0.51, PHP ≤ 0.50): markup không có `caption` → không gửi khoá → giữ. Docs
      vẫn khuyên PHP + JS cùng phiên bản kit.

    Thay đổi cổng (`td-media-gallery.js`):
    - `HOST_ATTRS` (L25–26) + `caption`, `alt-maxlength`, `caption-maxlength`.
    - `_ssrSame` (L1553–1574):
      - control caption line xử lý như alt (L1556–1565): chỉ lần đầu mới cho thêm `name` / `value`;
      - textarea: chỉ lần đầu mới cho thêm `name` + **đúng một** text node bằng caption đã chiếu (vắng khi rỗng).
        Gắn lại (`first = false`) → textarea phải rỗng;
      - bộ đếm / lỗi so chính xác (attribute + text) như mọi phần khác.
    - `_ssrFormOk` (L1577–1612):
      - `expect` bỏ thêm khoá `[caption]` (là control, không phải hidden);
      - kiểm `name` / giá trị caption như alt (L1601–1604);
      - luật thứ tự (L1605–1609) thành: `value` < alt-field < caption-field < crop / focal.
    - **Giữ caption gốc, chỉ thay khi người dùng thật sự đã sửa** (Codex plan-review r1 #2). Ở chế độ line, control chỉ
      chứa **phép chiếu** (`a\nb` → `a b`). Nếu đọc ngược control vào state thì xuống dòng của caption gốc (từ `items`)
      bị phá — đổi sang multiline sau đó sẽ thấy `a b` thay vì `a\nb`. Luật chung `_liveCaption(it, control)`:
      - `expected = captionValue(it.caption, mode)` (it lấy từ attribute `items`, raw);
      - `control.value === expected` → **giữ `it.caption` raw** (không đụng state);
      - khác → người dùng đã gõ trước khi define → `it.caption = normCaption(control.value)`.

      Áp ở **cả hai** nhánh:
      - `hydrateExisting` (L1484–1502), nhánh nhận: theo luật trên. Gán `.value = expected-hoặc-chữ-đã-gõ` (đánh dấu
        dirty) **trước**, rồi mới gỡ `name` + `value` / nội dung textarea. Sau cùng `_syncLimits()`: chữ gõ trước define
        có thể đổi số đếm, nên tính lại sau khi nhận, không phải lý do để từ chối.
      - `canHydrate` (L1446–1474) → `_restoreSsrState` (L1505–1518), nhánh từ chối: map `captions` (theo id item) **chỉ
        chứa các ô mà control khác `expected`** (đã sửa thật). Ô chưa sửa → state giữ raw từ `items`. Như alt nhưng có
        phép so với giá trị chiếu.
    - Cũng luật đó ở đường người dùng: `_onText` chỉ ghi state khi có event `input` thật, và `_commit` / `_syncCaption`
      ghi control từ state (một chiều state → control), không bao giờ đọc ngược khi không có event.

**E. Giao diện, cảm ứng, responsive**

20. **Bố cục + Minimal surfaces:**

    - Phím mũi tên / Enter trong textarea không bị controller cướp: controller chỉ nghe trên tay nắm.
