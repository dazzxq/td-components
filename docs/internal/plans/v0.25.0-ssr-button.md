# v0.25.0 — SSR hydrate tại chỗ: base lifecycle + td-button / link + lưới CSS + modulepreload + badge icon

Theo [ADR 0012](../decisions/0012-ssr-hydration.md) (Codex think-about CONSENSUS). Owner: "cứ làm hết cùng codex"; đề xuất
135 (FOUC `td-button`, `td_badge` icon). Không dependency mới; API công khai tương thích ngược.

## S1 — Base lifecycle (`src/base/td-base-element.js`)

- Hook mặc định `canHydrate() → false`, `hydrateExisting() → void`. Trong `connectedCallback` lần đầu (sau
  `_setupProperties` + replay property sớm): nếu `canHydrate()` → `hydrateExisting()` (không đụng `innerHTML`) rồi
  `afterRender()` + `_applyStyles?.()`; ngược lại `_doRender()` như cũ. Đánh dấu `_hydrated` (gỡ `data-td-ssr` sau khi
  nhận để lần render sau không nhầm). **Đổi có chủ ý vòng đời gắn lại:** hiện base **render lại** khi gắn lại
  (`_needsRebind` → `_doRender`). Với component **khai báo hydrate được** (`static hydratable = true` — v0.25 chỉ
  `TdButton`), gắn lại gọi bước gắn chung (`afterRender()` + `_applyStyles?.()`) **không** gán `innerHTML` (giữ identity
  node, focus); component khác **giữ nguyên** hành vi render lại. Listener không nhân đôi vì disconnect đã chạy
  `_cleanups`. Test base: TdButton gắn lại giữ node + listener chạy đúng một lần; một subclass không hydratable vẫn render
  lại như cũ (test hiện có còn xanh).
- Helper dùng chung `ssrMarker(el)` → `{ name, schema }` hoặc null; so khớp `name === <tag>` và `schema === <SCHEMA>`.

## S2 — `<td-button>` / link hydrate

- `TdButton.SSR_SCHEMA = 1`. `canHydrate()`: dấu `button@1` + con trực tiếp duy nhất là `<button class="td-btn …">`
  (hoặc `<a class="td-btn …">` khi host có `href`), có `.td-btn__spinner`, nhãn `.td-btn__label` hoặc icon hợp lệ. **Chính sách
  đối chiếu từng thuộc tính** (đọc host **sau** replay property sớm và mọi attribute đổi trước khi define):
  - **Cấu trúc — phải khớp, lệch → từ chối hydrate, render như cũ:** loại control (`<a>` ⇔ host **có thuộc tính `href`** —
    tính hợp lệ của URL chỉ quyết định `<a>` có `href` điều hướng được hay không, như hiện nay; ngược lại `<button>`);
    `target` / `download` (link) là **cấu trúc** — lệch so với control → từ chối hydrate, render; class `td-btn--{variant}` / `td-btn--{size}` / `td-btn--full` khớp
    `variant` / `size` / `full-width` đã chuẩn hoá; có / không icon + vị trí (`icon`, `icon-position`) và tên icon; có /
    không `.td-btn__label` và text của nó = `_getButtonText()`; `type` (button) khớp; `color` / `text-color` (custom) —
    PHP không in → host có thì từ chối.
  - **State — đối chiếu tại chỗ bằng `_syncState()` (đã có):** `loading`, `disabled`, `name`, `value`, `aria-label`,
    `aria-pressed` / `aria-expanded` / `aria-haspopup` / `aria-controls`, giá trị `href` (khi vẫn là link — `_syncState`
    đã gán lại / gỡ `href` theo disabled / loading / URL hợp lệ), spinner `hidden`.
  Không phát sự kiện. Test: markup PHP nguyên vẹn; đổi `variant` / `label` / `icon` trên host **trước define** → từ chối và
  render đúng; đổi `loading` / `disabled` / `aria-pressed` trước define → hydrate + đúng state; gán property sớm
  (`el.loading = true` trước define) → đúng.
- **Không đổi gì** cho `<td-button>` tạo bằng JS hoặc host in tay không dấu.

## S3 — PHP `td_button()` / `td_link()` chế độ element

- Element mode là **opt-in, mặc định vẫn in native như cũ**: option mới `'element' => true|false` (ghi đè) +
  `Td::configure($base, $dir, ['ssr_elements' => true])` (tham số thứ 3 tuỳ chọn; mặc định `false`; chỉ ảnh hưởng helper đã có contract: v0.25 = `td_button`, `td_link` không `bare`).
- Chế độ element in: `<td-button data-td-ssr="button@1" variant=… size=… [disabled] [loading] [name value] [href target
  download] [aria-*] …>` + **đúng subtree** JS sẽ tạo (`<button type=… class="td-btn td-btn--{variant} td-btn--{size}
  …" [name value disabled aria-*]>{icon?}<span class="td-btn__label">…</span><span class="td-btn__spinner …"
  hidden>…</span></button>` hoặc `<a class="td-btn …" href=…>…</a>`). Thuộc tính host **phát tường minh** (PHP mặc
  định `secondary` ≠ JS mặc định `primary` → in `variant` luôn). Không-JS: nút native hoạt động đầy đủ (submit, link).
- `td_link(…, ['bare' => true])` không đổi (không có element mode).
- **Bảng chiếu host ↔ control** (mọi option hiện có của `td_button` / `td_link`; test parity phủ hết):

  | Option PHP | Host `<td-button>` | Control `<button>` / `<a>` (không-JS) |
  |---|---|---|
  | label | `label` | `.td-btn__label` text |
  | variant / size / full_width | `variant` / `size` / `full-width` (luôn in variant) | class `td-btn--…` |
  | icon / icon_position | `icon` / `icon-position` | icon SVG trong control |
  | type | `type` | `type` |
  | name / value | `name` / `value` | `name` / `value` (submitter) |
  | disabled | `disabled` | `disabled` (button) / không `href` + `tabindex=-1` + `role=link` + `aria-disabled` (link) |
  | loading | `loading` | như hiện nay: `disabled` + `aria-busy` + `aria-disabled` (button) / không `href` (link), spinner hiện |
  | aria_label | `aria-label` | `aria-label` |
  | tooltip | — | `data-tooltip` (như hiện nay) |
  | href / target / download (link) | `href` / `target` / `download` | `href` (đã lọc URL) / `target` + `rel` / `download` |
  | id | `id` (component API) | — |
  | class | `class` (site) | — (class kit trên control) |
  | attrs | — | lên control như hiện nay (allowlist); key trùng option → option thắng (như hiện nay) |
  | aria-label (qua attrs) + aria-pressed / -expanded / -haspopup / -controls (qua attrs) | được **nâng lên host** khi element mode (JS chuyển xuống như v0.19 / `aria-label` như hiện có) | cũng in trên control (không-JS) |

- Escape + allowlist như hiện tại.

## S4 — Lưới an toàn CSS

`td.css`: `td-button:not(:defined):not([data-td-ssr])` → `display: inline-block; min-height: 2.5rem` (khớp `.td-btn` md;
`[size="sm"]` 2rem, `[size="lg"]` 3rem), không giả style nút. `td-input-field`, `td-toggle`, `td-checkbox`,
`td-dropdown` cùng mẫu `:not(:defined):not([data-td-ssr])` → `display` + chiều cao giữ chỗ cụ thể (field / dropdown
`min-height: 2.5rem`, toggle / checkbox `min-height: 1.5rem`). Test: đo `getBoundingClientRect().height` của host in tay
**trước** define bằng giá trị trên; host có `data-td-ssr` không bị áp.

## S5 — `Td::modulePreloads(array $names)`

Nhận tên export (`'button'`, `'@dazzxq/td-components/button'`), phân giải qua cùng bản đồ import map (theo phiên bản đã
configure), khử trùng, **ném** `InvalidArgumentException` với tên lạ, trả chuỗi `<link rel="modulepreload" href="…">`
(escape). Docs: thứ tự stylesheet → import map → modulepreload → entry module ngoài; chỉ là tối ưu.

## S6 — `td_badge($label, ['icon' => 'name'])`

In `<span class="td-badge__icon" aria-hidden="true">{svg size s}</span>` trước `<span class="td-badge__label">…</span>`
(label escape như cũ). Icon qua registry PHP (core + alias + `site-*` đã `registerIcons`); tên lạ → **bỏ icon, giữ
label đã escape** (không span icon rỗng) — giống `td_icon()` hiện trả chuỗi rỗng cho tên lạ. CSS `.td-badge__icon` cỡ `1em`, `flex: none`. JS: CSS-only badge không có JS — chỉ PHP + CSS.

## Test

- **Fixture dùng chung** `test/ssr/button.fixtures.json`: ma trận variant × size × icon (trái / phải / không) × disabled ×
  loading × href / target / download × name / value × aria × global on/off × per-call absent/false/true. Test PHP
  (`test/php`) in markup từ fixture; test browser nạp **đúng markup PHP sinh ra** (file sinh sẵn trong test) rồi
  `customElements.define` muộn (import động sau khi đo):
  - DOM cấu trúc / class / thuộc tính sau hydrate **bằng** `render()` JS cho cùng attribute (chuẩn hoá thứ tự thuộc tính);
  - bounding box host + control trước / sau define lệch 0 (và không có `layout-shift` entry);
  - node `<button>` / `<a>` giữ identity; focus trên nút trước define vẫn nằm đúng node sau define;
  - Dữ liệu form trước = sau: `new FormData(form, submitBtn)` **chỉ** với nút `type="submit"` đang bật (submitter hợp lệ,
    có `name=value`); nút `type="button"` → so `new FormData(form)`; link → kiểm `href` / điều hướng + trạng thái inert
    (disabled / loading). Nút `loading`: không-JS = native `disabled` (như hiện nay); sau hydrate chuyển sang hợp đồng JS hiện có
    (`aria-busy` + `aria-disabled`, click bị chặn, **không** `disabled` native) — được phép, test khẳng định đúng từng
    trạng thái chứ không so FormData; không-JS (không define) submit form / mở link hoạt động;
  - dấu sai schema / thiếu spinner / cấu trúc lạ → render lại (không lỗi); host in tay không dấu → như cũ;
  - đổi attribute sau hydrate (variant, loading, disabled, aria-pressed) cập nhật đúng; gỡ + gắn lại không nhân đôi listener.
- `:not(:defined)` placeholder: host in tay không dấu có chiều cao giữ chỗ trước define.
- `Td::modulePreloads`: URL đúng phiên bản, khử trùng, tên lạ ném lỗi, escape.
- `td_badge` icon: core, alias, `site-*`, tên lạ → chỉ label (không span icon rỗng); snapshot markup; contrast icon trong badge (gate).
- **3 engine:** các test hydrate SSR chạy trên Chromium, Firefox **và** WebKit — thêm group web-test-runner riêng
  (`*.ssr.browser-test.js`, 3 launcher Playwright) vào lệnh `test:browser` (nằm trong `npm test`).
- CSP: state `td-button.ssr` (markup PHP) + baseline; `npm test` đầy đủ.
