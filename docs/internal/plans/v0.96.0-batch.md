## Busy helper — chốt với Codex (think-about sol/high, 2 vòng, đồng thuận 04/11)

Owner hỏi có tối ưu nhất chưa (chấp nhận sửa hàng trăm nút). Kết luận: KHÔNG cần sửa markup nút; site chỉ thay hàm setBusy tự chế.
- API đúng hai hàm: `setButtonBusy(target, busy)`, `runWithButton(target, fn)` (nhận `button.td-btn`, `a.td-btn`, host `<td-button>`;
  sai kiểu → TypeError). `td-button` setLoading / run và hai hàm này đi qua MỘT hàm nội bộ `syncButtonState()`.
- Busy = `aria-busy` + `aria-disabled`, KHÔNG `disabled` gốc (giữ focus, giữ name=value của nút gửi form). Link: tabindex 0 trước khi bỏ
  href, role=link, ảnh chụp trong WeakMap, trả href trước tabindex.
- Chặn bấm: MỘT listener capture mỗi document (WeakSet<Document>), cài lười trong `syncButtonState()` lần đầu vào busy (cả đường
  `<td-button loading>`); bỏ guard riêng của td-button sau khi có test.
- Spinner: dùng `.td-btn__spinner` sẵn có (PHP đã in cho nút thường); markup viết tay thiếu thì tạo một lần bằng createElement(NS).
- Sửa a11y: lúc busy nhãn / icon dùng `opacity: 0` thay `visibility: hidden` (visibility làm mất tên đọc của nút).
- runWithButton: busy trước fn, promise đang chạy lưu WeakMap (gọi lại trả cùng promise), finally luôn gỡ.
- Docs: mẫu AJAX (`event.submitter`, `new FormData(form, submitter)` trong runWithButton) + công thức submit thường + bfcache (`pageshow.persisted`), ghi rõ giới hạn; server vẫn phải idempotent.
- KHÔNG làm: bắt buộc `<td-button>`, `data-td-busy-on`, live region mỗi nút, option PHP, quét trang. Spinner bằng `::after` (bỏ 4 nút DOM mỗi nút) = mục roadmap riêng, cần benchmark, đổi hợp đồng SSR.
