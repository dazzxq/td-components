# v0.52.0 — `<td-toggle>` `tone` + `locked`, `<td-choice-group variant="segmented">`

## Nguồn

- **dsuite, màn Users — cột 2FA** (owner duyệt 2026-10-06). Mirror hành vi dcms2 (chỉ đọc, tham chiếu):
  `dcms2/resources/js/modules/dcms-users.js` ~547–600 (render ô 2FA) và ~2129–2216 (`enableOtp` / `disableOtp`):

Ràng buộc: additive, không breaking; không dependency mới; light DOM; CSP strict (màu chỉ qua token / CSSOM sẵn có);

tự đúng); SSR `toggle@1` / `choice-group@1` **giữ số schema** (thuộc tính thêm là additive; markup không dùng tính năng
mới phải **giống từng byte** v0.51).

## Mục tiêu

1. `<td-toggle tone="success|warning">`: màu rãnh khi **bật** theo ngữ nghĩa, đạt ≥ 3:1 (rãnh vs trang, núm vs rãnh, icon
   vs núm) ở sáng + tối + palette sinh; **không chỉ bằng màu**: icon trên núm đổi hình (✓ / đồng hồ) + chữ trạng thái ẩn
   trực quan gắn `aria-describedby`, ghi đè được bằng `status-text`.
2. `<td-toggle locked locked-reason="…">`: trạng thái **không đổi được** (bật hoặc tắt — giữ nguyên trạng thái hiện có) có
   icon khoá, lý do qua `aria-describedby`, vẫn **focus được**, vẫn **submit** giá trị, không bao giờ phát `change`,
   `commit()` bị bỏ qua.
3. `<td-choice-group variant="segmented">`: thanh chọn một giá trị dạng viên thuốc (icon + nhãn, hoặc chỉ icon có tên truy
   cập), ngữ nghĩa radiogroup (ADR 0023), form-associated, ô bằng nhau, `size` sm / md / lg, chạm ≥ 44px; đủ cho công tắc
   theme Tự động / Sáng / Tối.
4. Docs: công thức 2FA (controlled + xác nhận + OTP + `commit`), công thức theme switcher (`data-td-theme` + cookie + PHP).
5. PHP parity: `td_toggle` (`tone`, `status_text`, `locked`, `locked_reason`), `td_choice_group` (`variant => 'segmented'`,
   `size`, `icon_only`, option `icon`); SSR hydrate tại chỗ, **không nháy trước nâng cấp**.
6. Definition of done của kit: test Node + 3 engine, bàn phím / ARIA, CSP, contrast, page-contrast, golden, responsive,
   touch, SSR + no-JS, docs tiếng Việt + story, CHANGELOG.

## Không làm (non-goals v0.52)

- toggle: `tone="danger|info"` (không có ca dùng; thêm sau là additive), chữ trạng thái **hiển thị** cạnh công tắc (Q3),
  chữ trạng thái khi **tắt**, tooltip tích hợp / API tooltip mới (QĐ 8), `locked` cho `td-checkbox` (lớp chung có sẵn
  đường, nhưng không có ca dùng — backlog), đổi màu mặc định `--td-switch-on`, đổi `commit()`.
- segmented: **thanh trượt có animation** (cần đo + CSSOM như td-tabs; viên thuốc tĩnh mỗi ô là đủ), chế độ cuộn ngang khi
  tràn, chọn nhiều, `hint` / `swatch` / `image` hiển thị trong ô (xem QĐ 13), `size` cho `variant="button|swatch"`,
  component chuyển theme riêng / API theme mới (chỉ công thức docs).
- Không đổi `td-tabs`, không đổi dsuite / 135.

## Quyết định

### A. `<td-toggle>` — `tone`

**QĐ 1 — `tone="success|warning"`, chỉ tô trạng thái BẬT.** Không có / giá trị lạ → như hiện nay (rãnh `--td-switch-on`
#16a34a, núm trắng) — **không** có giá trị `neutral` công khai (mặc định đã là xanh lá, gọi "neutral" sẽ sai nghĩa; thêm
`tone` vào thì mặc định vẫn là "không tone"). Khi **tắt**: rãnh xám như cũ bất kể `tone` ⇒ luồng 2FA không cần gỡ `tone`
khi quay lại, và `commit()` thất bại khi bật chỉ cần trả `checked` (tone tự "tắt" theo).

**QĐ 2 — Màu chỉ từ hợp đồng theme (generator-safe), không literal.** Token component mới (khối
`:root, [data-td-theme]` để re-resolve theo vùng, `src/styles/tokens.css` cạnh `--td-switch-*`):

| Token | Giá trị | Ghi chú |
|---|---|---|
| `--td-switch-on-success` | `var(--td-color-success)` | sáng #15803d: 4.8:1 vs `--td-color-bg` · tối #22c55e: 8.3:1 vs #111113 |
| `--td-switch-on-warning` | `var(--td-color-warning)` | sáng #b45309: 4.8:1 · tối #f59e0b: 8.8:1 |
| `--td-switch-thumb-tone` | `var(--td-color-on-status)` | sáng #fff trên status: ~5.0:1 · tối #111113 trên status: ≥ 8:1 |
| `--td-switch-thumb-on` | `var(--td-switch-thumb)` | núm khi bật (mặc định = núm thường; tone đặt lại) |

Lý do: palette generator (`src/theme/palette.js:414–446`) **đã** giải `--td-color-{success,warning}` ≥ 4.7 (GATE.text) trên
mọi bề mặt + nền popup và `--td-color-on-status` ≥ 4.7 trên từng màu status ⇒ mọi palette sinh / theme vùng tự đạt
≥ 3:1 cho rãnh-vs-trang và núm-vs-rãnh **không cần** thêm vào `SCHEME_TOKENS` hay `THEME_TOKENS`. Không dùng
`--td-solid-warning-bg` (#f59e0b ở **cả** sáng: 2.15:1 trên trắng — trượt). Hệ quả có chủ đích: ở **tối**, núm của
công tắc có tone là **núm tối** (#111113) trên rãnh sáng — xem Q1.

CSS (`src/styles/components/switch.css`, chỉ selector thuộc tính host — chạy **cả trước nâng cấp** vì PHP in `tone` lên
host):

```css
td-toggle[tone="success"]:not([color]) { --td-switch-on: var(--td-switch-on-success); --td-switch-thumb-on: var(--td-switch-thumb-tone); }
td-toggle[tone="warning"]:not([color]) { --td-switch-on: var(--td-switch-on-warning); --td-switch-thumb-on: var(--td-switch-thumb-tone); }
.td-switch__input:checked + .td-switch__track .td-switch__thumb { background: var(--td-switch-thumb-on); }
```

Icon ✓ trên núm đã tô `--td-switch-on` (switch.css:122–125) ⇒ icon = màu status trên nền on-status (≥ 4.7, ≥ 3 cần).

**QĐ 3 — `color` thắng phần MÀU; `tone` vẫn cho chữ + icon.** `color` (CSSOM inline trên host, `_applyColor`
td-checkable-element.js:112) vốn thắng mọi rule stylesheet; rule tone thêm `:not([color])` để **không** đổi núm khi site
tự chọn màu (núm on-status trên màu lạ có thể trượt). Thứ tự: `color` (riêng phần tử) > `tone` > token mặc định. Docs:
khuyên dsuite **bỏ `setColor()`**, dùng `tone`. `color` không hợp lệ (safeColor từ chối) nhưng có attribute → rule tone
vẫn tắt (do `[color]`) → về mặc định xanh: chấp nhận, ghi docs ("đừng đặt cả hai").

**QĐ 4 — Không chỉ bằng màu (WCAG 1.4.1 + 4.1.2):**
- **Hình:** `tone="warning"` → icon BẬT trên núm là `clock` (đồng hồ — "đang chờ") thay ✓; `success` giữ ✓. Người mù
  màu thấy khác hình; forced colors vẫn thấy (QĐ 11).
- **Chữ cho trình đọc màn hình:** `span.td-switch__status.td-sr-only#{hostId}-status`, **anh em sau `label`** trong host
  (không nằm trong `<label>` — nằm trong thì chữ nhập vào **tên** của switch). Input mang `aria-describedby` → id đó **chỉ
  khi đang bật** (qua hook `_describedByIds()` td-form-element.js:337 → `_syncDescribedBy()` :346, giữ id của trang).
  Chữ = `status-text` nếu có, không thì `TdToggle.messages.statusSuccess` / `statusWarning` (mặc định đề xuất "Đã xác nhận"
  / "Đang chờ" — Q2). `status-text` cũng dùng được **không** cần `tone` (mô tả khi bật cho toggle thường).
- Chữ mặc định từ `messages` là **trạng thái** (như "Hết hàng" của choice-group v0.49 QĐ 22): không so khi hydrate, áp lại
  ở `afterRender()` ⇒ site đổi `messages` không làm hỏng việc nhận tại chỗ. `status-text` của site: so như attribute.

**QĐ 5 — Đổi `tone` / `status-text` lúc chạy = vá tại chỗ, không render lại.** Luồng 2FA đổi `tone` ngay sau `commit()`
trong khi input **đang focus** ⇒ không được thay node. `attributeChangedCallback` của toggle: `tone` → đổi
`data-td-icon` của `.td-switch__icon--on` (`check` ↔ `clock`) + `fillIconSlots` riêng slot đó, thêm / gỡ span status;
`status-text` → `textContent`; `checked` → `_syncDescribedBy()`. Sau vá, DOM **bằng** `render()` của thuộc tính hiện tại
(kiểm trong test: so với render mới).

### B. `<td-toggle>` — `locked`

**QĐ 6 — `locked` = đóng băng trạng thái HIỆN TẠI (bật hoặc tắt), không phải `disabled`.** Không có biến thể
"locked-on" riêng: khoá chỉ là "người dùng không đổi được", trạng thái do server / code đặt (owner yêu cầu "tối giản").
Ca chính là bật-và-khoá (chính sách bắt buộc 2FA); khoá-khi-tắt hoạt động y hệt, docs nhắc `required` + khoá-tắt = form
không bao giờ hợp lệ (lỗi cấu hình của app).

| | `disabled` | `locked` |
|---|---|---|
| Focus / Tab | không | **có** (input không `disabled`) |
| Submit / FormData | không | **có** (`_syncForm` không đổi) |
| Validity | bỏ qua | tính như thường |
| Bật / tắt bằng chuột, chạm, Space, `<label>` | không | **không** |
| `change` | không | **không bao giờ** |
| `commit()` | (không ai gọi) | **bỏ qua**: trả `Promise.resolve(trạng thái hiện tại)`, `fn` không chạy, không event |
| Code: `checked = …` / `setAttribute` / `form.reset()` | được | **được** (khoá là UI; app vẫn điều khiển) |
| Hình | mờ 0.5 | **không mờ**, icon khoá trên núm, con trỏ `not-allowed`, không hover / hình nhấn |
| ARIA | `disabled` | `aria-readonly="true"` trên input + `aria-describedby` → lý do |

Ưu tiên: `disabled` (host hoặc fieldset) > `locked` > pending `commit()` > `controlled`. `locked` + `controlled`: không
phát `change`. Đặt `locked` khi `commit()` đang chờ: lần commit đó chạy hết (kể cả quay lại khi lỗi — code, không phải
người dùng), khoá áp cho thao tác sau.

**QĐ 7 — Cơ chế chặn = đường `_onInputClick` sẵn có** (td-toggle.js:145): nhánh `locked` đặt **đầu tiên**:
`preventDefault()` + đồng bộ lại `input.checked` ở `setTimeout(0)` (đúng mẫu nhánh pending :146–152). Space trên checkbox
sinh `click` ⇒ một chỗ chặn cho chuột / chạm / phím / `<label for>` ngoài. Không dùng `readonly` (vô hiệu với checkbox).
`aria-readonly` hợp lệ cho `role="switch"` (ARIA 1.2: kế thừa từ `checkbox`) — spike M0 kiểm nó được xuất ra cây trợ năng
3 engine; nếu một engine bỏ qua thì vẫn còn lý do trong mô tả (không chặn phát hành).
- **Lý do:** `span.td-switch__lock-reason.td-sr-only#{hostId}-lock` (anh em sau status), chữ = `locked-reason` hoặc
  `messages.locked` ("Không thể thay đổi"); luôn trong `aria-describedby` khi `locked`.
- **Icon khoá:** `span.td-switch__icon.td-switch__icon--lock[data-td-icon="lock"]` thêm vào **núm** (sau icon on) khi
  `locked`; CSS `td-toggle[locked]` ẩn icon on / off, hiện khoá (màu: bật → `--td-switch-on` như ✓; tắt →
  `--td-control-muted` như ✕). Khoá thắng đồng hồ của `warning` (chữ trạng thái vẫn đọc được) — ghi docs.
- `locked` / `locked-reason` đổi lúc chạy = **vá tại chỗ** như QĐ 5.

**QĐ 8 — Tooltip: không API mới.** Touch luật 10 (`docs/internal/design/touch.md:19`): tooltip không bật khi chạm, không
đặt thông tin bắt buộc trong tooltip. Thông tin bắt buộc đã có đường không phụ thuộc tooltip: hình icon (✓ / đồng hồ /
khoá) cho mắt, `status-text` / `locked-reason` cho trình đọc màn hình. Tooltip chỉ là **phần thêm** cho chuột / bàn phím:
docs dùng `data-tooltip` sẵn có **trên host `<td-toggle>`** (thay vì `div` bọc như dcms2) cùng nội dung với `status-text`.
Spike M0 kiểm: tooltip hiện khi rê host **và** khi focus bàn phím vào input bên trong; mô tả tooltip (gắn lên host, không
phải control được hỗ trợ — `tooltip.md` "Chính sách tên truy cập") **không** đọc lặp. Nếu spike thấy tooltip không hiện khi
focus input → ghi docs "dùng `title`/`data-tooltip` chỉ cho chuột" — vẫn không thêm API. Màn hình chạm: docs khuyên dsuite
hiện trạng thái bằng chữ / badge trong hàng (Q3).

**QĐ 9 — busy / snap-back: không API mới, chỉ công thức.** `commit()` đã đủ cho 2FA (kiểm theo đoạn dcms2):

```js
t.addEventListener('change', async (e) => {          // <td-toggle controlled tone="warning|success" …>
  if (e.detail.checked) {                            // BẬT: lạc quan, tone cam ngay (chưa xác minh)
    t.tone = 'warning'; t.statusText = 'Chờ người dùng quét mã QR khi đăng nhập';
    t.commit(() => api.post(`/users/${id}/totp/enable`).then((r) => r.ok));
    return;
  }
  const ok = await TdModal.confirm({ title: 'Tắt xác thực 2FA', confirmText: 'Tắt 2FA', confirmVariant: 'danger', … });
  if (!ok) return;                                   // controlled: công tắc chưa đổi → không cần "revert"
  t.commit(() => fetchWith2FA(`/users/${id}/totp/disable`, …).then((r) => r.ok)); // OTP step-up: otp-input.md mục 6
});
t.addEventListener('commit-error', () => toast.error('Không lưu được'));
```

Đã kiểm khoảng trống: (a) "đổi màu trước await" → `tone` đặt trước `commit()`, `commit` đổi `checked` đồng bộ
(td-toggle.js:111) ⇒ cùng tick, không nháy xanh; (b) hủy xác nhận → controlled nên không đổi (không cần `_revertToggle`);
(c) thất bại → `commit` tự quay lại + `commit-error`; (d) đang chờ → bấm thêm bị bỏ qua (:146). **Không thấy gap** → không
API mới. Tooltip của dcms2 ("Đã bật 2FA — chờ…" / "2FA đã thiết lập — …") → `status-text` + `data-tooltip` cùng chữ.

### C. Chung cho toggle

**QĐ 10 — SSR `toggle@1` additive + không nháy trước nâng cấp.**
- `render()` chỉ thêm phần mới khi thuộc tính có mặt ⇒ toggle không `tone` / `status-text` / `locked` render **giống từng
  byte** v0.51 (golden fixture cũ `test/ssr/form.fixtures.json` không đổi).
- Khung SSR nới (chỉ `toggle`, checkbox không đổi): host = `label.td-switch` + tối đa một `span.td-switch__status` + tối
  đa một `span.td-switch__lock-reason` (đúng thứ tự, text-only, thuộc tính `class` / `id`) + note lỗi; trong núm thêm slot
  `--lock` khi `locked`. Sửa `_ssrSkeletonOk` (td-checkable-element.js:206) / `_markupMatches` (:261), `OWN_INPUT_ATTRS`
  (:10) thêm `aria-readonly`. Chữ mặc định từ `messages` không so (QĐ 4).
- Kit cũ gặp markup mới → lệch khung → **render an toàn** (giữ checked / value / focus — đường có sẵn), không hỏng (tiền lệ
  stepper v0.49 QĐ 22). Kit mới gặp markup cũ → nhận tại chỗ.
- **Trước nâng cấp đã đúng hình:** màu tone + núm do selector **host** (PHP in `tone`, `locked`); icon đồng hồ / khoá do PHP
  in sẵn; span status / lý do do PHP in (+ `aria-describedby` / `aria-readonly` trên input) ⇒ Δ = 0 px, Δ màu = 0.
- **`locked` trước nâng cấp** (mẫu ADR 0025): `@media (scripting: enabled) { td-toggle[locked]:not(:defined) .td-switch {
  pointer-events: none } }` — chuột / chạm không lật được trong khoảng chờ module; bàn phím (Space) **vẫn** lật được trong
  khoảng đó và **không-JS** lật được hẳn (checkbox không có readonly native, CSP cấm `onclick`). Chấp nhận + docs bắt buộc:
  **server là nguồn sự thật**, field khoá phải bị server bỏ qua / kiểm lại khi nhận form (khoá UI không phải kiểm soát
  truy cập). Không in `disabled` (sẽ mất khỏi submit — đúng điều owner không muốn).

### D. `<td-choice-group variant="segmented">`

**QĐ 12 — Biến thể thứ ba của `td-choice-group`, KHÔNG phải `td-tabs`, không element mới.**
- Theme / chế độ hiển thị là **giá trị** (lưu, submit, khôi phục) ⇒ radiogroup. `tablist` = điều hướng giữa các panel nội
  dung trên trang; trình đọc màn hình đọc "thẻ 1 trên 3" và chờ một `tabpanel`; td-tabs mặc định **kích hoạt thủ công**
  (mũi tên chỉ dời focus), không form-associated, không `name` / `required` / reset / SSR form; bàn phím radio thì mũi tên
  **chọn luôn** (đúng kỳ vọng "chuyển chế độ"). Dùng tabs cho giá trị là lạm dụng ngữ nghĩa (APG).
- Dùng lại toàn bộ choice-group: nhóm radio native không form owner (ADR 0023), `value` / `options` / vá tại chỗ /
  validity / reset / bfcache / event `input`+`change` / SSR. Khác chỉ ở **mặt hiển thị** + `size` + `icon-only` ⇒ rủi ro
  thấp, không đường giá trị mới.

**QĐ 13 — Option thêm khoá `icon`; trường không hợp với segmented.**
- `icon`: tên icon registry (`/^[a-z][a-z0-9-]{0,63}$/` + `hasIcon()` td-icon.js:125 / `Td::iconDef` PHP); không hợp lệ /
  không có → bỏ icon + một cảnh báo (không bỏ option). Render `span.td-choice__icon[data-td-icon="…"][aria-hidden]` (slot,
  `fillIconSlots` — so khi hydrate theo thuộc tính, như icon toggle). Chuẩn hoá trong `normalizeOptions`
  (`src/utils/choice-options.js:81`) + `CHOICE_LIMITS.icon = 64` (JS :31 ↔ PHP `Td::CHOICE_LIMITS` td.php:397).
  `icon` chỉ hiển thị ở `segmented` (v0.52); ở `button` / `swatch` bỏ qua + cảnh báo một lần (mở rộng sau là additive).
- `hint`: không hiện trong ô (ô gọn), **vẫn** là mô tả (`td-sr-only`, `aria-describedby` — như swatch).
- `swatch` / `image`: bỏ qua ở `segmented` + cảnh báo một lần (không render svg / img).
- `disabled`: như mọi variant. `unavailable`: chọn được, nhãn gạch + ghi chú `td-sr-only`; `icon-only` → vạch chéo
  `::after` dùng lại của swatch (hai tông, thấy trên mọi nền).

**QĐ 14 — `icon-only` (boolean host, cấu trúc).** Nhãn từng option → `td-sr-only` (vẫn là **tên** truy cập qua
`aria-labelledby` sẵn có). Option **không có icon hợp lệ** → nhãn của option đó **hiện** (không bao giờ ra ô trống) + cảnh
báo. Nhóm vẫn cần tên (`label` / `aria-label` / `<label for>`) như mọi variant. Không tooltip tự động (luật 10) — docs: nếu
cần, `data-tooltip` do site đặt; tên đã đủ cho trình đọc màn hình.

## API đề xuất (chuyển dsuite)

### `<td-toggle>` (thêm)

| Attribute | Property | Kiểu | Mặc định | Mô tả |
|---|---|---|---|---|
| `tone` | `tone` | `success` \| `warning` | — | Màu rãnh khi **bật** + icon núm (✓ / đồng hồ) + chữ trạng thái mặc định. Lạ → bỏ qua |
| `status-text` | `statusText` | string | — | Mô tả khi **bật** (thay `messages.statusSuccess/Warning`); dùng được không cần `tone` |
| `locked` | `locked` | boolean | — | Không đổi được bởi người dùng; focus được, vẫn submit, không `change`, `commit()` bỏ qua |
| `locked-reason` | `lockedReason` | string | — | Lý do (mô tả); mặc định `messages.locked` |

`TdToggle.messages` thêm: `statusSuccess` ("Đã xác nhận"), `statusWarning` ("Đang chờ"), `locked` ("Không thể thay đổi")
— Q2. DOM thêm: `span.td-switch__status.td-sr-only#{id}-status`, `span.td-switch__lock-reason.td-sr-only#{id}-lock`,
`span.td-switch__icon--lock[data-td-icon="lock"]`; icon on `data-td-icon="clock"` khi `warning`; input `aria-readonly`.

PHP: `td_toggle($name, $checked, $label, ['tone' => 'warning', 'status_text' => '…', 'locked' => true,
'locked_reason' => '…'])`. **Bất kỳ khoá nào trong bốn khoá này ⇒ ép element mode** (`td__check_element`, td.php:4765),
vì chế độ native (td.php:1790) không có host để mang thuộc tính / không chặn được thao tác — dsuite **không** bật
`ssr_elements` (v0.51.1 audit) nên đây là đường dsuite sẽ đi; docs ghi rõ. `tone` lạ → bỏ, `E_USER_WARNING` không in giá
trị thô. Host reserve thêm `tone`, `status-text`, `locked`, `locked-reason` (danh sách td.php:4819).

### `<td-choice-group>` (thêm)

| Attribute | Kiểu | Mặc định | Mô tả |
|---|---|---|---|
| `variant` | `button` \| `swatch` \| **`segmented`** | `button` | |
| `size` | `sm` \| `md` \| `lg` | `md` | Chỉ `segmented` |
| `icon-only` | boolean | — | Chỉ `segmented`; nhãn thành tên truy cập ẩn |

Option thêm `icon` (tên registry). PHP: `variant => 'segmented'`, `size`, `icon_only`, option `icon`.

```html
<td-choice-group name="theme" aria-label="Giao diện" variant="segmented" size="sm" value="auto"></td-choice-group>
<script type="module">
  el.options = [
    { value: 'auto', label: 'Tự động', icon: 'monitor' },
    { value: 'light', label: 'Sáng', icon: 'sun' },
    { value: 'dark', label: 'Tối', icon: 'moon' },
  ];
  el.addEventListener('change', (e) => {               // công thức docs — kit không có API theme mới
    document.documentElement.setAttribute('data-td-theme', e.detail.value);
    document.cookie = `td_theme=${e.detail.value}; path=/; max-age=31536000; SameSite=Lax`;
  });
</script>
```

PHP in `value` từ cookie đã whitelist (đúng đoạn no-FOUC `theming.md` §"Không chớp trắng"); `theme-boot.js` trong `<head>`
vẫn cần (module chạy sau lần vẽ đầu).

## Bảo mật

- Text mới (`status-text`, `locked-reason`, `messages.*`, option `label`) → `escapeHtml` / `textContent` (JS),
  `Td::e()` (PHP). Không HTML.
- `tone` / `size` / `variant`: allowlist cố định cả hai phía; không bao giờ ghép vào selector / class thô (class
  `td-choice--{variant}` chỉ từ allowlist).
- `icon`: regex + registry ở cả hai phía; tên chỉ vào `data-td-icon` (attribute đã escape) rồi `tdIcon()` / `Td::icon()`
  dựng SVG từ registry (không markup do người dùng). Site icon đăng ký **một phía** → lệch markup → render an toàn (rủi ro
  ghi bên dưới), không XSS.
- Giới hạn độ dài: `status-text` / `locked-reason` ≤ 200 code point (cắt), cùng bảng ca JS ↔ PHP.
- **`locked` không phải kiểm soát truy cập** (QĐ 10): docs + `security-model.md` — server phải từ chối thay đổi field khoá.
- Hydrate: span mới vào allowlist thẻ / thuộc tính của `_ssrUnsafe()`; text-only.

## Câu hỏi mở (owner / dsuite)

1. **Núm ở dark khi có tone:** mặc định đề xuất = `--td-color-on-status` (núm **tối** trên rãnh xanh / cam sáng — đạt ≥ 8:1,
   theo được mọi palette sinh). Phương án thay: núm trắng + rãnh status **tối** riêng cho dark (#15803d / #b45309, ~3.7:1
   với trang) — phải thêm 2 token vào `SCHEME_TOKENS` + generator. Chọn cái nào?
2. **Chữ trạng thái mặc định** (`messages.statusSuccess` / `statusWarning` / `locked`): "Đã xác nhận" / "Đang chờ" /
   "Không thể thay đổi"? dsuite sẽ truyền `status-text` riêng cho 2FA ("Chờ người dùng quét mã QR khi đăng nhập" /
   "2FA đã thiết lập — người dùng nhập mã khi đăng nhập") — xác nhận dsuite làm vậy.
3. **Chữ trạng thái hiển thị** (không chỉ sr-only, cho màn chạm): v0.52 không có; dsuite hiện badge / chữ trong hàng bảng
   khi cần. Có cần `status-visible` ngay bản này không?
4. **Ô segmented đã chọn:** viên sáng + vòng 1px `--td-control-border-strong` + chữ đậm (đề xuất, gần iOS / td-tabs) hay
   **viên mực đặc** (nền `--td-btn-primary-bg`, chữ trắng — tương phản mạnh nhất, giống nút primary)?
5. **Icon "Tự động":** `monitor` (theo máy — như GitHub) hay `sun-moon` (Lucide)?
6. **`locked` ở chế độ native PHP:** ép element mode (đề xuất, vì dsuite không bật `ssr_elements`) — OK, hay muốn báo lỗi
   và bắt dsuite tự truyền `'element' => true`?
