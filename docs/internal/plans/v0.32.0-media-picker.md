## Quyết định đã chốt (owner uỷ quyền — không còn câu hỏi mở)

**Ranh giới (ADR 0013 mới)**

1. **Kit sở hữu vỏ tương tác tái dùng**: vòng đời dialog / sheet, tìm kiếm, facet, phân trang cursor, trạng thái tải /
   rỗng / lỗi / thử lại, lưới + xem chi tiết, chọn đơn / nhiều + `maxItems`, hàng đợi upload (tiến độ, huỷ), form
   metadata theo descriptor, hiện lỗi, bàn phím / focus / responsive / i18n / render text an toàn. **App sở hữu** endpoint,
   envelope, auth / CSRF / 2FA / quyền / audit, map DTO + chuẩn hoá lỗi, album / brand / tag / quyền ảnh, xử lý upload an
   toàn (magic byte, re-encode, SHA-256 dedup), lưu trữ, URL ký, `media_usages`, chèn vào nội dung. **Adapter = object
   callback**, không bao giờ chuỗi endpoint. Kit không diễn giải HTTP status, không nối URL, không dò envelope.
2. **Capability chỉ là gợi ý trình bày.** Action hiện khi **có method + cờ capability top-level + cờ per-asset không thu
   hẹp**. Mọi lời gọi adapter vẫn phải được server kiểm quyền. Lọc file phía trình duyệt (`accept`, size) chỉ là UX.
3. **Danh tính = `assetId`** (chuỗi opaque). URL (`urls.thumbnail` / `urls.preview`, `preview-src`) chỉ để hiển thị, không bao
   giờ là giá trị form / danh tính. Picker **không bao giờ** sửa nội dung host hay tạo usage — chỉ trả `SelectedMedia[]`.
4. **Supersede roadmap "Không làm … media-picker"**: dòng đó nói về *port module dcms2*; ADR 0013 ghi rõ td-media-picker là
   bản viết sạch theo hợp đồng adapter (ADR 0007: dcms2 vẫn độc lập, không sync, shim tương thích nếu cần nằm ở dcms2).

**Hợp đồng (JSDoc typedef trong `src/utils/media-picker-core.js`, đúng tên / trường của dsuite §2-3)**

5. Typedef nguyên văn dsuite cho `MediaListRequest`, `MediaAsset`, `MediaPage`, `FacetOption`, `FacetDescriptor`,
   `FieldDescriptor`, `MediaCapabilities`, `UploadProgress`, `UploadResult`, `UsageSummary`, `DeleteResult`,
   `DownloadResult`, `MediaAdapterError`, `MediaPickerAdapter` (có cả `delete?` / `download?` — v0.32 **không gọi**),
   `UsageDraft`, `SelectedMedia`, `PickerOutcome`, `OpenMediaPickerOptions`. **Bổ sung (additive, chốt luôn ở v0.32, adapter
   bỏ qua được):**
   - `MediaListRequest.kinds: ('image'|'video'|'file')[] | null` — từ `selection.kinds`; adapter nên lọc, kit vẫn **ẩn**
     mục sai loại (cảnh báo một lần).
   - `OpenMediaPickerOptions.selection.kinds?`, `title?` (mặc định `labels.title`), `pageSize?` (1-100, mặc định 40 →
     `limit`), `upload?: { accept?: string, maxSize?: string, multiple?: boolean = true }` (chuyển cho `td-dropzone`).
   - `capabilities` thiếu → suy ra: `search: true`, `upload: !!adapter.upload`, `editMetadata: !!adapter.update`,
     `delete` / `downloadOriginal: false`. v0.32 bỏ qua `delete` / `downloadOriginal`.
   - `crop.enabled === true` ở v0.32 → cảnh báo một lần ("crop UI có ở v0.33"), `usage.crop = null`.
   - `sort`: không có UI ở v0.32 (luôn `undefined`); site cần thứ tự → một facet `single` key `sort` do adapter hiểu.
6. **`TdMediaPicker.configureDefaults({ adapter, capabilities, assetFields, uploadFields, messages, context, upload,
   pageSize })`** — registry cấp module (tiền lệ icon registry, không `window`). **Thay thế toàn bộ** object mặc định mỗi
   lần gọi (một lần gọi trong bootstrap của site; dễ đoán hơn merge). Validate: `adapter.list` / `adapter.get` phải là hàm,
   không thì `TypeError`. `TdMediaPicker.defaults` (getter, bản sao nông). Thứ tự resolve **lúc mở**: tham số `open()` >
   `field.pickerOptions` > `field.adapter` > defaults (merge nông theo key; `selection` luôn do người gọi / field quyết).
   Không registry nhiều backend (YAGNI — chưa trang nào cần).
7. **`PickerOutcome`**: `{ status: 'selected', selection }` hoặc `{ status: 'cancelled', reason: 'close'|'escape'|
   'programmatic', selection: [] }`. Huỷ **resolve**, không reject. `usage` v0.32 = `{ altText: asset.defaultAltText ?? '',
   crop: null, focalPoint: null }`. Thứ tự `selection` = thứ tự người dùng chọn (initial trước).
8. **Lỗi adapter → `normalizeError(err)`**: `AbortError` / signal đã abort → im lặng. `code` ngoài enum → `'server'`. Chữ
   hiện cho người dùng **chỉ** từ `userMessage` (chuỗi, trim, cắt 200 code point) hoặc `labels.error.{code}` — **không bao
   giờ** `err.message` (có thể là exception thô / SQL). `fieldErrors`: chỉ own key là chuỗi (bỏ `__proto__` /
   `constructor`), giá trị `string[]` (mỗi chuỗi cắt 200, tối đa 5); key khớp descriptor → lỗi trên control, còn lại → danh
   sách lỗi chung của form. `retryable` mặc định `true` cho `network` / `rate-limited` / `server`. `console.warn` lỗi gốc
   (công cụ dev, không ra UI).
9. **Kết quả cũ không bao giờ thắng**: mỗi "khe" request (`list`, `facets`, `get` chi tiết, `update`) là một
   `LatestRequest` — gọi mới → abort controller cũ + tăng thế hệ; kết quả về khi thế hệ đã cũ hoặc signal đã abort → bỏ
   (kể cả adapter phớt lờ `signal`). Đổi query / filter → abort `list` + load-more + `facets`. Đóng picker → abort **mọi**
   thứ (kể cả upload, `get` của initialIds). Tìm kiếm debounce 250ms (Enter trong ô tìm = chạy ngay); facet reload cùng nhịp.
   Cache chỉ trong phiên mở (Map theo key request + theo id), xoá khi đóng; không localStorage.
   **Cache sau thay đổi** (review R1-7): upload / update thành công → ghi asset mới vào cache theo id; **xoá mọi** cache
   list + facet (thứ tự / đếm / kết quả lọc có thể đổi — không cố vá từng trang); làm mới list hiện tại (trang đầu, cùng
   query / filter) + facet; lựa chọn giữ theo id (snapshot asset trong `SelectionModel` thay bằng bản mới). Tìm đi rồi tìm
   lại query cũ → request mới, không bao giờ trả bản cũ từ cache.

**Picker UI**

10. **`<td-media-picker>` + `TdMediaPicker.open(options)`** (mẫu `td-drawer`): element khai báo có `options` (property),
    `open() → Promise<PickerOutcome>`, `close(reason = 'programmatic')`, `isOpen`; element tự nó không hiển thị gì
    (`display: none`). `TdMediaPicker.open()` tạo host tạm trên `<body>`, gỡ sau khi đóng. **Một picker một lúc**: `open()`
    khi đang có picker mở → resolve ngay `cancelled / programmatic` + cảnh báo một lần (không chồng picker).
    `open()` thiếu adapter hợp lệ → `TypeError` đồng bộ (lỗi lập trình).
    **Host bị gỡ khỏi DOM khi đang mở** (review R1-5): `disconnectedCallback` → `_teardown('programmatic')` **idempotent**
    (cờ `_settled`): abort mọi việc đang chạy (list / facets / get / initial / upload / update — controller của picker và
    `dropzone.clear()`), `handle.release()` của dialog-layer **ngay** (không chờ transition; root gỡ luôn, inert / scroll
    lease / layer trả lại), xoá timer / debounce / rAF, đóng hộp "bỏ thay đổi" nếu đang chờ (`TdModal.closeById(id đã
    lưu)` — chỉ instance của picker, quyết định 12),
    resolve Promise **đúng một lần** `cancelled / programmatic` + `cancel { reason }`. Mọi đường kết thúc khác (xác nhận,
    huỷ, `close()`) đi qua cùng `_teardown` → không settle hai lần.
11. **Vỏ = `openDialogLayer` + DOM / CSS của `td-modal`** (root `.td-modal.td-modal--5xl.td-media-picker`, dialog
    `.td-modal__dialog role=dialog aria-modal`), **không** qua `TdModal.show()`: `show()` không chặn được nút × / Escape khi
    còn dữ liệu chưa lưu (× gọi thẳng `closeById`, `escapeCloses` đóng vô điều kiện). Dùng lại nguyên `modal.css` → kích
    thước, chuyển động, **bottom sheet ≤ 640px**, reduced motion, forced colors có sẵn. `scrollLock: true`, `layer:
    LAYERS.modal`, opener = phần tử đang focus (trả focus khi đóng — dialog-layer lo).
12. **Một cổng kết thúc duy nhất** `_requestFinish(kind, reason)` (review R1-3) cho **cả** ×, "Huỷ", Escape **và** "Chọn
    (n)": sạch → kết thúc ngay. **Bẩn** (form metadata đã sửa chưa lưu, hoặc còn upload / update đang chạy) →
    hộp xác nhận **của picker** chồng lên (một hộp một lúc — bấm lại khi đang chờ bị bỏ). **Không dùng
    `TdModal.confirm()`** (review R2-5; đã kiểm L497-…: chỉ trả `Promise<boolean>`, id nằm trong closure → không đóng
    đúng instance được). Helper nội bộ `openDiscardConfirm(labels) → { id, promise }` = `TdModal.show({ title:
    labels.discardTitle, body: <p> dựng bằng DOM + textContent (Node, không chuỗi HTML), actions: [{ label:
    labels.keepEditing, value: false }, { label: labels.discard, variant: 'danger', value: true }], onClose: (v) =>
    resolve(v === true) })` (đã kiểm L170-205: `show()` trả id, `actions[].value` → `onClose(value)`; × → `onClose(undefined)`
    = false). Picker lưu `id`; teardown chỉ gọi `TdModal.closeById(id)` của **đúng** instance đó (không `close()` /
    `closeAll()` — tránh lỗi đóng nhầm modal trên cùng của dcms2); đồng ý → abort hết rồi kết thúc **đúng loại đã yêu cầu**: từ
    "Chọn" → resolve `selected` với lựa chọn **tại thời điểm đồng ý** (asset chưa lưu giữ snapshot cũ; upload bị huỷ không
    vào lựa chọn); từ ×/Huỷ/Escape → `cancelled`. Không → giữ picker, không đổi gì. **Escape đóng picker** khi sạch (addendum ADR 0006: picker không
    mất dữ liệu — lựa chọn chưa xác nhận không tính là dữ liệu). Escape trong ô tìm có chữ → xoá chữ, không đóng.
    Không có Enter toàn cục: chỉ nút "Chọn (n)" ở footer xác nhận.
13. **Lưới = `td-media-grid`** (picker dựng mục bằng DOM, `data-id = assetId`, `<button data-td-media-open>` +
    `<img loading="lazy" decoding="async" referrerpolicy="no-referrer" alt="">` + tên dưới ảnh). **Picker sở hữu lựa chọn**
    (`SelectionModel`: Map id → asset, thứ tự chọn), lưới chỉ phản chiếu:
    - `activate` (click / Enter khi lưới chưa có gì chọn) → `preventDefault()`, **chọn** mục đó (đơn: thay; nhiều: thêm)
      + xem chi tiết. Đang có lựa chọn → click / Space lật (mô hình media-grid). Enter luôn mở chi tiết.
    - **Đơn** (review R1-2, R2-2): lưới **không bao giờ** có thuộc tính `max` (đã kiểm `_max()` L156-159: `max=1` chặn id
      mới ở `_userFlip` → không thay được). Lưới **không có** event / hook "trước khi chọn" (đã kiểm: chỉ `select-change`
      sau khi đổi, `activate`, `select-limit`; `click` nghe **capture trên host** L122, `keydown` bubble trên host L123) →
      picker chặn **trước** lưới bằng listener **capture trên phần tử cha** `.td-media-picker__results` (capture ở tổ tiên
      chạy trước capture ở host): `click` trên nút mở / tick, hoặc `keydown` Space trên nút mở, của một mục **chưa chọn**
      khi lưới đang có lựa chọn → `grid.clear()` **im lặng** (không emit, `clear()` cũng xoá `_anchor` L494-497) rồi để
      sự kiện đi tiếp. Lưới lúc đó rỗng + không anchor → click nút mở = `activate` (picker chọn), tick / Space = lật một mục
      (Shift không anchor = lật đơn, L371-380) → `select-change { added: [id] }` đúng một id, live region đọc "Đã chọn 1".
      Không bao giờ suy đích từ `added` nhiều phần tử, không có trạng thái nhiều-chọn tạm. Mục **đã chọn**: để lưới xử lý
      (lật = bỏ chọn; Shift trên chính nó = không đổi). Picker vẫn kiểm `select-change`: `added.length > 1` (không được xảy
      ra) → coi là lỗi đồng bộ, giữ model, ghi lại lưới im lặng.
    - Đổi query / filter: `grid.clear()` (không emit) **trước** khi thay mục → MutationObserver của lưới không phát
      `removed`; sau khi vẽ: `grid.select(chọn ∩ đang hiện)` không emit. Lựa chọn ngoài trang hiện **giữ nguyên**.
    - **Nhiều + `maxItems`** (review R1-2): `cap = maxItems − số đã chọn ngoài lưới`. `cap ≥ 1` → lưới `max = cap` (cap của
      lưới + `select-limit` + thông báo của lưới dùng được). `cap ≤ 0` → **gỡ** `max` (đã kiểm: `max="0"` = không giới
      hạn) và picker **phủ quyết**: `select-change` có `added` vượt sức chứa → `grid.deselect(added)` (không emit), model
      không đổi, thông báo `labels.limit` ("Tối đa {max} mục"; picker không có event riêng). Phủ quyết chạy ở **mọi** cap (lưới là gợi ý, `SelectionModel` là nguồn sự thật; đếm toàn cục). Tính lại
      cap sau mỗi thay đổi lựa chọn / vẽ lưới.
    - Mục `status ≠ 'ready'` hoặc sai `kinds`: `ready` sai → huỷ thêm (deselect không emit) + thông báo
      `labels.notReady`; sai kind → không vẽ.
    - **Không tự chọn mục đầu.** Mở picker = không có gì chọn (trừ `initialIds`).
14. **Phân trang = nút "Tải thêm"** theo `nextCursor` (nối vào lưới — lựa chọn tự giữ). Không dùng `td-pagination` (cần
    `total-items`, kiểu số trang — không khớp cursor opaque). `previousCursor` không dùng ở v0.32. `total` có → chữ "Hiển
    thị {n} / {total}". Không cuộn vô hạn.
15. **`initialIds` = một giao dịch có revision** (review R1-4): `SelectionModel.revision` tăng ở **mọi** thay đổi của người
    dùng (thêm / bỏ / thay / bỏ tất cả). Mở picker → giao dịch có **một** `AbortController` + số thế hệ, chụp `rev0`,
    `adapter.get()` từng id (song song, cùng signal, tối đa `maxItems`, bỏ id trùng). **Huỷ ngay** (review R2-4): đường
    thay đổi lựa chọn của người dùng gọi `initial.invalidate()` **đồng bộ** trước khi đổi model → abort controller, tăng
    thế hệ, tách giao dịch (không bao giờ `await` adapter — adapter phớt lờ signal vẫn không giữ được gì); mọi settle
    về sau bị quan sát (`.then` gắn sẵn, không unhandled rejection) và **bỏ**. Còn hợp lệ (thế hệ khớp, `revision ===
    rev0`) khi **lời gọi cuối** settle → áp **một lần** các id thành công **theo thứ tự `initialIds` gốc**, lỗi → bỏ id
    đó (cảnh báo). Áp không tăng revision và không phát `selection-change`. Đóng picker trước khi xong → abort. Trong lúc chờ, khay hiện "Đang tải lựa chọn…" (không chặn
