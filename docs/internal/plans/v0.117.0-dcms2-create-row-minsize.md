# v0.117.0: chip-input create row with free typing, datetime clear padding, media picker minSize + beforeApply

Request: DCMS2 (zmag admin), 17/11. The owner approved all four items, including the UX choices in QĐ3 (small cards
stay visible but locked, unknown size is ineligible). The design was settled with Codex (sol/high, consensus round 2).
Already in the kit, no work needed (DCMS2 is told): crop ratio lock = `crop.aspectRatio` (0.35.0); custom upload error
text = adapter error `userMessage` / `labels.error.{code}`; byte limit = `upload.maxSize`.

## Goal

- `<td-chip-input allow-create create-label='Tạo bút danh “{text}”'>`: free typing still makes plain chips, and a
  pinned row emits `create` for the app to create a record.
- `td-datetime-picker` clearable (not editable): the calendar icon sits at the normal 14px inset while the clear
  button is hidden.
- `TdMediaPicker` `selection.minSize`: images below a minimum size cannot be selected or cropped below it, with a
  visible reason.
- `TdMediaPicker` `beforeApply(selection, { signal })`: an async app gate before the picker resolves.
- Every default stays byte-for-byte the same when the new attribute or option is absent.

## Decisions (QĐ)

**QĐ1. Chip input, normal mode (`allow-create` + `create-label`, no `selection-only`).**
- Rows after the suggestions:
  1. The existing `Thêm “{text}”` row. It commits through `_createFrom()` and the optional `create(text)` hook. Its
     visibility is unchanged.
  2. The external action row, pinned last. Its label is `create-label` with every `{text}` replaced by the cleaned
     query. A label without `{text}` is used literally. The label is set as text, never HTML.
- The external row is visible only when all of these hold: `allow-create`, a non-empty `create-label`, a non-empty
  cleaned query (cleaned and truncated as today by `max-length`), no fold-match (case and accent insensitive, the same
  `fold()`) against a selected chip's label or value or a current result or option's label or value, and the element
  is not full, disabled, loading or in error. Async stale results must never bring back a suppressed row.
- Keyboard and pointer:
  - Typing never makes either create row active.
  - Enter with no active row keeps today's path: exact match first, otherwise a plain chip through `_createFrom()`.
  - Arrow keys reach both rows. Enter on the external row, or a click on it, activates it.
  - A mouse press keeps focus in the input.
  - Enter during IME composition is still ignored.
- Activating the external row:
  - closes the popup and clears the query;
  - emits one `create` event `{ query }` (bubbles, composed), the same event as 0.87.0;
  - never calls the `create(text)` hook, never adds a chip, never emits `change`.
  The app creates the record and then calls `addItem({ value: id, label })`.
- The row is a real `role="option"` with a stable id, reached through `aria-activedescendant`, and its accessible
  name differs from the Thêm row's. It reuses the 0.87.0 create-row markup, CSS and token `--td-dropdown-create-fg`.
- `selection-only` + `create-label` keeps its 0.87.0 behaviour. The one additive change: when `create-label` contains
  `{text}` and the query is non-empty, the row shows the interpolated `create-label` instead of `labels.create`. An
  empty query still shows the literal `create-label`. `allow-create` is still ignored there, and still warns.
- `create-label` without `allow-create` or `selection-only` still does nothing and still warns. The warning text says
  it needs `selection-only` or `allow-create`.

**QĐ2. Datetime picker.** In `datetime-picker.css`, add a rule for the plain clearable trigger:
`.td-dtp--clearable:not(.td-dtp--editable) > .td-dtp__trigger:has(+ .td-dtp__clear[hidden]) { padding-inline-end: 14px }`
(the same value as the editable rule at `:390-392`). Split the existing editable selector list into two rules, so that
a browser without `:has()` does not drop the non-`:has` selector. Browsers without `:has()` keep the reserved padding.
The `td-datetime-picker:not(:defined)` native rule stays unchanged. Docs that say the width is always reserved are
updated.

**QĐ3. Media picker `selection.minSize`.**
- `selection: { minSize?: { width?: number, height?: number } }`. Absent or `null` keeps today's behaviour. Each axis
  given must be an integer from 1 to 100000, and at least one axis must be given. Anything else is a `TypeError` at
  `open()`. Like the rest of `selection`, it is per-open only and never comes from `configureDefaults()`
  (`media-picker-core.js:682`, `:713`); the defaults contract is unchanged.
- It applies to `kind === 'image'` only. Videos and files are unaffected.
- It is a constraint on the usable output:
  - Every mode (no crop, focal-only, free crop, fixed ratio): the source `width` / `height` must meet each given
    axis first, since no crop can be larger than its source.
  - Fixed-ratio crop adds the stricter test: the source must be able to hold a crop of that ratio that meets both
    minima.
  - Free or fixed crop step: Apply is blocked while the crop rectangle, in natural pixels, is below either minimum,
    with the reason shown. Resizing and zooming must not go below the minimum where the cropper allows a minimum. If
    the cropper cannot express a minimum, the check on Apply is enough. Pick the smallest correct mechanism and
    document it.
  - An image missing a required dimension is ineligible, with its own reason. No guessing from the thumbnail.
- Ineligible cards stay visible and the detail pane still opens. Only selection is locked:
  - the tick or checkbox is disabled;
  - a plain click or Enter in single mode opens the detail and announces the reason instead of selecting;
  - Space, range select, `autoSelectFirst` and `initialIds` skip the card.
- The reason is visible on the card and in its accessible description. Labels:
  - `sizeTooSmall`: "Ảnh phải có kích thước tối thiểu {w} × {h} px". When only one axis is set, the text names only
    that axis.
  - `sizeUnknown`: "Không xác định được kích thước ảnh để kiểm tra kích thước tối thiểu".
- Upload stays available. An undersized image that was just uploaded stays in the library and is ineligible in this
  picker, with the same reason.
- Docs say the server must check the size and the final crop again.

**QĐ4. Media picker `beforeApply`.**
- A top-level option on `open()` / `configureDefaults()`, not an adapter method:
  `beforeApply?: (selection, { signal }) => boolean | void | Promise<boolean | void>`. Absent keeps the old finish
  path unchanged.
- It is called once, with the exact final selection (after crop or focal point). How it settles:
  - `undefined`, `true` or any non-`false` value: proceed.
  - `false`: stay open, show `labels.applyRejected`.
  - A throw or rejection carrying `{ userMessage }`: show that text.
  - Any other error: `console.error`, then show `labels.applyFailed`. Raw text is never shown.
  - `AbortError`, or the signal already aborted: silent.
- While it runs:
  - The confirm button (the crop Apply button inside the crop step) shows loading, and the surface gets
    `aria-busy="true"`.
  - Selection, crop, filters, upload and detail edits are locked.
  - Close, Back and `close()` stay available. They abort the signal.
  - Only one call runs at a time. A session generation token drops a late result, even when the hook ignores the
    signal.
- Crop-step integration (`src/feedback/crop-dialog.js`): today the crop dialog closes on Apply and resolves at
  once. Add an optional async `onApply(result, { signal })` hook (internal, not a public API) to the crop dialog.
  While the hook is pending, the dialog stays open with Apply loading and the crop surface locked. If the hook
  rejects or returns `false`, the dialog stays open, shows the message inline and keeps the crop state for a retry.
  It resolves the applied result only after success. Closing or cancelling the dialog aborts the picker's controller.
  When there is no crop step, the gate runs on the picker's confirm button.
- Only after success does the existing teardown run, `confirm` fire and `selected` resolve. Every other outcome fires
  no `confirm`. `confirm` stays a non-cancelable notification.
- Labels: `applyRejected` = "Không thể chèn mục đã chọn", `applyFailed` = "Không kiểm tra được, thử lại sau". The error
  shows where picker errors already show: the toast or inline error of the active surface. Use the existing mechanism.

**QĐ5. Not doing.**
- No DCMS-specific endpoints or DTOs, and no automatic option insertion after `create`.
- No hiding or deleting of small assets.
- `minSize` is never merged into `upload.maxSize`.
- No renditions or saved crops.
- No `beforeApply` on the adapter.
- No RTL tests (owner rule).

## Tests

- **Chip input**, node and engines:
  - the attribute matrix (none / allow-create / create-label / both / selection-only ± create-label ± `{text}`);
  - row order and labels, with `{text}` absent, once and repeated;
  - escaping of quotes, `<`, `&` and Unicode;
  - Enter with no active row gives a plain chip; arrow to the action row then Enter gives one `create`, no chip and no
    `change`; a click does the same and keeps focus;
  - an exact folded label or value match, or an already selected chip, hides both rows; a partial match shows both;
  - an empty query (also with `show-on-focus`) shows no action row;
  - full, disabled, loading and error states; IME;
  - the `create(text)` hook is not called by the action row;
  - `aria-activedescendant`, `role=option` and distinct names;
  - the legacy `selection-only` outputs are unchanged.
- **Datetime picker**, engines:
  - computed `padding-inline-end` with the clear button hidden vs visible, for non-editable clearable, editable and
    non-clearable;
  - transitions through value, clear and reset;
  - native `:not(:defined)` unchanged.
  - Gate: CSP matrix states (rebaseline only the affected state, explained).
- **Media picker**, node (core) and engines:
  - `minSize` validation errors;
  - eligibility: no crop, focal, fixed ratio, unknown size, one axis only, video untouched;
  - card locked, reason visible and in the accessible description, detail opens, click in single mode does not
    select, Space, range, `autoSelectFirst` and `initialIds` skip it;
  - crop Apply blocked below the minimum;
  - an undersized upload becomes ineligible;
  - `beforeApply` true / undefined / false / `userMessage` / other error / AbortError;
  - busy state and locks; double click calls it once; close during the call aborts and fires no `confirm`; a late
    result is ignored;
  - with crop, the gate runs after crop; in the crop step, Apply is busy during the gate; a rejection keeps the
    dialog open with the crop intact, and a retry succeeds; closing the crop dialog during the gate aborts it;
  - free crop on a source smaller than `minSize` is ineligible;
  - without the options, the existing media picker suites pass unchanged.
- **Gates**: `check:css`, `check:dist`, `check:embed`, `test:node`, `test:csp` + `test:csp:combined`, touch and
  responsive (media picker), the engines suites of the three components.
