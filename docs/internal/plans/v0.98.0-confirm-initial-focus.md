# v0.98.0: `TdModal.confirm({ initialFocus })` (dsuite request 07/11)

## Goal

dsuite adds confirms to row "take action" buttons. On the order desk the next-step action is confirmed many times an
hour, so keyboard users need the first focus on the confirm button there. Dangerous actions keep Cancel. Today the
first focus is always Cancel (`src/feedback/td-modal.js` confirm(), `focusTarget: gate ? gate.input : cancelButton`).

## Contract

- `initialFocus: 'cancel' | 'confirm'`, default `'cancel'`. Any other value (incl. wrong case, non-string) → `'cancel'`,
  silently (it is a focus preference, not a security gate, so no rejection like `typeToConfirm`).
- `typeToConfirm` set → the field still gets the first focus, whatever `initialFocus` says.
- Unchanged: Enter / Esc handling, focus trap, busy state, focus return to the opener, every other option.
- Not in scope (dsuite asked explicitly): no `confirm` attribute on `<td-action-button>` or TdMenu items.

## No key bleed-through

Risk: the key that opened the dialog activates the confirm button once focus lands there.
- Enter on a native button fires `click` on keydown; focus moves in `onOpened` (a later frame), so a single press
  cannot reach it, but a HELD Enter auto-repeats keydown (`repeat: true`) on the now-focused confirm button → click.
- Space fires `click` on keyup: an opener that opens on keydown (custom key handler) lets the keyup land on confirm.
Guard (only when the first focus is the confirm button): a document capture listener for the dialog's lifetime records
keys pressed down AFTER the dialog opened (non-repeat keydown). On the confirm button, an Enter / Space keydown with
`repeat` whose key was not pressed after opening → `preventDefault()`; an Enter / Space keyup whose keydown was not seen
after opening → `preventDefault()` and the click that may follow in the same task is ignored. Mouse, touch, AT
activation (click without key events) and a fresh key press are never blocked. Listeners removed on close.

## Tests (3 engines, `src/feedback/td-v098-confirm-initial-focus.engines.browser-test.js`)

default → Cancel focused; `'confirm'` → Confirm focused; `typeToConfirm` + `'confirm'` → field; invalid values
(`'Confirm'`, `1`, `null`) → Cancel; Enter on Confirm resolves true; held Enter from the opener (sendKeys down Enter on
the opener, repeat) does not resolve; Space keydown-open + keyup on Confirm does not resolve; a fresh Enter afterwards
does; Esc / focus return unchanged (existing modal tests stay green).
