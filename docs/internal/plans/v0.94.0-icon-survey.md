# Icon survey (read-only) - td-components icons + EN/VI search + picker

## 1. Kit registry facts
- Authored source: /Users/theduyet/Documents/Code/components/src/icons/icons.json (36,979 B raw, ~4.6 KB gzip). Shape: `{ $schema, $comment, source{library:lucide,license}, aliases{alias:coreName}, icons{ name:{ lucide:"<upstream name>", viewBox:"0 0 24 24", paint:"stroke", nodes:[["path",{d}],...] } } }`. Geometry is inline SVG node data (no raw SVG strings), CSP-safe.
- Generated: src/icons/registry.js (30,796 B raw, ~3.9 KB gzip) by `npm run build:icons` -> scripts/build-icons.mjs (`--check` in `check:icons`, part of test:ci:static). Generator reads ONLY icons.json (no lucide package input, no pinned lucide dep: geometry is hand-copied from lucide-static; THIRD_PARTY_NOTICES.md says checked against lucide-static 1.48.0 / 1.52.0 / 1.53.0). It drops the `lucide` field, validates alias names (/^[a-z][a-z0-9-]{0,63}$/, must not shadow a core icon, must point to a core icon, no chains).
- Runtime: src/icons/td-icon.js (tdIcon, registerIcons, hasIcon, listIcons, resolveIconName, fillIconSlots, svgStringToDefinition, renderIconDefinition), td-icon-element.js (<td-icon>), icons.stories.js, icons-aliases.test.js, td-icon.browser-test.js. package.json exports: ./icons, ./icon-element, ./icons.json.
- Counts: 75 core icons + 15 aliases (x, chevron-left/right/up/down, ellipsis, external-link, expand, pen, archive-restore, folder-tree, tag, trademark, package, banknote). Note docs/components/icons.md still says "71 icon" (docs drift; real count 75).
- Resolution order: core/site icon name first; alias only if the name is neither core nor site icon. Site icons via registerIcons(data) (must be prefixed, collisions throw).
- PHP: php/td.php. `Td::icon($name,$size,$label,$class)` (~line 1029), `Td::iconAliases()` (~887), kit icons loaded from `<kitDir>/src/icons/icons.json` at runtime (~862-872; kitDir() required), `Td::registerIcons()` for site icons, ALIASES const as FALLBACK for a vendored icons.json without `aliases`. Same geometry allowlist as td-icon.js. So PHP and JS share icons.json; search data added there (or in a sibling JSON) is reachable by both.
- Docs: /Users/theduyet/Documents/Code/components/docs/components/icons.md; ADR docs/internal/decisions/0010-icon-registry.md; roadmap line 117 already lists this work as `planned` (td-icon-picker JS+PHP, Gợi ý group, lazy load).
- Size for lazy-loading: registry.js is 30.8 KB raw for 75 icons (~410 B/icon raw, pretty-printed JSON.stringify indent 2; icons.json ~490 B/icon). +95 stroke icons ~ +40 KB raw / ~5 KB gz in registry.js (minified much less). EN+VI search data (dsuite's kit-meta.json: 29 KB for 75 icons, ~390 B/icon) would be ~ 170 icons x 400 B ~ 70 KB raw. Conclusion: geometry could stay eager (small, gzips well), but search metadata should be a SEPARATE lazy module/JSON (loaded on picker open), not in registry.js.

## 7. Open questions
1. Reuse dsuite's FA-glyph manifests (CC BY 4.0, fill style, mixed visual style) vs lucide-stroke equivalents (consistent with kit). The kit rule says no Font Awesome for new UI.
2. The kit has no pinned lucide package; the 95 new geometries must be copied from lucide-static (which version? kit used 1.48-1.53). A generator reading lucide-static + a name map would replace hand-copying (the current build script only reads icons.json).
3. Kit names are td-owned semantic names (close, success...) - for new icons use lucide names verbatim (user, bell, ...) or semantic? Alias vs new for glyph-different pairs (check-circle vs success=circle-check-big fine; times-circle vs error=circle-alert differ).
4. 'only' (2 uses) is not an FA icon - ask dcms2 for call sites. youtube/brands: kit has no brand set; dsuite has ds-brand-*.
5. text-height, stream, pen-fancy, cogs, rectangle-ad, users-slash, spinner: pick replacements with dcms2.
6. Where to store search data: new src/icons/icons-search.json (lazy, EN+VI) vs inside icons.json (PHP reads whole icons.json each request via json_decode - adding ~70 KB hurts PHP). Prefer a separate file keyed by name; PHP picker reads only when rendering the picker.
7. docs/components/icons.md count (71) is stale vs 75.
