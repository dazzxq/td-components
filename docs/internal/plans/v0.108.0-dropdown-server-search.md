## QĐ1: API
- Property `search`: `(query: string, { signal: AbortSignal }) => Promise<option[]>` (cùng shape với `options`: value /
  label key, `description`, `image`, `meta`, `status`, `disabled`…). Không có attribute. Thêm vào danh sách property
  replay (dòng 26, sau `mode`). Gán `null` / không phải hàm → tắt (hành vi cũ).
- Attribute `min-chars` (số nguyên ≥ 0, mặc định 1; lạ → 1) và `search-delay` (ms ≥ 0, mặc định 250; lạ → 250), đọc lúc
  dùng (như chip-input). Chỉ có tác dụng khi có `search`.
- Event `search-error` `{ query, error }` (như chip-input). Không thêm event khác.
- `search` cần ô tìm: khi có `search`, ô tìm luôn hiện kể cả `searchable="false"` (ghi rõ docs).

## QĐ2: dữ liệu: kết quả tách khỏi `options`
- `_options` (từ `options` / `<select>` / `load`) giữ nguyên vai "danh sách gốc". Kết quả server chỉ vào
  `_filteredData`, đúng thứ tự trả về: không `_matches`, không `_ordered`, không nhóm, không `search-fields`.
- **Trạng thái dưới ngưỡng** = mọi query (đã trim) có độ dài < `min-chars`, KỂ CẢ query rỗng (`min-chars` ≥ 1): luôn
  hiện + đọc qua `role=status` `labels.searchMinChars` (`{n}`), không gọi server. Danh sách trong trạng thái này = danh
  sách gốc `_ordered(_options)` (host tự đưa qua `options` / `<select>` / `load`, ví dụ "gần đây"; không đưa thì rỗng),
  không lọc cục bộ, và không bao giờ trộn với kết quả server. `min-chars = 0` → không có trạng thái dưới ngưỡng; query
  rỗng gọi `search('')` khi mở.
- Hai trạng thái tách bạch: `_searchQuery` (query đang chờ / đang chạy) và `_shownQuery` (query của kết quả server đang
  hiện, `null` = đang hiện danh sách gốc). Mọi chỗ đang gọi lại local filter (danh sách ở Hiện trạng) đi qua một hàm
  `_applyQuery()`: có `search` → không bao giờ lọc cục bộ; dưới ngưỡng → danh sách gốc + gợi ý; đủ ngưỡng → hiển thị theo
  QĐ3 (không bao giờ hiện `_options` như kết quả của một query đủ ngưỡng).
- **Không nhóm**: khi `_filteredData` là kết quả server (`_shownQuery !== null`), `_renderMenuOptions` tắt nhánh nhóm
  (`_groupIndex` / wrapper nhóm) → dòng phẳng, đúng thứ tự trả về, kể cả khi đã cấu hình `groups`.
- **Gán `search` sau khi đã kết nối** (setter): hủy debounce + abort + seq++, reset `_searchQuery` / `_shownQuery` /
  `_searchState`, về danh sách gốc; nếu việc có / không có ô tìm đổi (`searchable="false"`) → dựng lại cấu trúc menu
  (đường render cấu trúc hiện có). Menu đang mở: dựng lại tại chỗ, giữ mở, focus về ô tìm (nếu ô vừa xuất hiện) hoặc
  trigger (nếu ô vừa biến mất). Bỏ `search` → hành vi cũ (lọc cục bộ theo query đang gõ).
- Chọn ở select mode: chọn một dòng kết quả → `_selectedItem` = chính item đó (nhãn trigger + giá trị form lấy từ nó),
  không cần có trong `_options`; không chạy `_reconcileSelection` cho kết quả. Giá trị ban đầu (attribute `value` /
  `setValue`) vẫn tra `_options` như cũ → docs: muốn có giá trị sẵn thì đưa item đó vào `options` / `<select>`.
- Action mode: `_pickItem` lấy item từ `_filteredData` như cũ; keep-open: không gọi lại search, giữ query + kết quả,
  dòng active nhảy như hiện nay.

## QĐ3: vòng đời request (async)
- Mỗi `input`: hủy debounce + request đang chạy (`_searchSeq++`, `abort()`), query < min-chars → hiển thị gợi ý ngay;
  ngược lại `setTimeout(search-delay)` → `_runSearch(q)`.
- Hiển thị trong lúc chờ (debounce + request) cho query đủ ngưỡng B:
  - đang hiện kết quả server của query A (`_shownQuery = A`) → giữ các dòng của A (cũ) cho tới khi B về; `aria-busy` +
    `labels.searching` khi request chạy quá 400 ms;
  - đang hiện danh sách gốc (vừa vượt ngưỡng) → xoá dòng ngay (list rỗng, không hiện `_options` như kết quả) +
    `aria-busy` + `labels.searching` ngay.
  Kết quả muộn của A (sau khi B đã chạy) bị bỏ theo seq / signal.
- `_runSearch`: seq mới, `AbortController` mới. Kết quả về: bỏ nếu `seq` cũ / `signal.aborted`; không phải
  mảng object → coi như lỗi (warn). OK → `_filteredData = results`, render, active = dòng enabled đầu (như `_handleSearch`),
  thông báo `resultCount` / `noResults` qua `p.td-dropdown__empty[role=status]` như hiện có.
- Lỗi (không phải abort / seq cũ) → `data-load="error"` + `labels.searchError` + nút `retry` có sẵn (click / Enter khi lỗi
  → chạy lại query hiện tại, không debounce) + `search-error`. `_loadState` của `load` không bị đụng: trạng thái tìm
  riêng (`_searchState`), `_syncLoadUi` ưu tiên trạng thái tìm khi có query ≥ min-chars.
- `close()` / gán `search` mới / `destroy()` / `disconnectedCallback` → hủy debounce + abort + seq++; close xoá query
  và về danh sách gốc (như hiện nay).
- Type-ahead trên trigger đóng (1740-1810) giữ nguyên (chạy trên các dòng đang có), không gọi server.
