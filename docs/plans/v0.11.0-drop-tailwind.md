# Plan — v0.11.0: drop the Tailwind peer dependency

ADR 0008 (drop Tailwind → token CSS), batch-4 inventory §6 (checklist) and D25. Branch `feat/v0.11.0-drop-tailwind`.
Every component is token-native since v0.10.0 (`_meta.mixed` empty, no `adoptStyles`). This release removes what is
left so a site needs **only `td.css`** (and a bundler for the ES modules). The version name is 0.11.0; the user may
rename it 1.0.0 (tag only) — no code depends on the number.

## Scope (from inventory §6, verified by a class-token scan of `src/**`)

1. **`td-sample`** (`src/base/sample/td-sample.js`, public export `./sample`) is the only component still rendering
   Tailwind classes. Rewrite it token-native: block `.td-sample` in a new `src/styles/components/sample.css`
   (`@layer td.component`, tokens only), the button as `.td-btn .td-btn--primary .td-btn--sm` markup. Same public API
   (attributes `label`, `count`, `disabled`; event `count-change`). **Wire it into the build** (review ISSUE-1): add
   `components/sample.css` to `src/styles/manifest.json` (before `utilities.css`), rebuild + commit `td.css`, extend the
   block-presence test (`src/styles/td-css.test.js`) with `.td-sample`. **Browser test** (review ISSUE-5) loading
   `td.css` only (no Tailwind): markup/classes, label escaping, count increment + `count-change`, `disabled` blocks the
   increment, the button gets the `.td-btn` look (computed style from td.css).
2. **Storybook**: remove `import '../src/styles/tailwind.css'` from `.storybook/preview.js`, delete
   `src/styles/tailwind.css` and `postcss.config.js`; stories keep working with `td.css` + `story-layout.css`
   (verified by `storybook build` and screenshots).
3. **`demo.html`**: drop the Tailwind CDN script, link `td.css`, replace the page's Tailwind layout classes with a small
   `demo.css` next to it (page chrome only), keep every demo working.
4. **package.json**: remove the `tailwindcss` peer dependency (+ its `peerDependenciesMeta` entry if any) and the
   `@tailwindcss/postcss` devDependency; bump `version` to 0.11.0 and refresh `package-lock.json` (root `version` fields,
   the removed root peer + direct `@tailwindcss/postcss` entries; `@tailwindcss/cli` stays) with
   `npm install --package-lock-only --ignore-scripts`, reviewing the lockfile diff (review ISSUE-2). **Keep** `@tailwindcss/cli` (devDependency) and `build:csp-fixture`: the
   `legacy+td` CSP profile loads Tailwind next to `td.css` as a **host-interference** check (Tailwind hosts such as dcms2
   must not alter td components). Profile ids stay (`legacy`, `legacy+td`) to keep baselines and scripts stable; their
   meaning is documented: `legacy` = td.css only, `legacy+td` = host Tailwind + td.css.
5. **Guard test**: a node test (`src/styles/no-tailwind.test.js`) scans every non-test `src/**/*.js` for
   `class=`/`className=` string tokens and fails on any token that is not `td-*`, `sb-*` (story layout), `fd-*`
   (foundations stories) or an interpolation — so Tailwind cannot creep back into rendered markup.
6. **Docs**: README (install/setup: `td.css` only, how Tailwind hosts coexist), docs/components.md (remove "legacy /
   needs Tailwind" notes), architecture.md (style model section: current, not "target"), conventions.md, vision.md,
   CLAUDE.md (stack table), ADR 0002 → Superseded by 0008, ADR 0008 status → Done (0.11.0), ADR 0005 re-checked
   (its status line was already updated in 0.10.0: adopted sheets superseded for components; verify no remaining wording
   implies components rely on them — review ISSUE-4), roadmap, CHANGELOG 0.11.0
   (Breaking: peer removed; `td-sample` DOM), docs/README status.

## Not in scope

New components (td-menu, td-chip-input, FormValidation — next releases); renaming CSP profile ids; removing the
Tailwind host-interference fixture; any change to component behaviour.

## Sequence

Implement on the branch (lead, no agents — small) → `npm test` + storybook build + screenshots → Codex impl-review
(no user-input surface changes → no security review unless the diff touches input handling) → merge `--no-ff` into
`main`, tag `v0.11.0`, never push.

## Acceptance

`npm test` green (node incl. the guard test, browser, CSP both profiles, token gate); storybook builds without
Tailwind/PostCSS; demo.html works with `td.css` only; the guard test (item 5) passes and no `src/**` module imports Tailwind (explanatory
comments such as "no Tailwind" are allowed — review ISSUE-3); package.json has no Tailwind peer; Codex impl-review APPROVE.
