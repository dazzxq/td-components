**Pre-existing cross-component bugs found while surveying (fixed "for free" by a token z-scale, see D5):**

1. **TdLoading renders UNDER any open TdModal.** Modal roots get inline `z-index: 9999 + 100·i`

3. **On a non-Tailwind site (dwp, 135 — the target consumers) the dropdown menu is not hidden, not fixed, and the

## 1. td-tooltip (`src/feedback/td-tooltip.js`, 515 lines)

### 1.1 Public API

- Exports `class TdTooltip` and the **auto-initialised singleton `tdTooltip`** (:505-515). Importing the module has
  a side effect: `init()` on DOMContentLoaded or immediately (`typeof document` guard, SSR-safe). Package export
  `./tooltip` (package.json:44).
- Declarative contract (the real public API): any element with `data-tooltip="text"`; optional
  `data-tooltip-position="top|bottom|left|right"` (default top, :333), `data-tooltip-color` (any CSS colour → tooltip
  background, :261-264), `data-tooltip-text-color` (:264-266; default: black/white by a simplified luminance,
  :496-502).
- Instance methods (public by shape, used by tests): `init()` (idempotent, :43-49), `show(el)` (:240-307), `hide()`
  (:312-320), `position(el)` (:328-428), `disconnect()` (only disconnects the MutationObserver, :227-232 — the four
  document listeners are **never removed**), `getTooltipContent(el)` (:458-460), helpers `isCurrentlyHovering`,
  `isMouseOverElement`, `_shadowRGBA`, `_toComputedRGB`, `_getAccessibleTextColor`. Fields `tooltip`,
  `tooltipContent`, `tooltipArrow`, `currentElement`, `isVisible` are read by tests (td-xss :149-159).
- Behaviour: capture-phase `mouseenter`/`mouseleave`/`mousemove` on `document` (:121-177) with internal-movement
  detection (icon ↔ text inside a button, :140-152); hide on scroll (capture), resize, window blur, Escape
  (:180-189); **30 s auto-hide "safety"** (:301-304); strips `title` from every `[data-tooltip]` element, at init and
  via a body-subtree MutationObserver (:196-222, and again in `show()` :247).
- **No keyboard trigger at all** (no focusin/focusout), no touch handling (mobile browsers synthesise `mouseenter`
  on tap → tooltip shows on tap and stays until scroll or 30 s).

### 1.2 Rendered DOM (createTooltipElement, :55-112)

```
<body>
  …
  <div class="td-tooltip" (CSSOM cssText: position:absolute; z-index:10010; visibility/opacity/display; glass…)>

    <span class="td-tooltip-arrow" (CSSOM: 0×0 box, 6px transparent border; colour + top/left per placement)></span>
  </div>
</body>
```
Internal classes: `td-tooltip`, `td-tooltip-content`, `td-tooltip-arrow` (hyphen names, not BEM). No `role`, no
`id`, nothing links it to the trigger.

### 1.3 Tailwind + JS-toggled classes

**None.** Tooltip never used Tailwind; everything is CSSOM. No class toggling (visibility via `style.display/
visibility/opacity`, :288-299, :315-317).

### 1.4 CSSOM / adoptStyles

- No adoptStyles. All styling is `el.style.cssText` (CSP-allowed CSSOM, INVENTORY.md:48): root :58-84 (absolute,
  z 10010, `rgba(30,30,30,.75)`, `blur(12px) saturate(160%)`, 10 px radius, `rgba(255,255,255,.1)` border,
  14 px/1.4, `max-width: 280px`, **`min-width: max-content`**, `box-shadow 0 8px 32px …`, centred text, 150 ms
  opacity/visibility transition); content :89-92; arrow :97-103.
- `show()` rewrites bg/colour/box-shadow/**backdrop-filter**/border on every show (:272-281) — liquid-glass row 279
  explicitly says "Không set `style.backdropFilter` từ JS (dòng 275), để CSS lo".
- `position()` writes `left/top` (page coordinates incl. scroll, :336-410) and the arrow's `borderColor/top/left`
  (:348-427).
- `_toComputedRGB()` appends and removes a probe `<div>` on `<body>` per call (:479-488) → triggers the body
  MutationObservers (tooltip's own + inert-lock's `sync()` while any lease is held).

### 1.5 Variants

4 placements (no auto-flip; clamped into the viewport with 10 px padding, arrow re-aimed at the anchor, :398-427);
custom background/text colour; that's all. **`min-width: max-content` beats `max-width: 280px`** (min-width wins in
CSS), so long text never wraps and wider-than-viewport tooltips overflow even after clamping.

  `tdTooltip.show(target)`, reads `tdTooltip.tooltip` (`querySelector('img')`, `textContent`), `tdTooltip.hide()`.

- Stories `src/feedback/td-tooltip.stories.js` (78 lines): Tailwind wrappers/buttons, `data-tooltip-color` demos

### 1.7 A11y / quality gaps

1. **Invisible to assistive tech**: no `role="tooltip"`, no `aria-describedby` on the trigger → the text is never
   exposed. Icon-only buttons that rely on the tooltip for meaning are **unnamed**.
2. **Strips `title`** from every `[data-tooltip]` element (:196-222, :247). When `title` was the only accessible name
   (common for icon buttons) the tooltip **removes the name** and replaces it with nothing (gap 1).
3. **No keyboard access** (WCAG 2.1.1 / 1.4.13): no focusin/focusout. dwp added it (`ui-tooltip.js:133-139`).
4. **WCAG 1.4.13 content on hover or focus**: *dismissible* ✓ (Escape, :187-189); *hoverable* ✗ (root is
   `pointer-events: none`, :64 — the pointer cannot move onto it); *persistent* ✗ (30 s auto-hide, :301-304).
5. Touch: shows on tap, never on long-press intent; covers content until scroll.
6. Custom colour: `data-tooltip-color` is not validated (CSSOM can't be injected, but invalid values silently fall
   back); `_getAccessibleTextColor` uses a simplified luma, not WCAG relative luminance; `_toComputedRGB` regex only
   matches `rgb()` (any alpha → `null` → hard-coded teal shadow `rgba(45,162,199,…)`, :470).
7. Position `absolute` + page scroll offsets (:330-339): wrong if `<body>` is positioned/transformed; 135 uses
   `fixed` + viewport coordinates.
8. z 10010 is below a second stacked modal (common infrastructure bug 2); when a modal is open the tooltip root is a
   body child with no lease → it becomes `inert` under the future modal lease (hidden from AT; see D4).
9. Leaks: `disconnect()` leaves 7 document/window listeners; there is no teardown for SPA/HMR.

### 2.7 A11y / quality gaps

1. **Contrast fails for every variant**: white 14 px text on `green-500` 2.28:1, `yellow-500` 1.92:1, `red-500`

2. **Live region created together with its content**: each toast is a new `role=status` element inserted with its
   text already inside (:171-177). `role=alert` insertions are announced reliably; **`role=status` insertions are
   not** (NVDA/JAWS/VoiceOver frequently skip a live region that did not exist before the change). The container is
   not a live region either.

6. Stacking: z computed from the modal stack with `getComputedStyle` per toast; container z is rewritten every time;

7. Icons defined but never rendered → colour is the only variant cue (WCAG 1.4.1 use of colour).

2. **Close button unnamed** (icon-only `<button>`, no `aria-label`; dwp: "Đóng", :96); X colour `gray-400` 2.54:1

   (opens a modal from a field) loses the field focus every time.
4. **No focus fallback**: with no focusable content (e.g. `closable:false`, body text only, no footer) nothing gets
   focus — dwp focuses the dialog (`tabindex=-1`, :77, :243). Initial focus order is `focusTarget` > first body input
   > first focusable (usually the X). dwp skips the X (:238-239).
5. **Weak trap**: the handler is on the modal element (:716), so it only runs when focus is already inside; a click on

6. **Background not inert** (no `acquireInert`); screen-reader virtual cursor reads the page behind.
7. **ESC**: correctly never closes (ADR 0006, keep), but there is no arbitration either: dwp's lesson (:183-205) is

   inside the dropdown's search box is hijacked by the trap. td's trap today ignores Tab from the portaled search
   input only because focus is outside the modal (gap 5) — i.e. it works by accident.
8. `onClose` fires before removal and before focus restore; `closeById` of a **non-top** modal must not move focus.
9. Motion: spring scale + fade via CSSOM, no reduced-motion path. Stack scrim 12.5–20 % black is weak;
   liquid-glass R12 wants `--td-glass-scrim` (45 % / dark 60 %), not blurred.
10. Glass: `bg-white/[0.9]` + `border-white/50` + blur 24 px → R6/R14 violations; stacked dialogs all keep glass
    (R3: only the top dialog keeps glass, covered dialogs go solid).
11. Headings: always `h3` (dwp uses `h2`); `showHeader:false` leaves no name at all.
12. z-scale: 9999+ inline breaks the token scale (bugs 1–2); toast derives from it with `getComputedStyle`.

State contract:
- **Stack** (`TdModalStackManager`): keeps `stack`, `push/pop/getTop/getStackSize/removeById/closeAll/
  ensureScrollState/generateId` and still computes `instance.zIndex/backdropOpacity/stackIndex` (read-only compat);
  **stops writing `style.zIndex` and backdrop opacity** unless a consumer changed `BASE_Z_INDEX` (D5). Sets
  `data-covered` on every non-top root and removes it from the new top on pop/remove. `closeAll()` delegates to a
  per-instance `close()` (as dwp) so traps, leases, focus and `onClose` all run once.
- **Open**: capture `opener = document.activeElement`; append root with `hidden` removed and `data-state="opening"`,
  push, `acquireInert([root], 400)` + scroll lease (existing), then after 2 rAF (liveness-checked as B2) set
  `data-state="open"`, run initial focus: `focusTarget` > first body field > first focusable **other than the X** >
  the X > the dialog (`tabindex=-1`), then call `onShow(root, onShowPayload)` in try/catch (D7).
- **Keyboard**: one document `keydown` **capture** listener shared by the stack; acts only for the top modal and
  only if no higher floating layer is open (`hasFloatingAbove(400)`, D4). Tab: wrap within the dialog, and pull focus
  back if it is outside (lightbox `trapTab` semantics). Escape: **ignored** (ADR 0006) and never
  `stopPropagation`ed, so popovers/tooltip get it. A `focusin` guard re-focuses the dialog if focus lands outside
  the top modal and outside any registered floating layer (toast, menu).
- **Close** (any path: X, footer, `close/closeById/closeAll`, datetime-picker): idempotent per instance; release
  inert + scroll, `data-state="closing"`, remove after `--td-dur-base` (or immediately with reduced motion),
  **restore focus to `opener` only if this modal was the top one and `opener.isConnected`** (else, if another modal
  becomes top, focus its dialog), then `onClose`. Order change (onClose after focus restore) documented.
- **Async actions** (additive, D6): `show({ actions: [{ label, variant, value, close, disabled, onClick }] })`
  renders `.td-btn`s in the footer; thenable result → `aria-busy="true"` + `disabled` on the other actions and the X
  while pending; resolved `false` (or sync `false`, or `close:false`) keeps the modal open; rejection keeps it open
  and re-enables. `footer` (raw elements) keeps working unchanged; `actions` wins if both are given.
- **Promise dialogs**: same resolve-once semantics; `role="alertdialog"` + `aria-describedby` → message; `message`
  rendered with `textContent` (no more `escapeHtml` into an HTML string), additive `messageHtml` (trusted, D8);
  `confirmVariant` allowlist → `.td-btn--{variant}`, unknown → primary.
- **Sizing**: `size` → modifier class; `width`/`height` → `--td-modal-w/-h` after a dimension check (D22);
  `fullViewport` → `td-modal--viewport` (100vw × 100dvh, radius 0, no sheet); `bodyPadding` →
  `--td-modal-body-pad`, `bodyOverflow` allowlist `visible|hidden|auto|scroll|clip` → `--td-modal-body-overflow`.
- Tokens (new, tokens.css + theme-dark.css where colour): `--td-modal-w-xs 20rem, -sm 24rem, -md 32rem, -lg 42rem,
  -xl 48rem, -2xl 56rem, -3xl 64rem, -4xl 72rem, -5xl 80rem, -full calc(100% - 2rem)` (the old `sm:` breakpoint
  values; < 640 px is a sheet anyway), `--td-modal-radius: var(--td-glass-radius)`, `--td-modal-sheet-radius: 24px`,
  `--td-modal-pad-x/-y`. Reduced motion: opacity only (no scale/translate). Forced colours: dialog `Canvas` +
  `1px solid CanvasText` (recipe), backdrop stays (it is not colour-bearing information).

## 9. Open design decisions (recommended answers)

| # | Question | Recommendation | Why |
|---|---|---|---|
| **D1** | Does td-dropdown become the base of the future `td-menu`? | **No.** Extract shared **floating primitives** instead: `src/utils/floating.js` (`placeFloating(trigger, panel, {gap, margin, listSelector, maxListPx})` = today's `_placeMenu`, reference-hidden check, RAF scroll/resize, outside-pointerdown) + the layer registry (D4) + a CSS surface contract (`.td-dropdown__menu` and future `.td-menu` both = glass strong, `--td-glass-pad/-radius`, concentric items). td-dropdown and td-menu (and later datetime popover, chip-input suggestions) consume them. | Different semantics: dropdown = form-associated value picker (`combobox`+`listbox`, `aria-selected`, FormData, error contract); menu = actions (`menu`/`menuitem`, no value, no form, roving focus not activedescendant, submenus, danger items). | **D2** | Popover API / top layer vs body portal | **Body portal + z tokens for 0.9.** Revisit top layer only as a whole-system switch (modal, loading, lightbox, toast, menus together) in 1.x. | Mixing is the trap: a `popover` menu in the top layer renders **above** the loading overlay (480) and toasts regardless of tokens; modal as non-top-layer can't sit above it.
