## 1. td-menu (sources: dwp `menu.js` + `ui-menu-button.js`, 135 kit CSS)

### 1.1 Source API survey

**`openMenu(anchor, items) → HTMLElement|null`** (dwp menu.js:258-512; 135 port identical API, 135 menu.js:4-16
documents it):
- **Toggle**: same anchor already open → close, return `null` (:259-263). Otherwise closes any open menu first —
  **one menu at a time** (module-level `current`, :22, :264).
- Guard: no anchor / empty `items` → `null` (:265-267).
- Item shape (135 menu.js:9-16 is the clearest summary):
  - `{ label, onClick?, danger?, icon?, checked?, disabled?, hint?, action?, node?, keepOpen? }`.
  - `label` → `span.dwp-menu__label` via `textContent` (:289-292) ✓ safe.
  - `icon` → dwp: `<i class="dwp-icon dwp-icon--{slug}">` mask (:294-299); 135: `<svg><use href="#td-icon-{slug}">`
    sprite that the **page must pre-mark** (135 menu.js:304-311). Both trailing (label `flex-grow` pushes it right,
    :293 comment "phong cách X/Threads"). Slug sanitised `[^a-z0-9-]` (:296).
  - `danger` → modifier `dwp-menu__item--danger` (:287).
  - `checked: boolean` → `role="menuitemradio"` + `aria-checked` + JS class `is-checked` + trailing sprite check
    `#dwp-icon-check` (:300-308, :28-37).
  - `disabled` → **real `disabled`** + `aria-disabled` + class `is-disabled`; `hint` → `title` + `small.dwp-menu__hint`
    — **hint is rendered only for disabled items** (:318-331). No `onClick` attached (:316-317).
  - `action: { svg, label, onClick }` → a sibling `button.dwp-menu__action[role=menuitem]` in a `.dwp-menu__row`;
    **`act.innerHTML = it.action.svg`** (caller-supplied SVG string, :364) — a raw-HTML hatch. No current caller in
    dwp or 135 (grep `action: {` → 0 hits outside menu.js).
  - `node: HTMLElement` → appended as-is in `.dwp-menu__custom`, no close on interaction (:275-284). Real caller:
    the theme switch in the "me" menu (aehh-theme sidebar.js:168-170, `{ node: buildThemeControl(), keepOpen: true }`).
- DOM: `div.dwp-menu[role=menu]` appended to `<body>` (:269-272, :382); items `button.dwp-menu__item[role=menuitem]`
  (:285-288). **No accessible name** on the menu (no `aria-labelledby` to the anchor); no `id`, anchor gets no
  `aria-controls`.
- Position (:237-256): below, **right-aligned to the anchor** (`left = r.right - mw`), clamped with 8 px padding,
  flipped above when it would overflow the bottom; written through CSSOM `el.style.top/left` (CSP-legal, see the
  2026-09-21 correction :391-396). No list height cap (long menus overflow the viewport).
- Anchor: `aria-expanded="true|false"` only (:398-400, :231-233).
- Dismiss: outside `pointerdown` (capture) → close **and swallow the rest of that gesture** (`click`/`auxclick`/
  `contextmenu` of the same pointer, `swallowGestureActivation`, :56-219, 7 review rounds of edge cases) + stop the
  `pointerdown` itself (+ `preventDefault` for mouse only, :402-423); `window resize` → close; **any `scroll` (capture,
  including inside the menu) → close** (:503-504).
- Keyboard (document capture listener, :471-504): ArrowUp/Down with wrap, Home/End → real `focus()` on
  `.dwp-menu__item:not([disabled]), .dwp-menu__action:not([disabled])` (:445-469); Escape/Tab → preventDefault +
  stopPropagation + close + focus anchor (:490-499) — **the listener stops propagation of arrow keys globally while
  a menu is open, even when focus is elsewhere** (:478-480). No type-ahead, no Enter/Space handling (native button
  activation), no ArrowUp-opens-at-last.
- Initial focus: first `.dwp-menu__item` (:507-510) — disabled items are `disabled` so `focus()` on the first one
  fails silently if it is disabled (the selector does not exclude `[disabled]` here, :507).
- `closeMenu()` exported (:221-235).

**`ui-menu-button.js`** (dwp :1-69; 135 port 70 lines):
- `openMenuButton(anchor, getItems)` (:15-23): items built **lazily at open** (`getItems()`), then `openMenu()`; no
  early return on `[]` so a same-anchor toggle still closes (:20-22). Used by SSR buttons through event delegation
  (aehh news-card-menu.js:42-65, sidebar.js:157-178, social-actions.js:1232, :1376, :2299, :3058; 135
  admin-roll.js:92).
- `createMenuButton({ icon = 'ellipsis', ariaLabel = 'Tùy chọn', label = '', getItems, items })` (:25-67) →
  `button.dwp-menu-btn[aria-haspopup="true"][aria-expanded="false"][aria-label]`, sprite icon
  `svg.dwp-icon > use[href=#dwp-icon-{slug}]` (:41-52), optional `span.dwp-menu-btn__label` (:53-57); click →
  preventDefault + stopPropagation + `openMenuButton` (:60-64).

**Consumers (what the API must cover):** share menus (social-actions.js:1565-1571: 5 items with icons), report

### 1.3 Behaviours: keep vs drop

| Source behaviour | Decision | Why |
|---|---|---|
| Imperative `open(anchor, items)`, lazy `getItems`, same-anchor toggle, one menu at a time | **Keep** (D1) | Every consumer is imperative + delegated; lightbox toolbar hands an anchor it owns |
| Items as `<button>`, label via `textContent` | **Keep** | Safe, native activation |
| `danger`, `checked` (radio), `disabled` + `hint` | **Keep**, `hint` for any item (fixes 135 site.js:21-22), disabled = `aria-disabled` (still focusable, D6) | APG: disabled menu items stay discoverable by arrow keys |
| `icon` via page sprite `<use href>` / mask `<i>` | **Replace** with the td registry (`data-td-icon` + `fillIconSlots`) | ADR 0010; no page-level sprite dependency |
| `action: { svg }` sibling button (innerHTML) | **Drop** (D6) | Raw-HTML hatch, 0 callers, nested row breaks the menu model |
| `node` custom content (`keepOpen`) | **Drop**; cover its only use with `type: 'checkbox'` (`menuitemcheckbox`, stays open) | A switch inside `role=menu` is not reachable: arrows skip it (:445-447) and Tab closes the menu (:490-499) |
| Links via `onClick: location.href` | **Add** `href` items (`<a role=menuitem>`, scheme whitelist) | Real links: middle-click, new tab, status bar |
| Position right-aligned, flip, no height cap, close on any scroll/resize | **Replace** with `placeFloating` + `align: 'end'` + list cap + reposition on scroll + close when the anchor is hidden (D7) | Same rules as dropdown (0.4.1 B5); scrolling inside a long menu must not close it |
| Hand-written capture `keydown` on document (Escape/Tab/arrows, global stopPropagation) | **Replace**: Escape/Tab via `layers.js`; arrows/Home/End/type-ahead on the menu element only | Architecture rule: components never listen for Escape/Tab on document (architecture.md "Lớp nổi") |
| `swallowGestureActivation` (outside press only dismisses) | **Drop** for 0.12 (D5) | 160 lines of engine-specific gesture logic; inconsistent with td-dropdown; revisit if dwp migration proves it necessary |
| `__dwpPopover` JS-property marker | **Drop** | `layers.js` registry is the td equivalent (`hasActiveAbove`) |
| z-index scan of `.dwp-modal` (removed 2026-09-21, :383-390) | n/a | td z = tokens; floating lease handles modals |
| Focus not restored after mouse activation (:333-338) | **Fix**: close → focus anchor → then call `onSelect` | Modal opened from a menu item must restore to the anchor |

### 1.4 A11y target (WAI-ARIA APG "Menu Button" + "Menu")

- Trigger: `aria-haspopup="menu"` (ARIA 1.2 value; `"true"` is equivalent), `aria-expanded`, `aria-controls` = menu
  id **while open**. Keys on the trigger (only when bound by td, D1): Enter/Space/ArrowDown → open + focus first
  enabled item; ArrowUp → open + focus last. A site's own button that just calls `TdMenu.open()` from `click` still
  gets Enter/Space for free (native activation) — documented.
- Menu: `role="menu"`, `aria-labelledby` = trigger id (auto-assign `td-menu-trigger-{n}` if missing) or
  `aria-label` option; `aria-orientation` default vertical (omit). Items `role="menuitem" | "menuitemradio" |
  "menuitemcheckbox"`, `tabindex="-1"`, **roving real focus** (D2). `role="separator"` for dividers (not focusable).
- Keys in the menu: ArrowDown/ArrowUp (wrap), Home/End, **type-ahead** (printable char → next item whose label
  starts with it, `fold()` diacritic-insensitive, 500 ms buffer — APG "should"), Enter/Space activate (native on
  `<button>`; `<a>` needs Space handled), Escape → close + focus trigger (layers), Tab/Shift+Tab → close + focus
  trigger then let the key continue (D4). Disabled items (`aria-disabled="true"`) are focusable by arrows, not
  activatable (APG "Keyboard Navigation Inside Components: focusability of disabled controls").
- Checkable items: `aria-checked`; radio closes the menu, checkbox **keeps it open** and toggles in place (APG
  allows either; the theme-switch use case needs open).
- Hint: `span.td-menu__hint[id]` referenced by the item's `aria-describedby` (not `title`, which duplicates on
  hover and is not reliably announced).
- **Submenus: out of scope** (D25). No consumer uses one; APG submenu keyboard (ArrowRight/Left, hover intent,
  nested boundaries) would double the component.

### 1.5 Security

- `label`, `hint`, `ariaLabel` → `textContent` / `setAttribute` only (build with DOM APIs, or `escapeHtml` in a
  template). Never `innerHTML` of item data.
- `icon` → registry name only (`hasIcon()`); unknown → no icon. Optional `iconNode: SVGElement` (trusted, cloned,
  `aria-hidden`) exactly like the lightbox toolbar (td-lightbox.js:416-425). No SVG strings (drops dwp `action.svg`,
  menu.js:364).
- `href` → `new URL(href, location.href)` + protocol whitelist `http:`/`https:` (security.md §4 "URL từ dữ liệu
  ngoài qua whitelist scheme"); anything else (`javascript:`, `data:`) → item rendered disabled + `console.warn`.
  `target="_blank"` only via an explicit `newTab: true` (+ `rel="noopener noreferrer"`).
- Ids generated from a counter, never from labels; no selector built from data.

### 1.6 Proposed public API

```js
import { TdMenu } from '@dazzxq/td-components/menu';        // src/feedback/td-menu.js, class TdMenu (static)

// 1. Core — any anchor (SSR button + delegation, lightbox toolbar button, JS-created button)
const handle = TdMenu.open(anchor, items | () => items, {
  align: 'end',            // 'start' | 'end' | 'center' (default 'end' = dwp/135 look)
  side: 'bottom',          // preferred side, flips when there is no room
  label: '',               // menu aria-label when the anchor has no usable name
  onClose: (reason) => {}, // 'select' | 'escape' | 'tab' | 'outside' | 'hidden' | 'api'
});                        // → { element, close(), isOpen } | null (toggle-close or empty items)
TdMenu.close();            // closes the open menu (no-op when none)
TdMenu.isOpen(anchor?)     // boolean

// 2. Convenience — wire a button you own (aria + ArrowDown/ArrowUp open + click toggle)
const unbind = TdMenu.bind(button, items | () => items, opts);

// 3. Factory — port of createMenuButton, returns a bound <button class="td-menu-btn">
const btn = TdMenu.button({ icon: 'more', label: '', ariaLabel: TdMenu.labels.trigger, items | getItems, ...opts });

TdMenu.labels = { trigger: 'Tùy chọn' };   // site-overridable (TdModal.labels pattern)
```

Item (`items: Array<Item>`):
```js
{ label: string,                 // required (text)
  onSelect?: (ctx) => void,      // alias onClick (dwp compat); ctx = { item, anchor, checked }
  href?: string, newTab?: boolean,
  icon?: string, iconNode?: SVGElement,
  hint?: string,                 // secondary line, any item
  danger?: boolean, disabled?: boolean,
  type?: 'item' | 'radio' | 'checkbox',   // default 'item'; `checked: boolean` without type → 'radio' (dwp compat)
  checked?: boolean,
```

### 2.5 Security

- Chip labels, option labels/descriptions, typed text in the create row, status messages → text only

### 3.2 Bugs / gaps verifiable by reading

1. **Focus-first no-ops on wrappers**: `_focusElement` returns after `el.focus()` whenever `focus` is a function
   (:147-155) — true for every `HTMLElement`, so a `[data-field]` wrapper `<div>` is "focused" (nothing happens) and
   the inner-control fallback (:157-158) is dead code. (td elements are fine: `TdFormElement.focus()` delegates,
   td-form-element.js:458-462.)
2. **First invalid = server key order**, not document order (:284-297) → focus can land mid-form.
3. Double scroll + motion: `focus()` already scrolls; then an unconditional **smooth** `scrollIntoView` ignores
   `prefers-reduced-motion` (:161-168).
4. Native fallback without id: note selector `:scope > .dcms-form-error-note` (:87-90) matches **any** note in the
   same parent → two id-less controls in one wrapper share/overwrite one note; ids from `Math.random()` (:96).
5. `aria-errormessage` without `aria-describedby` (:106) — patchy AT support (td's contract adds both,
   td-form-element.js:341).
6. `summaryContainerId` wipes the container with `innerHTML = ''` (:243) — destroys site content in it.
7. `role="alert"` + `aria-live="polite"` on the same node (:201-202); `a[href="#"]` links (:215-218) — should be
   buttons (or real `#id` fragment links).
8. `fieldMap` ids resolved globally (:57) → a stale id outside the form (another open modal) gets the error.
9. `apply()` never clears fields that are no longer in the error map; callers must call `clear()` first (topics
   does, :1280) — easy to forget.
10. Errors never clear on edit — the red note stays after the user fixed the value until the next submit.
11. No client-side validation at all; topics duplicates constraints td components already compute (see correction 1).

### 3.3 Behaviours: keep vs drop

| Keep | Drop / change |
|---|---|
| Static, stateless API (`apply`, `clear`) + `{ applied, unmapped }` result | Add `validate()` (client, from constraint validity) and `attach()` (submit + live revalidation) (D15) |

### 3.4 A11y target

- Per field: exactly the TdFormElement contract — `aria-invalid="true"`, note id in `aria-errormessage` **and**
  `aria-describedby` (page ids preserved), note text = message. Native controls get the same through the fallback.
- On a failed submit/validate: focus the **first invalid control in document order** (`compareDocumentPosition`),
  which also scrolls it into view (native); announce via the summary (`role=alert`, created fresh so it is
  announced) when shown, otherwise the focused field's description carries the message.
- Summary (optional): heading-less `div.td-form-summary[role=alert]` with a title `p` and a list of
  `button.td-form-summary__link` ("{label}: {message}" — label from the field's accessible name when resolvable,
  else the message alone); activating one focuses the field. Unmapped server errors are listed as plain `li` text.
- Live revalidation (after the first failed attempt, D20): errors are removed as soon as a field becomes valid
  (`input`), new errors appear on `change`/`blur` only ("reward early, punish late"); server errors on a field are
  dropped at the first user edit of that field.
- Native browser bubbles: `attach()` sets `novalidate` on the `<form>` (restored by `detach`) so td's inline
  messages are the single presentation; constraint validation itself still runs (`validity`).

### 3.5 Native constraint validation interplay

- **Source of truth = the Constraint Validation API.** td form elements already compute validity on the host
  (`ElementInternals`: `valueMissing`, `tooLong`, `typeMismatch`, ranges… td-input-field.js:436-500;
  td-dropdown.js:366-374; checkable td-checkable-element.js:105-110; datetime D5 bounds). Native controls have
  their own `validity`. `validate(root)` only **reads** `el.willValidate && !el.validity.valid` — no second rule set.
- **Custom rules** (JS, D16) are pushed *into* that API with `el.setCustomValidity(msg)` (TdFormElement implements
  it without wiping subclass flags, td-form-element.js:171-174; natives have it) → a plain `form.submit` /
  `checkValidity()` also honours them, even without TdFormValidation.
- **Which elements**: `root.elements` for a `<form>` (listed elements incl. form-associated td hosts) or a
  `querySelectorAll('*')` walk for a non-form root (dcms modal bodies are `<div>`s) filtered to (a) `TdFormElement`
  instances and (b) `input, select, textarea` that are **not inside a TdFormElement host** — td components render
  unnamed inner natives (td-checkbox.js:44, td-toggle.js:62, td-slider.js:151, td-input-field.js:161) that are
  listed elements of the form and must be skipped. `type=hidden|submit|reset|button|image`, `button`, `fieldset`,
  `output` skipped; `willValidate === false` (disabled, `<fieldset disabled>`, readonly natives) skipped.
- **Messages**: td hosts → `el.validationMessage` (Vietnamese after D21). Natives → `validationMessage` is in the
  *browser's* language, so map the first failing `ValidityState` flag through `TdFormValidation.messages` (vi
  defaults, `{min}/{max}/{minLength}/{maxLength}` placeholders read from the element; `patternMismatch` → the
  element's `title` if present). Per-call `messages: { [name]: { valueMissing: '…' } | string }` overrides.
- **Interplay with `td-input-field[validate-on]`**: both write the same single error slot (`setError`); they agree
  because both use the host's validity message. Documented: with `attach()`, sites should drop `validate-on`.

### 3.6 Security

- Messages (client or server) → the td note / summary via `textContent`; field labels in the summary via
  `textContent`. Server error **keys** are never interpolated into selectors without `CSS.escape` and are resolved
  inside the root only; `fieldMap` ids via `root.querySelector('#' + CSS.escape(id))`.
- No HTML messages (no `messageHtml` hatch). No `style` writes at all (the dcms `#ef4444` border is replaced by the
  site's own `[aria-invalid="true"]` rule for native controls, D18).
