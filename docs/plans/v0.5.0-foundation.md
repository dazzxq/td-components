# Plan — v0.5.0 foundation (token CSS + Liquid Glass)

Status: approved direction ([ADR 0008](../decisions/0008-drop-tailwind-token-css.md)); this plan = implementation.
Branch: `feat/v0.5.0-foundation`. No existing component changes appearance in this release.

## Goal

Ship the token/layer/glass foundation as ONE canonical stylesheet `td.css`, reset-free, so that:
- token-native components (first: `td-lightbox`, next release) can be built on it;
- legacy Tailwind components keep working unchanged (mixed period);
- sites theme by overriding public `--td-*` tokens in unlayered CSS, never editing core.

## Deliverables

1. **`src/styles/`** (authoring sources, plain CSS, no preprocessor)
   - `layers.css` — `@layer td.tokens, td.component, td.utilities;` (the only layer-order statement).
   - `tokens.css` — `@layer td.tokens { :root { … } }`: base tokens adopted from 135 `td-tokens.css`
     (type, spacing, gray ramp, radius, shadow, z-index scale, motion, semantic colours, controls)
     + PUBLIC glass tokens from `docs/design/glass-tokens.css` (light). Neutral palette (not 135's warm paper).
   - `theme-dark.css` — `@layer td.tokens { :root[data-td-theme="dark"] { … } }` token remap only
     (inside the tokens layer, so a site's unlayered `:root { --td-* }` override still wins over it
     regardless of selector specificity; sites override dark values with their own
     `:root[data-td-theme="dark"]` rule). **No automatic
     `prefers-color-scheme`** (user decision: dark is opt-in; light-only sites never flip).
   - `glass.css` — `@layer td.component`: `.td-glass-surface` recipe (Regular) with modifiers
     `--strong` (text-bearing), `--lg` (large: thicker blur + bigger shadow), `--clear` (over media),
     plus `.td-glass-dim` (Clear dimming layer; `--text` variant 60%) and `.td-glass-tint` (one primary
     action on a floating bar). Components read `var(--_td-glass-X, var(--td-glass-X))`-style
     resolution; the fallback block (`@layer td.tokens`, `!important`) sets PRIVATE `--_td-glass-*`
     on every filter/tint-bearing recipe itself (selector list `.td-glass-surface, .td-glass-tint,
     .td-glass-dim` — every public glass recipe is in that list) — never on `:root` — for:
     `@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px)))`
     (exact condition; both properties are always emitted), `prefers-reduced-transparency: reduce`,
     `html[data-td-glass="off"]`, `prefers-contrast: more`, `prefers-reduced-motion: reduce`,
     and `forced-colors: active` LAST (system colour pairs Canvas/CanvasText, no shadow/filter).
   - `utilities.css` — `@layer td.utilities`: `.td-sr-only` only (keep minimal; reset-free).
   - `manifest.json` — ordered file list.
2. **`scripts/build-css.mjs`** — deterministic concat per manifest → `td.css` at package root, with a
   generated-file banner; `--check` mode exits 1 if `td.css` is stale. npm: `build:css`, `check:css`;
   `npm test` runs `check:css` first.
3. **package.json** — export `"./td.css": "./td.css"`, add `td.css` to `files`. Tailwind peer stays
   (legacy components). Vite: `import '@dazzxq/td-components/td.css'`; PHP: `<link rel="stylesheet" nonce>`.
4. **Token-native CSP/glass gate** — new `test/csp/tokens.spec.mjs` (separate from the legacy Tailwind
   parity harness, which is untouched = dual profile). Runs Chromium, Firefox, WebKit
   (playwright-core, browsers already installed). Page serves `td.css` + a glass fixture page:
   - profile A `style-src 'self'`; profile B nonce-only `style-src 'nonce-td'; style-src-attr 'none'`
     with `<link nonce>` → **zero CSP violations** in all 3 engines.
   - computed-style asserts: surface background/backdrop-filter resolve from tokens; a subtree override
     of `--td-glass-bg` on an ancestor reaches the surface (the ADR 0008 `:root`-alias flaw);
     `html[data-td-glass="off"]` → opaque `--td-glass-solid`, no backdrop-filter, even when the site
     overrides `--td-glass-bg` unlayered; `forced-colors` (Chromium emulation) → no box-shadow;
     `prefers-contrast: more` where emulatable; `data-td-theme="dark"` swaps tokens; no dark flip
     without the attribute under `colorScheme: 'dark'` emulation.
   - Every fallback assertion covers Regular surface, Clear surface, tint and dim (not only Regular):
     `data-td-glass="off"` → no backdrop-filter anywhere, tint falls back to opaque `--td-glass-tint`;
     forced-colors → system colours, no shadow/filter on all recipes.
   - Probe (informational, printed + recorded in docs): CSSOM `el.style.setProperty` and
     `CSSStyleSheet.replaceSync` + `adoptedStyleSheets` under nonce-only CSP per engine — decides whether
     legacy `adoptStyles` components can claim nonce-only support (documented, not gated).
   - `npm run test:tokens`; included in `npm test`.
   - **Combined-profile legacy parity**: `test/csp/csp.spec.mjs` gains an opt-in profile
     (`CSP_PROFILE=legacy+td`) that links `td.css` AFTER the Tailwind fixture and compares against the
     SAME existing legacy baselines (no re-capture). `npm test` runs both the unchanged legacy-only run
     and the combined run → proves `td.css` is reset-free for legacy components.
5. **Storybook** — `.storybook/preview` imports `td.css` (reset-free → legacy stories unchanged);
   new `src/styles/foundations.stories.js`: Glass Regular (over text-heavy page), Strong, Clear over a
   photo with dim/dim-text, tint capsule, fallback toggle (`data-td-glass="off"`), dark theme.
   Photo = local generated gradient/SVG (no network, CSP-safe).
6. **Docs** — `docs/architecture.md` style section (how to author component CSS, layers, private vs public
   tokens, override recipe), `docs/design/glass-tokens.css` marked superseded by `src/styles/*`,
   `docs/migration/class-map.md` skeleton (filled per batch), roadmap + CHANGELOG `0.5.0`.

## Out of scope (this release)

Migrating any existing component; Tailwind removal; markup-contract golden fixtures (start with
`td-lightbox`, the first token-native component); refraction; Tailwind preset; auto dark mode.

## Acceptance

- `npm test` green: node, browser (legacy), legacy CSP parity 73/73 unchanged in BOTH the legacy-only and
  the combined (`Tailwind + td.css`) profile, `check:css`, token gate
  (3 engines × 2 CSP profiles, zero violations).
- `npm run build-storybook` OK; legacy stories visually unchanged (td.css reset-free).
- A site can theme by `:root { --td-glass-bg: … }` unlayered without editing core, and cannot defeat
  the reduced-transparency / glass-off / contrast / forced-colors fallbacks that way.

## Risks

- Firefox/WebKit emulation gaps (reduced-transparency, contrast) → assert via `data-td-glass="off"` and
  document which queries were emulated per engine.
- `@layer` + `!important` semantics: important declarations in an earlier layer beat later/unlayered
  important ones — intended for the private fallback block; verified by the gate.
