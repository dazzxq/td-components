### 1.7 A11y / quality gaps (vs WAI-ARIA APG "Date Picker Dialog", "Listbox", "Spinbutton")

1. **Not keyboard-operable at all** (WCAG 2.1.1): the only opener is `click` on a readonly `input` (:239). Enter
   in a readonly text input inside a `<form>` triggers **implicit form submission** instead of opening; Space /
   ArrowDown / Alt+ArrowDown do nothing. The hour/minute wheels are `div`s with click handlers (:454-464): no role,
   no `tabindex`, no key handling — hour/minute are unreachable by keyboard and invisible to screen readers.
2. **Trigger has no accessible name**: the `<label>` has no `for` and does not wrap the input (:219); host
   `aria-label` is ignored; an external `<label for=host>` names the host (FACE) but not the inner input — the
   naming helper `_applyAccessibleName` is never called. No `aria-haspopup="dialog"`, no `aria-expanded`. The
   readonly input reads "edit text, read only", which wrongly suggests the value can't be changed.
3. **Inputs in the modal are unnamed**: `Ngày/Tháng/Năm` labels are sibling `<label>`s without `for` (:339, :344,
   :349). Section titles are `h6` under the modal's `h2` (skipped levels, :336, :376); the time group has no label
   for either wheel ("Giờ"/"Phút"); the `:` separator is read aloud.
4. **Error not exposed**: the modal error box (:354) is a plain `div` toggled with `hidden` — not a live region,
   not linked by `aria-describedby`/`aria-invalid` to the offending input. The host has **no error contract**
   (`error-text`/`setError`) — every other form control has it since 0.7–0.9 (roadmap "every batch ships the error
   contract"); dcms added `setError` to its picker in `7f3f03d5`.
5. **Focus is lost after "Chọn"** (bug 1.8.1): the opener is re-rendered before the modal closes.
6. **Escape does nothing** (TdModal consumes it, td-modal.js:228) — APG date-picker dialogs close on Escape; the
   only way out by keyboard is Tab to "Đóng" (see D4).
7. Motion: smooth scrolling + `scale(1.1)` on the selected option, no `prefers-reduced-motion` handling.
8. Contrast: unselected options `text-gray-400` (2.54:1) are the *choices* the user must read; the grey fade bands
   drop them further; footer "Bây giờ" white on blue-500 3.68:1. Two filled buttons (blue + near-black) in one
   footer (liquid-glass R7: one primary).
9. Touch: options are 40 px high (`h-10`, :361) < `--td-touch-min` 44 px on coarse pointers (R9); the wheel
   relies on JS scroll-end debounce (150 ms, :467-479), not CSS scroll snapping — flings land between options until
   the timer fires, then jump.
10. Picker state leaks: `_setupModalEvents` runs on a fixed `setTimeout(100)` (:421) instead of `onShow` (available
    since 0.9.0); element lookups by global id (collide if two copies of the module are loaded — both start `_nextId`
    at 0).

### 1.8 Bugs verifiable by reading

1. **Focus lost on confirm.** `_confirm()` calls `this.setAttribute('value', value)` (:584) → base
   `attributeChangedCallback` re-renders the host (td-base-element.js:113-117) → the readonly input that opened the
   modal is detached → `_close()` (:592) → TdModal `_closeInstance` sees `opener.isConnected === false`, no modal
   below → `target = null` → **blurs** (td-modal.js:341-348). Focus lands on `<body>` after every successful pick.
   (Closing via X/"Đóng" restores correctly — the opener is still connected.)
2. **Invalid times are accepted and submitted.** The parser accepts any 1–2 digit hour/minute (:114); `_validate()`
   never checks them (:191-207). `value="15/06/2026 - 25:99"` is **valid** and submits `2026-06-15T25:99:00`
   (ISO) — a string no backend parses as intended.
3. **`getValue()` / `getDBValue()` return "now" when empty.** With no value `_initFromValue` fills the parts with the
   current time (:98-104) and `getValue()` formats them unconditionally (:598, :601) → an empty picker reports a
   value. dcms returns `''`/`null` (dcms-datetime.js:1110-1119) — a regression against the port source. After a
   parse error `getValue()` returns stale parts (the previous date), not the raw string.
4. **Year field cannot be typed.** The date inputs clamp on every `input` event (:432-435): typing "2" in the year
   field becomes `2000` immediately, then "20000" → `2099`. Day "0" → 1 (can't type "05"). Only the native spinner
   arrows work. (Same code in dcms :876-889.)
5. **Minute state ≠ what the wheel shows.** On open the minute wheel centres the *snapped* value (:482-486,
   `_snapMinute`) but `this._minute` keeps the unsnapped value until a scroll event fires; when the centring scroll
   is a no-op (e.g. snapped 0 → `scrollTop` already 0) no event fires and "Chọn" commits e.g. `10:02` while the wheel
   shows `00` (the preview also shows `:02`, :391). `_snapMinute` rounds with `Math.round(...) % 60` (:187): 10:58
   with step 5 snaps to **10:00** (no hour carry).
6. **Stale scroll timer mutates the value after confirm.** The 150 ms scroll debounce (:468-478) is never cancelled
   on close; a scroll that ends ≤ 150 ms before "Chọn" fires after `_confirm()` and rewrites `_hour`/`_minute`
   (:511-512) → `getValue()` no longer matches the committed `value` attribute.
7. **`setDBValue` accepts garbage and is engine-dependent.** `new Date(dbValue)` (:628) on `'YYYY-MM-DD HH:mm:ss'`
   (space, no `T`) is implementation-defined (historically Invalid Date on Safari); an Invalid Date yields `NaN` parts
   (the `try` catches nothing) → value `"NaN/NaN/NaN - NaN:NaN"`, then `_syncForm` flags it invalid only via day
   checks. Needs an explicit regex parse.
8. **Disconnect while open**: nothing closes the modal (no `disconnectedCallback`), and "Chọn" then writes to a
   detached host. Toggling `disabled` while open leaves the modal usable.
9. `label`, `placeholder`, `minute-step` changes fully re-render the host (base behaviour) — harmless, but the
   first-render `readonly` input is replaced (see 1.8.1 for why that matters).

### 2.7 A11y / quality gaps (vs WAI-ARIA APG "Table" + "Sortable Table", WCAG 1.3.1/2.1.1/2.4.3/4.1.3)

1. **No table name**: the title is an `h3` in a separate header bar (:391), not a `<caption>` and not referenced by
   `aria-labelledby`; with no title the table is anonymous. The `title` attribute is also the global HTML attribute →
   a native tooltip over the whole table.
2. **No `scope`** on `th` (:351, :358) (fine for simple tables in practice, but cheap to add; row headers unsupported).
3. **Sort state invisible to AT**: no `aria-sort` on the sorted `th`; the state is only the SVG shape/opacity (:226-246);
   the dimmed "sortable" icon (`opacity 0.4` on gray-600) is ≈ 1.9:1 (WCAG 1.4.11 wants 3:1 for the affordance).
   SVGs are not `aria-hidden` (harmless, no title) — the button name is just the label, so "sortable" is not
   conveyed either (APG adds it via the icon or `aria-description`; `aria-sort` on the active column is the minimum).
4. **Focus loss** on sort (:173 `_doRender`) and page change (:219): the whole subtree is replaced → the focused sort
   button / page button is detached → focus on `<body>` (WCAG 2.4.3). td-pagination's own focus restore
   (td-pagination.js:118) runs on the old element that the table then throws away.
5. **Announcements lost / doubled**: each re-render creates new td-pagination elements whose `aria-live` info
   (td-pagination.js:74) is inserted with its content → not reliably announced (same root cause as batch-3 D12);
   when it is announced it is announced by **both** paginations.
6. **Loading is silent**: no `aria-busy`, no status text; skeleton bars pulse (`animate-pulse`) without a
   reduced-motion stop (Tailwind v4 does not gate `animate-pulse` on `motion-safe`).
7. **Horizontal scroller not keyboard-scrollable**: `.overflow-x-auto` (:406) has no `tabindex`/`role=region`/name;
   a wide table without focusable cells can't be scrolled by keyboard (browser auto-focusable scrollers are not
   universal).
8. Empty state duplicates text: title hard-coded "Không có dữ liệu" (:366) + default `empty-text` "Không có dữ liệu"
   (:142) → the same sentence twice. The nested `td-empty-state` also carries a `title` attribute (native tooltip).
   Its dashed card inside the table card is a card-in-card.
9. Row hover uses `:hover` only (fine); no focus-within row highlight; `transition` without reduced motion.
10. Header text `text-xs uppercase tracking-wider` gray-600 on `bg-gray-50/60`: ≈ 7:1, OK.

### 2.8 Bugs verifiable by reading

1. **`zebra` can never be turned off**: `_isZebra() { return !this.hasAttribute('zebra') || this.hasAttribute('zebra'); }`
   (:138) is always true (already recorded as `zebraNote`, matrix.json:762).
2. **Server mode resets the page on every data load.** The documented server flow is `onPageChange(page)` → consumer
   fetches → `table.data = rows`; the `data` setter (and `setData`) sets `_currentPage = 1` (:124, :490) → the table
   shows page N's rows while both paginations say page 1. dcms does not reset on `setData` (dcms-table.js:156). Only
   `update({data, page})` works (:526-530).
3. **Stale page after `per-page`/data shrink** (client mode): `_getCurrentRows` never clamps `_currentPage`
   (:205-208). On page 5 of 47 rows, `per-page="50"` → `start = 200` → zero rows → the **empty state** renders
   ("Không có dữ liệu") while `hasData` (47 > 0) still renders both paginations, which clamp themselves to page 1
   (td-pagination.js:51).
4. **Render column without `key` renders nothing; duplicate keys render the wrong column.** Render cells are
   resolved in `afterRender` by `this._columns.find(c => c.key === colKey)` (:452-454) where `colKey` is the
   escaped **string** from `data-col-key` (:377): `key: undefined` → `''` ≠ `undefined` → cell stays empty; two
   render columns sharing a key (e.g. two `actions` columns) both use the first renderer; a numeric key (`0`) never
   matches `'0'`. The column index (`data-col`) is right there (:378).
5. **Numeric sort keys never show as active**: `_handleSort(btn.dataset.sortKey)` stores the string (:470-471),
   `_getSortIcon(col.key)` compares with `===` to the original (number) key (:227).
6. `update({ data: {} })` (a non-array truthy value) is assigned unchecked (:526-527) → `[...{}]` throws in
   `_getCurrentRows` (:184). The setters guard with `Array.isArray` (:117, :123); `update` does not.
7. Loading skeleton hides the (known) title behind a grey bar (:314) and uses `Math.random()` widths (:305) — the only
   non-deterministic output in the library (excluded from parity, matrix.json:781-786).
8. `_getCurrentRows()` runs twice per render (render :340 + afterRender :444), sorting twice — minor cost, and a
   custom `render()` receives `rowIdx` = index **within the page**, undocumented.
9. Server mode without `total-items`: rows show, pagination says "Hiển thị 0-0 / 0 mục" (:181, `hasData` true via
   rows). Documented default is "—" (components.md:407).
10. components.md:400 still documents `active-color` default `#ef4444` (it is the td-pagination token since 0.8.0).

## 9. Open design decisions (recommended answers)

| # | Question | Recommendation | Why |
|---|---|---|---|
| **D1** | Picker UI model: keep wheels or switch to a grid calendar? | **Keep the current model** (3 date fields + hour/minute wheels in a dialog) and make it accessible: date fields = labelled `input[type=number]` (native spinbutton semantics), wheels = **select-only listboxes** with CSS scroll-snap. **No grid calendar in 0.10** (stays in roadmap backlog "datetime: picker dạng lưới lịch", roadmap.md:66). | Parity with dcms and existing users (same visual model, same values). An APG grid calendar is a new component in all but name: month navigation, 42-cell `grid` with roving tabindex, 12+ key bindings, week start (Mon for vi), disabled days for min/max, plus a *separate* time control anyway — 3–5× the code and tests of the listbox fix. The wheel's real problems (no keyboard, no roles, JS offset math) are fixable locally. Listbox (not spinbutton) for the wheels because the UI shows neighbouring options that are clickable — listbox semantics match what sighted users see; spinbutton would hide that. |
| **D2** | Inline vs modal vs popover | **Modal only (TdModal)**. No inline mode, no anchored popover in 0.10. | TdModal already provides focus move/trap/restore, inert background, scroll lock, mobile bottom sheet and glass — the picker gets all of it for free. A popover needs a floating-layer registration, placement, outside-click and its own focus management (the batch-3 dropdown machinery) for a control used a few times per form. Revisit with the grid calendar. |
| **D3** | Trigger element | **`button[role=combobox][aria-haspopup="dialog"][aria-expanded]`** with the value as its text, label via `<label for>` + `_applyAccessibleName` — same recipe as the batch-3 dropdown trigger (D17 there). Updated **in place** (never re-rendered for value/error/disabled). | A readonly text input announces "read only", triggers implicit form submission on Enter, and gets the muted readonly look from field.css:102-104. `button` alone may not carry `aria-invalid`/`aria-required` in ARIA 1.2; `combobox` may, and "combobox + dialog popup" is the APG date-picker-combobox shape. In-place updates fix the focus loss (1.8.1) at the root. Typing a date directly into the trigger is out of scope (D24). |
| **D4** | Escape inside the picker dialog | Additive TdModal option **`escapeCloses: boolean` (default `false`)**; the picker passes `true`. Implementation: the modal's `onEscape` closes the instance when the option is set and it is not busy (td-modal.js:228). ADR 0006 addendum: allowed only for dialogs whose close loses no user data (the picker keeps a *pending* copy; the committed value is untouched). | APG date-picker dialog: Escape closes. ADR 0006 protects form data in general-purpose modals — that rationale does not apply to a picker. Cost ~5 lines + 2 tests. **Alternative** (zero TdModal change): keep Escape inert and rely on Tab → "Đóng"; acceptable but user-hostile. |
| **D5** | `min` / `max` | Add `min`/`max` attributes accepting the **display format or ISO-local** (`YYYY-MM-DD[THH:mm]`) through the shared parser; validity `rangeUnderflow`/`rangeOverflow` with vi messages ("Không được trước {min}" / "Không được sau {max}"); the panel shows the error and "Chọn" refuses; year field `min`/`max` derived from them. Default range when unset stays **2000–2099** (current behaviour, dcms parity). No disabled options in the wheels. | Real forms need "end ≥ start"-type bounds; accepting ISO matches `<input type=datetime-local>` habits and the submitted ISO; accepting display matches the `value` attribute. Validation-only keeps it small. |
| **D6** | Value / format / locale | Public value contract unchanged: `value` attribute = `dd/mm/yyyy - hh:mm`, FormData per `form-value-format` (iso/display/db). **Move parsing/formatting into pure helpers in `src/utils/datetime.js`** (`parseDisplay`, `parseDb`, `parseIsoLocal`, `formatDisplay/Db/IsoLocal`, `isValidParts`) with node tests, used by the picker (strict regexes, hour 0–23, minute 0–59, real dates). Vietnamese default strings in `static labels` (site-overridable). **No `locale`/`format` attribute**, no 12-hour clock. `TdDateTime.toAbsolute/toISO` bugs (§3) documented, fixed only if trivial. | One tested parser for both the component and the utility removes the three "ISO" meanings and the engine-dependent `new Date(string)` (1.8.7). A locale/format API is a design of its own; td's consumers are Vietnamese sites. |
| **D7** | Time step | Keep `minute-step` (1–30, divides 60). Snap **down** (`floor`) — never into the next hour/day; the snapped value is written to the pending state on open, so the wheel and the committed value always agree. "Bây giờ" snaps down too. Out-of-step committed values stay as-is until the user opens + confirms. | Fixes 1.8.5 without a carry cascade (10:58 → 10:55, not 10:00 or 11:00). |
| **D8** | `getValue()` when empty / malformed | Return `''` (and `getDBValue()` → `''`) when there is no valid value. CHANGELOG as a behaviour fix. | dcms parity (dcms-datetime.js:1110-1119); "now" for an empty field is a silent wrong value. |
| **D9** | Date-field input handling | Validate on `input` (message + `aria-invalid`, no rewriting), clamp on `change`/blur; keep `type="number"` + `inputmode="numeric"`. | Fixes 1.8.4; keeps native spinbutton semantics and arrow keys. |
| **D10** | Picker block names | `.td-dtp` (host), `.td-dtp-panel` (modal body), `.td-dtp-wheel` (wheel) — keep the existing `td-dtp` prefix. | 135 has no picker block to adopt; `td-dtp-` is already the documented prefix (matrix, MATRIX.md), shorter than `td-datetime-picker__…`. |

| **D12** | Sorting | Keep the 3-state cycle and callbacks; `aria-sort` on the active `th` only; registry icons `sort`/`up`/`down` (`aria-hidden`); `Intl.Collator('vi', {numeric:true, sensitivity:'base'})`; additive `sort-change` event; track by column index.
