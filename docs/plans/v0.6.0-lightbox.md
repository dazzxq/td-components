# Plan — v0.6.0 `td-lightbox` (first token-native component)

Decision: [ADR 0009](../decisions/0009-td-lightbox-hooks.md). Clean-room port of the generic core of
`dwp/engine/dwp-core/assets/ui/lightbox.js` (behaviour reference) + `135/public/assets/css/td-lightbox.css`
(BEM CSS starting point). dwp and 135 are NOT modified. Branch `feat/v0.6.0-lightbox`.

## Goal

An image/video viewer any site can drop in: small core, every site-specific concern behind a hook,
token/glass styling from `td.css`, CSP-strict, no window globals, no side effects on import, no new deps.

## Public API (`src/feedback/td-lightbox.js`, export `./lightbox`, re-exported from `index.js`)

```js
import { TdLightbox } from '@dazzxq/td-components/lightbox';
const lb = TdLightbox.open(items, options);   // → handle | null (null when no valid item)
lb.next(); lb.prev(); lb.goTo(i); lb.close(); lb.index; lb.count; lb.token; lb.isOpen
TdLightbox.close(); TdLightbox.isOpen;          // static convenience for the single active viewer
const unbind = TdLightbox.bind(root = document, options); // opt-in click delegation → unbind()
```

- **Item** `{ type?: 'image'|'video', src, poster?, caption?, alt?, provider?, data? }`. `data` is opaque
  (consumer identity for toolbar/panel callbacks). Invalid items (no allowed `src`) are dropped; an empty
  list → `open()` returns `null` and nothing is mounted.
- **Options** (all optional):
  - `index` (clamped), `labels` (Vietnamese defaults: `dialog` "Trình xem ảnh", `prev` "Ảnh trước",
    `next` "Ảnh sau", `close` "Đóng", `back` "Quay lại", `fullscreen` "Toàn màn hình", `download` "Tải xuống",
    `info` "Thông tin ảnh", `counter: (i, n) => \`${i} / ${n}\``).
  - `isAllowedUrl(url, item) → boolean` — default: parse with `URL` against `location.href`; allow `https:`
    always and `http:` only when the page itself is `http:` (security review: no cleartext downgrade); every
    other scheme (data:, blob:, file:, app schemes) must be opted into by the site. Applied to `src`,
    `poster` and download URLs. Fail-closed.
  - `download(item, ctx) → string|null` — null/'' hides the button. Default: same-origin image → its `src`
    (the `download` attribute only works same-origin); otherwise hidden.
  - `video(item, mountEl, { signal }) → {destroy()}|Promise<{destroy()}>|null` — default renders a native
    `<video controls playsinline preload="metadata">` (created with `createElement`, `src`/`poster` via
    `isAllowedUrl`) for `provider` `html5`/absent; non-html5 providers without a hook fall back to the poster
    image. The `signal` aborts on navigate/close; late resolutions are destroyed (render-token guard).
    Plyr is an adapter a site passes here — never bundled.
    **Failure isolation:** a synchronous throw, a rejected promise, or a resolved value without a
    `destroy` function is consumed (never propagates); the mount is emptied and the slide falls back to the
    poster image (or an empty stage when there is none). `destroy()` is called inside `try/catch` — a
    throwing `destroy()` never stops navigation or close teardown.
  - `history`: `false` (default) | `true` | adapter `{ push(), back(), onPop(cb) → unsubscribe }`
    (e.g. a site's navigation controller). `true` is implemented AS an adapter (`pushState` of
    `{ ...history.state, tdLightbox: token }` / `history.back()` / `popstate`) — one code path. Contract:
    - `push()` is called once per viewer session (first `open()`, not re-entrant opens). It may return a
      Promise. Pushed = returned without throwing AND (if a Promise) did not reject; a throw/rejection means
      "not pushed" (close then never calls `back()`), and a late rejection only resets the flag of ITS own
      push (sequence number), never a newer session's.
    - `onPop(cb)` is subscribed on the first successful push and the adapter calls `cb()` when the user
      navigates back off the lightbox entry. The core keeps a pending-back counter: a pop that follows a
      programmatic `back()` is consumed (does not close a newer session); otherwise a pop closes the viewer
      without calling `back()` again.
    - `back()` is called by a programmatic close (✕, Esc, backdrop, swipe, API) only when pushed. It may
      return a Promise; a throw/rejection decrements the pending counter (so the next real Back is not
      swallowed).
    - Unsubscribe happens when the viewer is closed AND the pending counter is 0 (immediately on a
      pop-close, or when the consumed pop / failed back arrives). A new session re-subscribes if needed.
    - **Pending push vs. close (per-session state `none → pushing → pushed`, keyed by session token):**
      - close while `pushing`: nothing is called now; the session is marked closed. If that push later
        fulfils, the core immediately unwinds it with `back()` (counted in the pending-back counter, so its
        pop is consumed). If it rejects, nothing happens. Either way the settlement touches only its own
        session record — never the current session's state or subscription.
      - A new session does **not** push while any earlier history operation is unsettled (a pending push or a
        pending back): it runs history-less (✕/Esc/backdrop still close). This keeps the history stack
        ordering trivially correct; the next session after everything settles pushes normally.
      - Fake-adapter tests: close before push fulfils (→ one unwinding back, pop consumed, viewer stays
        closed), close before push rejects (→ no back), close→open while the first push is still pending
        (→ second session history-less; first push's fulfilment unwinds without closing the second viewer).
  - `panel`: `false` (default) | `true` (built-in caption panel) | `(ctx) → HTMLElement|null` (custom; a
    string is ignored — nodes only). Panel layout (2 columns ≥ 900px, bottom sheet below) is enabled only
    when the renderer returns an element; a throwing renderer → no panel, viewer keeps working.
  - `toolbar: [{ id, label, icon?, iconNode?, onClick(ctx, button), visible?(ctx) }]` — `icon` is a name
    from the shared icon registry (ADR 0010, added to this release at the user's request; replaces the
    earlier `iconPath` idea); `iconNode` is a trusted `SVGElement` (cloned); neither → the label as text.
    Button refs kept in a `Map` (no selector built from `id`). Inserted before the close button.
  - `closeOnBackdrop` (default `true`, ADR 0009: an image viewer has nothing to lose).
  - `isForeignLayerOpen() → boolean` — default: a td-modal is open (`TdModalStackManager.stack.length > 0`).
    While true the viewer ignores keys (Esc/arrows/Tab trap) so dialogs opened on top keep them.
- **ctx** passed to hooks: `{ index, count, item, token, handle }`.
- **Events** on `document`: `td-lightbox-open`, `td-lightbox-change`, `td-lightbox-close`,
  `detail: { index, count, token, item }` (close carries the last index).
- **`bind()`**: delegated `click` on `root` for `[data-td-lightbox]` (single trigger) and
  `[data-td-lightbox-group] [data-td-lightbox-item]` (gallery; index by ELEMENT identity, never by src
  dedupe). Collection keeps `{ element, item }` pairs through validation; invalid pairs are dropped and
  the start index is the position of the clicked ELEMENT in the filtered list (clicking an invalid item
  opens nothing). Item data from `data-td-lightbox-src|type|poster|caption|provider`, else the inner/own `<img>`
  (`currentSrc || src`), a wrapping `<a href>` to an image file, caption from `<figcaption>` → `alt`.
  Ignores modified clicks (ctrl/meta/shift/middle). Calls `preventDefault()` only when it opens.
  Markup contract (SSR adapters emit exactly this) documented in `docs/components.md` with a golden
  fixture `test/contracts/lightbox.html` exercised by the browser tests.

## Behaviour (core, ported + fixed)

- Singleton overlay built on first `open()` (`role="dialog"`, `aria-modal="true"`, `aria-label`,
  `tabindex="-1"`), appended to `<body>`. Re-entrant `open()` while open replaces the gallery (new token)
  without re-locking/re-saving focus.
- Open: save focus, `lockScroll()` lease (shared with the modal stack), background `inert` — record exactly
  the `<body>` children IT set (skip ones already inert, skip `#td-toast-container`) and restore only those;
  2-rAF fade-in guarded by lifecycle + token; focus the dialog.
- Slides: counter (`textContent`), caption (`textContent`), image preload with spinner after 1 s, stale
  results dropped by render token; `alt` from item. Prev/next wrap; buttons + counter hidden for 1 item.
- Close (idempotent): cancel drag/zoom state, abort video, exit fullscreen, release scroll lease, restore
  inert set, history back when we pushed, restore focus if still in the DOM, emit event.
- Keyboard (listener added on open, removed on close): Esc close, ←/→ navigate, F fullscreen, Tab trap.
  `isForeignLayerOpen()` suppresses ALL lightbox keys (the layer on top owns the keyboard). Focus inside the
  video mount (or `defaultPrevented`) suppresses only the media-conflicting keys (arrows, Esc, F) — **Tab
  always runs the dialog trap**, including focusable descendants supplied by the video hook.
- Pointer Events (one code path for touch/pen/mouse; no `'ontouchstart'` sniffing): two pointers → pinch
  1–4×; one pointer while zoomed → pan (clamped to the clipping column, not the stage); double-tap (touch/pen)
  or click (mouse) → toggle 2× at the point; mouse move while zoomed → pan; not zoomed: horizontal swipe
  > 50 px → navigate, vertical down > 90 px → animated close (stage follows the finger via CSSOM
  `--td-lb-drag`), up > 60 px → open the panel sheet. Fixed 190 ms timer (not `transitionend`) finishes the
  animated close. Panel sheet: grab button (`aria-expanded`) + swipe on the sheet (down only at scrollTop 0).
- Fullscreen via Fullscreen API; button hidden when `document.fullscreenEnabled` is false.
- State for CSS via attributes only: overlay `data-state="open|closing"`, `data-dragging`, `data-zoomed`,
  `data-panel`, `data-closing-down`; sheet `data-sheet="open"`; `[hidden]` for binary visibility. CSSOM only
  for continuous values (transform, `--td-lb-drag`). No inline `style=""`, no injected `<style>`.

## Styles (`src/styles/components/lightbox.css`, in `td.css` via manifest)

Adapted from 135 (BEM `.td-lightbox__*`), always dark (own local tokens), using the kit: toolbar + counter
carry `td-glass-surface td-glass-surface--clear` (recipe + fallbacks from `glass.css`, no duplicated
fallback CSS) with a local dim `::before` reading `var(--_td-glass-dim, var(--td-glass-dim))`; panel +
sheet solid; buttons 40 px, `var(--td-touch-min)` (44 px) on `(pointer: coarse)`; z-index
`var(--td-z-lightbox)`; safe-area insets; reduced motion; `[hidden]` guard; forced-colors button colours.
Attribute selectors replace 135's `.is-*` classes.
