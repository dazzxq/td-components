# Plan — v0.13.0: backlog quick wins

Roadmap "Later — backlog" items that are small, additive and need no design sign-off. Branch `feat/v0.13.0-backlog`.
Lead-built (no agents). Every addition is opt-in; no existing behaviour changes.

## In scope

1. **`TdButton.run(asyncFn)`** (backlog "button `run(asyncFn)`"): `await btn.run(async () => …)` sets the existing
   `loading` state (aria-busy, clicks swallowed, focus kept) for the duration, clears it in `finally`, returns the
   function's result / rethrows its error. Re-entrant calls while running return the SAME in-flight promise (no double
   submit). Non-function → `TypeError`. Tests: busy during, cleared after resolve AND reject, result/error propagated,
   re-entrancy, a disconnected button still clears.
2. **`td-toggle` `commit(asyncFn)` + pending** (backlog "toggle `commit()` / trạng thái pending (optimistic)"):
   `toggle.commit(async (next) => save(next))` — for pages that persist a switch. The switch shows `next` immediately
   (optimistic), is marked pending (`aria-busy="true"` on the input + `[data-pending]` on `.td-switch`, further
   activation ignored), then: resolved (not `false`) → keeps `next`; resolved `false` or rejected → reverts to the previous
   state and emits `commit-error` `{ checked: previous, error }`. Returns a promise of the final checked state. Usable
   from a `change` handler of a `controlled` toggle (`e.detail.checked` → `commit(() => save(e.detail.checked))`).
   CSS: pending thumb dimmed + `cursor: progress`, reduced-motion safe. Tests: optimistic value, pending ARIA +
   ignored clicks, success, `false`, rejection + event, form value follows the final state, one `change` per user action
   (commit emits no extra `change`).
3. **Textarea auto-resize** (backlog "textarea autoresize bằng CSS `field-sizing`"): additive `autoresize` boolean on
   `td-input-field type="textarea"` (review ISSUE-1: `field-sizing: content` ignores `rows`, so the minimum is carried
   explicitly): the component writes the parsed `rows` (default 4) to the CSSOM custom property `--td-field-rows` on the
   control, and field.css applies, under `[data-autoresize]`: `field-sizing: content; min-block-size: calc(var(--td-field-rows)
   * 1lh + <the control's vertical padding + border>); max-block-size: var(--td-field-autoresize-max, calc(16lh + …));
   overflow-y: auto` (progressive: engines without `field-sizing` keep the fixed `rows` height — no JS fallback). Tests
   (Chromium): empty textarea with default `rows` (4) and with `rows="2"` is exactly as tall as the non-autoresize one
   with the same rows; typing many lines grows it; it stops at the max and scrolls.
4. **`demo.html` form section** (backlog): a real `<form>` using td-input-field, td-dropdown, td-chip-input,
   td-datetime-picker, td-checkbox, td-toggle (with `commit`), and a `type="submit"` td-button. Flow (review ISSUE-2):
   `TdFormValidation.attach(form, { onValid })`; an invalid submit is prevented by attach() and neither calls `run()`
   nor touches the output; `onValid` calls `submitButton.run(async () => { await fakeDelay(); render(new FormData(form)) })`
   — the output lists the entries as text only. Checked in a browser (0 console errors,
   validation + submit path work).
5. **GitHub CI** (backlog): `.github/workflows/test.yml` — on push/PR: checkout, Node 22, `npm ci`, `npx playwright-core
   install --with-deps chromium firefox webkit` (the pinned revisions), `npm run build:csp-fixture`, `npm test`.
   **Not verifiable locally** (never pushed, per the user's rule); documented as such.
6. **Docs:** components.md (button `run`, toggle `commit` + `commit-error`, input-field `autoresize`), roadmap (mark the
   items done; "story cho datetime-picker" is already done since 0.10.0; fix the stale "Done" pointer), CHANGELOG 0.13.0,
   version 0.13.0 + lockfile root.
